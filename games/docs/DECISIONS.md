## 2026-08-14：五目並べの盤を「交点に石を置く」正しい碁盤にした

`app/globals.css` の `.gm-cell` の罫線を、マスの境界（上辺・左辺の border）から
**マスの中心を通る線**（背景グラデーション2本の十字）に変えた。盤の端では外へ
はみ出す側の半分を落とし、四隅は縦横とも半分にしている。

**理由**：五目並べ（囲碁）の石は**線の交点**に置くもので、マスの中には置かない。
境界に線を引いていたため石がマスの中に浮き、碁盤に見えていなかった。
罫線を中心に通せば、石の位置（セル中央）がそのまま交点になる。

**あわせて2つのバグを直した。** `.gm-cell.win` と `:hover` が `background` の
一括指定で色を差していたため、**罫線（background-image）ごと消えていた**。
`background-color` に変え、勝ち5連は四角い塗りではなく石にリングを付ける形にした
（マスを塗ると、交点に石を置く盤という見え方が崩れるため）。
直前の手の印も四角い枠から丸に変えている。

**グラデーションの向きと線の向きは入れ替わる。** `linear-gradient(to right, …)` は
左右方向に色が変わるので**縦線**になる。最初これを取り違えて端の処理を書き、
盤の外周が1マス内側にずれた。CSSにその旨をコメントで残してある。

## 2026-08-14：大富豪にローカルルールを3つ足し、CPUの速さと相手の残り札を見えるようにした

`lib/daifugo.ts` に **5飛ばし・9リバース・階段のON/OFF** を足して9種類にし、
`RULE_LABELS` の説明を具体例つきに書き直した。画面には**CPUの速さ**（ゆっくり
2秒／ふつう1.3秒／はやい0.7秒）の切り替えと、**相手の残り札を裏向きの札で見せる**
表示を足した。ページには `RULE_LABELS` から作るルール表と、縛りの追加解説を置いた。

**理由**：運営者から「CPUが速い」「ローカルルールを増やしたい」「縛りが何なのか
分からない」「相手の手札を可視化してほしい」の4点の要望があった。

**手番の向きを state に持たせた**（`direction: 1 | -1`）。9リバースは席順の計算を
逆にするルールなので、席を求める箇所（`nextActive` / `nextInTrick`）を `seatAt()` に
集約して、そこだけが向きを知る形にした。5飛ばしは「出した枚数だけ次の人を飛ばす」で、
4人戦で3枚以上出しても**自分の番には戻らない**ところで止めている。

**ルールの説明文は `RULE_LABELS` の1か所だけに持つ。** 設定パネルとページの表の
両方が同じ配列から作られるので、片方だけ直して食い違うことがない。
説明は「例: ♥5 の次に ♥8 を出す → 以降その場は ♥ だけ」のように、
**何が起きるかを具体的な札で**書くようにした。

**相手の手札は伏せたまま枚数だけを札で見せる。** 中身が見えると勝負にならない。
裏向きの札には白いフチを付けている（フチが無いと模様が続いて1枚の帯に見え、
何枚あるのかが読めなかった）。狭い画面で14枚が並びきらないぶんは切っている
（枚数は数字が示しているため）。

**CPUの待ち時間を消す選択肢は作らなかった。** 革命・8切りなどの実況を読む時間が
要るので、いちばん速い「はやい」でも0.7秒は残している。

## 2026-08-14：大富豪を追加した（トランプ対戦系の1本目）

`lib/daifugo.ts`（札・役の判定・場の進行・CPU）と `app/daifugo/`。
1人＋CPU3人の4人戦を5回戦戦い、通算点で最終の階級を決める。
8切り・革命・縛りは標準で有効、都落ち・11バック・スペ3返しは設定パネルで切り替える。
仕様は [../../docs/features/game-daifugo.md](../../docs/features/game-daifugo.md)。

**理由**：トランプはソリティア系3本だけで、**対戦型のトランプゲームが1本も無かった**。
主要な無料ゲームポータルには必ず置かれている枠で、games への表示クエリの大半が
トランプ系（ソリティア・スパイダー）である以上、いま来ている検索者の回遊先として
そのまま効く。名称・ルールともパブリックドメインで権利面もクリーン。

**役は「同じ数字の組」と「同じスートの階段」の2種類だけにした。** 判定を
`classify()` の1関数に閉じ込め、出せる手の数え上げ（`enumeratePlays`）も
CPUもすべてここを通す。ジョーカーが絡むと同じ札の集合が2通りの役に読めるが
（`♠5 ♠6 ジョーカー` は 4-5-6 とも 5-6-7 とも読める）、**1通りに決め打った**
— プレイヤーに読み方を選ばせる画面は、使う場面のわりに操作が重い。

**CPUの3段階は、五目並べ・リバーシと同じく「見る項目の違い」で分けた。**
乱数で悪手を混ぜると「たまに変な手を打つ強いCPU」になって理解できない負け方に見える。
かんたん＝出せる役から適当に選ぶ（切り札を序盤に切ってしまう）、ふつう＝弱い役から
順に出す、つよい＝それに加えて組を崩さない・8切りを活かす・手札が多いうちは
切り札を温存して見送る。どの段階でも上がれる手は必ず出す。

**ローカルルールはON/OFFにした。** 大富豪は地域差がいちばん大きい遊びで、
「自分の知っているルールと違う」がそのまま離脱になる。もっとも一般的な構成
（8切り・革命・縛り）を初期値にし、割れる3つ（都落ち・11バック・スペ3返し）は
畳んだ設定パネルに置いた。設定は記録ではないので `lib/records.ts` には入れず、
リバーシ・五目並べの強さ設定と同じく画面側の localStorage キーで持つ。

## 2026-08-14：五目並べを追加した（CPU対戦の2本目）

`lib/gomoku.ts` + `app/gomoku/`。13×13の盤で、先に5つ並べたほうが勝ち。
CPUは3段階で、リバーシと同じく「深さ違い」ではなく**見る項目の違い**で分けた
（かんたん＝自分の並びだけ／ふつう＝自分と相手の並び／つよい＝上位候補を反復深化で読む）。
どの段階でも「即勝ち」と「5連の防ぎ」だけは必ず正確に打つ。

**理由**：11本のうち相手と競う対戦型はリバーシ1本だけで、「CPUと勝負したい」層の
受け皿が薄かった。リバーシで作った骨格（盤面UI・手番管理・CPU・強さ選択・戦績）が
そのまま効くので、対戦型としては一番安く足せる1本だった。

**判断**：盤は13×13。連珠公式の15×15はスマホ（360px幅）で1マス24px前後になり操作しづらい。
禁じ手（三三・四四・長連）は入れない — カジュアル層には説明コストが利益を上回るため。
そのぶん先手が有利になるので、**先手を1局ごとに入れ替える**ことで釣り合いを取った
（色を選ばせるリバーシとはここだけ作りが違う）。禁じ手を入れていない以上、
競技ルールの名称である「連珠」は名乗らない。仕様は
[docs/features/game-gomoku.md](../../docs/features/game-gomoku.md)。
## 2026-08-13：ブロックパズル（8×8の配置パズル）を追加した

`lib/block-puzzle.ts`（盤面・ピース・配置判定・消去・得点・終了判定）と
`app/block-puzzle/`。仕様は
[../../docs/features/game-block-puzzle.md](../../docs/features/game-block-puzzle.md)。

**理由**：既存の10本に「配置パズル」型が1本も無かった。この型は世界的に遊ばれていて
ルール説明のコストが低く、時間制限も落下も無いので滞在時間が伸びやすい。

**回転は入れていない。** この型の標準仕様で、回転できると「どこにでも置ける」に寄って
ゲームオーバーの緊張感が消えるため。そのぶん回転済みの形を配り札の候補として持つ
（`rotate90` は候補を組み立てるときだけ使い、遊んでいる最中は回さない）。

**配り札は均等ではなく重み付きで選ぶ。** 候補から均等に引くと5マス以上の大物ばかりが来て
数手で詰む。形の一族ごとに重みを持ち、回転で増えた分はその中で等分している
（向きの多い形が出やすくなるのを防ぐため）。

**ドラッグ中はピースを指の1.6マスぶん上に出す。** スマホでは指がピースを完全に隠すので、
置き先が見えない。掴む当たり判定も、見た目のピースより大きく取っている。

**記録は共通モジュール（`lib/records.ts`）に載せた。** 最初は独自キー
（`block-puzzle:best`）で書いていたが、並走していた記録の共通化が先に main に入ったため、
`useRecords('block-puzzle')` に移した。個別キーは作らない。

## 2026-08-13：全10ゲームに記録（ベスト・勝敗・クリアタイム）を揃えた

`lib/records.ts` に共通モジュールを作り、キーを `hasokon-games:records:<gameId>:v1` に
統一した。記録があったのは10本中4本（2048・リバーシ・ノノグラム・フリーセル）だけで、
GA4のページビュー上位（ソリティア35・マインスイーパー39・スパイダー35。2026-08-13 取得）が
すべて「記録なし」側だった。旧キー（`g2048:best`・`freecell:best`・`nonogram:solved`）は
初回読み込み時に新形式へ移行して消す。

**理由**：定番ゲームは他サイトでも遊べるので、「自分の記録がここにある」ことが
このサイトで遊び続ける理由になる。ベストタイムと勝率は「もう1回」の動機そのもの。

**判断**：`localStorage` は Safari の ITP で7日間訪問がないと消えるため、記録の近くに
保存先の注記を置いた（初回だけ開いて見せ、以後は折りたたむ）。黙って消えるより先に伝えるしかない。
サーバー保存は、アカウントもAPIも持たない静的配信の方針に反するので採らない。
リバーシの `reversi:level` / `reversi:color` は遊んだ記録ではなく「設定」なので移行せず、
これまでどおりゲーム側に残した。仕様は
[docs/features/game-records.md](../../docs/features/game-records.md)。

## 2026-08-05：無料ミニゲーム集の初期実装（ナンプレ・リバーシ・ブロック崩し）

ゲームロジックは `lib/{slug}.ts` の純関数に置き、`Game.tsx` は入力と描画だけにしている
（ブロック崩しの物理演算も含む）。

境界値と終了条件をテストで押さえられる形にした。
