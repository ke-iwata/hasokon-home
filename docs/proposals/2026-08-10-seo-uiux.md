## 提案1：年収の壁の判定を「学生かどうか」から「年齢」に直す（正確性・最優先）

**このサイトで最も重い問題です。SEOではなく、計算結果そのものが誤っています。**

### 根拠

`lib/nenshu-kabe.ts` は利用者の立場を4つに分けています。

```ts
type Position =
  | 'spouse'     // 配偶者の扶養内で働く（パート等）
  | 'student'    // 親の扶養内・19〜22歳の学生
  | 'dependent'  // 親の扶養内・その他
  | 'none';      // 扶養に入っていない
```

ところが、150万円・159万円・197万円の壁の根拠になっている制度は
いずれも**年齢だけで決まり、学生であることを要件にしていません**。

| 制度 | 実際の要件 | 出典 |
|---|---|---|
| 健康保険の被扶養者認定（150万円未満） | 19歳以上23歳未満（配偶者を除く）。**学生である必要はない** | [日本年金機構](https://www.nenkin.go.jp/oshirase/taisetu/2025/202508/0819.html) |
| 特定親族特別控除（159万・197万） | 19歳以上23歳未満で生計を一にする親族。**学生要件なし** | [国税庁 No.1177](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1177.htm) |
| 勤労学生控除（163万） | 学生であること。**年齢要件はない** | 所得税法 |
| 短時間労働者の社会保険適用拡大（106万） | 週20時間以上・51人以上等。**昼間学生は適用除外** | [厚労省の適用要件](https://www.zeem.jp/useful/column/socialinsurance_parttimeworkers_3/) |

つまり、**年齢で決まるものを学生条件にし、学生で決まるものに年齢条件を付けている**という
取り違えが起きています。

### 実際の出力（`evaluateKabe` を直接呼んで確認）

```
19-22歳の学生・51人以上・週20h   => 106万円の壁 / 119万 / 150万(学生) / 159万(学生) / 163万(学生) / 178万 / 197万(学生)
20歳フリーター(親の扶養/学生でない) => 119万 / 130万 / 136万(扶養) / 178万
25歳の大学院生(親の扶養)          => 119万 / 130万 / 136万(扶養) / 178万
```

3パターンすべてに誤りがあります。

1. **19〜22歳の学生に106万円の壁が出る** → 昼間学生は適用拡大の対象外なので、出るべきではない
2. **20歳のフリーター（学生でない）に130万円の壁が出る** → 正しくは**150万円**。
   さらに159万・197万（特定親族特別控除）が出るべきなのに出ない。
   **この層は扶養の範囲を20万円少なく案内されている**ことになります
3. **25歳の大学院生に163万円の壁（勤労学生控除）が出ない** → 勤労学生控除に年齢要件はないので、出るべき

2 は影響が大きいです。19〜22歳で学生でない人（既卒・フリーター・専門学校を出た人など）が
「親の扶養内・その他」を選ぶと、**実際には働ける20万円分を働かないよう案内してしまいます**。

### 提案する対応

`Position` を「立場（配偶者／親の扶養／扶養外）」と「年齢が19歳以上23歳未満か」「学生か」の
**3つの独立した入力に分解する**のが素直です。

```ts
interface KabeInput {
  income: number;
  position: 'spouse' | 'dependent' | 'none';
  age19to22: boolean;   // 19歳以上23歳未満（12/31時点）
  isStudent: boolean;   // 昼間学生
  size51: boolean;
  hours20: boolean;
}
```

そのうえで各 `applies` を直します。

| 壁 | 現在 | 直した後 |
|---|---|---|
| 106万 | `position !== 'none' && size51 && hours20` | `+ !isStudent` |
| 130万 | `spouse \|\| dependent` | `+ !(dependent && age19to22)` |
| 150万 | `student` | `dependent && age19to22` |
| 159万・197万 | `student` | `dependent && age19to22` |
| 163万 | `student` | `isStudent`（年齢を問わない） |

UI（`Calculator.tsx`）は立場のセレクトに加えて、
「19〜22歳」「学生」のチェックボックスを2つ足す形になります。

**テストを先に足してください。** 上の3パターンはそのまま回帰テストになります。
ラベルの「（学生）」という表記も「（19〜22歳）」に変える必要があります。

### 期待できる効果

順位や流入への直接効果はありませんが、**このサイトの competitive advantage そのものを守る施策**です。

[docs/RESEARCH-2026-08.md](https://github.com/ke-iwata/hasokon-tools/blob/main/docs/RESEARCH-2026-08.md) は
「量産型サイトは改正が他制度へ波及する効果まで追えない、精度で勝てる」を戦略の柱に置いています。
その柱になっているページ自身が誤った金額を出している状態は、戦略と噛み合っていません。

年収の壁は YMYL（Your Money or Your Life）領域で、
検索エンジンも正確性を強く見ます。**流入を増やす前に直すべき順序**だと考えます。

### 工数

**1〜1.5日。** ロジックの修正は半日、テストの追加とUIの入力追加、
ページ本文とFAQの文言修正を含めてこの程度です。

## 提案2：2026年10月の「週20時間の壁」に先回りする（コンテンツ・期限あり）

### 根拠

**2026年10月、106万円の壁（賃金要件・月8.8万円）が撤廃されます。あと約2ヶ月です。**
週の所定労働時間が20時間以上なら、年収に関係なく社会保険の加入対象になります
（学生を除く）。新たに約200万人が対象になる見込みです。

現在の `lib/nenshu-kabe.ts` は、この改正を**note の1文でしか扱っていません**。

> 賃金要件（月8.8万円）は2026年10月に撤廃予定で、以降は週20時間以上なら年収に関係なく加入対象になります。

CLAUDE.md にも「10月以降に note とページFAQの文言を見直すこと」と宿題として書かれています。

改正後は**106万円という金額の壁が消えます**。金額で判定している現在の作りのままだと、
10月以降は「106万円の壁」という存在しないものを表示し続けることになります。

### 提案する対応

**A. 既存ページを10月の改正に合わせて作り替える（必須・期限あり）**

- 106万円の壁を「週20時間の壁」として作り直す（金額ではなく労働時間の判定に変える）
- 施行前後で表示を切り替える（施行日を定数に置き、それ以前は現在の表示のまま）
- ページ本文とFAQを書き換える

**B. 社会保険の「働き損」計算機を新設する（RESEARCH-2026-08 の最有力案）**

[docs/RESEARCH-2026-08.md](https://github.com/ke-iwata/hasokon-tools/blob/main/docs/RESEARCH-2026-08.md)
が2026年8月時点で「最有力」と結論づけた案です。当時から状況は変わっていません。

> 「扶養内で働き続ける場合」と「加入する場合」を並べて比較し、手取りの逆転と損益分岐点を出すものがない

改正の2ヶ月前というタイミングは、この調査結果を実行に移す好機です。
検索需要は施行の直前から立ち上がり、施行後しばらく続きます。
`lib/nenshu-kabe.ts` と `lib/furusato-nozei.ts` の令和8年分の税額計算をそのまま再利用できます。

### 期待できる効果

- A は**やらないと10月に誤情報になる**ため、効果というより必須の保守です
- B は RESEARCH の分析どおりなら空白のあるキーワードです。
  ただし前回調査から2ヶ月経っており、**着手前に競合の再確認をしてください**。
  量産型サイトは改正当日に対応してくることが分かっています

### 工数

**A は10月までに必ず終わらせる必要があります。**

   `hasokon-home/index.html` のカード一覧は tools / games のレジストリと**手動同期**です
   （ファイル内のコメントにもそう書かれています）

### 期待できる効果

## 調査環境の状態

次回この調査をするときのために記録しておきます。

### 使えるようになったもの

- **hasokon.com への直接アクセス**（2026-08-10 に許可設定）。
  301の検証・HTTPヘッダ・配信後の実HTMLの確認ができるようになりました
- **GA4 Data API**（`analyticsdata.googleapis.com`）は有効化されています

### まだ使えないもの

- **GA4 Admin API**（`analyticsadmin.googleapis.com`）が GCPプロジェクト `hasokon-site`
  （番号 495907315040）で無効のままです。

  ```
  Google Analytics Admin API has not been used in project 495907315040 before or it is disabled.
  reason: SERVICE_DISABLED
  ```

  **Data API を叩くにはプロパティIDが必要で、その一覧を取得する手段が Admin API です。**
  測定ID（`G-2Z0K6Y2FX0`）からプロパティIDは引けないため、**今回もGA4のデータは取れませんでした**。

  解決策は2つあり、どちらか一方で足ります。

  1. Admin API を有効化する
     → https://console.developers.google.com/apis/api/analyticsadmin.googleapis.com/overview?project=495907315040
  2. **GA4のプロパティIDを直接この定期タスクに渡す**（Admin APIなしで済む簡単な方）
     GA4管理画面の「管理 > プロパティ > プロパティの詳細」に表示される9〜10桁の数字です。
     これが分かれば `properties/{id}:runReport` を直接叩けます

  あわせて、サービスアカウント `claude@hasokon-site.iam.gserviceaccount.com` が
  GA4プロパティの「閲覧者」に入っているかも確認してください
  （Data API のプローブは `PERMISSION_DENIED` を返しており、権限付与の成否は未確認です）

### 調査に使ったAPI

| 用途 | エンドポイント |
|---|---|
| クリック・表示・順位 | `webmasters/v3/sites/{site}/searchAnalytics/query` |
| サイトマップの状態 | `webmasters/v3/sites/{site}/sitemaps` |
| ページ単位のインデックス状況 | `searchconsole.googleapis.com/v1/urlInspection/index:inspect` |
| （未使用）GA4のレポート | `analyticsdata.googleapis.com/v1beta/properties/{id}:runReport` |

認証は環境変数 `GOOGLE_SERVICE_ACCOUNT_JSON`。Search Console では `siteFullUser` 権限を持っています。
