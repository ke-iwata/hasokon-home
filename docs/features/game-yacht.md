## 2026-08-22：サイコロを立体にした

運営者から「ヨットとかサイコロのやつ、描画を強化できない？」（参考として
CSSの3Dサイコロの記事を提示）。**3×3の点を並べた平面から、CSSの3D変換で
作った立方体に差し替えた。**

**サイコロツール（`tools/app/_roulette/Dice3D.tsx`）に同じ作りが既にあったので、
記事から起こさずそちらを移植した。** あちらは陰影の付け方・端末判定・
アニメーションの止まり方まで詰めてあり、記事の内容はその一部にあたる。
tools と games は別アプリでコードを共有できないため、**片方を直したら
もう片方も見ること**（両方のソースにその旨を書いてある）。

### ヨット固有の作り

- **キープした駒は転がさない。** 振り直しても手元に残っているのが見えないと、
  キープが効いているのか分からない。転がすかどうかは駒ごとの `spinKey` で決め、
  **残り回数（`rollsLeft`）が減ったときに、キープしていなかった駒だけ**増やす。
  出目の変化では判定できない（振り直して同じ目で止まることがある）
- **`Math.random()` を使わない。** 静的書き出しなので、描画のたびに値が変わると
  サーバー側で書き出したHTMLと食い違う。転がり方は駒の番号から決まる値で出す
- **立方体の影絵が枠に届かない大きさにする。** 押す先の48pxは変えずに内側の
  余白で調整した（立方体30px。斜めから見ると約1.26倍＝38pxに見える）。
  詰めすぎると立方体が枠を覆い、**キープ中の色が見えなくなる**（実際に一度なった）
- キープ中は枠の外側にもう1本の輪を足した（`box-shadow`。場所を取らないので
  隣の駒とぶつからない）。立体だと枠の色だけでは細い線しか残らない

### 移植元から引き継いだ注意

- **陰影は面ごとに固定しない。** 止まったときの向きから法線を計算して濃さを出す。
  固定すると、出目が変わって立方体が回った瞬間に手前の面が暗くなって破綻する
- **陰影は `filter` ではなく巨大な inset シャドウで付ける。**
  `filter` は重ね合わせの文脈を作るので立体が潰れる
- **アニメーションに `fill-mode` を付けない。** 付けると、アニメーションが
  走らない状況（タブが裏・強い省電力）で途中の姿勢のまま止まる
- **`preserve-3d` は「対応している」と報告されても潰れることがある。**
  実際に描かせて測り（`detect3D`）、駄目なら平面表示に落とす。
  判定はマウント後にしかできないので、判定前は平面で出す
- `prefers-reduced-motion` を見て、転がりを止められるようにしてある

`main .card` の高さは変わっていない（320×568 で 806px。変更前と同じ値を実測）。

### 続けて直したこと（同日・運営者の指摘2件）

**1. 取った役は、役ごとに印が残る。**
最初は「直前に記入した役」だけに印を付けたが、運営者から
「そうではなくて役ごとにちゃんと選択したのは残るようにしてほしい」。
**直前の1つではなく、取った役すべてに印を残す**のが正しい——
残り何を狙えるかの判断に毎手番使う情報なので、表を見ただけで分かる必要がある。

- 自分が取った役：地を変え、**左端に線**を引く（行の高さも列幅も動かさない）
- CPUが取った役：**点数の欄にだけ**地を敷く（同じ役を先に取られたかが分かる。
  行そのものの見た目＝自分が取ったかどうかとは混ざらない）
- **記入済みの点数を薄くしない。** 元は `--muted` だったので、
  「その局で何を取ったか」という唯一の記録が、いちばん読みにくい字になっていた。
  薄くするのは役名のほうだけにした（押せなくなった目印）

**2. 役の条件を絵で見せる。**
運営者から「役の意味がわかるようなサイコロの表示が欲しい（フォーダイスなら
4つが同じでないといけないというのがひとめでわかるように）」。
役名の下に小さな絵（`app/yacht/YakuMark.tsx`）を敷いた。
色の付いた四角＝そろえる目、枠だけ＝どの目でもよい、薄い色＝別の同じ組、
階段＝連続する目、サイコロ1個＝その目を集める。

**大きさは実測から決めた。** 役名の欄は320px幅の端末で53pxしかなく、そこでは
下段の役名（フォーダイス等）がすでに2行に折り返す。行の高さは44pxで固定なので、
**下段の絵は高さ9pxまで**。一方**上段（エース〜シックス）は役名が短く1行に収まる**ので、
サイコロの目が読める15pxまで上げてある。絵の言葉が2つ（サイコロと四角）に
なるのは承知のうえで、それぞれの役でいちばん分かりやすい描き方を採った。

**フルハウスは色を分けないと「5つそろえる」に見える。** 3つと2つで濃さを変えている。

文字の説明（`CATEGORY_HINT`）は行の `aria-label` に残してあり、
**絵は `aria-hidden`**（同じことを二重に読み上げさせない）。

**3. サイコロは左から1つずつ止まる。**
**ずらすのは長さ（duration）であって、開始（delay）ではない。**
`animation-delay` でずらすと、`fill-mode` を付けていないぶん、待っているあいだ
新しい目を見せたまま止まって見え、そのあとで転がり出す（先に着地して振り直した
ように映る）。5個いっせいに転がり出して、止まる時間だけを 0.58秒から 0.1秒ずつ
延ばしている（`--i` を渡して `calc()` で出す）。

## 権利面（先に確定）

- **ゲームのルール自体は著作権・商標の保護対象ではない。** 規制されるのは
  名称（Yahtzee／ヤッツィー）だけ。ルール（上段ボーナスを含む）を踏襲すること
  自体に権利リスクはない
- 名称は**パブリックドメインの伝統ゲーム名「ヨット（Yacht）」**で出す。
  `title` / `description` / `h1` / slug に「ヤッツィー」を使わない。
  本文で「ヤッツィーの名でも知られる」と事実として触れるのは可。
  役名はフルハウス・ストレート等の一般名を使う
- 二角取り（#152）で同じ作法を通しているので整合している

## 背景と根拠

### ジャンルの空白：カードと盤面はあるが、ダイスゲームが1本もない

現在の23本はトランプ8・盤面パズル9・アクション3・花札1・麻雀牌2という構成で、
**サイコロを使うゲームが1本もない**（tools側に「サイコロを振る」ツールはあるが
ゲームではない）。ヨットは「5個のサイコロを最大3回振って役を作り、
12〜13カテゴリのスコアシートを埋める」定番ダイスゲームで、
このジャンルの空白を1本で埋められる。

### 需要と競合（2026-08-21 調査）

- ひといきゲーム・ゲームのつぼ・8kz など主要な無料ブラウザゲームサイトが
  軒並み掲載する定番。ボードゲームアリーナでも常設で、「桃鉄」系の
  ミニゲーム収録などで若い層にも名前が通っている
- 競合のブラウザ版は**古いFlash移植風のUIが多く、スマホ最適化が弱い**。
  当サイトの「モバイル1画面・タップ完結」の型がそのまま差別化になる
- 「ヨット ゲーム」「サイコロ ポーカー」「ダイスゲーム 無料」系の
  恒常クエリの受け皿になる

### 実装資産の再利用が効く

- **対CPU 1人プレイの型**（スタート待ち・思考時間の演出）は
  大富豪・スピード・リバーシ等で確立済みの共通作法を流用する
  （ただし先攻後攻の選択は置かない。上記のとおり手番が独立しているため）
- CPUの手は「各カテゴリの期待値計算」だけで成立する（残り2回の振り直しで
  どの目をキープするかの全探索は 2^5 × 6^k 程度で軽い）。
  探索木も機械学習も不要で、カードゲームのCPUより単純
- 盤面はサイコロ5個＋スコア表だけ。絵柄アセットはCSS/SVGの目玉描画のみで、
  カード画像のような大きな新規アセットは不要

## ゲーム仕様（想定）

- 1人プレイ（対CPU）。12カテゴリの一般的なヨット構成
  （エース〜シックス／フルハウス／フォーダイス／S・ストレート／L・ストレート／
  ヨット／チョイス）
- **上段ボーナス（上段6カテゴリの合計63点以上で+35点）は採用する。
  設定トグルは作らない**（確定）。理由：トグルはスマホの画面を1段確実に食い
  （`mobile-one-screen` はリバーシ・大富豪で400〜600px削った経緯がある）、
  国内の主要無料サイトの「ヨット」も実質どれも上段ボーナスあり構成なので、
  ここで伝統ルールに寄せてもユーザーの期待とズレるだけで得がない
- 3回まで振れる。キープはサイコロをタップで切り替え
- **先攻・後攻の選択は置かない**（確定）。ヨットは相手の手が自分の手に一切
  影響しない並行プレイで、先攻後攻を選ばせても勝率も体験も変わらないため。
  共通作法のうち「スタート待ち・思考時間の演出」は流用し、手番選択だけ外す
- CPUは強さ2段階（期待値最大化＋弱いほうはランダム性を混ぜる）。
  **上段ボーナスがカテゴリ横断の条件（合計63点）なので、1手ごとの貪欲な
  期待値最大化だけだとボーナスを取りに行かない**（序盤にエース〜シックスを
  捨てて後半に35点を落とす打ち方になる）。強いほうのCPUは上段の進捗
  （63点までの貯金）に重みを乗せる補正を入れる（完全な動的計画法までは不要。
  「たまに負ける」強さで十分。ターン内の振り直し全探索は 2^5 × 6^k で軽い）
- 記録は既存の game-records の仕組みに乗せる（ベストスコア・平均・回数）
- **スマホ1画面のレイアウト**：スコア表は上段6＋ボーナス＋下段6で実質13行あり、
  サイコロ5個・残り回数・「振る」ボタン・記録の帯と合わせると幅390pxで
  縦に積みきれない。**スコア表は上段6・下段7の2列に折る**（縦13行→7行）。
  ゲームの盤は早見表と違い横スクロールで逃がせない（遊ぶたびにスクロールが
  要る）ため、折り返しで解く前提を先に置く。`--chrome` の実測値は実装時でよい

## やらないこと

- オンライン対戦（静的サイトのため）
- 2人対戦（同一端末のパス&プレイ）は初版では見送り。需要があれば後続

## 期待される効果

- ダイスゲームという新ジャンルの面を最小工数で開設し、サイト全体の
  「定番ゲームはだいたいある」感を強化（回遊・滞在の底上げ）
- 恒常クエリ「ヨット ゲーム 無料」等での新規流入。カード系と客層が
  少しずれる（ボードゲーム好き・桃鉄経由の若年層）ため、入口の多様化になる

## 必要な工数（消費トークンの目安）

- 役判定・スコア計算＋テスト: 小（純粋関数の集合）
- CPU（期待値計算）＋テスト: 中
- 画面（サイコロ・キープUI・スコア表・記録）: 中
- ページ本文（ルール・コツ・由来・FAQ）: 小
- 合計: **1〜2セッション・概算 150k〜200k トークン**
  （スピード・リバーシ級。カードアセット新規作成が無いぶん軽い）
