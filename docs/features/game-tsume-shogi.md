## 背景と根拠

### 需要は候補の中で 2 位、しかも季節性が無い

  **Yahoo! 約 14,800／Google 約 59,200**（aramakijake.jp の推定。桁の目安）。間違い探し（22,000／88,000）に次ぐ 2 位で、

### 生成すれば、権利と作問コストの問題が消える

- 問題は「玉の位置と周囲の駒をランダムに置き、攻方の持ち駒を与え、詰み探索で**手数ちょうど・唯一解**を確認する」で作る。
  合法手生成と深さ 1〜3 の探索は盤が 9×9・駒 8 種で閉じるので、ブラウザ内で 1 問あたり数十 ms〜数百 ms
- 盤・駒の絵は**漢字 1 文字（王・飛・角・金・銀・桂・香・歩・成駒は と・成香・成桂・成銀・馬・龍）を SVG のテキストで描く**。
  特定メーカーの駒字体・盤の木目は使わない（権利と作りやすさの両方）
- 詰将棋のルールは一般のもの（下記「ルール」）。ルールに著作権は及ばない（#236 で整理した考え方）

## ルール（画面に出す定義。実装の仕様でもある）

1. 攻方（プレイヤー）が先手で、**王手の連続**で玉方の玉を詰ます。王手でない手は**指せるが不正解**で、「王手ではありません」と理由を出して
   やり直し（初心者に親切な側に揃える。ハイライトは合法手すべてに出し、王手かどうかは指してから判定する。#317 レビュー nit）
2. 玉方は王手を**必ず**外し、**最も長く逃げる**手を選ぶ（3 手詰で 1 手目に対し複数の応手があれば、詰まないものがあれば不正解、
   すべて詰むなら最長のもの）
3. 攻方の持ち駒は問題で指定。**玉方の持ち駒は「残り駒全部」**（盤上と攻方の持ち駒と玉を除く全部。合駒に使える）
4. 二歩・打ち歩詰め・行き所のない駒（1 段目の歩香、1〜2 段目の桂）は禁止。成れるときは成・不成の両方を手として扱う
5. **余詰なし**（作意以外の初手で詰まない）。1 手詰は「詰む初手がちょうど 1 つ」、3 手詰は「3 手で詰む初手がちょうど 1 つ、
   かつ 1 手で詰む手が無い」。**唯一性は初手についてだけ。3 手目は、その局面で詰む手ならどれでも正解**（最終手の余詰は許容。
   `judge` は `solution[2]` と照合せず、指した手のあとの局面が詰みかで判定する。#317 レビュー must 3）
6. **合駒・無駄合い**：合駒で外れる王手は詰みにならない（1 手詰・3 手詰とも。判定は `legalMoves` に任せる）。**生成では 1 手詰・3 手詰とも、
   合駒ができる位置（玉から 2 マス以上離れた飛・角・香の王手）を避ける**。無駄合いの判定（合駒が手数を延ばすだけで詰みを防げない場合は
   作意に含めない慣例）は曖昧さの元で、生成側で合駒自体を出さないほうが安全（#317 レビュー nit）
7. 攻方の玉は盤に置かない（通常の詰将棋どおり）。**駒の数は種類ごとに上限を守る**：歩 18・香 4・桂 4・銀 4・金 4・角 2・飛 2・玉 2
   （攻方の玉は盤外に置かず計算から除く）。成駒は元の駒として数える。玉方の持ち駒は**種類ごとに**「上限 − 盤上 − 攻方の持ち駒」で出す
   （総数 40 枚だけで引くと歩 19 枚などの不正な状態を作れる。#317 レビュー must 5）

## 提案する仕様

### 画面（1 画面）

- **モード**：「1手詰」「3手詰」「今日の 1 問」（3 手詰・全員同じ）。既定は 1 手詰（初心者の入口）
- 上部に玉方の持ち駒（折り畳まない。「残り全部」は枚数で表示）、中央に 9×9 の盤、下部に攻方の持ち駒。
  盤の筋・段の番号（１〜９・一〜九）は盤の外に小さく
- 操作：駒をタップ → 動ける先がハイライト → 先をタップ。持ち駒も同じ。成れるときは「成／不成」の 2 択を盤上に出す
- **44px の規則の当てはめ**（#317 レビュー must 4）：9 マスの盤で隣り合うマスのタップ領域を広げることはできない（重なる）。
  **盤のマスは横幅いっぱいの正方形（390px 幅で約 38px）のままにし、誤タップ対策は「選ぶ → ハイライト → 先をタップ」の 2 段で取る**
  （五目並べ 13×13・1 マス 24〜26px の先例と同じ）。**44px 以上を守るのは、持ち駒・「成／不成」の 2 択・各ボタン**
  （games/CLAUDE.md の「押す先は 44px を割らない」はここに効く）
- 玉方の応手は一拍（[cpu-speed.md](./cpu-speed.md) の「ふつう」）置いて指し、動いた駒を一瞬ハイライト。
  **同じ長さの応手が複数あるときは決定的に選ぶ**（盤の座標順（0〜80）で最初のもの。日替わりで全員が同じ応手を見るため。乱数は使わない。#317 レビュー must 3）
- 結果：正解なら「詰み！ ◯秒」と記録の帯（`.rec-strip`。ベスト・連続日数）。不正解なら「王手ではありません」「玉が逃げられます（逃げ先を表示）」
  「打ち歩詰めです」と理由を 1 行出し、やり直し。3 回間違えたら「答えを見る」を出す（タイムは記録しない）
- 「次の問題」は生成器から即座に。「今日の 1 問」は `dailySeed(localDateKey(), version)` から同じ問題を作る
- キーボード：矢印でマスを移動・Enter で選択（アクセシビリティ。盤の `aria-label` は「3 三 歩」の読み）

### 計算ロジック（`games/lib/tsume-shogi.ts`。純関数のみ）

```ts
export type Piece = 'K' | 'R' | 'B' | 'G' | 'S' | 'N' | 'L' | 'P' | '+R' | '+B' | '+S' | '+N' | '+L' | '+P';
export interface Board { cells: (Square | null)[]; attackerHand: Hand; defenderHand: Hand; }
export interface Problem { board: Board; moves: 1 | 3; solution: Move[]; seed: number; }

export function legalMoves(board: Board, side: Side): Move[];        // 二歩・打ち歩詰め・行き所なし・自玉の王手放置を除く
export function isCheck(board: Board, side: Side): boolean;
export function apply(board: Board, move: Move): Board;
export function solve(board: Board, maxPly: 1 | 3): { solutions: Move[][]; } // 作意候補の列挙（余詰の検出に使う）
export function generate(rng: () => number, moves: 1 | 3): Problem;   // 唯一解・手数ちょうど・無駄合いなし になるまで再抽選
export function judge(problem: Problem, move: Move): 'mate' | 'not-check' | 'escapable' | 'illegal' | 'continue';
export function defenderReply(board: Board): Move;                    // 最長手順の応手
```

- **玉方の持ち駒は `defenderHand` を盤面から導出**して保持する（40 枚 − 盤上 − 攻方の持ち駒 − 玉）。手で持たない
- `generate` は「玉を 1〜3 段目（上辺側）のどこかに置く → 攻方の駒 2〜4 枚を玉の近傍に、玉方の守り駒 0〜2 枚を置く → 攻方の持ち駒 1〜2 枚 →
  `solve` で検証」を、条件を満たすまで繰り返す。**見つからなければ seed を進めて続ける**（日替わりは `version` を上げれば全員同じ問題のまま作り直せる）
- **生成の速度の受け入れ基準**（#317 レビュー must 6。ランダム配置で唯一解の 3 手詰が出る率は実装するまで分からないので、見込みの回数ではなく上限で縛る）：
  - **中位のスマホで 1 問の生成が 500ms 以内**（Chrome の CPU 4 倍スロットリングで計測し、結果を仕様書に書く）
  - 超える場合は、(a) 生成を **Web Worker** に逃がして盤に「問題を作っています」を出す、(b) 1 問あたりの試行回数に上限（例：3 手詰 300 回）を置き、
    超えたら seed を進めて打ち切り・再試行、の両方を入れる。メインスレッドを固めない
  - 3 手詰の生成は「1 手詰の局面に玉方の応手 1 つを足す」など、ランダム配置より当たりやすい作り方を先に試す（実装時の判断。仕様書に結果を残す）
- 探索は深さ 3 の素朴な DFS で足りる（王手の連続に限定するので分岐が小さい）。3 手詰の検証は「初手 × 玉方の全応手 × 3 手目」で
  **玉方の応手すべてに対して 3 手目で詰む初手がちょうど 1 つ**
- 盤の座標は内部では 0〜80、表示は将棋の慣例（右上が１一）。**テストで `toLabel(0) === '９一'`、`toLabel(80) === '１九'`** の
  ように表示変換を押さえる（左右を間違えると全問が鏡になる）

### テスト（`games/tests/tsume-shogi.test.ts`）

- 駒の動き 14 種（成駒含む）を全部。盤端の切り落とし、桂の二段跳び、香の直進、馬・龍の 1 マス移動
- 禁手：二歩（同じ筋に不成の歩）、打ち歩詰め（歩を打って詰みになる手が除外される／歩を**動かして**の詰みは合法）、
  1 段目の歩香・1〜2 段目の桂は打てない・不成で進めない
- 王手の判定：飛・角・香の遠距離、間に駒があると王手でない、合駒で王手が外れる
- `solve`：既知の 1 手詰（**玉 ５一、攻方 歩 ５三、持ち駒 金 → 「５二金打」のみ**。頭金。５二は５三の歩が守っているので玉で取れず、
  ４一・６一・４二・６二は金の利き。４一・６一の金打は詰まない）、既知の 3 手詰、**余詰のある局面で solutions が 2 本返る**。
  テストの期待値は実装前に手で盤に並べて確かめる（#317 レビュー must 2 で、最初に書いた例（玉 ５一・金 ６二）は紐が無く詰んでいなかった）
- `judge`：3 手目は `solution[2]` 以外でも、指したあとの局面が詰みなら `'mate'`（最終手の余詰は許容）
- `generate`：seed 固定で同じ問題が出る（日替わりの前提）。**200 問**生成して全部が条件を満たす（唯一解・手数ちょうど・**種類ごとの駒数が上限以内・玉方の持ち駒が種類ごとに負にならない**）。
  **CI の時間を食わないよう件数は 200、1 問あたりの試行は上限で打ち切る**（それでも 10 秒を超えるなら件数を減らす）
- `defenderReply`：逃げられる応手があれば必ずそれを選ぶ（詰む応手を選ばない）。同じ長さの応手が複数ある局面で**毎回同じ手**を返す（決定性）
- 座標の表示変換（上記）
- 既存の見張り（`stage.test.ts`・`jsonld.test.ts`・`llms.test.ts`・`game-art.test.ts`）に乗る

## やらないこと

- **5 手詰以上。** 探索が深くなり、無駄合い・変化同手数の判定が要る。1 手・3 手で定着してから別提案
- **指し将棋（vs CPU）。** 評価関数と探索が別物。本提案の駒のルールは流用できるが、スコープに入れない
- **他人の作品の収録・投稿機能。** 著作物を扱わない。すべて生成
- **棋譜の読み上げ・解説文の生成。** 「詰み／逃げられる」の理由 1 行までにとどめる
- **駒の木目・字体のリアルな再現。** 漢字 1 文字の SVG テキストで統一（権利と可読性）
- **対人戦・ランキングのサーバー。** 静的サイトの約束。記録は端末内
