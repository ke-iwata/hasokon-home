## 何が起きているか（2026-11-22、コードを読んで確認）

`tools/lib/shitsugyo-hoken.ts` は「65歳以上は対象外」として `AGE_MAX = 64` を置いているが、**入力は止めていない**。

| 箇所 | いま |
|---|---|
| `Calculator.tsx` | `<input type="number" max={AGE_MAX}>` だけ。`ageNum = clamp(Number(age) \|\| 0, 0, 120)` で **66 歳でもそのまま計算に渡る** |
| `benefitRuleFor(age)` | `Math.min(age, AGE_MAX)` で**65歳以上を「60〜64歳」の算式に寄せる**（コメントにも「65歳以上は上限区分（60〜64歳）として扱う」） |
| `calcKihonTeate()` | `total = benefitDaily × prescribed.days`（基本手当の所定給付日数）を返す |
| 画面 | 「基本手当日額」「総支給額の目安（◯日分）」を大きく出し、**その下に**「65歳以上は高年齢求職者給付金になります。この計算機の対象外です」の注意 |

**数字は出したうえで「対象外」と書いている**ので、読む人は大きい数字のほうを持ち帰る。

### 例（66歳・一般の離職・加入10〜20年・退職前6か月の賃金 360万円＝賃金日額 20,000円）

| | いまの画面 | 正しい額（高年齢求職者給付金） |
|---|---|---|
| 日額 | 7,830円（60〜64歳の上限） | **7,450円**（30歳未満の上限） |
| 日数 | 120日（基本手当の所定給付日数） | **50日**（被保険者であった期間1年以上） |
| 合計 | **939,600円** | **372,500円**（一時金で一括） |
| スケジュール | 「120日分を使い切る日」まで | 1回の認定で一括支給 |

差は **567,100円**。「失業保険が90万円出るなら、もう少し休んでから次を探そう」という判断を誤らせる。

## 根拠（一次情報）

### 雇用保険法 第37条の4（e-Gov 法令API `law_data/349AC0000000116` で 2026-11-22 に条文本文を取得）

- **第1項**：高年齢求職者給付金の額は、高年齢受給資格者を受給資格者とみなして**第16条から第18条まで（第17条第4項第2号を除く）**を適用した場合の基本手当の日額に、算定基礎期間が **1年以上なら50日、1年未満なら30日** を掛けた額（認定日から受給期限までの日数がそれより短ければその日数）
- **第2項**：賃金日額が**第17条第4項第2号ニ（離職の日に30歳未満である受給資格者）の額**を超えるときは、その額を賃金日額とする
- 第16条第2項の「45%」は「離職の日において**60歳以上65歳未満**」に限る読み替えなので、**65歳以上は第16条第1項（80%→50%）のまま**

→ 65歳以上は「**30歳未満の表**」と同じ算式・上限になる。

### 厚生労働省「基本手当日額の計算式及び金額（令和8年8月1日～）」（参考1・https://www.mhlw.go.jp/content/001726936.pdf）

30歳未満の表（＝65歳以上に当てる表）：

| 賃金日額 w | 基本手当日額 y |
|---|---|
| 3,203円以上 5,480円未満 | 0.8w |
| 5,480円以上 13,490円以下 | 0.8w − 0.3 × {(w − 5,480) / (13,490 − 5,480)} × w |
| 13,490円超 14,900円以下 | 0.5w |
| 14,900円超 | **7,450円** |

端数は1円未満切り捨て。**上限は 7,450円 × 50日 = 372,500円**。

### その他の要件（実装時にハローワークの案内で再確認する）

- 受給資格：離職の日以前1年間に被保険者期間が通算**6か月以上**（第37条の3）
- 受給期限：離職の日の翌日から**1年**（期限を過ぎると受け取れない。期限までの残り日数が50日／30日より短いとその日数に減る＝第37条の4第1項かっこ書き）
- 待期7日・給付制限（正当な理由のない自己都合は原則1か月）は基本手当と同じに扱われる（ハローワークの案内で確認してから画面に書く）
- **老齢年金と併せて受け取れる**（65歳未満の基本手当と違い、年金の支給停止が無い）。検索でよく聞かれる点なので FAQ に入れる

## 機能（仕様）

### 1. 65歳以上を入れたら「高年齢求職者給付金」に切り替える

- **年齢は離職日の時点の年齢で判定する**（65歳以上の被保険者＝高年齢被保険者として離職したかで決まる。いまの基本手当の年齢区分も「離職の日において」で区切っている）。年齢計算ニ関スル法律（明治35年法律第50号）と民法第143条により**65歳の誕生日の前日に65歳になる**扱い。画面で受け付けるのは「離職時の年齢」のまま（生年月日は取らない）
- **結果の型（判別共用体にする）**：画面の入口を新しい関数 `calcShitsugyoHoken(input)` にし、戻り値を
  `{ kind: 'kihon'; result: KihonTeateResult } | { kind: 'kourei'; result: KoureiKyushokushaResult }` にする。`age >= 65` なら `calcKoureiKyushokusha()`、それ以外は `calcKihonTeate()` を呼ぶ。画面は `kind` で出し分ける
  - `calcKihonTeate()` は**基本手当専用**にし、`age >= 65` を渡されたら `RangeError` を投げる（60〜64歳の算式に黙って寄せない）
  - `KihonTeateResult.age65OrOver` は**消す**（入口で分岐するので要らない）。いまの注意書きもこれと一緒に消える
  - `AGE_MAX = 64` は **`KIHON_TEATE_AGE_MAX` に名前を変えて残す**（「基本手当の対象の上限年齢」。画面の入力の上限ではない）。`tests/shitsugyo-hoken.test.ts:565-575` の「65歳以上は基本手当の対象外として印を付ける」は、「66歳は `calcShitsugyoHoken` が `kind: 'kourei'` を返す」「`calcKihonTeate` に66歳を渡すと `RangeError`」の2本に置き換える
  - `KoureiKyushokushaResult`：`wage`（上限下限を当てた賃金日額）・`benefitDaily`・`days`（30／50。期限で減らしたあとの値）・`baseDays`（減らす前）・`total`・`deadline`（受給期限）・`certificationEstimate`（認定日の見積もり。日付を入れたときだけ）・`restriction`（給付制限。基本手当と同じ `restrictionFor()` を使う）
  - 算式は `BENEFIT_RATE_RULES` の **30歳未満の行**を使う（定数を二重に持たない。8月の改定で一緒に動く）
  - 日数：被保険者であった期間 `lt1` → 30日、それ以外 → 50日
  - 合計：`日額 × 日数`
  - 受給期限（離職日の翌日から1年）を離職日から出し、**認定日から期限までの日数が日数より短い場合は減らす**（第37条の4第1項かっこ書きは「認定のあつた日から」。**申込日からではない**）
  - **認定日の見積もり**：申込日（受給資格決定日。省略時は離職日の2週間後＝いまの基本手当と同じ）＋待期7日、給付制限があればその満了日、の**翌日**を「最も早い場合の認定日」とする。待期・給付制限の満了日は既存の `restrictionFor()`／`buildSchedule()` の計算を使う。実際の認定日はハローワークが指定するので、画面では「目安（最も早い場合）」と書く
  - 例：自己都合（給付制限1か月）で離職日のおよそ10か月後に申込むと、認定日の見積もりは「申込日＋7日、さらに1か月」の翌日になり、期限まで30日を切る（50日分は受け取れない）
- `benefitRuleFor()` の「65歳以上は60〜64歳として扱う」をやめる（呼ばれない形にする）
- 離職理由の区分（一般／特定受給資格者／就職困難者）による**日数の違いは無い**。画面では離職理由の選択肢を残すが、「65歳以上は日数に影響しません（給付制限の判定にだけ使います）」と書く

### 2. 画面

- 結果の見出しを「**高年齢求職者給付金（一時金）**」にする。「基本手当日額」「総支給額の目安（◯日分）」の文言は出さない
- 大きく出す数字：**一時金の額**（例：372,500円）。その下に「日額 7,450円 × 50日」
- スケジュール：「◯日分を使い切る日」を出さず、「待期7日（＋給付制限）のあとの認定日に一括」「受け取れる期限：離職日の翌日から1年（◯年◯月◯日）」
- 年齢欄の `max` を外し（または 99）、ラベルに「離職日の時点の年齢（65歳の誕生日の前日から65歳の扱い）。65歳以上は高年齢求職者給付金で計算します」。**「◯日までに辞めると得」のような退職時期の勧めは書かない**（事実だけを書き、助言に寄せない）
- **UI は今の結果カードの部品をそのまま使って切り替える。** 高年齢求職者給付金のためだけに新しい色・枠・バッジを足さない。スマホでは「一時金の額 → 日額×日数 → 受け取り期限」を縦1列に並べ、横並びの表にしない
- 注意書き（いまの「この計算機の対象外です」）は消す

### 3. 本文・FAQ（`page.tsx`）

- 見出し「65歳以上で退職したら（高年齢求職者給付金）」を1節足す：計算式・30歳未満の上限を使う理由（第37条の4第2項）・50日／30日・**年金と併せて受け取れる**・**65歳を過ぎてからの離職のたびに受け取れる**（6か月以上の加入があれば）
- FAQ 2問：「65歳以上でも失業保険はもらえますか」「高年齢求職者給付金と年金は両方もらえますか」
- `title` / `description`：**いまの主キーワード（失業保険・基本手当）を先頭に残し**、「高年齢求職者給付金」は後ろに足すだけ（Search Console の表示は8件・順位30で、需要の根拠としては弱い。期待効果は控えめに見る）
- 待期・給付制限が高年齢求職者給付金にも当たることは、**ハローワークの案内で確認した出典を `page.tsx` の参考に足してから**画面に書く

### 4. テスト（`tools/tests/shitsugyo-hoken.test.ts`）

1. 66歳・賃金日額 20,000円・加入10年 → 日額 7,450円・50日・**372,500円**（いまの 939,600円 にならないこと）
2. 65歳ちょうど → 高年齢求職者給付金（64歳は基本手当のまま）
3. 66歳・加入 `lt1` → 30日
4. 66歳・賃金日額 10,000円 → 逓減式（30歳未満の行）で `floor(0.8w − 0.3 × (w−5480)/(13490−5480) × w)`
5. 賃金日額 3,000円 → 下限 3,203円に引き上げ、日額 2,562円
6. **見積もった認定日**から受給期限まで残り40日（例：会社都合で給付制限なし、申込日＋7日の翌日が期限の40日前）→ 40日分に減る。自己都合（給付制限1か月）で同じ申込日なら、認定日の見積もりが1か月後ろにずれ、さらに減る（**申込日からの日数では判定しない**こと）
7. 64歳は `kind: 'kihon'`、65歳・66歳は `kind: 'kourei'`。`calcKihonTeate` に66歳を渡すと `RangeError`（いまの 565-575 行のテストの置き換え）
8. 30歳未満の行の上限額を変えると、高年齢求職者給付金の上限も一緒に変わる（定数を二重に持っていないこと）

## やらないこと

- 受給資格の判定（被保険者期間6か月の確認はハローワークの決定事項。要件の説明だけ）
- 在職老齢年金・年金額との合算（[zaishoku-rorei-nenkin.md](./zaishoku-rorei-nenkin.md) へリンクで回遊）
- 別ツールに分けること（同じ入力で答えだけ変わるので、同じページで切り替える）
- 生年月日の入力（年齢で足りる。誕生日の前日の扱いはラベルと FAQ で説明する）
- 退職時期の損得の助言

## 期待される効果

- **公開中のツールの誤りがなくなる**（65歳以上に2.5倍の額を見せない）
- 「高年齢求職者給付金 計算」の検索の受け皿になる（ただし Search Console の表示はまだ8件なので、効果は控えめに見積もる）。調べた範囲（2026-11-22）では、**2026年8月改定の上限 7,450円を使って額を出す無料の計算機は見当たらず**、解説記事の多くは改定前の数字のまま
- 定年・継続雇用の終了で65歳以上の離職は毎年多い。3月末の退職に向けて2〜3月に検索が増える
