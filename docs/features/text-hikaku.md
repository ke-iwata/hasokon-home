### 競合の状況（2026-11-06 の Web 調査）

「テキスト 比較」「差分 チェック」「diff ツール」で上に出るものは、日本語のもの・英語のものとも
2 つの欄に貼って色分けする、まではどれも揃っている。調べた範囲で足りていないのは次の 4 点で、ここを差別化にする：

1. **比べた文章をサーバーに送る・保存するものがある。** 比較結果を共有 URL にして一定期間保存する方式（Lifehacker の紹介記事で確認）や、
   フォームを送信してサーバー側で比べる方式がある。**契約書・人事の文書・顧客名簿を貼るのにためらう**。
   当サイトはブラウザの中だけで比べ、`fetch` を一切しない、を冒頭に書いて約束する
2. **日本語の「単語単位」が効かない。** 英語向けのツールは空白で単語に区切って比べるので、
   日本語の文では「行全体が変わった」としか出ないことが多い。**行で対応を取ってから、変わった行の中を文字単位で比べる**
3. **全角⇔半角・空白の違いを無視できない／見えない。** Excel やチャットから貼ると、
   全角スペース・ノーブレークスペース（U+00A0）・ゼロ幅スペース（U+200B）・タブが混ざり、
   「見た目は同じなのに違うと言われる」。JSON 整形の `ZENKAKU_NAMES`（`tools/lib/json-seikei.ts` 189 行。全角スペース・ノーブレークスペースの呼び名）を土台に、ゼロ幅の文字とタブを足して使い、
   **違いの原因が見えない文字なら、その文字に印（`␣` `⇥` `[ZWSP]` など）を付けて示す**
4. **違いの「数」と「次の違いへ」が無い。** 長い規程だと色分けだけでは見落とす。
   上に「追加 ◯ 行・削除 ◯ 行・変更 ◯ 行／文字数 +◯・−◯」を出し、`次の違い`／`前の違い`（キーボード `n`／`p`）で飛べるようにする

**本文には競合の名前を出さない**（JSON 整形の企画レビュー #444 の約束と同じ）。

## 提案する仕様

### 入力と出力

- **入力**：左右 2 つの欄（左「元の文章」・右「新しい文章」）。それぞれにファイルの読み込み（`.txt` `.csv` `.md` `.json` など、テキストとして読めるもの。`FileReader` で読むだけで送らない）と「入れ替え」「クリア」
- **比べるタイミング**：両方の欄が合わせて 2 万字以下なら入力が止まって 300ms 後に自動で比べる。それを超えたら `比較する` ボタンで比べる（入力中に固まらないため）
- **出力**：
  - **パソコン（幅 900px 以上）**：左右並び（side-by-side）。行番号つき、削除は左に赤、追加は右に緑、変更は両側に黄で、行の中の変わった文字だけを濃く
  - **スマホ・狭い幅**：上下 1 列（unified）。削除行（`−`）の直後に追加行（`＋`）を並べる。左右並びへの切り替えも置く
  - 上部に**要約**：「追加 3 行・削除 1 行・変更 5 行／文字数 1,204 → 1,251（+47）」。違いが無ければ「**2つの文章は同じです**」（無視のスイッチが入っていれば「〜を無視すると同じです」）
  - `次の違い`／`前の違い` ボタン（`n`／`p` キー）。今どこか「3 / 9」
  - `変わった行だけ表示` のスイッチ（同じ行は前後 2 行だけ残して畳む）
  - `結果をコピー`：unified diff の形式（`-`／`+` 行頭）のテキストでコピー。メールやチャットにそのまま貼れる

### 無視のスイッチ（既定はすべてオフ）

| スイッチ | 中身 |
|---|---|
| 空白の違いを無視 | 行頭・行末の空白を削り、連続する空白（半角・全角・タブ・U+00A0）を 1 つとみなす |
| 全角・半角を区別しない | 比べる前に NFKC で正規化（`ｱ`→`ア`、`１`→`1`、`Ａ`→`A`）。`tools/lib/hankaku-zenkaku.ts` と同じ扱いにそろえる |
| 大文字・小文字を区別しない | `toLowerCase()` で比べる（英字のみ） |
| 空行を無視 | 中身が空白だけの行を比べる前に除く |

- **改行コード（CRLF／LF／CR）の違いは常に吸収**し、混ざっていたら「改行コードが違います（左：CRLF・右：LF）」と 1 行だけ知らせる
- 無視して比べたときも、**表示は元の文字のまま**（正規化した文字を見せない）

### 比較の約束（テストで固定する）

1. **行の対応**は Myers の O(ND) 差分（最短の編集）で取る。外部ライブラリは入れず `tools/lib/text-hikaku.ts` に自前で持つ（依存を増やさない。[dependency-vulnerability-audit.md](./dependency-vulnerability-audit.md)）
2. 削除と追加が隣り合う区間は、行ごとに対にして「**変更**」として扱い、その対の中を**文字単位**で再び Myers で比べる。
   対にする条件は「2 行の文字の一致率が 40% 以上」。下回ったら変更ではなく削除＋追加として出す（全く別の行を黄色で並べない）
3. 文字単位の比較は**書記素（`Intl.Segmenter` の grapheme）単位**。絵文字・結合文字（`が` を `か`＋濁点で書いたもの）・異体字セレクタを途中で割らない
4. 「見えない文字」（全角スペース U+3000・U+00A0・U+200B〜U+200D・U+FEFF・タブ）が違いに含まれるときは、その文字の位置に印を出す。
   呼び名は `json-seikei` の `ZENKAKU_NAMES` と同じ一覧を共有する（どちらかに足したら両方に効く）。U+200B〜U+200D・U+FEFF・タブはこのツールで足す
5. 上限：片側 **20 万字・1 万行**まで。超えたら比べずに「長すぎます（◯字）。分けて比べてください」。
   行の対応の編集距離が 5,000 を超えたら、文字単位の比較を省いて行単位だけで出す（固まらないため）
6. 両方が空・片方が空（全部追加／全部削除）・末尾の改行の有無だけが違う（「最後の行に改行がありません」と示す）を境界値として持つ
7. 貼った文字列は **React のテキストとして描くだけ**で、`dangerouslySetInnerHTML` を使わない（HTML を貼られても実行されない）。テストで `<script>` `<img onerror>` を貼っても文字として出ることを確かめる

### スマホ（直近28日で約2割）での画面

- 入力欄は縦に 2 つ。iOS の自動拡大を避けて 16px。高さは 6 行から始めて伸びる
- 結果は上下 1 列（unified）が既定。行は折り返す（`pre-wrap`）。横スクロールさせない
- `次の違い` はタップ域 44px 以上で、結果の上に固定（スクロールしても押せる）

### 本文（[thin-tool-content.md](./thin-tool-content.md) の型）

- 冒頭に「**貼った文章・読み込んだファイルはこのブラウザの中だけで比べ、どこにも送らず、保存もしません**」（実際に `fetch` を一切しない）
- 使いどころの例（短く）：契約書・規程の改訂前後／原稿の修正前後／名簿・品番の一覧の突き合わせ／設定ファイルの新旧
- FAQ（構造化データ `FAQPage`）の候補：
  1. 見た目は同じなのに「違う」と出るのはなぜ？（全角スペース・ゼロ幅スペース・改行コード。印の読み方）
  2. Word や PDF の文書は比べられる？（本文をコピーして貼れば比べられる。書式・図は比べない。Word の「比較」機能のほうが向く場面も書く）
  3. Excel の 2 つの列を比べたい（列をコピーして貼ると 1 セル 1 行になる。並び順が違うときは並べ替えてから）
  4. 順番が入れ替わっただけの行は？（入れ替えは「削除＋追加」として出る。v1 では移動の検出はしない）
  5. 比べた内容はどこかに残る？（残らない。タブを閉じれば消える）
- `metadata` に `robots: robotsFor('text-hikaku')`
- title の案：「テキスト比較｜2つの文章の差分を色分けチェック（日本語の文字単位・送信なし）」
- description の案：「2つの文章を貼るだけで追加・削除・変更を色分け。日本語は変わった文字まで示します。全角半角・空白の違いを無視、見えない文字の検出、次の違いへジャンプ。入力は送信しません。」

### 計測

- `trackToolUse('text-hikaku', …)` を、比べた回の**規模の区分**（`lines-lt100`／`lt1000`／`gte1000`）・入っていた無視のスイッチ・表示の形（`split`／`unified`）で送る
  （[tool-use-coverage.md](./tool-use-coverage.md)）。**比べた文字列そのもの・行数の実数は送らない**
- `次の違い` を押した回数（`jump`）と `結果をコピー`（`copy`）も送る。多ければ要約の出し方を見直す材料になる

## やらないこと

- 比較結果の共有 URL・保存・履歴（ブラウザ内で完結を崩さない）
- Word（.docx）・PDF・Excel（.xlsx）のファイルを直接読む（書式の比較は別物。本文のコピーで足りる）
- 行の移動の検出・3 つ以上の比較・マージ（v1 は 2 つを見比べるだけ）
- 単語単位の比較（日本語では効かない。英文だけ単語単位にする切り替えは、利用の計測を見てから考える）
