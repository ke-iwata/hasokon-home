## 背景と根拠

### いまのゲームの偏り

ゲームは7本。内訳を見ると**同じ型に寄っている**。

| 型 | 本数 | 中身 |
|---|---|---|
| トランプ | 3 | ソリティア・スパイダー・フリーセル |
| 論理パズル（グリッド） | 2 | マインスイーパー・ナンプレ |
| アクション | 1 | ブロック崩し |
| 数字合成 | 1 | 2048 |

トランプ3本は `games/lib/cards.ts` と `games/app/_cards/CardView.tsx` の
共通基盤で安く出せたが、**同じ層に同じものを3本出した状態**でもある。
次の1本は「別の入口を作る」ほうが増分が大きい。

### なぜノノグラムか

**定番のペンシルパズルのうち、実装が現実的で未着手なものとして最有力**である。

| 観点 | 内容 |
|---|---|
| 需要 | 雑誌・アプリで長く売られ続けている定番。無料ゲームサイトはほぼ全て所持している |
| 既存資産の再利用 | `games/lib/nanpre.ts` の**一意解を保証する生成器の型**（`countSolutions(board, limit=2)` で解が2つ以上ないことを確認してから出題する）がそのまま使える考え方 |
| UIの再利用 | `games/app/minesweeper/Game.tsx` の**格子UI**（`role="grid"`・`onContextMenu` での右クリック、フラグモードのトグル）がほぼそのまま使える |
| 差別化 | 「解いたら絵が出る」という**達成の見え方**が既存7本のどれとも違う。完成画像がSNSに貼りやすい |
| 滞在時間 | 1問5〜15分。GA4の平均エンゲージメント時間（現状のゲームは1回あたり数十秒〜数分）を押し上げる |

### 権利関係（重要）

このパズルは**呼び名ごとに権利者が違う**。ルール自体に著作権は無いが、**名前は選ぶ必要がある**。

| 呼称 | 権利 | 採否 |
|---|---|---|
| ピクロス | 任天堂の登録商標 | **使わない** |
| お絵かきロジック | 世界文化社の登録商標 | **使わない** |
| イラストロジック | 商標登録あり | **使わない** |
| **ノノグラム** | 一般名称。特定企業の商標ではない | **これを採用** |

出典：[ピクロス (ゲームソフト) - Wikipedia](https://ja.wikipedia.org/wiki/%E3%83%94%E3%82%AF%E3%83%AD%E3%82%B9_(%E3%82%B2%E3%83%BC%E3%83%A0%E3%82%BD%E3%83%95%E3%83%88))

- **ゲーム名は「ノノグラム」**。URLは `/games/nonogram/`
- 本文中で「お絵かきロジック・ピクロスなどとも呼ばれるパズルです」と**説明として一度だけ触れる**のは
  記述的な使用にとどまるが、**タイトル・見出し・meta title には入れない**。
  検索流入のために商標を名前に使うのは、この件では割に合わない
- 出題する絵は**すべて自前で作る**。既存作品のキャラクター・ロゴは一切使わない

## 提案する仕様

### ルール

格子の各行・各列に「連続して塗るマスの数」がヒントとして並ぶ。
ヒントを満たすようにマスを塗り、絵を完成させる。

### 盤面サイズと難易度

| 難易度 | サイズ | 想定時間 |
|---|---|---|
| かんたん | 5×5 | 1〜2分 |
| ふつう | 10×10 | 5〜10分 |
| むずかしい | 15×15 | 15〜30分 |

**20×20以上は作らない。** スマホの画面幅（375px）で1マスが16px を割り、
指で押し分けられなくなる。GA4のデバイス比率はデスクトップ48セッション・
モバイル20セッション・タブレット4（2026-07-12〜08-10、2026-08-11取得）で
モバイルが3分の1を占めるため、モバイルで破綻するサイズは入れない。

### 出題データ

**乱数生成ではなく、絵を手で用意する。** ランダムに塗ったマスからヒントを作ると、
解けはするが「絵にならない」ので、このパズルの価値がなくなる。

```ts
// games/lib/nonogram/puzzles.json
[
  { "id": "cat-10", "size": 10, "title": "ねこ", "level": "normal",
    "cells": "0011000000 0111100000 ..." }
]
```

- 各サイズ **10問以上**を用意する。1問あたりの制作は数分（格子に絵を打つだけ）
- **`countSolutions()` 相当で一意解であることを検証してからJSONに入れる**。
  ナンプレと同じ約束（`games/lib/nanpre.ts:98`）。一意解でない絵は
  「論理だけでは解けない」＝当てずっぽうを強いる悪問になる
- 検証はビルド時ではなく、`node --test` のテストで全問を走査する。
  出題データが増えても壊れないことを機械が保証する

### 操作（ここが勝負どころ）

既存のマインスイーパーは右クリック＝フラグだが、**ノノグラムはドラッグで連続塗りができないと苦痛**になる。

| 操作 | 動作 |
|---|---|
| クリック／タップ | 塗る ⇄ 空白 |
| ドラッグ／スワイプ | **なぞった範囲を、最初のマスと同じ状態にそろえる**（塗り／消しを途中で反転させない） |
| 右クリック／モード切替ボタン | ×印（塗らないと確定したマス） |
| もどす | 直前の1手（ドラッグ1回＝1手として扱う） |

- ドラッグは**行または列の一直線に固定する**。斜めに指がぶれても行がずれない
- モバイルでは `touch-action: none` で盤面上のスクロールを止める。
  ただし盤面の外は普通にスクロールできること
- ヒントの数字は**満たしたものを薄くする**。どこまで進んだかが一目で分かる

### アクセシビリティ

既存のマインスイーパー（`role="grid"` + マスごとの `aria-label`）と同じ水準にそろえる。
マスの `aria-label` は「3行5列 塗り」「3行5列 未確定」の形にし、
ヒントは盤面の前に読み上げられる位置に置く。

## やらないこと

- **絵を自動生成する。** 乱数の塗りつぶしからヒントを作ると絵にならず、
  このパズルの魅力（解けたら絵が出る）が消える。手で用意するほうが安くて良い
- **カラーノノグラム（多色版）。** ルールもUIも一段複雑になり、
  白黒版の需要を確かめる前に作る理由が無い
- **20×20以上の大盤面。** モバイルで1マスが押し分けられない（上記のとおり）
- **「ピクロス」「お絵かきロジック」をタイトルやmeta titleに使う。**
  検索流入は増えるが他社の登録商標である（上記「権利関係」）
- **タイム計測とランキング。** サーバを持たない静的サイトなので
  ランキングは作れない。ベストタイムのローカル保存は2048と同じ形で後から足せる
