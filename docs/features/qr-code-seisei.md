# 新ツール「QRコード作成」（完全ローカル生成・データ送信なしを正面に出す）

**状態**：提案（2026-08-18 起票。未実装。実装時は `stage: 'wip'` で入れ、
ページ・テストが揃ったPRで `public` に上げる）
**対象**：`tools/`（`hasokon.com/tools/qr-code/`）
**起票**：2026-08-18

---

## 背景と根拠

### 恒常的に大きい需要と、当サイトの売りが刺さる珍しい市場

「QRコード 作成」「QRコード 作成 無料」は年間を通じて検索量の大きい定番クエリで、
店頭掲示・イベント案内・Wi-Fi共有・名刺と用途が生活にも業務にも広がっている。

競合は多いが、**上位サイトの多くはサーバーでQRを生成する**（＝URLや文言が
サービス側に送信される）か、無料版に有効期限・アクセス解析つきの
「動的QR」を混ぜて誘導する構造になっている。実際「無料QRコード作成サイトで
作ったQRが期限切れで別サイトに転送された」という注意喚起が繰り返し
記事になっており、**「作ったQRがずっと使えるのか」「入力内容が送信されないか」**は
このジャンルの明確な不安点である。

当サイトのツール群の売りは一貫して「登録不要・データ送信なし」。
QR生成は**ブラウザ内だけで完結でき、生成した瞬間から永久に有効**
（静的QRはただの画像）なので、この売りがそのまま競合との差別化になる。

### サイト構成上の位置づけ

- ツール28本のうち「何かを生成する」ツールがまだ1本もない
  （計算・変換・カウント系のみ）。ジャンルの幅を広げる1本になる
- `aspect-ratio`・`hankaku-zenkaku`・`mojisu-count` と同じ
  「実務で急に必要になる系」クラスタに加わり、エンジニア・事務職の
  再訪動機を増やす

## 提案する仕様

1. **入力**：テキスト／URL（1タブ）、Wi-Fi設定（SSID・暗号化方式・パスワード→
   `WIFI:` スキーム）の2モードから始める。電話・メール等のスキームは追わない
2. **生成はすべてブラウザ内で完結**
   - QRコード（モデル2・バイトモード・誤り訂正レベル M/Q 切替）のエンコーダを
     TypeScript で自前実装する（Reed-Solomon 含む。仕様は公知・特許は失効済みで、
     「QRコード」の商標表記だけデンソーウェーブのガイドラインに従い脚注を入れる）
   - 外部ライブラリ・外部APIを使わない（既存方針どおり依存を増やさない）
   - SVGで描画し、PNG（512px）/ SVG のダウンロードボタンを付ける
3. **ページの説明部**（このツールの検索面はここが本体）
   - 「無料QRコード作成サイトの注意点」：動的QRの期限切れ・転送の仕組み、
     静的QRとの違い、このツールは静的QRのみで期限が存在しないこと
   - 印刷サイズと読み取り距離の目安表、誤り訂正レベルの選び方
   - FAQ（JSON-LD）：「作ったQRはいつまで使える？」「入力した内容は送信される？」等
4. **テスト**
   - エンコーダは既知のテストベクタ（仕様書の例・他実装の出力）と突き合わせる
   - 版数選択・誤り訂正符号・マスク評価をユニットテストで固定する
   - ユニットテストに加えて、**実装PRのマージ前に複数機種のスマホ標準カメラで
     実際にスキャンできることを確認する**（テストベクタの一致だけでは
     実機での読み取り可否まで保証できないため）

## 期待される効果

| 効果 | 測り方 |
|---|---|
| 大ボリュームの定番クエリ群への新しい受け皿 | GSC の `/tools/qr-code/` の表示・クリック |
| 「QRコード 無料 期限なし」「QRコード 安全」系の不安解消クエリで差別化 | 同上（クエリ別） |
| 生成系ジャンルの開拓（今後のパスワード生成等への足がかり） | ツール一覧の回遊 |

ビッグクエリ本体で急に上位は取れないが、不安解消系のロングテール
（期限・安全性・データ送信）は解説の厚みで戦える。既存の
「登録不要・データ送信なし」ブランドを最も説得力ある形で見せられるページになる。

## 必要な工数（消費トークン目安）

| 作業 | 消費トークン（目安） |
|---|---|
| QRエンコーダ（Reed-Solomon・マスク評価含む）＋テストベクタ | 150k〜200k |
| UI（2モード入力・SVG描画・PNG/SVGダウンロード） | 60k |
| ページ執筆（注意点解説・FAQ・JSON-LD） | 50k |
| **合計** | **約260k〜310k**（レビュー往復込みで 400k 以内） |

既存ツールより重め。エンコーダが資産になる（将来の連絡先QR・複数一括生成に再利用）
ことを含めて判断してほしい。

## やらないこと

- **動的QR・短縮URL・アクセス解析。** サーバーが要る上、このツールの
  存在理由（送信しない・期限がない）と正面から矛盾する
- **ロゴ埋め込み・色変更などの装飾。** まず読み取り確実性を優先。需要が見えたら別途
- **電話・SMS・vCard等のスキーム対応。** テキスト/URL/Wi-Fiで用途の大半を覆う。
  増やすのは検索クエリで需要が確認できてから

## 一次情報・参考

- QRコードの技術仕様は ISO/IEC 18004（公知）。基本特許は失効済み
- 「QRコード」はデンソーウェーブの登録商標（ページ脚注に表記を入れる）
  https://www.qrcode.com/faq.html
- 無料QR作成サービスの期限切れ・転送問題の注意喚起記事（複数、2024〜2026）
