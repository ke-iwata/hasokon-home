## 背景と根拠

### なぜいま：令和8年分の年末調整は、生命保険料控除の計算が初めて変わる年

令和7年度税制改正で、**23 歳未満の扶養親族がいる人の「一般の生命保険料控除」（新契約）の上限が 4 万円 → 6 万円**になった。
**令和8年分（2026 年の年末調整）が最初の適用**で、会社員は 10 月下旬〜11 月に配られる
「保険料控除申告書」で、この新しい表を自分で当てはめて控除額を書く。

国税庁 No.1140（令和8年4月1日現在法令等）が示す表：

| 区分 | 年間の支払保険料等 | 控除額 |
|---|---|---|
| 新契約（一般・介護医療・個人年金） | 2 万円以下 | 全額 |
| | 2 万円超 4 万円以下 | ×1/2 + 1 万円 |
| | 4 万円超 8 万円以下 | ×1/4 + 2 万円 |
| | 8 万円超 | 4 万円 |
| 旧契約（一般・個人年金） | 2.5 万円以下 | 全額 |
| | 2.5 万円超 5 万円以下 | ×1/2 + 1.25 万円 |
| | 5 万円超 10 万円以下 | ×1/4 + 2.5 万円 |
| | 10 万円超 | 5 万円 |
| **新契約の一般・23 歳未満の扶養親族あり（令和8年分〜）** | 3 万円以下 | 全額 |
| | 3 万円超 6 万円以下 | ×1/2 + 1.5 万円 |
| | 6 万円超 12 万円以下 | ×1/4 + 3 万円 |
| | 12 万円超 | **6 万円** |

- 新旧両方ある区分：旧の支払額が 6 万円超なら旧だけ（最高 5 万円）、6 万円以下なら新＋旧の合計（最高 4 万円、
  特例ありの一般は 6 万円）
- 3 区分の合計の上限は **12 万円**（特例があっても変わらない）
- 出典：国税庁 No.1140 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1140.htm

**住民税**は別の表（新契約：1.2 万円以下は全額／3.2 万円以下は ×1/2+6,000／5.6 万円以下は ×1/4+1.4 万／超は 2.8 万円。
旧契約：1.5 万／4 万／7 万円で区切り最高 3.5 万円。新旧合算の上限 2.8 万円、3 区分合計の上限 **7 万円**）。
出典：東京都中野区「令和8年度 住民税の計算」 https://www.city.tokyo-nakano.lg.jp/kurashi/zeikin/kakusyushiryo/minnanokuzei-r7.files/keisan1_r8.pdf ほか。
**23 歳未満の特例は住民税には無い**（所得税だけの改正。実装時に総務省・自治体の令和9年度の案内で再確認する）。

### 検索の形と当サイトの型

- 「生命保険料控除 計算」「生命保険料控除 新旧 両方」「生命保険料控除 6万円 23歳未満」は、
  **毎年 10〜11 月に山が来る**定番の検索。答えが「表に当てはめた数字」で決まるので、1 ページ 1 機能の計算機の型に合う
- 申告書の記入欄（a〜i の欄）と同じ順で途中の額を出せば、**そのまま書き写せる**のが競合の解説記事より強い
- 当サイトの客の主力は Yahoo! の AI アシスタント・ChatGPT・Bing（GA4、2026-09-12〜10-09 の 28 日：
  bing 604・openai 282・chatgpt.com 77 セッション）。**税の表の当てはめは AI アシスタントが間違えやすい計算**で、
  計算機へのリンクが引用されやすい（[yahoo-ai-search-referral.md](./yahoo-ai-search-referral.md)）
- 当サイトの年末調整の計算機（`nenmatsu-chosei`）は、生命保険料控除を「計算済みの額」で受け取っている。
  ここに「計算機で出す」リンクを足せば 2 本が互いに送り合える

### 法的な位置づけ

- 税額の**一般的な計算**で、個別の税務相談（税理士法 2 条）にはしない。「申告書の書き方の目安。最終的には勤務先・税務署へ」と書く
- **保険会社名・商品名は出さない**（例も「終身保険」「医療保険」などの一般名で）
- 保険の加入・見直しを勧める文は書かない（保険業法の募集に当たる表現を避ける）

## 提案する仕様

### 画面（スマホ 390×844 で入力と結果の 1 行目が収まること）

1. **23 歳未満の扶養親族がいる**（2026-12-31 時点。16 歳未満の子も含む）：はい／いいえ
2. 区分ごとに 2 欄（控除証明書の「申告額」＝年間の支払額。12 月まで払う見込み額でよい）
   - 一般の生命保険料：新契約 ／ 旧契約
   - 介護医療保険料：新契約のみ（旧契約の医療保険は「一般・旧」に入れる、と注記）
   - 個人年金保険料：新契約 ／ 旧契約
3. 結果
   - **所得税の控除額**（申告書の欄の順：一般 → 介護医療 → 個人年金 → 合計）。区分ごとに「新だけ／新＋旧／旧だけ」の
     どれを採ったか（いちばん有利なほうを自動で選ぶ）を 1 行で
   - **住民税の控除額**（同じ順）
   - 特例を使ったときは「特例で +◯円（所得税）」を強調。使わない場合との差
   - 税額の目安：所得税率（5・10・20・23%…を選ぶ。既定 5%）× 控除額 × 1.021 ＋ 住民税 10% × 住民税の控除額
   - **「この額を年末調整の計算機で使う」**ボタン：`/tools/nenmatsu-chosei/?life=<所得税の控除額>`
     （受け側はクエリを読んで生命保険料控除の欄を埋める。受け側の変更は 1 か所で、別 PR にしてもよい）

### 計算ロジック（`tools/lib/seimei-hokenryo-kojo.ts`。純関数のみ）

- `kojoJuminzei({ ippanNew, ippanOld, kaigo, nenkinNew, nenkinOld })`

## 期待される効果

- 10〜11 月の定番の検索（毎年来る）に、**令和8年分の特例を反映した**計算機で入れる。競合の解説記事の多くは表の転載で、
  新旧の合算・特例・住民税の 3 つを同時に当てはめた答えは出さない
- `nenmatsu-chosei`（公開中）との相互リンクで、年末調整の季節に 2 本が回遊する
- 毎年使える（`RULES_BY_YEAR` に足すだけで翌年分に回る）。季節物でも「年 1 回の山が毎年来る」型

## やらないこと

- **地震保険料控除はこのページに入れない。** 表が別で、旧長期損害保険の扱いで入力が増える。
  1 ページ 1 機能を守る（需要が見えたら別ツール）
- **保険料の「おすすめの払い方」「入るべき保険」は書かない**（保険の募集・勧誘に当たる表現を避ける）
- 確定申告の書き方（申告書第一表の欄）は扱わない。会社員の年末調整の申告書に合わせる
