# ふるさと納税に「令和8年対応の控除上限額 早見表」を足す（シーズン前SEO）

**状態**：提案（2026-08-21起票、未実装。同日レビュー4本の指摘を統合反映済み）。
**公開条件**：9月中の公開を目標にする（ふるさと納税の検索は9月から立ち上がり、
11〜12月にピークを迎える。12月に入ってからでは間に合わない）。
既存ページへの追記なので stage の操作は不要。
**対象**：`tools/`（`hasokon.com/tools/furusato-nozei/` への追記と
`lib/furusato-nozei.ts` の関数追加。新ページは作らない）
**起票**：2026-08-21

## 背景と根拠

### 検索面がふるさと納税クエリに「表示され始めている」（2026-08-21 取得）

Search Console API（`tool.hasokon.com` プロパティ・2026-07-24〜08-20）で、
ふるさと納税系のクエリに表示が付き始めている。

| クエリ | 表示 | 掲載順位 |
|---|---|---|
| ふるさと 納税 生命 保険 料 控除 シュミレーション | 4 | 82 |
| ふるさと 納税 控除 額 | 3 | 92 |
| ふるさと納税 シミュレーション | 2 | 95 |
| 計算式・試算・限度額 などの変種 | 各1 | 87〜99 |

順位は2桁後半でクリックはまだ無い。ただしふるさと納税は**9〜12月に検索が
集中する季節クエリ**で、シーズン前のいま面を厚くしておく意味が大きい。

### 「早見表」クエリの受け皿がない

「ふるさと納税 上限額 早見表」は、総務省・さとふる・楽天など全ポータルが
専用コンテンツを持つ定番中の定番クエリだが、当ページには早見表が**ない**。
計算式の解説と計算機だけで、「表を引きたい」層（計算機に入力する前に
だいたいの規模感を知りたい層）を受け止められていない。

**この追記の一番の理由は「SEOのため」ではなく、「計算機に数字を入れる前に
規模感を知りたい人」への回答である**（レビューの指摘に同意）。
表の見せ方はそちらを軸にする。

### 当サイトだけが持っている差別化要素が2つある

1. **令和8年改正を織り込んだ計算ロジックが既にある。**
   `lib/furusato-nozei.ts` は令和8年分の基礎控除引き上げ（本則62万円+特例加算）・
   給与所得控除の最低保障74万円を実装済みで、ページ本文でも
   「所得税率の区分が1段下がって上限額が**下がる**人がいる」ことを解説している。
   世間の早見表の多くは令和7年以前の前提のままで、**「2026年対応の早見表」は
   それ自体が差別化になる**（例：給与収入500万円・独身は約61,000円→約58,000円）。
2. **社会保険料の厚生年金上限を反映した概算を使っている。**
   一般的な早見表は社会保険料を一律15%と仮定するが、当サイトのFAQは既に
   その不正確さを指摘している。自前の早見表なら同じロジックから生成でき、
   「FAQで他所の早見表の欠点を指摘しているのに自分の早見表はない」という
   ねじれも解消する。

## やること

1. `lib/furusato-nozei.ts` に、既存の上限額計算を年収×家族構成の格子に
   適用する関数を足す（**表の数値を手書きしない**。ロジックから生成して
   計算機と食い違わないようにする）
   - 年収軸：300万〜1,500万円（〜800万は50万円刻み、以降100万円刻み）
   - 家族構成軸は**次の4列で確定**（ポータル各社の早見表と同じ軸にして
     比較検索に応える）：
     1. **独身・共働き**（＝配偶者控除を受けない場合）
     2. **夫婦**（配偶者控除あり・70歳未満）
     3. **夫婦＋子1人（16〜18歳）**
     4. **夫婦＋子2人（16〜18歳と19〜22歳）**（高校生1人＋大学生1人。
        `dependentsGeneral: 1` + `dependentsSpecific: 1`）
   - **表示の丸めは必ず切り捨て（安全側）**。早見表はスクリーンショットで
     持ち帰られるため、計算機の上限額を1円でも超える数字を載せると、
     その差がそのままユーザーの自己負担増になる。千円単位に丸める場合も
     切り捨てのみ
   - **テストは一致ではなく不等式で担保する**：「表の各セルの値 ≦ 同じ条件で
     `calcFurusato` が返す上限額」を全セルについて検証する
     （丸め単位を変えてもテストが生き続ける）
2. `app/furusato-nozei/page.tsx` に `<h2>控除上限額の早見表（2026年・令和8年分）</h2>`
   を追加し、ビルド時に表を静的に焼き込む（`shuzei-kaisei` の早見表と同じ方式）
   - **表の生成前提（この仕様で確定。実装者は変えない）**：
     - 収入は額面給与のみ（給与所得控除は令和8年分）
     - 社会保険料は `estimateSocialInsurance` の概算
       （協会けんぽ全国平均・本人負担分：健康保険4.99%・厚生年金9.15%で
       標準報酬月額の上限反映・雇用保険0.55%）
     - **介護保険料は含めない（`kaigo: false`＝40歳未満相当）**
     - その他の所得控除は0・住宅ローン控除なし
     - **ワンストップ特例を利用する前提（`onestop: true`）**
   - **表の直下に出す注記（必須）**：
     - 「15歳以下のお子さんは上限額に影響しないため、『夫婦』の列を
       ご覧ください」（16歳未満は扶養控除の対象外のため。総務省の早見表が
       「子は高校生を指す」と注記しているのと同じ理由。当サイトの計算機は
       年齢区分を持っているので正確に言い切れる）
     - 40〜64歳の方は介護保険料のぶん上限額が数千円下がること
     - 生命保険料控除など他の控除がある人はずれること（計算機への導線）
     - ワンストップ特例を前提にした表であること
   - スマホ表示は既存の早見表ツールの作法に揃える：
     **外側を `overflow-x: auto` のラッパーで囲み**（`saitei-chingin` /
     `shuzei-kaisei` / `tabako-zei-neage` / `tsubo-heibei` と同じ形）、
     **`<table>` に `white-space: nowrap`**（#151 で `waribiki-percent` に
     入れたのと同じ。6桁の金額×5列は折り返しの典型）。
     **新しいCSSクラスは増やさない**
3. **title は「足す」のではなく同等の長さで「書き換える」。変更後の文字列は
   次で確定**（レビューでの調停結果。実装者は変えない）：

   ```
   ふるさと納税 控除額の計算機・上限額早見表｜令和8年分
   ```

   - 現行28字→新27字。実測で表示が付いている「控除額」（3imp）を残したまま
     「上限額」「早見表」「令和8年分」を入れ、実績のない
     「所得税・住民税の内訳」だけを落とす
   - **撤退条件**：公開4週間後に Search Console で「控除額」
     「シミュレーション」系クエリの掲載順位を確認し、悪化していたら
     現行 title に戻す
   - description にも「早見表」「2026年（令和8年分）」を足す
4. FAQ「早見表と金額が違うのはなぜですか？」に、この早見表は計算機と
   同じロジックである旨を追記
5. **年表記が腐る対策**：h2・description・title の「令和8年分」の文字列は
   ロジックと違い自動では追随しない。`tools/CLAUDE.md` の「データ更新箇所」に
   1行足す（「ふるさと納税の年度改定時 → `lib/furusato-nozei.ts` の定数と、
   `app/furusato-nozei/page.tsx` の早見表見出し・title・description の年表記」）
6. JSON-LD・構造は既存のまま（FAQPage に追記した分だけ反映される）

## やらないこと

- 早見表の独立ページ化（`/tools/furusato-nozei-hayamihyo/`）。
  既存ページの評価に乗せるほうが立ち上がりが速い。分離はページが育ってから検討
- **総務省・各ポータルの早見表の数値を転記しない**（自前ロジックから生成する。
  表という形式は転記の誘惑が働くが、権利面で問題が起きるとすればここだけ）
- ワンストップ特例の申請期限リマインダー等の機能追加（別提案に切る）

## 期待される効果

- 「ふるさと納税 上限額 早見表」「ふるさと納税 上限 年収」系の
  定番シーズンクエリへの露出開始。既に表示が付き始めている
  「控除額」「シミュレーション」系クエリの評価補強
- 令和8年改正対応を前面に出すことで、旧前提の早見表との情報鮮度の差を
  検索結果で主張できる（title・h2・description に「令和8年分」を明記）

- 合計: **1セッション・概算 50k〜80k トークン程度**（新ページを作らないため小さい）
