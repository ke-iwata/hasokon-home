### 世の中の需要と競合（2026-11-28 の Web 調査）

- 日本語の時差サイトは**サマータイムを自動で反映しないものがある**（「サマータイム期間中は表示時刻に +1 時間してください」と注記して利用者に足させる型。bloomeria.jp の世界時計）。
  **ここを間違えると、会議に 1 時間ずれて出る**
- 夏時間を考慮した変換ができるサイト（miniwebtool のタイムゾーン変換器・zeitverschiebung.net）は**3都市まで・英語のみ**など制限がある
- 足りていないのは：①**サマータイムの自動反映と「いつ切り替わるか」を同じ画面に出す**、②**日本時間を基準にした会議の候補帯**（相手の 9〜18 時と自分の 9〜18 時が重なる帯）、
  ③**フライトの到着の現地時刻**（出発の現地時刻＋飛行時間 → 着いた国の時刻と日付。「日付変更線をまたぐと前の日に着く」が分かる）

## 提案する仕様

### 入力

1. **基準の日時**（既定：いま。「いまの時刻」は 1 分ごとに進む）。日付と時刻を変えると**その日の**時差で出す（サマータイムの判定は日付に依存するため）
2. **基準の都市**（既定：東京）
3. **比べる都市**（最大 8 つ。既定：ニューヨーク・ロサンゼルス・ロンドン・パリ・シンガポール・シドニー）。都市名の検索（日本語・英語・国名）で足す
4. 選んだ都市は URL のクエリ（`?c=new-york,london`）と端末（`localStorage`。try/catch で包む）に残す。**時刻は URL に入れない**（共有された時刻が古くなるため）

### 結果

- 都市ごとに：**現地の日付・時刻（曜日つき）**・**日本との時差（「−14時間」「+1時間」）**・UTC オフセット・**サマータイム中かどうか**
- サマータイムの都市には**次の切り替え日時**を出す（例：「ニューヨーク：2027-03-14（日）午前2時に夏時間へ。日本との時差は −14時間 → −13時間」）
- 日付が日本と違う都市は「**前日**」「**翌日**」の印を付ける（色だけに頼らない）
- 30分・45分ずれる地域（インド +5:30・ネパール +5:45 など）を正しく出す

### 会議の候補帯

- 選んだ都市それぞれの「勤務時間」（既定 9:00〜18:00。都市ごとに変えられる）を、**日本時間の 24 時間の横帯**に並べる
- **全員が勤務時間内の帯**を太く示し、「日本時間 22:00〜翌 1:00（ニューヨーク 8:00〜11:00）」のように文で出す。重なりが無いときは「重なる時間はありません。いちばん負担が少ないのは…」と、**勤務時間外にはみ出す合計が最小の 1 時間**を出す
- 帯の表は横スクロールさせず、幅 390px では都市を縦に積む

### フライトの到着時刻

- 出発地・出発の現地日時・飛行時間（時間と分）・到着地 → **到着の現地日時**と「日本時間では何時か」
- 例のプリセット（羽田→ホノルル 約 7 時間など）は**置かない**（便ごとに違い、古びる）。入力欄の例示だけにする

### 計算の約束（`tools/lib/jisa.ts`。純関数）

1. 時刻の計算は**すべて UTC のエポック秒**で持ち、表示のときにだけ `Intl.DateTimeFormat` の `timeZone`（IANA 名）で現地に直す。
   **`Date` のローカルのタイムゾーン（利用者の PC の設定）に依存しない**（[UNIX時間](./unix-jikan-excel-serial.md)の約束と同じ）
2. オフセットは `timeZoneName: 'shortOffset'` で読み、「GMT-5」「GMT+5:30」をパースして分にする（テストで固定）
3. 次の切り替え日時は、基準から 1 年先までを**1 日刻みでオフセットの変化を探し、変化した日の中を二分探索**して分単位で決める
4. 現地の時刻入力（フライトの出発時刻）は、**夏時間の切り替え時刻にかかると「存在しない時刻」（例：2027-03-14 2:30 ニューヨーク）か「2回ある時刻」（2027-11-07 1:30）**になる。
   前者は「この時刻はサマータイムの切り替えで存在しません」、後者は「夏時間／標準時のどちらか」を選ばせる。**黙ってどちらかに丸めない**
5. 判定の基になるタイムゾーンのデータは**ブラウザ（`Intl`）が持つ IANA tz データベース**。国の制度変更（夏時間の廃止など）はブラウザの更新で反映される。
   本文に「各国の制度変更はブラウザのデータに依存します。航空券・会議の確定は相手先の案内で確かめてください」と出す

### 都市の一覧（`tools/lib/jisa-cities.ts`）

- **約 80 都市**。各都市に `slug`・日本語名・英語名・国名・IANA タイムゾーン名・よみ（検索用）を持たせる
- 選ぶ基準：日本からの渡航先と主要な取引先（北米・欧州・アジア・オセアニア・中東・中南米・アフリカの各主要都市）、
  **ハワイ（ホノルル）・グアム・サイパン**（年末年始の旅行先）、**30分・45分の地域**（デリー・カトマンズ・アデレード）
- テストで固定すること：IANA 名が `Intl.supportedValuesOf('timeZone')` に含まれる（Node 22 で確認）／slug の重複なし／日本語名の重複なし

### ページの構成

1. 見出し・リード（「日本時間と世界の都市の時刻を並べます。サマータイムは日付から自動で反映」）
2. ツール（いまの時刻の一覧 → 会議の候補帯 → フライトの到着）
3. **2027 年のサマータイムの期間の表**（米国・カナダ：3/14〜11/7、欧州：3/28〜10/31、オーストラリア南東部（シドニー・メルボルン）：〜4/4・10/3〜。
   **表の日付は `Intl` から計算して描画し、手で書かない**（年が変わっても嘘にならないように。テストで 2027 年の値を固定する））
4. 本文：時差の読み方（「日本は UTC+9、夏時間は無い」）・日付変更線と「前日に着く」・夏時間の切り替え日の注意（会議の招待の時刻）
5. FAQ（6問：ニューヨークとの時差は？（夏 −13 時間・冬 −14 時間）／ロンドンとの時差は？／ハワイにサマータイムはある？（無い）／
   サマータイムはいつから？／会議の時刻を相手に伝えるときのこつ（UTC か相手の現地時刻を併記）／日本にサマータイムはある？（1948〜1951 年に実施、いまは無い））
6. JSON-LD（`WebApplication`・`FAQPage`）と `metadata` の `robots: robotsFor('jisa')`

**FAQ の時差の数字は都市データと `Intl` から生成して本文に差し込み、手で書かない**（`tools/tests/jisa.test.ts` で 2027-01-15 と 2027-07-15 の値を固定）。

### 送らない・計測

- 計算はすべてブラウザ内。GA4 の `tool_use` には**都市の数と、使った機能（一覧・会議・フライト）だけ**を送る（都市名の組み合わせは送らない）。
  [tool-use-coverage.md](./tool-use-coverage.md) のとおり、初回の操作で1回
