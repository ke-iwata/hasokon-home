## A1：割引・パーセント計算が浮動小数の誤差で 1 円ずれる（`waribiki-percent`）【高】

### 現状

`tools/lib/waribiki-percent.ts`

```ts
// 104〜108 行
const kept = rates.reduce((acc, r) => acc * (1 - r / 100), 1);
return (1 - kept) * 100;
// 181〜182 行
const rawDiscounted = input.price * (1 - eff / 100);
const discounted = roundBy(rawDiscounted, input.rounding);
// 198〜199 行
const rawIncluding = discounted * (1 + rate);
const includingTax = roundBy(rawIncluding, input.rounding);
```

`roundBy`（`tools/lib/rounding.ts` 49 行）は `floor` / `ceil` をそのまま掛けるので、二進小数の誤差が 1 円のずれになる（`round` だけは `Number.EPSILON` を足しているが、x.5 の境目では足りない）。

### 再現（起票者が Node で確認）

| 入力 | 端数 | いまの出力 | 正しい値 |
|---|---|---|---|
| 1000円の 80%オフ | 切り捨て | **199円** | 200円 |
| 1000円の 70%オフ | 切り上げ | **301円** | 300円 |
| 100円の 55%オフ | 切り捨て | **44円** | 45円 |
| 1000円を 30%オフ → さらに 20%オフ | 切り捨て | **559円** | 560円 |
| 税抜 100円に 10% | 切り上げ | **111円** | 110円 |

価格 1〜20,000円 × 割引 1〜99%（整数）の総当たりで、切り捨て 13,163 件・切り上げ 11,605 件・四捨五入（x.5 の境目）6,194 件がずれる。
税込への換算は 10% の切り上げで 10 万件中 5,524 件、8% で 751 件。早見表は四捨五入でキリのよい値なので影響なし。

### 仕様（直し方）

1. **率は 0.01% 単位の整数に直す**（`r100 = Math.round(r * 100)`）。
   **小数 2 桁を超える入力（`33.333` など）は計算せず、入力欄の下に「割引率は小数第 2 位まで入力してください（例：33.33）」と出す**。
   いまの入力欄は `step="any"`（`tools/app/waribiki-percent/Calculator.tsx` 265・306 行）で何桁でも入るため、黙って 0.01% に丸めると画面の率と計算に使った率が食い違う。
   判定は文字列で行う（入力の文字列の小数点以下の桁数を数える。`r * 100` が整数かを浮動小数で見ると、それ自体が誤差でぶれる）。`step` は `0.01` に改める
2. 割引後の額は**分子・分母を整数のまま持って丸める**：
   `numer = price × Π(10000 − r100ᵢ)`、`denom = 10000ⁿ`。`floor` は整数の割り算、`ceil` は `(numer + denom − 1) / denom`、`round` は `(2·numer + denom) / (2·denom)` の切り捨て。
   二重割引の段数（n ≤ 3）と価格の上限で `Number.MAX_SAFE_INTEGER` を超えうるので **`BigInt` で計算**する
3. 税込は消費税計算機（`tools/lib/shohizei.ts`）と同じく `discounted × (100 + 税率%) / 100` を整数で
4. 実効の割引率の表示（`effectiveRate`）は表示用なので小数のままでよいが、**丸めの計算には使わない**
5. **「AのB%はいくら」（`percentOf`、`tools/lib/waribiki-percent.ts` 241〜244 行。`Calculator.tsx` 508 行で `roundBy` している）も同じ整数化の関数を通す**。
   いまは `(base * percent) / 100` を浮動小数で出しているので、**375円の 18.4% が `68.99999999999999` になり、切り捨てで 68**（正しくは 69）。
   価格 1〜2,000 × 率 0.1〜99.9%（小数 1 桁）の総当たりの切り捨てで 127 件ずれる（企画レビュー #466 で確認）。
   A・B とも小数 2 桁まで（超えたら 1. と同じ案内）とし、`numer = A100 × B100`、`denom = 1,000,000` を `BigInt` で丸める。
   丸めない表示（端数「そのまま」）も `numer / denom` を文字列で小数に起こし、`68.99999999999999` のような表示を出さない
6. 上の再現の 5 行と、375円の 18.4%（切り捨てで 69）をテストに足す。あわせて「価格 1〜2,000円 × 割引 1〜99% の総当たりで、`BigInt` で求めた正解と一致する」性質テストを 1 本

## A2：ヘボン式ローマ字が末尾の長音「お」を落とす（`hebon-romaji`）【高】

### 現状

`tools/lib/hebon-romaji.ts` 227〜233 行は、直前の母音が `o` で次が「う」「お」「ー」なら**位置にかかわらず**長音として書かない。
そのため **たかとお → `TAKATO`**、**みそのお → `MISONO`** と出る。

### 根拠

神奈川県パスポートセンター「ヘボン式ローマ字綴方表」（2026-07-24 更新） https://www.pref.kanagawa.jp/docs/h6d/passport/hepburn.html

> 末尾の長音の「お」は「O」で表記します。（例：高遠（たかとお）⇒ TAKATOO）

末尾以外の「お」（大野 ONO）と、位置にかかわらず「う」（佐藤 SATO）は書かない。

### 仕様（直し方）

1. **氏・名それぞれの最後の音節が「お段＋お」のときは O を残す**（たかとお → TAKATOO、みそのお → MISONOO）。「お段＋う」「お段＋ー」は従来どおり書かない
2. OH 表記の代替案を出すときも、末尾の「お」は OH にしない（TAKATOH ではない。非ヘボン式の扱いになるので B2 の案内に寄せる）
3. 本文の「間違えやすい表記ルール」の表（`page.tsx` 163 行付近）に「末尾の長音『お』は O を書く（高遠 TAKATOO）」の行を足す
4. テスト：たかとお・みそのお・おおの（ONO のまま）・さとう（SATO のまま）・ようこ（YOKO のまま）
