# 年齢計算に「年齢早見表」と満◯歳◯ヶ月を足し、付き始めた検索クエリを受け止める

**状態**：実装済み（2026-08-18。本番反映はタグリリース待ち）
**対象**：`tools/`（`hasokon.com/tools/nenrei-keisan/`）
**起票**：2026-08-18

---

## 背景と根拠

### 検索クエリは付き始めたのに、ページがその形をしていない

GSC（Search Analytics API・直近28日・2026-08-18 取得）で、
`/tools/nenrei-keisan/`（10表示・掲載順位 86.2）に付いているクエリは
次の3グループにきれいに分かれる：

1. **「満◯歳◯ヶ月」系**（4クエリ）
   「満 何歳何ヶ月」「満何歳 何ヶ月」「満何歳何ヶ月」「満年令」（順位 91〜96）
2. **逆引き系**：「18 歳 何 年 生まれ」（順位 81）
3. **年号×年齢系**：「平成2年 西暦 年齢」（順位 85）、「子供 年齢 計算」（順位 74）、
   「生年 月 日 年齢」（順位 100）

ところが現状のページは：

- 計算結果は**満年齢（年単位）だけ**で、「◯歳◯ヶ月」を出さない
  （赤ちゃん・子どもの月齢、書類の「満何歳何ヶ月」欄という明確な用途があるのに）
- 西暦・和暦早見表（明治〜令和）に**年齢の列がない**。
  「平成2年 西暦 年齢」と聞かれて和暦↔西暦しか答えられない
- 「◯歳は何年生まれ」の**逆引きの受け皿がない**

つまり、**表示が付き始めた3グループのどれにも半歩ずつ届いていない**。
アスペクト比計算機で成功したのと同じ「既に表示が出ているページを、
付いているクエリの形に合わせて埋める」一手
（[aspect-ratio-gyakubiki-seo.md](./aspect-ratio-gyakubiki-seo.md) の再現）。

### 「年齢早見表」は年齢系で最大の定番クエリ

「年齢早見表」（「年齢早見表 2026」「令和8年 年齢早見表」）は年齢系クエリの
最大ボリューム帯で、keisan.casio.jp や印刷用早見表サイトが必ず持っている定番。
当ページは title に「早見表」の語を持ちながら、**掲載しているのは
西暦・和暦対応表で、年齢早見表（生まれ年→満年齢）ではない**。
既存の表に列を1本足すだけでこのクエリ群の受け皿になる。

## 提案する仕様

既存ページの拡張のみ。計算ロジックの変更はしない。

1. **計算結果に「満◯歳◯ヶ月」を追加**（`Calculator.tsx`）
   - 現在の満年齢表示の直下に「満◯歳◯ヶ月（◯日）」を出す
   - 月数は「誕生日の日を基準に、まだ迎えていない月は数えない」満年齢と同じ
     数え方（民法の期間計算に合わせ、月末生まれの繰り上がりも既存ロジックの
     流儀に揃える）。境界（誕生日当日・月末日・うるう年2/29）はテストで固定
2. **西暦・和暦早見表に「年齢」列を追加**（`page.tsx` の `WarekiTable`）
   - 「今年の誕生日で◯歳（誕生日前は◯歳）」が読み取れる列を1本足す
   - 年は**ビルド時の年**から出す。見出しを「年齢早見表【2026年版】」の形にし、
     何年基準の表かを本文にも明記する
   - **年の取り違えを腐らせないためのテストを足す**：表の基準年が
     `new Date().getFullYear()` と一致することを `tools/tests/` で検証
     （年が変わった最初のビルドでテストが落ち、更新を強制する。
     `saitei-chingin` の `DATA_CHECKED_AT` と同じ「鮮度を見張る」発想）
3. **逆引き「◯歳は何年生まれ」**（`page.tsx`）
   - 0〜100歳の「年齢 → 生まれ年（西暦・和暦）」早見表を追加
     （今年誕生日を迎えた場合／まだの場合の2列。18歳→2007年度・2008年生まれ、
     のような学年の断り書きも1行入れる）
   - 「18歳 何年生まれ」「20歳 何年生まれ」系クエリの直接の受け皿
4. **title / description / FAQ の調整**
   - title に「年齢早見表」を明示（例：「年齢計算・年齢早見表【2026年版】｜
     満何歳何ヶ月と西暦和暦変換」。文字数は実装時に調整）
   - FAQ（JSON-LD）に「満18歳になるのは何年生まれ？」「満何歳何ヶ月はどう数える？」
     「年齢早見表は何年基準？」を追加
5. **registry の `updatedAt` を更新**

## やらないこと

- 計算ロジック（満年齢・和暦変換・干支）の変更。既存テストは触らない
- 印刷専用ページや PDF 配布（需要はあるが別提案。まず1ページ内で受ける）
- 数え年の計算モード追加（FAQ で数え方の違いに触れるにとどめる）

## 期待される効果

- 既に表示が付いている9クエリ（順位74〜100）を、ページ内に答えの実体がある
  状態にして30位台以内へ。とくに「満何歳何ヶ月」系4クエリは競合が
  計算機能で答えており、結果表示の追加が順位に直結しやすい
- 「年齢早見表」系の大ボリューム帯に初めてエントリーする
  （新規ページを作らず、既存ページの評価に乗せる）
- 効果は GSC の `/tools/nenrei-keisan/` の表示・順位・クリックで計測する

## 工数（消費トークン目安）

約60k〜90k（月齢計算＋境界テスト 30k、早見表2本と基準年テスト 20k、
文言・FAQ・title 調整 10k〜20k）。レビュー往復込みで120k以内。
計算ロジックを触らないため退行リスクは小さい。
