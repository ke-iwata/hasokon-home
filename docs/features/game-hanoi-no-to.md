## 提案する仕様

### 遊び方

- 柱は3本（左・中・右）。始めは左の柱に n 枚（3〜8。既定 4）が大きい順に重なっている
- 1手で動かせるのは**いちばん上の1枚だけ**。**小さい円盤の上に大きい円盤は置けない**
- 全部を**右の柱**に移したら完成。手数・時間と、最少手数 2ⁿ−1 を並べて出す
- 操作：
  - **タップ2回**：取る柱 → 置く柱。1回目で一番上の円盤を少し持ち上げて見せる。置けない柱をタップしたら、円盤を元に戻し、柱を一瞬赤く縁取る
    （エラー音は出さない）。同じ柱をもう一度タップしたら取り消し
  - **ドラッグ**：円盤をつまんで柱の上で離す（`card-drag.ts` の仕組みを借りるかは実装時に判断。タップ2回が主）
  - キーボード：`1`・`2`・`3` で柱を選ぶ（取る→置くの2回）。`Z` で1手戻す
- 1手戻す（何手でも）・最初から

### ヒントと自動再生

- **ヒント**：今の局面から最短で完成させる手の**最初の1手だけ**を、取る柱と置く柱を光らせて示す。
  任意の局面からの最短手は、大きい円盤から順に「どこへ行くべきか」を決める再帰で求まる（局面の探索は要らない。O(n)）
- **自動再生**：最初の局面から最短の 2ⁿ−1 手を 0.4秒／手で再生する（停止・1手ずつ送り）。
  再生中は手数の記録をつけない
- ヒントを使ったか・自動再生を見たかは記録に残す（「ヒントなしで最少手数」を別に数える）

### 記録

- `lib/records.ts` に**枚数ごと**（variant ＝ `'3'`〜`'8'`）の最少手数・最短時間・クリア回数
- 最少手数で解けたら「最少手数！」の印。8枚を最少の255手で解いたら、記録欄に印を残す

### 画面

- 盤は横長。スマホ（375px）で柱3本と8枚の円盤が収まる幅（円盤の最大幅 ≒ 柱の間隔の 90%）。
  [mobile-one-screen.md](./mobile-one-screen.md) の約束どおり、スタート後は盤・手数・ボタンが1画面に収まる
- 円盤は枚数ごとに色を変える（色だけで区別させない：幅の差で必ず区別できる。色覚に依存しない）
- 盤の下に「最少手数は 2ⁿ−1（n 枚なら）」と、n=3〜8 の表（7・15・31・63・127・255）を SSR で出す
- 本文（SSR）：遊び方／最少手数の理由（大きい1枚を動かすには、その上の n−1 枚をどけておく必要がある、を3行で）／FAQ 3問
  （「何枚から難しい」「最少手数は」「1枚目はどこに動かす（枚数が奇数なら右、偶数なら中）」）。FAQ は `FAQPage` の JSON-LD に同じ文
- `metadata` に `robots: robotsFor('hanoi')`

## テスト

- n=3〜8 の最短手順の長さが 2ⁿ−1 で、どの手も合法、最後が完成になる
- 任意の局面（ランダムに合法手を 0〜200手打った局面）から「次の1手」を繰り返すと完成し、
  その手数が既知の最短手数の式（大きい円盤から数える）と一致する
- 大きい円盤を小さい円盤の上に置く手が拒否される
- 1手戻すを繰り返すと最初の局面に戻る
- 記録の variant が枚数ごとに分かれる

## 期待される効果

- 名前がそのまま検索語の定番パズルが1本増える（Bing と AI アシスタントの両方の入口）
- 短い（数分）・何度も遊べる・子どもでも分かる、の3つを満たし、パズル系の滞在時間の長さに乗る
- 実装が小さいので、公開待ちの列が詰まっているときでも**レビューと確認の負担が軽い**
