### 競合（2026-11-28 時点の見立て）

英語の chmod 計算機は多いが、日本語のものは**チェックボックスと数字の相互変換だけ**が中心。足りていないのは：

1. **`ls -l` の表示（`-rwsr-xr-x` `drwxrwxrwt`）を貼って読む**機能。特殊ビットの `s` `S` `t` `T`（大文字は実行権が無い）を正しく読むものは少ない
2. **記号モード（`u+x,g-w,o=r`・`a+X`）を「いまの権限」に適用した結果**。`X`（ディレクトリか実行権のあるときだけ x）を扱うものはほとんど無い
3. **umask から新規ファイル（666）・ディレクトリ（777）の既定値**を出す
4. **「よくある用途」の早見表と、危ない設定の警告**（777、他人が書けるディレクトリにスティッキービットが無い、秘密鍵が 600 より広い）

## 提案する仕様

### 入力（どれを触っても他が同期する）

1. **数字**：3桁（`755`）か4桁（`4755`）。先頭の `0` は許す（`0644`）。8進数の0〜7以外は「0〜7の数字で入れてください」
2. **記号**：9文字（`rwxr-xr-x`）か、`ls -l` の10文字（`-rw-r--r--`・`drwxr-xr-x`・`lrwxrwxrwx`）。末尾の `.` `+` `@`（SELinux・ACL・拡張属性）は外して読み、「ACL などの印は計算に含めていません」と出す
3. **チェックボックス**：所有者・グループ・その他 × 読み・書き・実行の9個 ＋ setuid・setgid・スティッキーの3個
4. **種類**：ファイル／ディレクトリ（`ls -l` の先頭の文字から自動。記号モードの `X` と警告の出し分けに使う）
5. **記号モードの適用**（折りたたみ）：`u+x,go-w` を入れると、いまの権限に適用した結果を出す
6. **umask**（折りたたみ）：`022` を入れると、新規ファイル `644`・ディレクトリ `755`

**入力は URL のクエリに入れない**（[サブネット](./subnet-keisan.md)と同じ。GA4 の `page_location` に載るため）。数字だけは `#755` のようにハッシュに残して共有できるようにする

### 結果

- 数字（3桁・4桁）・記号（9文字）・**コマンド例**（`chmod 755 ファイル名`・`chmod u=rwx,go=rx ファイル名`）をコピーのボタンつきで
- **日本語の説明**：「所有者は読み・書き・実行ができ、グループとその他は読みと実行だけ」
- ディレクトリのときは「読み＝一覧を見る、書き＝中にファイルを作る・消す、実行＝中に入る（`cd`）」と**ファイルと意味が違うこと**を出す

### 計算の約束（`tools/lib/chmod.ts`。純関数）

1. 内部は 12 ビットの整数（`0o7777` まで）で持つ。r=4・w=2・x=1、setuid=`0o4000`・setgid=`0o2000`・スティッキー=`0o1000`
2. 記号の特殊ビット：実行権ありで `s`／`t`、**実行権なしで `S`／`T`**（GNU coreutils の `ls` と同じ）
3. 記号モードは POSIX の `chmod` の文法（`[ugoa]*[+-=][rwxXst]*` をカンマでつなぐ。`=` は指定した対象の rwx を置き換える。`u=g` のように**他の対象の権限を写す形**も受ける）。
   対象を省いた `+x` は POSIX では umask の影響を受けるが、**本ツールは umask を掛けずに `a+x` として扱い、そう注記する**
4. `X` はディレクトリ、または**変更前に誰かの実行権がある**ファイルのときだけ x を付ける
5. umask：ファイル `0o666 & ~umask`、ディレクトリ `0o777 & ~umask`。umask は3桁か4桁の8進数

### 警告（結果の下に。断定しすぎない文面で）

| 条件 | 文面の要点 |
|---|---|
| その他に書き込み（`o+w`）があり、ディレクトリでスティッキーが無い | 誰でもファイルを消せる・置き換えられる。共有の置き場なら `1777`（`/tmp` と同じ） |
| `777`／`666` | 「とりあえず 777」はおすすめしない。Web サーバーで書き込みが要るなら所有者を合わせて `755`/`644` から |
| ファイルに setuid・setgid | そのプログラムが所有者の権限で動く。**Linux ではシェルスクリプトの setuid は無視される** |
| 「秘密鍵」の用途を選んで 600 より広い | OpenSSH はグループ・その他に読める秘密鍵を `UNPROTECTED PRIVATE KEY FILE!` で拒む。`chmod 600 ~/.ssh/id_ed25519` |

### よくある用途の早見表（本文。クリックで入力に入る）

`755`（ディレクトリ・実行ファイル）・`644`（普通のファイル・HTML）・`600`（秘密鍵・`.env`）・`700`（`~/.ssh`）・`640`（グループだけ読む設定ファイル）・
`1777`（`/tmp`）・`2775`（共有ディレクトリでグループを引き継ぐ）・`4755`（`passwd` のような setuid のプログラム）。
**特定のホスティング会社の推奨値は書かない**（会社ごとに違い、古びる）

| 入力 | 期待 |
|---|---|
| `755` / `0644` / `4755` / `1777` | `rwxr-xr-x` / `rw-r--r--` / `rwsr-xr-x` / `rwxrwxrwt` |
| `-rwSr--r--` | `4644`（実行権なしの setuid） |
| `drwxrwxrwT` | `1776` |

| `644`（ファイル）に `a+X` | `644`（変わらない）／ディレクトリなら `755` |
