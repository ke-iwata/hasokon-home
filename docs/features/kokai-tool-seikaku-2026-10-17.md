### A. 年末調整：給与所得を別表第五で出していない

**一次情報**：国税庁「令和8年度税制改正による所得税の源泉徴収事務への主な改正点」
（https://www.nta.go.jp/publication/pamph/gensen/2026kaisei.pdf 1頁 ⑵）:

- ロ「給与所得控除の最低保障額の引上げに伴い、所得税法で定める令和８年分以後の『**年末調整等のための給与所得控除後の給与等の金額の表**』が改正されました。」
- ハ「令和８・９年分の給与等の収入金額が69万1,000円以上220万円未満である場合には、その給与等に係る給与所得の金額については、上記イ及びロにかかわらず、次の金額とすることとされました。」

  | 給与等の収入金額 | 給与所得の金額 |
  |---|---|
  | 69万1,000円以上 74万1,000円未満 | なし |
  | 74万1,000円以上 219万1,000円未満 | その収入金額 − 74万円 |
  | 219万1,000円以上 219万3,000円未満 | **145万1,000円** |
  | 219万3,000円以上 219万6,000円未満 | **145万3,000円** |
  | 219万6,000円以上 220万円未満 | **145万6,000円** |

- 所得税法 28条4項：給与等の収入金額が 660万円未満の場合、給与所得の金額は**別表第五**による。別表第五は 220万円以上の帯で
  **収入金額を 4,000円刻み**にした表で、刻みの下端の収入に控除の式を当てた額になる
  （サイト内では `tools/lib/juminzei-hikazei.ts` の `kyuyoShotoku()` が 4,000円の切り捨てとして実装済み。大阪市の境目の目安表と一致を確かめてある）

**いまの実装**：

- `tools/lib/nenmatsu-chosei.ts` の `incomeToTotal()`（368行あたり）と `calcYearTax()`（437行あたり）が、
  `tools/lib/furusato-nozei.ts` の `salaryDeduction()`（式。159〜166行）を**収入そのもの**に当てている。別表第五の 4,000円刻みも、219.1万〜220万円の特例も無い
- `tools/lib/juminzei-hikazei.ts` の `kyuyoShotoku()` は 4,000円刻みを持つが、令和9年度（令和8年分の所得）の
  `salaryMinUntil: 2_200_000` より下はすべて式なので、**219.1万〜220万円の特例の 9,000円の帯だけ式のまま**
- 画面と FAQ は「国税庁『年末調整のしかた』の手順どおり」（`app/nenmatsu-chosei/page.tsx` 47行・215行）と言い切っている

**ずれの例**（令和8年分。node で計算）：

| 給与収入 | いまの給与所得 | 正しい給与所得 | 差 |
|---|---:|---:|---:|
| 2,195,000 | 1,455,000 | **1,453,000** | +2,000 |
| 2,199,000 | 1,459,000 | **1,456,000** | +3,000 |
| 4,001,999 | 2,761,599 | **2,760,000**（4,000,000 で計算） | +1,599 |
| 5,555,555 | 4,004,444 | **4,001,600**（5,552,000 で計算） | +2,844 |

差は 4,000円刻みの端数 ×（1 − 控除率）なので最大でおよそ 3,200円（219.1万〜220万円の帯では最大 3,000円）。課税給与所得は 1,000円未満切り捨てなので、
課税所得が 1〜4 段（1,000〜4,000円）ずれ、税率 5%・10%・20% の帯で算出税額が **50〜800円**、年調年税額（×1.021、100円未満切り捨て）を経て
**還付額が 0〜数百円**変わる（多くの人は 5%・10% の帯で 0〜400円）。
過大に出るのは給与所得なので、**年税額を多め・還付を少なめ**に出す向き。

ふるさと納税（`furusato-nozei`）の上限額も同じ `salaryIncome()` の式を通るが、上限額は「目安」と明記していて、ずれは数十円なので今回は対象外にする（下の「やらないこと」）。

## 提案する仕様

### A. 給与所得を「表」で出す関数を 1 つ足し、年末調整と住民税非課税の判定がそれを使う

1. `tools/lib/furusato-nozei.ts` に **`salaryIncomeByTable(income)`**（令和8・9年分）を足す。中身は：
   - 691,000 未満は式どおり（0）／691,000〜740,999 は 0
   - 741,000〜2,190,999 は `収入 − 740,000`
   - 2,191,000〜2,199,999 は上の特例の 3 段（**定数の表として持ち、【データ更新箇所】コメントと出典 URL を付ける**）
   - 2,200,000〜6,599,999 は `floor(収入 / 4,000) × 4,000` に `salaryDeduction()` を当てる
   - 6,600,000 以上は式どおり
   **既存の `salaryIncome()` / `salaryDeduction()` は変えない**（`lib/kyuyo-nenkin-kojo.ts` が「控除額の定義」として式を使っている。15〜16行のコメント。
   ここを表にすると 280万円の上限の判定が変わる）
2. `tools/lib/nenmatsu-chosei.ts`：`YearRules` に `salaryIncome: (income) => number` を足し、`RULES_R8` は `salaryIncomeByTable`、
   `RULES_R7`（改正前の比較用）は令和7年分の別表第五（最低保障 65万円・190万円で式につながる）で同じ関数を作る。
   **令和7年分の表に 219万円帯のような特例の段があるかは、実装時に「令和7年分 年末調整のしかた」の表で確かめる**（無ければ 4,000円の切り捨てだけ）。
   `incomeToTotal()` と `calcYearTax()` はこの関数を呼ぶ。画面に出す「給与所得控除額」は `収入 − 給与所得` で出す（表の結果と矛盾させない）
3. `tools/lib/juminzei-hikazei.ts`：`kyuyoShotoku()` の令和9年度を `salaryIncomeByTable` に置き換える（自前の 4,000円の切り捨てを 2 か所で持たない）。
   令和8年度（令和7年分）は 2. の令和7年分の関数に置き換える
4. `tools/app/nenmatsu-chosei/page.tsx` の FAQ「年税額はどうやって計算していますか？」の (1) を
   「年収から、国税庁の『年末調整等のための給与所得控除後の給与等の金額の表』で給与所得控除後の金額を出す（660万円未満は 4,000円刻み）」に直す

## やらないこと

- **ふるさと納税・iDeCo・確定申告が必要か・働き損の計算は式のまま**にする。いずれも「上限の目安」「判定」で、ずれが数十円・境目に影響しない。
  必要になったら別の点検で `salaryIncomeByTable` に寄せる
- **`lib/kyuyo-nenkin-kojo.ts` は触らない**（給与所得控除の「額」を式で測る設計。コメントのとおり）
- 660万円以上は式どおりで正しいので触らない

## 期待される効果

- 年末調整の計算機の年税額・還付額が、会社の年末調整（＝国税庁の表）と**円単位で一致**する。11〜12月に「源泉徴収票と比べたら合わない」と離れる客を減らす
- 「国税庁の手順どおり」という本文の主張が実装と一致する（AI アシスタントの引用元としての信頼）
- 住民税非課税の判定と年末調整が**同じ給与所得の関数**を使い、4,000円の切り捨てを 2 か所で持たなくなる
