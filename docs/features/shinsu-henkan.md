## 提案する仕様

### 入力

1本の入力欄＋「何進数として読むか」の選択（既定は**自動**）。

| 入れたもの | 自動判定 |
|---|---|
| `0b1010`・`1010b` | 2 進 |
| `0o17`・`017`（先頭 0 は**8進と読まない**。「8進のつもりなら 0o を」と添える） | 8 進は `0o` のときだけ |
| `0x1F`・`1Fh`・`#1F` | 16 進（`#` は「色なら カラーコード変換へ」の案内も出す） |
| `255`・`-5` | 10 進 |
| `1010` のように 0/1 だけ | 10 進として読み、「2進数のつもりなら」の切り替えボタンを出す（勝手に決めない） |

- 空白・`_`・`,` は区切りとして無視する（`1111_0000`・`0xFF FF`）
- 基数は選択で 2〜36 も選べる（`zz`＝1295）
- **整数は BigInt で桁数の上限なし**（ただし 2の補数・ビット演算はビット幅の範囲で）

### 出力（整数）

- 2・8・10・16 進を同時に表示し、それぞれにコピー
- 2 進は **4 ビットごと**、16 進は **2 桁（1 バイト）ごと**に区切る（区切りなしの表示とコピーも選べる）
- ビット数・バイト数・「2 のべき乗との位置」（例：255 は 2⁸−1）

### ビット幅と2の補数

- ビット幅：8／16／32／64（既定は「自動」＝入るいちばん小さい幅）
- **符号なし・符号つき（2の補数）の両方の読み方**を並べる（`0xFF` → 符号なし 255／符号つき −1）
- 負の数を入れたら2の補数で表示し、**途中式**を出す：「5 → 0000 0101 → 反転 1111 1010 → ＋1 → 1111 1011」
- 範囲外は止めずに言う：「−200 は 8 ビットの符号つき（−128〜127）に入りません。16 ビットなら 1111 1111 0011 1000」
- バイト順（エンディアン）：16／32／64 ビットのとき、ビッグエンディアン・リトルエンディアンのバイト列を併記（ログ・バイナリを読む人向け）

### ビット演算

- A と B（どちらも上の入力と同じ形式）と演算子：AND・OR・XOR・NOT・左シフト `<<`・算術右シフト `>>`・論理右シフト `>>>`
- **桁をそろえた縦の筆算**で出す（A・B・結果の 2 進を上下に並べ、1 の桁を色＋太字で示す）。結果は 2・10・16 進で
- シフトはビット幅で切り詰め、はみ出たビットを薄く表示する
- よく使う形の例ボタン：「下位 4 ビットを取り出す（AND 0x0F）」「フラグを立てる（OR）」「反転（XOR 0xFF）」

### 小数（10進の小数 ⇔ 2進数・IEEE 754）

- `0.1`・`-12.375` を入れると 2 進の小数を出す。**循環する場合は循環節を示して**「0.0 0011 0011 …（0011 のくり返し）」と書く
  （分母が 2 のべき乗でない小数は有限桁で表せない、を一言で）
- **IEEE 754** の単精度（32 ビット）・倍精度（64 ビット）で、符号部・指数部・仮数部を色分けしたビット列と 16 進、
  **実際に格納される値**（`0.1` → `0.100000001490116119384765625`（単精度））と元の値との誤差
- 16 進（`0x3DCCCCCD`）から浮動小数点の値に戻す向きも
- `NaN`・`Infinity`・`-0`・非正規化数は名前を添えて出す

### 途中式（学習向け。このツールの売り）

- 10 進 → 2 進：**2 で割った余りを下から読む**表（16 ビットまで。それより大きい数は折りたたむ）
- 2 進 → 10 進：**重み（2⁷・2⁶ …）をかけて足す**表
- 2 進 ⇔ 16 進：**4 ビットずつ区切って読む**表
- 小数：**2 をかけて整数部を上から読む**表（循環を見つけたらそこで止める）
- 「途中式を印刷」（A4 縦。tools の `bosai-bichiku-keisan` の `@media print` にそろえる。広告は印刷しない）

### 共有 URL と計測（[subnet-keisan.md](./subnet-keisan.md) の決定に合わせる）

- **共有 URL は作らない**（初版）。入力値をクエリに載せると GA4 の `page_location` に入るおそれがある（サブネットで #553 のレビューが指摘）
- 計測は既存の `trackToolUse('shinsu-henkan', action)`。action は**操作の種類だけ**：`convert`（入力欄の `onBlur`）・`select-width`・`bitop-{and|or|xor|not|shl|shr|ushr}`・`float-{32|64}`・`copy`・`print`。
  **入力した値は送らない**（action を文字列の直書きにする。[tool-use-coverage.md](./tool-use-coverage.md) の約束）
- 既定の例のまま開いただけでは送らない

### ロジック（`tools/lib/shinsu.ts`。純関数のみ）

- `parseInput(text, base | 'auto')` → `{ value: bigint, base, warnings }`／小数なら `{ kind: 'fraction', … }`
- `toBase(value, base, { group })`・`toTwosComplement(value, width)`・`fromTwosComplement(bits, width)`
- `bitOp(a, b, op, width)`
- `fractionToBinary(numerator, denominator, maxDigits)` → 有限・循環（循環節の開始位置と長さ）を返す。**10 進の小数は文字列から分数にして扱い、`Number` を通さない**（0.1 を `Number` にした時点で誤差が入るため）
- `float32Bits(x)`・`float64Bits(x)`・`bitsToFloat(hex, width)`（`DataView` で）
- `steps*`（途中式の表を返す関数群）

### テスト（`tools/tests/shinsu.test.ts`）

- 基本：`255` → `0xFF`・`0b1111_1111`・`0o377`／`zz`（36 進）→ 1295／`2^64−1` → `0xFFFFFFFFFFFFFFFF`（BigInt で桁が落ちない）
- 2の補数：8 ビットで `−1` → `1111 1111`・`−128` → `1000 0000`・`127` → `0111 1111`・`−129` は範囲外／`0xFF` を符号つき 8 ビットで読むと −1
- ビット演算：`0b1100 AND 0b1010 = 0b1000`・`XOR = 0b0110`・8 ビットで `NOT 0` = 255・`-8 >> 1 = -4`・32 ビットで `-8 >>> 28 = 15`
- 小数：`0.5` → `0.1`（有限）・`0.1` → 循環節 `0011`（小数第2位から）・`0.375` → `0.011`
- IEEE 754：`0.1` 単精度 → `0x3DCCCCCD`・倍精度 → `0x3FB999999999999A`／`0.5` 単精度 → `0x3F000000`／`-0` → `0x80000000`／`0x7F800000` → `Infinity`
- 自動判定：`017` は 10 進の 17 として読み、警告に「8 進のつもりなら 0o」を含む／`1010` は 10 進で、切り替えの候補に 2 進を含む
- ページの `metadata` に `robots: robotsFor('shinsu-henkan')`（既存の `stage.test.ts` が見る）。`tool-use-coverage` のテストが入っていれば、それも通る

### 画面（幅 360px のスマホを基準に）

- 入力欄 → 4 つの進数（縦に並べる）→ ビット幅と2の補数 → ビット演算 → 小数・IEEE 754 → 途中式、の順。下の3つは見出しで折りたためる
- 64 ビットの 2 進は 360px で 2 行に折り返す（バイトの区切りで折る。横スクロールさせない）
- 等幅フォント。1 の桁は色だけでなく太字でも示す

### 本文（[thin-tool-content.md](./thin-tool-content.md) の型）

- **計算のしかた**（途中式の4つの表の読み方を、1つずつ例で）
- **2の補数とは**（「反転して1を足す」の理由を、8 ビットの時計の図で）
- **0.1 + 0.2 が 0.30000000000000004 になる理由**（倍精度の格納値で説明。プログラマがいちばん検索する形）
- FAQ 5問：先頭が 0 の数は 8 進か／16 進の A〜F はいくつか／2の補数と1の補数の違い／単精度と倍精度の違い／`chmod 755` の 8 進の読み方
- 出典：IEEE 754-2019（規格名の引用のみ）・ECMAScript 仕様の `Number`・`BigInt`・情報処理技術者試験の出題範囲（IPA「試験要綱」）・高等学校学習指導要領（情報）。
  **実装 PR で URL を確かめてから載せる**

### やらないこと

- **任意精度の小数演算・四則演算の電卓**：別のツールの領分。小数は「変換」と「IEEE 754 の内訳」だけ
- **共有 URL**（上の計測の理由。要望があれば subnet と同じ「クエリを消す」作りで後から）
- **文字コード（UTF-8・Shift_JIS のバイト列）**：需要はあるが別のツール（文字コード変換）として切り出す。ここでは数だけ
- 128 ビット以上のビット幅・固定小数点・BCD（需要が小さい）
