## 提案する仕様

### 入力

- **色を1つ**：HEX（`#rgb`・`#rrggbb`・`#rrggbbaa`、`#` 無しも可）／`rgb()`・`rgba()`／`hsl()`／CMYK（%）／色の名前（CSS の名前 `rebeccapurple` など）。**貼った形式を自動で判定**する（Base64 の自動判定と同じ考え方）
- **2色（文字色・背景色）**：コントラストのタブ。入れ替えボタン
- カラーピッカー（`<input type="color">`）と、スポイト（`EyeDropper` API。対応ブラウザだけ出す。非対応では表示しない）
- 入力は URL のクエリに反映し、**共有・ブックマークできる**。値は送信しない（静的ページ・ブラウザ内で完結）
  - 変換タブ（1色）：`?c=1a1a1a`／コントラストタブ（2色）：`?fg=1a1a1a&bg=ffffff`。値は `#` 無しの HEX（6桁または8桁）だけを書き出す
  - **不正なクエリ値（HEX として読めない・桁が違う）は、何も表示せず既定値（文字 `#1a1a1a`・背景 `#ffffff`）に戻す。** エラーを出さない（共有 URL の途中切れで画面が壊れたように見えないため）
  - クエリの組み合わせは無数に URL ができるので、**canonical は常に `/tools/color-code/` に固定**する（既存ツールと同じ `alternates: { canonical: `${SITE_URL}/color-code/` }`。クエリ付きの URL を sitemap・内部リンクに出さない）

### 出力

1. **変換**：HEX・RGB・HSL・HSV・CMYK・CSS の `oklch()`。それぞれコピーボタン
   - CMYK は**簡易変換（ICC プロファイルなし）**であることを明記する。「印刷所に入稿する色は印刷所の指定で」と注記
2. **コントラスト比**：`4.52 : 1` のように小数2桁。判定表：

| 対象 | AA | AAA |
|---|---|---|
| 通常の文字 | 4.5 以上 | 7 以上 |
| 大きな文字（24px 以上、または太字 18.66px 以上） | 3 以上 | 4.5 以上 |
| アイコン・ボタンの枠など（1.4.11） | 3 以上 | — |

   - 実際の文字色・背景色で「見本の文（漢字かな交じり）」を大小・太字で表示する
3. **合格する一番近い色**：落ちたとき、**色相と彩度（HSL の H・S）を保ったまま明度だけを動かして**、AA（または AAA）にちょうど届く色を文字色側・背景色側それぞれ出す。「この色に替える」ボタン
   - **明るくする側と暗くする側の両方を探し**、届くもののうち元の明度に近いほうを出す（明度の差が同じなら暗い側を優先する。この決め方をテストに書く）
   - **どちらに動かしても届かないことがある。** 例：背景が `#777777` だと、文字色を白にしても 4.48・黒にしても 4.69 で、AAA の 7 には文字色をどう動かしても届かない。このときは空欄や誤った色を出さず、「文字色の明るさだけでは届きません。背景色側を変えてください」と出す（背景色側の提案は別に出す。両側とも届かなければ「両方の色を変えてください」）
4. **色の見え方（近似）**：P型・D型・T型（1型・2型・3型の2色覚）とモノクロでの見え方を並べる。Brettel／Viénot の近似式
   - 言葉づかい：「異常」「障害」は使わない。見出しは「色の見え方のちがい（近似）」、各見本は「P型（1型2色覚）」のように書く
   - 注記：「シミュレーションは目安で、見え方には個人差がある。**診断ではない**」
5. **近い色の名前**：CSS の色名と JIS 慣用色名から、色差（CIEDE2000）が最小のものを3つ。JIS 慣用色名の値は**「近似」と表示**する（「JIS の規定値」とは書かない。規定はマンセル値で、sRGB は換算した近似のため）

### ロジック（`tools/lib/color/`。純関数のみ）

- `parse(input) → { r, g, b, a } | エラー`／`toHsl`・`toHsv`・`toCmyk`・`toOklch`
- `relativeLuminance(rgb)`：sRGB の線形化は WCAG 2.2 の式（しきい値 0.04045。8bit の入力では 0.03928 と結果が変わらない）
- `contrastRatio(a, b) = (L1 + 0.05) / (L2 + 0.05)`。**判定は丸める前の値で行う**（4.499 を 4.50 と表示して合格にしない）
- 透明度つきの文字色は、背景に合成してから比を出す
- **`tools/tests/link-contrast.test.ts` の `luminance()`・`contrast()` をこの lib に寄せて共有する**（サイト自身の配色テストと同じ式を使う）
- `nearestPassing(fg, bg, target) → 色 | null`：明度の二分探索を**明るい側・暗い側の両方**で行う。どちらでも届かなければ `null`
- **HSL・HSV は内部では丸めずに浮動小数で持ち、表示だけ丸める**（H は整数、S・L は小数1桁。例 `hsl(210 12.5% 34.9%)`）。変換の連鎖（HEX→HSL→明度を動かす→HEX）はすべて丸める前の値で行う
- 色名の表は自前で持つ。**JIS 慣用色名と CSS の色名だけ**（伝統色の一覧は出典を立てられないので今回は入れない）
  - CSS の色名：CSS Color Module Level 4 の名前付き色（仕様の値をそのまま使う）
  - JIS 慣用色名：**名前とマンセル値（JIS Z 8102:2001 の慣用色名）だけ**を使う。規格票は日本規格協会の著作物なので、**表（名前＋マンセル値＋説明）を丸ごと写さない**。説明文は持たない
  - sRGB の値は、マンセル値から **Munsell Renotation Data（RIT Munsell Color Science Laboratory が公開している `real.dat`。CIE xyY・C光源）を補間して xyY を出し、Bradford 変換で D65 に順応させて sRGB に換算した近似値**を、自前のスクリプト（`tools/scripts/gen-jis-color-names.mjs` などで生成し、生成結果を lib に置く）で計算する。出典（規格番号・Renotation Data）は FAQ とファイル冒頭に書く
  - **他サイトの色見本の値を写さない**

### テスト（`tools/tests/color.test.ts`）

- 黒と白で `21 : 1`、同じ色で `1 : 1`
- `#777777` と白で 4.48（AA 不合格）、`#767676` と白で 4.54（合格）—— 境目の定番の例
- 形式の自動判定（`fff`・`#FFFFFF`・`rgb(255 255 255 / 50%)`・`hsl(0 0% 100%)`）
- `nearestPassing` が返す色が必ず目標の比以上、かつ色相が元と同じ
- HEX → HSL（丸めない浮動小数）→ HEX の往復で値が変わらない。**全 1,677 万色を回すと遅いので、短い HEX の 4,096 色＋種を固定した乱数 10,000 色**で確かめる。表示用に丸めた HSL（小数1桁）からの往復は**保証しない**（テストもしない）
- `nearestPassing('#777777' を背景、文字は無彩色、目標 7)` が `null` を返す（届かない組み合わせ）
- 両方向の探索：元の明度より明るい側にしか解が無い組み合わせ・暗い側にしか無い組み合わせで、それぞれ正しく見つける
- 不正なクエリ（`?fg=zzz`・`?c=12345`）で既定値に戻り、例外を投げない
- `robots: robotsFor('color-code')` を書いている（既存の `stage.test.ts`）

### 画面（幅 360px のスマホを基準に）

- **既存ツールの部品・トークン（`tools/app/globals.css`）をそのまま使い、このツール専用の配色を作らない。** ページ自体の文字と背景のコントラストも `link-contrast.test.ts` と同じ基準で満たす
- 文字色・背景色の入力は**縦に積み**、入れ替えボタンはその間に置く
- 変換結果（HEX・RGB・HSL・HSV・CMYK・oklch の6行）は**1行1形式＋右端にコピー**。長い値は折り返さず省略せず、行の中で収まる文字サイズにする。**横スクロールを出さない**
- 判定表は3列（対象・AA・AAA）で 360px に収める。合否は色だけで伝えず、「合格」「不合格」の文字と記号を併記する
- 色の見え方の4見本（P型・D型・T型・モノクロ）は **2×2**
- 合格する色の提案は、判定表のすぐ下（落ちたときだけ出す）

### やらないこと

- 画像から配色を抜き出す・パレット生成（別ツールの規模。需要を見てから）
- APCA（WCAG 3 の草案の方式）の判定：まだ草案。**WCAG 2.2 の比だけ**にする。FAQ で触れる程度
- ICC プロファイルを使った正確な CMYK 変換
- ページ全体を読み込んでの自動診断（クローラー型）：送信なしの約束に反する
