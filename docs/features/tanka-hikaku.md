### 競合の状況（2026-11-19）

上位に出る比較ツール（業務系の計算サイトの単価計算、個人の「どっちが安い」比較、iPhone の単価比較アプリなど）は、
**2〜3 品を 100g / 100ml で比べる**・**税込⇔税抜（10% / 8%）**までは揃っている。調べた範囲で足りていないのは次の点で、ここを差別化にする：

1. **単位が混ざると比べられない**（片方が kg・片方が g、片方が L・片方が ml、「1 個あたり」と「10 個入り」）。
   入力した単位で自動でそろえて「100g あたり」「1kg あたり」「1 個あたり」を切り替えられるものが少ない
2. **まとめ買いの書き方**（「350ml×6 缶」「×2 パック」「3 個で 498 円」）を、そのまま入れられない
3. **割引・ポイントを足したうえでの比較**（「20%引き」「30 円引き」「ポイント 5%」）を同じ画面でできない
4. **前の内容量と比べる「実質値上げ率」**を出すものがほぼ無い（値上げのニュースの読み方として需要がある）
5. 2〜3 品の上限。**何品でも**（棚の 5〜6 品）並べたい

## 提案する仕様

### 入力（1 行 = 1 品。既定は 2 行、「＋ 品を足す」で何行でも）

| 欄 | 例 | 約束 |
|---|---|---|
| 名前（任意） | 「A 店」「大袋」 | 空なら A・B・C… |
| 値段 | 298 | 円。整数と小数（0.1 円単位の業務用単価）を受ける |
| 税 | 税込 / 税抜 8% / 税抜 10% | 既定は**税込**（店頭は総額表示が原則のため）。税抜を選んだ行だけ税込に直してから比べる |
| 内容量 | 350 | 数値 |
| 単位 | g / kg / ml / L / 個 / 枚 / 本 / 回分 | 重さ（g・kg）・量（ml・L）・数（個・枚・本・回分）の3系統。重さと量は**系統の中で換算して比べる**（g と kg、ml と L）。**数の系統は換算できないので、同じ単位どうしだけ比べる**（個と枚、本と回分は比べない）。比べられない行には「単位が違います」と出して順位から外す。g と ml の比重での換算もしない。**数と重さもまたがない**（「1 個あたりの重さ」を入れて重さで比べる機能は持たない） |
| 入り数（任意） | 6 ×（パック）2 | 「350ml × 6 缶 × 2」を **350 / ml / 6 / 2** で入れられる。掛けた合計の内容量を表示する |
| 割引（任意・折りたたみ） | ◯%引き / ◯円引き / ポイント◯% | 順序は「円引き → %引き → 税」（下の「割引・ポイントの掛け方」）。ポイントは**比較用の実質単価**として別の列に出し、支払う額には含めない |

- 数字の入力は `inputMode="decimal"`。全角数字・カンマ・「円」「g」の混入は受け流して数字だけ読む（`tools/lib/hankaku-zenkaku.ts` の `convertWidth` を流用）

### 割引・ポイントの掛け方

- **割引は「入れた値段」に掛ける。** 税込の行は税込の値段に、税抜の行は税抜の値段に掛け、税抜の行は割引のあとで税込に直す
  （消費税は値引き後の対価に掛かるため、税抜の売り場の値引きは税抜の額から引かれる）
- **順序は円引き → %引き。** 商品に貼る値引きシール（◯円引き）が先に付いていて、レジでの会員割引・クーポン（◯%引き）があとから
  掛かる売り場が多いため。順序で結果が変わるので、**結果の欄に「30円引きのあと20%引きで計算」と順序を書いて出す**
- **端数は最後に1回だけ。** 途中（円引き・%引きのあと）は丸めず、税込にした最後の額を 1 円未満切り捨てにする
- 例（どちらも「30円引き」と「20%引き」を両方使った場合）：
  - **税込の行** 321 円 → 30 円引き 291 円 → 20%引き 232.8 円 → **232 円**
  - **税抜 8% の行** 298 円 → 30 円引き 268 円 → 20%引き 214.4 円 → 税込 231.552 円 → **231 円**
- **ポイント％は、税込の支払額（割引後）に掛ける。** 店によって税抜額に掛ける・1 円未満の扱いが違うので、画面と Q&A 3 に「店により異なる」と書く。
  例：支払額 232 円・ポイント 5% → 11.6 → **11 ポイント**（切り捨て）→ 比較用の実質 **221 円**

### スマホ（幅 390px）の組み方

- **1 品＝1 枚のカード**（表の 1 行に 7 欄を並べない）
  - 1 段目：名前（任意）と削除ボタン（×）
  - 2 段目：値段 ＋ 税（税込 / 税抜 8% / 税抜 10% のトグル）
  - 3 段目：内容量 ＋ 単位
  - 入り数と割引は**カードの中の折りたたみ**（使う人だけ開く）
- 「＋ 品を足す」はカードの並びの下。**2 品より少なくはできない**（2 品のときは削除ボタンを押せない状態にする）
- **結果は横長の表にせず、安い順のカードの並び**：単価を大きく、「いちばん安い」の印・「◯円（◯%）高い」・同じ値段で買える量を小さく
- パソコン（幅 768px 以上）では入力カードを 2 列に並べてよい。結果は同じカードの並び
- 部品は既存のツールに揃える（`waribiki-percent` の `card`・`field`・`field-row`・`chip`・`panel`／`metric` の組み立て、トグルは既存の `chip`）

### 結果

- **基準の単位を自動で決める**：重さは「100g あたり」、量は「100ml あたり」、数は「1 個あたり」。
  切り替えボタンで「1kg / 1L / 10 個あたり」にもできる
- 単価の安い順に並べ、**一番安い行に「いちばん安い」の印**、ほかの行には「◯円（◯%）高い」を出す
- **同じ値段で買える量**も1行で出す（「B と同じ 298 円なら A は 412g 買える」）。単価の差を量で言い換えると伝わりやすい
- 端数：単価は **小数第2位まで表示**（四捨五入）。比較・順位は丸める前の値で行う（同点に見えて順位が付くとき「ほぼ同じ（差 0.1% 未満）」と出す）

### 実質値上げ率（タブ B）

- 「前の値段・前の内容量」と「今の値段・今の内容量」を入れると、**単価の変化率**を出す
  （例：200g 198 円 → 180g 198 円 = 単価 **+11.1%**）。値段の変化と量の変化に分けて見せる
- 表現は**計算結果だけ**に留め、特定の商品・メーカー名は例に出さない（下の「やらないこと」）

- h1「単価比較 計算機（100g あたり・どっちが安い）」、metadata の description と `robots: robotsFor('tanka-hikaku')`
- 本文の Q&A（各 2〜4 行）：

  3. ポイント還元は単価に入れていい？（実質の比較用として。支払う額とは別。**税込の支払額に掛けて計算しているが、税抜額に掛ける店・端数の扱いが違う店もある**）

### 送らない・残さない

- 計算はブラウザ内で完結し、入力を送信しない。`localStorage` に残すのは**単位の切り替えの選択だけ**（品の値段は残さない）
- `tool_use` は「比較を出した」「実質値上げ率を出した」の 2 種を、品数（2・3・4 以上）だけ付けて送る（値段・名前は送らない）

### 計算の約束（`lib/tanka-hikaku.ts`。純関数）

- `toBase(qty, unit) → { kind: 'mass'|'volume'|'count', base: number }`（g・ml・個に正規化）
- `effectivePrice(price, tax, discounts) → number`（円引き → %引き → 税込化。税率は `shohizei-keisan`／`waribiki-percent` の定数を import し、ここに数字を書かない）
- **割引の計算は `tools/lib/waribiki-percent.ts`（`applyDiscount`・`TAX_RATES`・`effectiveRate`）を流用できるかを実装時に先に見る**。
  丸めは切り捨てに固定する（`waribiki-percent` のように丸め方を選ばせない）ので、合わないところだけ薄い包みを書く
- `unitPrice(item, per) → number`、`rank(items, per) → RankedItem[]`、`shrinkflation(before, after) → { pricePct, qtyPct, unitPct }`
- 消費税の税込化の端数は 1 円未満切り捨て（値札の一般的な扱い。根拠と「店により異なる」旨を Q&A に書く）

## 確かめること（テストとテスト環境）

1. `toBase`：1.5kg = 1500g、0.5L = 500ml、350ml×6×2 = 4200ml
2. g と ml の行が混ざったとき、その行が順位から外れ、理由が表示される。**「個」と「枚」の行が混ざったときも同じく外れる**（数の系統は同じ単位どうしだけ）
3. 税抜 8% 298 円 → 税込 321 円（切り捨て）で比較される
4. 円引きと%引きを両方入れたとき、入力の並びにかかわらず**円引きが先**に掛かる
5. 実質値上げ率：200g 198 円 → 180g 198 円 = +11.1%、200g 198 円 → 200g 218 円 = +10.1%
6. 品を 8 行に増やしてもスマホ（390px）で横スクロールが出ない
7. `tools/tests/stage.test.ts`・`llms.test.ts` が通る（`wip` のあいだ一覧・sitemap・llms.txt に出ない）
8. 割引の例：税込 321 円・30 円引き・20%引き → 232 円、税抜 8% 298 円・同じ割引 → 231 円。ポイント 5% → 11 ポイント・実質 221 円
9. 品が 2 つのとき削除ボタンが押せない。結果の欄に割引の順序が書いてある

## やらないこと

- **特定の商品名・メーカー名・店名を例に出さない**（値上げの例も「◯◯ 200g → 180g」のような一般形で書く）。比較サイト・価格情報の取得もしない
- バーコード読み取り・カメラでの値札読み取りは入れない（実装と保守が重く、ブラウザの対応差が大きい）
- 比重での g ⇔ ml の換算はしない（食品ごとに違い、誤差の責任を負えない）
