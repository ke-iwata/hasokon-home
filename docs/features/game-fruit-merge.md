# 新ゲーム「フルーツ合体パズル」（落として合体させる物理パズル・サイト初の物理マージ系）

**状態**：提案（2026-08-31 起票・未実装）。実装したら `stage: 'wip'` → `preview` で
操作感を確認 → **「公開の条件」の判定リストを満たしたら** `public` へ
（ピンボールが係数調整の運営者確認で `preview` に留まっている先例があるため、
期限のないゲートにしない。本文「先例とリスク」参照）。
**名称・権利の注意（実装前に必ず読む）**：「スイカゲーム」は Aladdin X 社の商品名（商標）。
**ゲーム名・slug・title・h1 に使わない**。見た目（顔つきの果物のデザイン・配色・UI）も
真似ない。「落として同じもの同士を合体させる」というメカニクス自体はアイデアであり
著作権の保護対象ではなく、各ストアに同系ゲームが多数ある。本文で
「『スイカゲーム』で人気になったジャンル」と**事実として触れるのは可**だが、
メタデータには入れない（[game-yacht.md](./game-yacht.md) のヤッツィー/ヨットと同じ整理）。
果物の絵は `GameIcon`・SVG の自作アセットで、写実でもスイカゲーム風のデフォルメでもない
**このサイトのフラットな絵柄**に揃える。
**対象**：`games/`（`hasokon.com/games/fruit-merge/` を想定）
**起票**：2026-08-31

## 背景と根拠

### エンゲージメント実測：このサイトでは「スコアを伸ばす系パズル」が最も遊ばれている

GA4（直近28日）で、ゲームの平均セッション時間の上位は
**ブロックパズル 840秒（PVもゲーム中1位）**・五目並べ 799秒・大富豪 613秒・
色水ソート 449秒・2048 345秒。「区切りなくスコアを伸ばし続ける」タイプが
滞在時間を強く伸ばしている。落ちもの物理マージはこのタイプの代表格で、
1プレイ3〜10分・リトライ率が高く、AdSense の観点でも滞在時間が効く。

### ジャンルの空白と旬

- 現在のラインナップはカード（10本）・盤上（3本）・論理パズル（4本）・
  アクション（3本）・マージ（2048）と広いが、**物理演算を使った「落として積む」系が無い**
  （ピンボールは preview 止まり。物理はあるがマージではない）
- スイカゲーム系（物理マージ）は2023年の大流行から3年経っても
  ランキング常連で、派生作（宇宙・スイーツ等の題材替え）が2026年も出続けている
  定着ジャンル。ブラウザで手軽に遊べる需要は根強く、「〇〇ゲーム 無料 ブラウザ」系の
  検索の受け皿になる
- **`games/lib/pinball.ts` に重力・反発係数・円の衝突の物理実装が既にある**（837行・
  自作。外部ライブラリなし）。円同士の衝突・重なり解消はこの延長で書けるので、
  外部依存ゼロの方針（package.json は react/next のみ）を保てる

## 提案する仕様

### ルール（同系の一般的な作法に従う）

1. 箱の上部から果物を落とす。横位置を選んで（ドラッグ or タップ）指を離すと落下
2. **同じ果物同士が触れると合体して1段大きい果物になる**（11段階。
   最小〜最大の並びは自作の果物で決める。最大同士は合体して消滅＋ボーナス）
3. 合体の連鎖で高得点。**箱の上限ライン（ゲームオーバーライン）を果物が一定時間
   超えたら終了**
4. 次に落ちる果物を予告表示（小さい方の5段階からランダム）
5. スコア・ベストスコアは `game-records` の既存機構（[game-records.md](./game-records.md)）に載せる

### 実装の要点

- **物理は自作の円限定エンジン**：全アイテムを円として扱い、
  固定タイムステップ＋位置補正（重なりを押し戻す）＋速度解決（反発・摩擦）の
  シンプルな構成。`pinball.ts` の重力・反発の作法（縦横比を座標に持たせる・
  1秒²あたりの重力定数）を踏襲する。矩形は箱の壁3枚だけなので衝突判定は円-円と円-壁のみ
- **決定的な乱数**：`Math.random()` を直接使わず、シード付き乱数で
  静的書き出しとの食い違いを避ける（ヨットの作法に同じ）。初回描画は空の箱なので
  SSR との差分は出にくいが、クライアント専用コンポーネントとして扱う
- **1画面に収める**：[mobile-one-screen.md](./mobile-one-screen.md) の作法どおり、
  320×568 で箱・スコア・次の果物予告が収まること。箱は縦長（幅:高さ ≒ 2:3）
- **パフォーマンス**：最大同時 60〜80 個を想定し、`requestAnimationFrame` 1本＋
  Canvas 描画。低速端末では物理サブステップを減らす。
  `prefers-reduced-motion` では合体エフェクトを省略
- **ページ**：他ゲームと同じく ルール・コツ・FAQ（+JSON-LD の VideoGame / FAQPage）、
  `robots: robotsFor('fruit-merge')`、`stage: 'wip'` から。
  公開時に `home/index.html` のカードと `home/llms.txt` の行を同じPRで足す（公開の約束どおり）

### 遊びやすさ（同系ゲームの定番の不満を先回りする）

- 落とす前の果物に**落下予測線**（縦の点線）を出す。タップ操作でも狙いがつけやすい
- 合体はスコアだけでなく**軽い拡大アニメーション**で分からせる（エフェクト過多にしない）
- ゲームオーバーラインは常時表示し、**超えている間は点滅**で警告（突然死の理不尽感を消す）

## 先例とリスク：ピンボールと同じ止まり方をし得る

このサイトで唯一の物理ゲームであるピンボールは、実装完了後
「運営者が実機で打ち出しと打ち返しの手応えを確かめ、係数の調整が終わったら
`public` に上げる」という条件（[game-pinball.md](./game-pinball.md)）のまま
**`preview` で止まっており、公開に至っていない**。本件は物理の
「積み上がりの安定」という同じ性質の調整を品質の肝に置いているので、
**約430kかけて実装した後、同じ場所で止まる筋書きが現実にあり得る**。
これを避けるため、公開の条件をあらかじめ判定可能な形で決めておく。

### 公開の条件（preview 段階で運営者が短時間で判定できるリスト）

以下をすべて満たしたら `public` に上げる（満たしたかどうかで判定でき、
「手応え」のような開いた条件を置かない）：

1. 320×568 の実機で、箱・スコア・次の果物予告が**1画面に収まる**
2. **果物を60個積んだ状態で、震え（ジッター）とすり抜けが目視で出ない**
   （デバッグ用に60個を自動配置する再現手段を用意する）
3. 1プレイが**3〜10分**に収まる（ゲームオーバーラインの高さと出現確率で調整）
4. 中位のスマホで**60fpsを維持**（落ちる場合はサブステップ削減で見た目が破綻しないこと）

### 目標水準に届かなかった場合の撤退・縮小の線

preview 段階で条件2・4が満たせない場合は、**段階数を11→8に減らす・箱を小さくして
同時個数の上限を下げる**の順で縮小して再判定し、それでも駄目なら
**`wip` のまま置いて撤退する**（`preview` で塩漬けにしない）。

| 作業 | 消費トークン（目安） |

見込んでいる。`preview` 段階で実機（スマホ）確認を挟むこと。

## やらないこと

- **外部物理ライブラリ（matter.js 等）の導入**。円限定なら自作で足り、
  依存ゼロの方針を守る
- **スイカゲームの名称・ビジュアルの模倣**（冒頭の権利注意のとおり）
- **ランキング・オンライン要素**（記録は端末内の `game-records` のみ）
- 効果音（サイト全ゲーム無音の現状に合わせる。入れるならサイト横断で別途検討）
