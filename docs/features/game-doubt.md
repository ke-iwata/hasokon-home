## 提案する仕様

### ルール（骨格は一般に流通している形。1 回に出せる枚数だけは当サイトのルールとして決める）

- 4 人（自分＋CPU 3 人）。ジョーカーなしの 52 枚を全部配る（13 枚ずつ）
- 最初の人から時計回り。**場に宣言する数は A → 2 → … → K → A と 1 つずつ進む**（手番の人が選ぶのではなく、順番で決まる）
- 手番の人は**手札から 1〜4 枚を伏せて出し**、「◯が◯枚」と宣言する。宣言した数の札でなくてもよい（ウソ）。
  - **「1 回に 1〜4 枚」は当サイトのルール**：国内の説明には「1 枚ずつ伏せて出す」とするものも多く、複数枚を出せるのは流派の 1 つ
    （App Store の「トランプ・ダウト」は 1〜4 枚。https://apps.appfollow.io/ios/tauto/1507888373 ）。採る理由は、
    ①毎手「何枚出すか（本物だけ／本物にウソを混ぜる）」の判断が増え、②引き取りで 30 枚を超えた手札でも終盤まで手数が持つ（1 枚ずつだと 40 枚の手札は 40 手番かかる）、
    ③宣言の数を 4 枚持っている人がまとめて出せる、の 3 つ。ページのルールの節に「当サイトでは 1 回に 1〜4 枚出せます」と明記し、FAQ に 1 問置く（下記）
  **出さないこと（パス）はできない**（宣言の数を持っていなければウソをつくしかない。ここがゲームの山場）
- 出したあと、**ほかの 3 人は「ダウト」と言える**（言わなくてもよい）。複数人が言ったら、出した人から見て時計回りで近い人が優先。
  自分が押したときに、時計回りでより近い CPU も言っていたら、その CPU のダウトとして扱い、結果の 1 行に「**CPU 1 が先にダウト！**」と出す
  - 出した札が**全部宣言どおり** → 言った人が場札を全部引き取る
  - **1 枚でも違う** → 出した人が場札を全部引き取る
  - 誰も言わなければ場札は積まれたまま次の手番へ
- 引き取りのあとも宣言の数は次に進む（一般的な形。設定で「引き取った人の次から A に戻す」は入れない）
- **手札が 0 枚になった人が上がり**。ただし最後の札を出した手番でダウトされ、ウソだったら引き取って続行
- 1 位が決まったら終わり（既定）。設定で「最後まで（4 位まで）続ける」を選べる

### 段階（CPU の強さ）

| 段 | CPU の出し方 | CPU の疑い方 |
|---|---|---|
| よわい | 持っていれば正直に全部、無ければ 1 枚だけウソ | ランダム（約 15%） |
| ふつう | 正直＋時々 1 枚混ぜる | **見えている情報で確率を出す**：自分の手札にある宣言の数の枚数＋これまでに公開された札から、「宣言の枚数がそろう見込み」が低いほど言う |
| つよい | ふつう＋相手の手札が少ないときは正直を優先、自分の上がりが近いときは大胆に | ふつう＋**相手が 1〜2 枚で上がりそうなときは必ず疑う**・場札が多いほど慎重（引き取りの損が大きい） |

- **CPU は伏せ札の中身を見ない**（ズルをしない）。使うのは自分の手札・ダウトで公開された札・各人の手札枚数・場札の枚数だけ。
  純関数 `cpuDecideCall(view, rng)` の引数の型（`PublicView`）に伏せ札を**入れない**ことで、型で保証する
- 確率の計算は超幾何分布。**母集団 N** は「その CPU から見えていない札」＝ほかの 2 人の手札＋伏せられた場札（今回の分を除く）＋出した人の**出す前の**手札。
  **r** は宣言の数 4 枚から、自分の手札にある枚数と、ダウトで表になって場から誰かの手札に移ったことが分かっている枚数を除いた残り。
  **h** は出した人の**出す前の**手札の枚数、**k** は宣言の枚数。r < k なら確率 0（必ずウソ）。
  求めるのは「N 枚から h 枚を無作為に取ったとき、r 枚の当たりが k 枚以上入る確率」
  しきい値は段ごとに定数で持ち、DECISIONS.md に書く

### 画面・操作（スマホ 1 画面。mobile-one-screen.md の約束）

- 上と左右に CPU 3 人（名前・手札の枚数・直前の宣言）。中央に**場札の山（枚数）と「次は 7」の大きな表示**
- 下に自分の手札（数の順に並べる）。**札をタップで選ぶ（1〜4 枚）→「出す（7 が 2 枚）」ボタン**。
- **手札が多いとき（引き取りで 20〜40 枚になるのが普通）**。mobile-one-screen.md の約束どおり、横スクロールも縦スクロールもさせない：
  - **13 枚以下**：大富豪と同じく 1 列に並べ、札を重ねる（見える幅は 360px で 1 枚あたり 24px 以上）
  - **14〜26 枚**：2 段に分けて重ねる（上の段が A〜7、下の段が 8〜K）。見える幅は 1 枚あたり 24px 以上
  - **27 枚以上、または 1 枚あたりの見える幅が 24px を切るとき**：**数ごとにまとめた表示**に切り替える。A〜7 と 8〜K の 2 段に 7＋6 個の
    「数のチップ」（中に数と枚数。例「7 ×3」）を並べ、**チップ 1 つは 44×44px 以上**。チップをタップするとその数の札が 1 枚選ばれる
    （同じチップをもう一度押すと 2 枚目。長押し、または「−」で 1 枚戻す）。**ダウトではマークは勝敗に関係しない**ので、どの札を選ぶかは
    数だけ決めればよく、マークは自動で選ぶ。360px で 7 個 × 44px と隙間 6px × 6 を足して 344px なので、左右に 8px ずつ残る
  - どの表示でも、いま選んでいる札は手札の上に小さく並べて見せ、「出す」ボタンに枚数を出す
  - 切り替えのしきい値（24px）は実装時に 320・360・390・768px の 4 つの画面幅で確かめ、DECISIONS.md に書く
  宣言の数は自動で決まるので、自分が選ぶのは枚数と札だけ。選んだ札が宣言と違うと、ボタンの下に「ウソが混ざっています」と小さく出す（自分だけに見える）
- CPU が出したあと、**「ダウト！」と「通す」の 2 つの大きなボタン**を 3 秒（CPU の速さ設定に連動）出す。押さなければ「通す」
  - `prefers-reduced-motion` と「ゆっくり」設定では時間切れを無くし、どちらかを押すまで待つ
- ダウトの結果は札を表にして 1.5 秒見せ、「ウソでした！ CPU 2 が 12 枚を引き取ります」と 1 行で出す
- 記録の画面には、既存の `records.ts` が持つ項目（遊んだ回数・勝ち・負け・最速の勝ち）だけを出す。
  **ダウトの成功率は記録画面に出さない**（`RecordEntry` にこれを持つ項目が無く、`records.ts` は改修しないため。`score` を流用すると
  「ベストスコア」として出て意味がずれる）。成功率は GA4 の `call` / `call-hit` で全体の値として測る（下記の計測）

### テスト（`games/tests/doubt.test.ts`）

- **配り**：13 枚ずつ・52 枚が重複なく配られる（固定の種）
- **宣言の進行**：A → … → K → A。引き取りのあとも進む
- **ダウトの判定**：全部正直 → 言った人が引き取る／1 枚でも違う → 出した人が引き取る／誰も言わない → 場札は残る／
  複数が言ったら時計回りで近い人
- **上がり**：最後の札でダウトされウソなら続行・正直なら上がり
- **CPU は伏せ札を見ない**：`publicView` に伏せ札が含まれない（型と実行の両方で確認）
- **CPU の確率**：自分が宣言の数を 4 枚持っているとき、相手の宣言は必ずウソ → ふつう・つよいは必ずダウト
- **段階の差**：固定の種 200 局で、つよい CPU 3 人を相手にしたときの **よわい CPU の 1 位率 < ふつう CPU の 1 位率**
- **確率**：N・r・h・k の小さな例を手で計算した値と一致する／r < k で 0／自分の手札は N にも r にも入らない
- **同時ダウト**：自分と CPU が両方言ったら、時計回りで近いほうのダウトになる
- **記録**：勝ちの局だけ `timeMs` を渡し、負けの局は `{ outcome: 'loss' }` だけ
- **手札の表示の切り替え**（純関数 `handLayout(count, widthPx)`）：13 枚 → 1 列、20 枚 → 2 段、30 枚 → 数のチップ、360px で 1 枚あたり 24px を切る枚数でチップへ
- `stage.test.ts`・`llms.test.ts` が通る
