## 提案する仕様

### ルール（一般に流通している形に揃える）

- 4 人（自分＋CPU 3 人）。ジョーカーなしの 52 枚を全部配る（13 枚ずつ）
- 最初の人から時計回り。**場に宣言する数は A → 2 → … → K → A と 1 つずつ進む**（手番の人が選ぶのではなく、順番で決まる）
- 手番の人は**手札から 1〜4 枚を伏せて出し**、「◯が◯枚」と宣言する。宣言した数の札でなくてもよい（ウソ）。
  **出さないこと（パス）はできない**（宣言の数を持っていなければウソをつくしかない。ここがゲームの山場）
- 出したあと、**ほかの 3 人は「ダウト」と言える**（言わなくてもよい）。複数人が言ったら、出した人から見て時計回りで近い人が優先
  - 出した札が**全部宣言どおり** → 言った人が場札を全部引き取る
  - **1 枚でも違う** → 出した人が場札を全部引き取る
  - 誰も言わなければ場札は積まれたまま次の手番へ
- 引き取りのあとも宣言の数は次に進む（一般的な形。設定で「引き取った人の次から A に戻す」は入れない）
- **手札が 0 枚になった人が上がり**。ただし最後の札を出した手番でダウトされ、ウソだったら引き取って続行
- 1 位が決まったら終わり（既定）。設定で「最後まで（4 位まで）続ける」を選べる

### 段階（CPU の強さ）

| 段 | CPU の出し方 | CPU の疑い方 |
|---|---|---|
| よわい | 持っていれば正直に全部、無ければ 1 枚だけウソ | ランダム（約 15%） |
| ふつう | 正直＋時々 1 枚混ぜる | **見えている情報で確率を出す**：自分の手札にある宣言の数の枚数＋これまでに公開された札から、「宣言の枚数がそろう見込み」が低いほど言う |
| つよい | ふつう＋相手の手札が少ないときは正直を優先、自分の上がりが近いときは大胆に | ふつう＋**相手が 1〜2 枚で上がりそうなときは必ず疑う**・場札が多いほど慎重（引き取りの損が大きい） |

- **CPU は伏せ札の中身を見ない**（ズルをしない）。使うのは自分の手札・ダウトで公開された札・各人の手札枚数・場札の枚数だけ。
  純関数 `cpuDecideCall(view, rng)` の引数の型（`PublicView`）に伏せ札を**入れない**ことで、型で保証する
- 確率の計算は「宣言の数 4 枚のうち、自分の手札と公開済みを除いた残り r 枚が、出した人の手札 h 枚の中に k 枚以上ある確率」（超幾何分布）。
  しきい値は段ごとに定数で持ち、DECISIONS.md に書く

### 画面・操作（スマホ 1 画面。mobile-one-screen.md の約束）

- 上と左右に CPU 3 人（名前・手札の枚数・直前の宣言）。中央に**場札の山（枚数）と「次は 7」の大きな表示**
- 下に自分の手札（数の順に並べる）。**札をタップで選ぶ（1〜4 枚）→「出す（7 が 2 枚）」ボタン**。
  宣言の数は自動で決まるので、自分が選ぶのは枚数と札だけ。選んだ札が宣言と違うと、ボタンの下に「ウソが混ざっています」と小さく出す（自分だけに見える）
- CPU が出したあと、**「ダウト！」と「通す」の 2 つの大きなボタン**を 3 秒（CPU の速さ設定に連動）出す。押さなければ「通す」
  - `prefers-reduced-motion` と「ゆっくり」設定では時間切れを無くし、どちらかを押すまで待つ
- ダウトの結果は札を表にして 1.5 秒見せ、「ウソでした！ CPU 2 が 12 枚を引き取ります」と 1 行で出す
- 記録の画面に勝率と「ダウトの成功率（言った回数のうち当たり）」を出す

### テスト（`games/tests/doubt.test.ts`）

- **配り**：13 枚ずつ・52 枚が重複なく配られる（固定の種）
- **宣言の進行**：A → … → K → A。引き取りのあとも進む
- **ダウトの判定**：全部正直 → 言った人が引き取る／1 枚でも違う → 出した人が引き取る／誰も言わない → 場札は残る／
  複数が言ったら時計回りで近い人
- **上がり**：最後の札でダウトされウソなら続行・正直なら上がり
- **CPU は伏せ札を見ない**：`publicView` に伏せ札が含まれない（型と実行の両方で確認）
- **CPU の確率**：自分が宣言の数を 4 枚持っているとき、相手の宣言は必ずウソ → ふつう・つよいは必ずダウト
- **段階の差**：固定の種 200 局で、つよい CPU 3 人に対する ふつう CPU の 1 位率 < よわい CPU の 1 位率
- `stage.test.ts`・`llms.test.ts` が通る

## やらないこと

- **ジョーカー（何にでもなる札）・2 組の山・宣言の数を手番の人が選ぶ変種は入れない**（まず一般的な形 1 つ）

- **CPU に表情・セリフの演出は付けない**（読み合いの情報は「枚数・宣言・これまでの結果」だけにする）
