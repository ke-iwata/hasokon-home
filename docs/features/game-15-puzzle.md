## 提案する仕様

### ルール

- 盤は N×N（3・4・5）。1〜N²−1 の板と空きマス1つ。**空きマスに隣り合う板を空きへすべらせる**。左上から 1, 2, 3 … と並び、右下が空けば完成
- **同じ行・列の板はまとめて動かせる**：空きマスと同じ行（列）の板をタップすると、その板と空きの間の板が一度にすべる。**手数はすべった板の枚数で数える**（数え方を画面に書く）
- 盤は**必ず解ける配置だけ**を出す（下のロジック）

### 遊び方の種類

| モード | 中身 |
|---|---|
| 大きさを選ぶ | 3×3（かんたん）・4×4（ふつう）・5×5（むずかしい）を選んで、ばらばらの盤から |
| 今日の1面 | **`games/lib/daily.ts` の `localDateKey`（端末のローカル日付）と `dailySeed`・`mulberry32`** で作る 4×4 の盤。同じ日付なら全員が同じ盤（日付の境目は端末の時計に従う。UTC・日本時間を個別に取ると連続日数が切れるので使わない）。手数・時間を共有テキストで（盤そのものは載せない。[game-fukuwarai.md](./game-fukuwarai.md) の「今日のお題」と同じ作り） |
| 写真 | 自分の写真を選ぶと、それを切った絵合わせになる。**画像は端末の中だけで扱い、送信も保存もしない**（`URL.createObjectURL`。ページを閉じたら消える）。数字を重ねて出すかを切り替えられる。大きな写真は canvas で盤の大きさまで縮めてから使い、スマホ写真の向き（EXIF）を反映する。新しい写真を選んだら前のものを `URL.revokeObjectURL` で捨てる。`tool_use` の `photo` には画像の情報（大きさ・名前など）を一切載せない |

最初の画面は「大きさを選ぶ」の 4×4 の盤がもう配られていて、**押せばすぐ始まる**（[mobile-one-screen.md](./mobile-one-screen.md)：390×664 で盤全体と手数が1画面に入る）。

### 操作

- タップ／クリックで上のとおりすべらせる。スワイプ（空きマスに向かう方向）でも動く。**盤に `touch-action: none` を付け**、盤の上のスワイプでページがスクロールしないようにする（盤の外は普通にスクロールできる）
- キーボード：矢印キーで「空きマスに板を入れる向き」に動かす（← で空きの右の板が左へ）。向きの定義は設定で反転できる
- もどす（無制限）・やり直し（同じ盤の最初から）・新しい盤
- 「完成図を見る」：押している間だけ完成形を重ねる（写真モードで特に要る）
- 記録：**`lib/records.ts` と `app/_records/Records.tsx`（`useRecords` / `useStopwatch` / `RecordStrip`）を使い、ゲームごとの localStorage キーは作らない**（games/CLAUDE.md の約束。`tests/records.test.ts` が直接使用を落とす）。
  区分（variant）は `3x3` / `4x4` / `5x5` / `daily` の4つ。大きさ別の区分はベスト手数・ベスト時間・クリア回数を持ち、
  `daily` は今日の1面をクリアしたときに `lastClearedOn` / `streak`（連続日数）を更新する（数え方は `lib/daily.ts` の `nextStreak`）

### ヒントと最短手数（3×3 だけ）

- 3×3 の解ける配置は 181,440 通りなので、**完成形からの BFS を一度だけ作り**（メインスレッドで百 ms 程度。重ければ Worker に移す。Worker は必須にしない）、各配置の最短手数を引ける
- 「最短 ◯ 手」を開始時に出し、終わったら「あなたは ◯ 手（最短 ◯ 手）」と比べる。**ヒント**ボタンで最短の次の一手を光らせる
- 4×4・5×5 は最短を出さない（4×4 でも最短探索は配置によって数秒〜分かかる）。ヒントは「1 段目→1 列目…と順に揃える」人の解き方に沿った次の一手を返す、非最短の手順にする
  （**最短とは書かない**。画面の文言は「ヒント（最短とは限りません）」）

### ロジック（`games/lib/fifteen.ts`。純関数のみ）

- **解けるかの判定**：空きを除いた並びの転倒数を数える。N が奇数なら転倒数が偶数のとき解ける。N が偶数なら「転倒数＋空きマスの行（下から数えて 1 始まり）」が奇数のとき解ける
- **配り方**：ランダムな置換を作り、解けなければ空き以外の2枚を入れ替えて直す（**ランダムに動かして崩す方式は使わない**。手数が少ない盤に偏る）。
  完成形そのもの・完成から 5 手以内の盤は配り直す。**判定は完成形から深さ 5 までの探索**（直前の手を戻す枝を除くと各段 3 方向以下で数百通り）で、配った盤がその中にあれば配り直す
- 今日の1面のシードは日付文字列から（既存のゲームに日替わりの乱数があればそれを使う。新しく書かない）
- 移動：(盤, タップした位置) → (新しい盤, 動いた枚数) か「動かせない」

### テスト（`games/tests/fifteen.test.ts`）

- 解けるかの判定：3×3・4×4 の既知の解けない配置（14 と 15 を入れ替えた「14-15 パズル」）を「解けない」と返す
- 配った盤は 1,000 回とも解ける判定になり、完成形にならない
- 行・列まとめての移動で手数が枚数ぶん増える。もどすで元の盤と手数に戻る
- 3×3 の BFS：最大の最短手数が 31（8パズルの既知の値）、完成形は 0
- 記録：区分 `3x3` / `4x4` / `5x5` / `daily` に分かれて保存され、`daily` を2日続けてクリアすると `streak` が 2（`useRecords` 経由。localStorage を直接触らない）
- 4×4 のヒントを繰り返したどると、ランダムな盤 20 個がすべて完成する（上限 2,000 手）
- 同じ日付からは同じ今日の1面

### やらないこと

- **写真のアップロード・共有・ランキング。** サーバーが要り、他人の写真を扱うことになる
- 6×6 以上（スマホで板が小さくなりすぎる）
- 4×4 の最短手数（IDA* で解けるが、配置によって待たせる。ヒントは非最短で足りる）
- 「14-15 パズル」の解けない盤をわざと出す遊び（解けないと知らずに遊ぶ人が出る。本文の読み物で触れるだけ）

## 本文

遊び方・コツ（「上の段から、最後の2枚は2枚まとめて入れる」）・**なぜ解けない並べ方があるのか**（転倒数の話を小学生にも分かる言葉で）・
歴史（1870〜80 年代の流行）。**考案者は Noyes Chapman とされる**。「サム・ロイドが考案し、14 と 15 を入れ替えた盤に懸賞金を出した」という話は広く知られているが、
**後年の創作で史実ではないとされる**ので、本文では「〜と伝えられるが、史実ではないとされる」と書き、出典を付ける
（Jerry Slocum・Dic Sonneveld『The 15 Puzzle』（2006）。実装 PR で書誌を確かめる）・FAQ 4 問（最短手数は何手か／写真は送信されるか／解けない盤は出るか／手数の数え方）。
