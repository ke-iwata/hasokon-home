## なぜ作るのか、そしてなぜ「記事を書かない」方針と両立するのか

`tools/docs/CONCEPT.md` は、**ブログ型を最初に除外している**。理由は
「運営者はコンテンツ制作が得意ではなく、継続的な発信を前提にしたモデルは破綻する」から。
学習セクションはこの方針と正面からぶつかるので、**乗せ方を変えて両立させる**。

1. **コンテンツを構造化データとして持つ。** 章の定義は `lib/curriculum.ts`、
   参考文献は `lib/sources.ts` に集約する。registry と同じ「単一の情報源」の型。
   これにより「出典のない章」「存在しない文献を指している脚注」を**テストで落とせる**
2. **古びない部分と古びる部分を分ける。** 複利・分散・リスクとリターンといった原理は
   古びない。古びるのは制度（NISA・iDeCo・税率）だけで、これは既存ツールの
   「年1回の更新」と同じサイクルに収まる。章ごとに `volatility` を持たせて、
   どれが毎年の点検対象かを機械的に出せるようにする
3. **書き続けなくても死なない。** 更新が要るのは制度編の数章だけ。
   ニュースを追いかける設計にはしない

## 守ること（金融商品取引法・編集方針）

**投資助言・代理業の登録はしていない。** したがって以下を守る。
これは体裁の問題ではなく、越えると登録が要る線なので**例外を作らない**。

- **個別銘柄を推奨しない。** 「この株を買うべき」「いま買い時」は書かない
- **個別の売買タイミングを助言しない。** 一般的・客観的な情報提供にとどめる
- **断定的判断を提供しない**（金商法38条2号）。「必ず儲かる」「元本は保証される」は書かない。
  期待リターンを書くときは必ず「過去の実績であり将来を約束しない」と併記する
- **民間の個別商品名・証券会社名を出さない**（運営者の判断）。
  公的なもの（個人向け国債・NISA・iDeCo・GPIFの基本ポートフォリオ）と
  指数（TOPIX・S&P500）は実名で書く。信託報酬などは
  「0.1%と1.5%で20年後にいくら差が出るか」のように**一般化した数値例**で実践性を担保する
- **すべての章に免責を出す。** 共通コンポーネントで機械的に入れる（書き忘れを防ぐ）

## 参考文献の出し方

「参考文献はちゃんと明示して」が要望の核なので、**出典を後付けの飾りにしない**。

- 文献は `lib/sources.ts` に**IDつきで1件ずつ**定義する（著者・タイトル・発行元・URL・確認日）
- 章は本文中で `ref('fsa-guide')` のようにIDで参照し、ページ下部の参考文献リストは
  参照されたIDから**自動生成**する。手書きしない
- **存在しないIDを参照したらビルドが落ちる**（静的書き出しなので必ず気づく）
- **1件も参照していない章はテストが落とす**。出典なしの章を作れないようにする
- 一次資料（金融庁・国税庁・日本証券業協会・投資信託協会・JPX・財務省・日本銀行・GPIF）を
  優先する。学術・書籍は原理の裏付けが要るところにだけ使う

## 図解

運営者の「もっと図解が多い感じがいいです」（2026-09-07）から。
**説明で足りるところに図は置かない。** 置くのは、文章だけだと必ず読み違えるところ。

- **すべてインラインSVG**（`app/_chapter/Figure.tsx`・`Diagram.tsx`）。
  画像ファイルを置かないのは、明暗テーマで色を変えられること・
  拡大しても粗くならないこと・読み込みが増えないことの3つが要るため
- **数字は `lib/calc.ts` から取る。** 図と本文で同じ数字を2回書かない。
  最初の版は表を手打ちしていて3か所間違えており、図が増えれば同じことが起きる
- **色だけで区別しない。** アクセントが1色なので、線種・形でも見分けられるようにする
- **レイアウトは実測で確かめる。** 目視では気づけない崩れを5つ踏んだ
  （詳細は learn/CLAUDE.md「図のレイアウトは実測で確かめる」）

  ここから該当ツールへリンクする（iDeCo・ふるさと納税・手取りなど既にある）
