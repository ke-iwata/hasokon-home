### 需要と競合の状況（2026-11-16 の Web 調査）

「正規表現 チェッカー」「正規表現 テスト」「正規表現 置換」は通年の定番で、エンジニアだけでなく**事務の置換作業**
（Excel・テキストエディタ・スプレッドシート）で調べられる。国内の上位（luft.co.jp の正規表現テスター・置換プレビュー、
miniwebtool の正規表現テスター、toolsbase.dev のテキスト置換・regex tester など）は、
**JavaScript の正規表現で当たった箇所と置換を見せる**ところまではどれも同じ。調べた範囲で足りていないのは次の 4 つ：

1. **使う先との違いを言ってくれない。** 2024〜2025 年に Microsoft 365 の Excel に `REGEXTEST`・`REGEXEXTRACT`・`REGEXREPLACE`
   が入り（PCRE2 系）、Google スプレッドシートの `REGEXMATCH` ほか（RE2）と並んで、**事務の人が正規表現を書く場面が増えた**。
   ところがブラウザで試せるのは JavaScript の方言だけで、たとえば**後読み `(?<=…)` や後方参照 `\1` はスプレッドシート（RE2）では使えない**。
   「チェッカーでは当たったのに、シートではエラー」が起きる
2. **日本語の部品が無い。** 「ひらがなだけ」「カタカナ（長音 ー を含む）」「漢字」「全角数字」は毎回調べて書くことになり、
   `[ぁ-ん]` のように**ゔ・ゕ・ゖ や「ー」を落とす書き方**がそのまま貼られている
3. **重いパターンで画面が固まる。** `(a+)+$` のような式を長い文章に当てるとタブごと止まる（破滅的バックトラック）。
   入力するたびに走らせる作りだと、書いている途中の式で固まる
4. **見えない文字に気づけない。** 全角スペース・NBSP・ゼロ幅スペースが混ざった文章で「なぜか当たらない」を説明できない

## 提案する仕様

### 入力と出力

| 入力 | 内容 |
|---|---|
| パターン | 1 行。`/…/g` の形で貼られたら、スラッシュとフラグを分けて読み直す |
| フラグ | `g`（すべて）・`i`（大文字小文字を区別しない）・`m`（行ごと）・`s`（`.` が改行にも当たる）・`u`／`v`（Unicode。**どちらか一方**のラジオボタン。`new RegExp(…, 'uv')` は SyntaxError）。既定は `g` と `u` |
| 試す文章 | 複数行。上限 200,000 文字（超えたら先頭だけで試し、その旨を出す） |
| 置換後の文字列（任意） | `$1`・`$<名前>`・`$&` を使える |
| 使う先 | **JavaScript（既定）／Excel（Microsoft 365）／Google スプレッドシート** の 3 択 |

| 出力 | 内容 |
|---|---|
| 当たった箇所 | 文章の上に色を塗る（**色を塗るのは最初の 1,000 件まで**。それ以降は件数だけ出す。数万件の DOM を組むとスマホで固まり、Worker の時間切れでは防げないため）。件数と、1 件目〜最大 1,000 件の一覧（位置・行と列・当たった文字列） |
| グループ | 番号つき・名前つきのグループごとの中身の表 |
| 置換の結果 | 置換後の全文と、変わった箇所の印。コピーのボタン |
| 使う先での注意 | 下「使う先の違い」に当たる書き方があれば、パターンの下に 1 行ずつ出す |
| そのまま貼れる形 | `/…/gu`（JavaScript）・`=REGEXTEST(A1,"…")`（Excel）・`=REGEXMATCH(A1,"…")`（スプレッドシート）。`"` は `""` に直して出す |

### 判定の約束（テストで固定する）

1. 判定は**ブラウザの `RegExp` そのもの**で行う（自前の正規表現エンジンを書かない）。使う先が Excel・スプレッドシートでも、
   当たり方は JavaScript で見せ、**違いは「注意」として言葉で出す**（方言ごとの完全な再現はしない。下「やらないこと」）
2. 構文エラーは `RegExp` の例外の文をそのまま出さず、よくある 6 種を日本語にする：閉じていない `(`・`[`／
   前に何も無い `*`・`+`・`?`／`{2,1}` のような逆順／`u` フラグでの不正なエスケープ（**文字クラスの外の** `\-` など。`[\-]` は `u` でも正しい書き方なので誤りにしない）／後読みの中身の誤り／名前つきグループの名前の重複
3. **長さ 0 の当たり**（`^`・`\b`・`a*` など）で無限ループしない。`g` があるときは `matchAll` を使い、一覧には「位置 n の空の当たり」と出す。**`g` が無いときは `matchAll` が TypeError になるので、`exec` を 1 回だけ呼んで最初の 1 件を出す**
4. 位置は**書記素（見た目の 1 文字）で数えた列**と、UTF-16 の位置の両方を出す（絵文字・異体字セレクタで列がずれるのを防ぐ）。
   書記素の区切りは `Intl.Segmenter`
5. `i` フラグのとき、トルコ語の İ・ı のような**大文字小文字の対応が言語で割れる文字**が文章にあれば注意を出す。全角英字（Ａ／ａ）は JavaScript では `/ａ/iu.test('Ａ')` が true でふつうに対応するので、JavaScript では注意しない。使う先が Excel・スプレッドシートのときだけ「当たり方が JavaScript と違うかもしれない。使う先で確かめて」と出す
6. 置換の `$` の読み方は `String.prototype.replace` のとおり（`$$` は `$`）。**Excel の `REGEXREPLACE` も Google スプレッドシートの `REGEXREPLACE` も置換文字列は `$0`／`$1`〜 で書く**
   （例：`=REGEXREPLACE(A1,"(\w+),\s(\w+)","$2 $1")`。`\1` を使うのは C++ の RE2 API だけ）。したがって `$1` には注意を出さない。
   `$<名前>`・`$&`・`` $` ``・`$'` は JavaScript だけの書き方なので、使う先が Excel・スプレッドシートのときはこの 4 つに注意を出す。
   **実装時に Microsoft サポートと Google ドキュメント エディタ ヘルプで確かめ、確認日を本文に書く**
7. 文章の中の**見えない文字**（全角スペース・NBSP・ゼロ幅・BOM・タブ）に印を付ける。印の付け方は `tools/lib/invisible-chars.ts` に揃える
8. 改行は `\r\n`・`\n` のどちらで貼られても `\n` に揃えて試し、揃えたことを 1 行出す（`m` フラグの `$` の当たり方が変わるため）
9. 入力のたびの再計算は 150ms 待ってから（打っている途中の式で走らせない）
10. URL に状態を残さない（パターンや文章に個人情報・社内の文字列が入りうるため。共有したいときは「そのまま貼れる形」をコピーする）

### 日本語の部品（ボタンで差し込む）

| ボタン | 差し込む式（`u`／`v` フラグ前提） | 注意として本文に書くこと |
|---|---|---|
| ひらがな | `\p{Script=Hiragana}` | `[ぁ-ん]` では ゔ・ゕ・ゖ が落ちる。長音「ー」はひらがなに入らない |
| カタカナ（長音・半角の濁点を含む） | `[\p{Script=Katakana}ーｰﾞﾟ]` | 長音「ー」、半角の長音「ｰ」（U+FF70）、半角の濁点・半濁点「ﾞ」「ﾟ」（U+FF9E・U+FF9F）はどれも Common で Katakana に入らないので足す（`[\p{Script=Katakana}ーｰ]` では「ｶｰﾄﾞ」が当たらない。2026-11-17 に Node.js 22 で確認）。半角カナ（ｱ）は Katakana に入る。**当たるべき例に `ｶﾞｰﾄﾞ`・`ﾊﾟﾝ`・`カード`、当たらない例に `かーど` を入れる**。`\p{Script_Extensions=Katakana}` でも ー・ｰ・ﾞ・ﾟ・゛・゜ が入るが、中黒「・」も入るので使わない。外したいときは `[ァ-ヺー]` |
| 漢字 | `\p{Script=Han}` | 々・〇 は Han に入るが、〆（Common）・ヶ（Katakana）は入らない。地名・人名を拾うなら `[\p{Script=Han}〆ヶ]` の形も示す（2026-11-16 に Node.js 22 で確認） |
| 全角数字 | `[０-９]` | `\d` は `u` フラグでも ASCII の 0〜9 だけ |
| 全角・半角スペース | `[ 　]` | `\s` は全角スペースにも当たる |
| 郵便番号 | `\d{3}-?\d{4}` | ハイフンの全角（－）・長音（ー）は別に書く |
| 携帯電話番号 | `0[6-9]0-?\d{4}-?\d{4}` | 形の確認であって、実在の確認ではない。**060 は 2024-12-20 の電気通信番号計画の変更で携帯電話の番号帯（060-1〜060-9）に加わった**（総務省「音声伝送携帯電話番号への060番号の追加」・「060から始まる携帯電話番号について」。各社の提供開始は令和8年7月以降の予定とされていたが延期の注記あり。実装時に開始状況と確認日を書く） |
| メールアドレス（ざっくり） | `[^\s@]+@[^\s@]+\.[^\s@]+` | 厳密な判定は正規表現でやらない（RFC 5322 は正規表現 1 本に収まらない）と本文で書く |

部品は**データとして 1 か所**（`tools/lib/regex-parts.ts`）に置き、各部品に「当たるべき例・当たらない例」を持たせてテストで回す。
`v` フラグは文字クラスの中のエスケープの決まりが `u` と違うので、**部品は `u` と `v` の両方でテストする**（8 部品とも両方で `new RegExp` が通り、同じ例に同じ結果になること）。

### 使う先の違い（注意を出す書き方。データで持つ）

| 書き方 | JavaScript | Excel（PCRE2 系） | スプレッドシート（RE2） |
|---|---|---|---|
| 後読み `(?<=…)`・`(?<!…)` | ○ | ○ | **×** |
| 先読み `(?=…)`・`(?!…)` | ○ | ○ | **×** |
| 後方参照 `\1`・`\k<名前>` | ○ | ○ | **×** |
| 名前つきグループ `(?<名前>…)` | ○ | ○ | `(?P<名前>…)`（RE2 は 2023 年から `(?<名前>…)` も読む。スプレッドシートでの扱いは実装時に実機で確かめて表を直す） |
| `\p{Script=Hiragana}` | ○（`u`） | `\p{Hiragana}` | `\p{Hiragana}` |
| フラグ | `/…/gimsuv` | 関数の引数（大文字小文字）・式中の `(?i)` | 式中の `(?i)` だけ |

方言の表は**出典を書いて**持つ：ECMAScript（ECMA-262）・MDN、Microsoft サポート「REGEXTEST 関数」ほか 3 関数の説明、
Google ドキュメント エディタ ヘルプ「REGEXMATCH」・RE2 の Syntax。**確認日を本文に書く**（関数の対応は更新されうる）。

### 安全の約束

1. **照合は Web Worker で行い、1 回 1 秒を超えたら Worker を止めて**「このパターンは時間がかかりすぎます（同じものの繰り返しを入れ子にしていないか）」と出す。
   止めたら新しい Worker を作り直す（メインのスレッドは固めない）
2. 入れ子の量指定子（`(a+)+`・`(\w*)*` など）は、走らせる前に**字面で見つけて注意**を出す（止めるのは 1. の時間切れだけ。字面での判定は誤検知があるので止めない）
3. 入力は**どこにも送らない**。保存もしない（`localStorage` に残すのは「使う先」の選択だけ）
4. 当たった箇所の色塗りは文字列を `textContent` で組む（`innerHTML` に入力を入れない）
5. **色を塗るのは最初の 1,000 件まで**（上「出力」）。それより多いときは「1,000 件を超えたので、色は最初の 1,000 件だけ」と出す

## やらないこと

- **Excel・スプレッドシートの当たり方の完全な再現**（PCRE2・RE2 をブラウザで動かすこと）。WebAssembly の同梱が要り、
  重さに見合わない。違いは注意として出し、最後は使う先で確かめるよう本文に書く
- 正規表現の自動生成（「この文字列に当たる式を作って」）。当たる式は無数にあり、意図と違う式を正しそうに見せてしまう
- Python・PHP・.NET など、他の言語の方言の注意（需要を見て、`regex-parts.ts` の方言の表に列を足せる形にだけしておく）
