# docs/features — 機能仕様書

1機能 = 1ファイルで、**これから実装するもの／実装したもの**の仕様を置く場所です。

`../DECISIONS.md` が「なぜそうしたか」の時系列の記録なのに対して、
ここは「その機能は結局どういう仕様なのか」を1枚で読める形にまとめておく場所です。
実装が終わったら、仕様書はそのまま残し、DECISIONS.md に1行足して相互に参照させます。

## 書き方の約束

親フォルダの [../README.md](../README.md) の約束に加えて、次の見出しを持たせます。

| 見出し | 内容 |
|---|---|
| 背景と根拠 | **計測値と取得日を必ず書く**。どのAPI・どの画面から取ったかも書く |
| 現状 | いま何がどうなっているか（再現手順つき） |
| 提案する仕様 | 変更後にどうなるか。触るファイルまで書く |
| 期待される効果 | 何がどれだけ良くなるか。測り方も書く |
| 工数の見積り | 作業時間の目安 |
| やらないこと | 検討して見送った案と、その理由 |
