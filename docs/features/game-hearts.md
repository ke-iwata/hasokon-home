## 背景と根拠

### Windows 標準の 5 本で、当サイトに無いのはハーツだけ

Windows に長く同梱されていたトランプ・パズルは **ソリティア（クロンダイク）・フリーセル・スパイダー・マインスイーパー・ハーツ**の
5 本。当サイトは前の 4 本を公開済みで（`games/lib/registry.ts`）、**ハーツだけ無い**。
「懐かしい Windows のゲームを探す」客は 4 本のどれかで当サイトに着地するので、5 本目があれば回遊先になる。

- Microsoft は「Hearts」を Microsoft Store で今も配信している（`https://www.microsoft.com/ja-jp/p/hearts/9nblggh1pb09`、2026-09-30 確認）。
  需要が途切れていない証拠であると同時に、**画面・札の絵柄は Microsoft のものを真似ない**（下記「名称と権利」）
- ブラウザ競合（2026-09-30 確認）：トランプスタジアム（playingcards.jp）の
  **「注目度上昇中のゲーム」1 位がハーツ**（2 位ナンプレ、3 位こいこい、4 位四川省＝二角取り、5 位セブンブリッジ）。
  同サイトの「人気のゲーム」上位はフリーセル・クロンダイク・スパイダー・大富豪・ピラミッドで、
  **当サイトの既存ラインナップとそのまま重なる**。「人気」と重なっているサイトで「次に来ている」のがハーツ。
  Soritia.jp も CPU 3 段階のハーツを提供（`https://www.soritia.jp/hearts`）
- ブラックジャックの仕様書（#265、2026-09-26）で整理した「ブラウザ競合が全社そろえていて当サイトに無いトランプ」は
  **ババ抜き・ブラックジャック・ポーカー・ページワン・ハイ＆ロー・ダウト・ハーツ**。ブラックジャックは実装済み（`wip`）、
  ババ抜きは同仕様書で「自分の選択が少なく滞在が伸びにくい」として後回しにした。**残りのうち、
  1 局ごとの判断が多く（毎トリックで 1 枚選ぶ）、記録（順位・累計点）が付けやすいのがハーツ**

### トリックテイキング型が 1 本も無い

当サイトのトランプ 11 本（ソリティア系 6・大富豪・七並べ・神経衰弱・スピード・ブラックジャック）に、
**「台札に合わせて 1 枚ずつ出し、トリックの勝者が次を出す」型が無い**。
ハーツ・ナポレオン・スペードなどこの型の入口としてハーツがいちばん簡単（切り札が無く、ビッドも無い）。
1 本作れば CPU の「フォロー・ディスカード・リード」の部品が 2 本目以降（スペード等）に使い回せる。

## 提案する仕様

### ルール（一般に流通している形。出典：トランプスタジアム・Soritia.jp の説明ページ、2026-09-30 確認）

1. **4 人**（自分 1 人＋CPU 3 人）、52 枚を 13 枚ずつ配る。ジョーカー無し
2. **パス**：局のはじめに手札から 3 枚を選び、局ごとに **左 → 右 → 向かい → パス無し** の順で回す
   （4 局で 1 周。パス無しの局はそのまま始める）
3. **♣2 を持つ人が最初のトリックをリードする**（♣2 から出す）
4. **フォロー義務**：台札のスートを持っていればそのスートを出す。無ければ何を出してもよい（ディスカード）
5. トリックは台札のスートの最も強い札を出した人が取り、次をリードする（A が最強、2 が最弱。切り札は無い）
6. **ハートブレイク**：ハートは、誰かがディスカードでハートを出す（＝ハートが「割れる」）まで**リードできない**。
   ハートしか持っていない場合だけ例外
7. **最初のトリックにハートと♠Q は出せない**（手札がそれしか無い場合を除く。一般的な追加ルールで、初版から入れる）
8. **点**：ハート 1 枚 1 点、♠Q は 13 点。局の終わりに取ったトリックの中の点を集計し、**少ないほうが良い**
9. **シュートザムーン**：1 人で 26 点すべてを取ったら、その人は 0 点で**他の 3 人に 26 点ずつ**
   （初版は「他の 3 人に足す」だけ。「自分から 26 引く」の選択は設定に足さない）
10. **誰かが 100 点に達した局で終了**。最少点の人が勝ち（同点は同順位）。1 局だけで終える「1 局モード」を設定に置く
11. ♦J の −10 点（オムニバス）・♠Q でハートブレイクなどの派生ルールは持たない（下記「やらないこと」）

### 画面・操作（スマホ 1 画面）

- 大富豪と同じ配置：上に向かい、左右に CPU、下に自分の手札を横並び。**中央にトリック（4 枚分の枠）を `height` で固定**
  （games/CLAUDE.md 1「盤面は動かさない」。4 枚出そろう前も枠は 4 つ置く）
- 自分の番は**出せる札だけを持ち上げる**（フォロー義務とハートブレイクを満たさない札は暗くする）。
  1 タップで出す（確認ボタンは置かない。大富豪の「選んで出す」と違い 1 枚しか出さないため）。
  押す先は 44px を割らない（同 4）。13 枚を横に並べると 390px で 1 枚 30px 幅になるので、**重ね幅を詰めて
  「見えている部分」は 30px でも、当たり判定は札 1 枚ぶん（左隣の札との重なりは右の札が勝つ）** にする
- パスの局は手札から 3 枚を選び「渡す」を押す（この局だけ確認ボタンがある）。パスの向きは局のはじめに 1 行で出す
  （「左の人に 3 枚渡す」）。**この 1 行の枠はパス無しの局でも空のまま置く**
- 局の点は各プレイヤーの名前の横に「今局／累計」の 2 値で常時表示。局の終わりに「この局の点」の一覧を出す
- CPU の手番は `delayFor` に通した間を置く（[cpu-speed.md](./cpu-speed.md)）。1 トリック 4 枚が出そろったら
  短い間のあとにまとめて取る（取ったことは、取った人の名前の横の点が増えるのと、トリック枠が空くので分かる）
- 局面（`phase`）は `passing → playing → roundEnd → matchEnd` の 4 つ。表示の出し分けは `phase` で決める（games/CLAUDE.md 7）
- **設定は隠さない**（同 5）：「1 局で終える／100 点まで」の 1 トグルと CPU の強さ（2 段階）だけ。局の途中は無効化
- 記録：`records.ts` の設計どおり**キーはこのゲームで 1 本**（`hasokon-games:records:hearts:v1`）。
  初版は既存の `RecordEntry` の項目だけを使い、**新しい項目は足さない**：
  - `plays`：**1 試合（100 点まで、または 1 局モードの 1 局）を 1 プレイ**とし、最初の 1 枚を出した試合で数える
  - `wins` / `losses`：試合の終わりに自分が単独最少点なら勝ち、それ以外は負け（同点最少は勝ちに数える。
    `draws` は使わない — 4 人の順位で「引き分け」を定義すると説明が要る）
  - `bestScore`：**シュートザムーンの回数**（大きいほうが良い、の項目をそのまま使える。「最少点」は小さいほうが良いので
    `bestScore` に入れると `Records.tsx` の表示と食い違う）
  - variant は「1 局／100 点」で分ける（試合の長さが違うので混ぜない）

### ロジック（`games/lib/hearts.ts`・純関数）

- `dealRound(rng) → hands[4]`、`passDirection(roundIndex) → 'left' | 'right' | 'across' | 'none'`
- `legalCards(state, player) → Card[]`：フォロー義務・ハートブレイク・最初のトリックの制限をすべて含む
- `playCard(state, player, card) → state`：トリックが 4 枚そろったら勝者を決めて次のリードへ
- `scoreRound(tricks) → number[4]`：ハート 1 点・♠Q 13 点・シュートザムーンの置き換え
- `isMatchOver(totals) → boolean`（100 点到達）、`ranking(totals) → number[]`
- CPU（`chooseCpuPass` / `chooseCpuCard`）：
  - パス：♠A・♠K・♠Q と高いハートから渡す。♠Q を持っていて♠が 4 枚以上あるなら守る（渡さない）
  - リード：ハートが割れていなければ、♠Q を持っていない相手に♠を引かせるために低い♠をリード。
    それ以外は「自分が最も少ない枚数しか持たないスート」の低い札
  - フォロー：台札のスートがあるなら「取らずに済む最も高い札」、それが無ければ最も低い札。
    最後の手番で点が乗っていないトリックなら高い札を処理する
  - ディスカード：♠Q → 高いハート → 高い♠ → その他の高い札、の順に捨てる
  - 強さ 2 段階は「シュートザムーンを狙う相手を止める（点が 1 人に偏ったらハートを取りに行く）」を入れるかどうかだけ
- 境界テスト：♣2 のリード強制、最初のトリックにハートと♠Q を出せない（例外：それしか無い）、
  ハートしか無いときのハートリード、ディスカードでハートが割れる、♠Q を出してもハートは割れない、
  同スートの最強札が取る（A > K > … > 2）、シュートザムーンで他 3 人に 26 点、100 点到達で終了、同点最少は同順位、
  パスの向きが 4 局で 1 周する、CPU の `legalCards` 違反が 1,000 局の乱数試行で 0 件

## やらないこと

- **♦J の −10 点（オムニバス）・「♠Q でもハートブレイク」・「シュートザムーンで自分から 26 引く」の派生ルール**：
  Windows 版にも無く、初版で設定を増やすほど画面が割れる。要望があれば `.df-rules` と同じ畳み方で足す
- **3 人・5 人のハーツ**（枚数を抜く変則）：4 人固定。3 人打ちの需要は確認できていない
- **対人・オンライン**（当サイトは全ゲームがクライアント完結）
- **CPU の読み（相手の手札の推定・カウンティング）**：初版はヒューリスティックだけ。「強すぎる／弱すぎる」は
  テスト環境の手応えで 2 段階目を調整する
- **ババ抜き**：同じ「空いている定番」だが、自分の判断がほぼ無い（ブラックジャック仕様書の整理のとおり）。
  家族・子ども層の入口としては残るので、次回以降の候補のまま
- **ポーカー**：国内の競技ポーカーは 2025〜26 が過去最大の盛り上がり（JOPT 2025 Grand Final 4,525 エントリー、
  `https://light-three.com/pokerevent/` 2026-09-29 更新）だが、対 CPU のヘッズアップは CPU の強さで評価が割れ、
  役の一覧を 1 画面に入れると盤面が割れる。ブラックジャックの AdSense 観察（#265 の 2 週間）の結果を見てから判断する
