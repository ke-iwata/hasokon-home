## 提案する仕様

### A. 日付で出し分ける「締切の帯」（計算結果の下、早見表の上）

`lib/furusato-nozei.ts` に純関数を 1 つ足す（日付は**閲覧者のブラウザの日付を JST に直して**判定する。
静的書き出しなので、ビルド日で固定すると腐る）。

```ts
export type DeadlineNotice =
  | { kind: 'year-end'; taxYear: number; daysLeft: number }          // 11/1〜12/31
  | { kind: 'one-stop'; taxYear: number; deadline: string; daysLeft: number } // 1/1〜1/10
  | { kind: 'kakutei'; taxYear: number }                              // 1/11〜3/15
  | null;                                                             // それ以外は出さない
export function deadlineNotice(todayJst: string): DeadlineNotice;
```

| 期間（JST） | 帯の文（例は 2026 年） |
|---|---|
| 11/1〜12/31 | 「**令和8年分にするには 12月31日まで**に寄附を終えてください（あと N 日）。年末は決済・入金の日で年が分かれることがあるので、28 日ごろまでに済ませると安全です。ワンストップ特例の申請書は 2027年1月10日まで（5 団体以内）。」 |
| 1/1〜1/10 | 「**令和8年分のワンストップ特例の申請書は 1月10日まで**（あと N 日。自治体の多くは必着）。間に合わないときは確定申告で控除を受けられます。いまの計算機は令和9年分（2027 年の寄附）を計算しています。」 |
| 1/11〜3/15 | 「令和8年分でワンストップ特例の申請が間に合わなかった方は、確定申告（3月15日まで）で控除を受けられます。」＋確定申告が必要か判定（`/tools/kakutei-shinkoku-hantei/`）へのリンク |
| 3/16〜10/31 | 出さない |

- 「28 日ごろまで」は**目安**として書く（ポータルの年末の案内に多い日付。断定しない。数字は定数 1 つに）
- **サーバーで描く初期表示は帯なし**にして、クライアントで日付を見てから出す（水和の不一致と、ビルド日での固定を避ける）。
  帯の高さぶんの場所を先に取っておき、CLS を出さない（[mobile-one-screen.md](./mobile-one-screen.md)）
- `taxYear` は `DEFAULT_TAX_YEAR` ではなく**日付から**決める（1/1〜3/15 は前年分）。
  r9-kirikae の `DEFAULT_TAX_YEAR` の切り替えと独立に正しくなるようにする

### B. FAQ を 3 問足す（`page.tsx` の `faq`。JSON-LD の `FAQPage` にも自動で載る）

1. **「ふるさと納税はいつまでに寄附すれば今年の分になりますか？」**
   — 12 月 31 日までに寄附金の支払いを終えた分が今年の分。年の判定は受領証明書の日付で、振込は入金の日、
   カード決済は決済の日とする自治体が多いが扱いは自治体ごと。年末は余裕をもって。
2. **「ワンストップ特例の申請書はいつまでに出せばいいですか？」**
   — 寄附した翌年の 1 月 10 日まで（5 団体以内・確定申告をしない人だけ）。間に合わなければ確定申告で控除を受けられる
   （所得税分は還付、住民税分は翌年度の住民税から）。住所が変わったら 1 月 10 日までに変更届。
3. **「ふるさと納税のポイントはなくなったのですか？」**
   — 2025 年 10 月から、寄附に伴ってポイントを付ける募集は総務省の基準で禁止された。控除額の計算・上限額は変わらない。
   クレジットカード会社が決済に付けるふつうのポイントの扱いは各社の案内を見る（当ページは断定しない）。

既存の FAQ「いつ戻ってきますか？」の後ろに 1・2、末尾に 3 を置く。**既存の FAQ の文は書き換えない**（r9-kirikae の実装と行がぶつからないように）。
