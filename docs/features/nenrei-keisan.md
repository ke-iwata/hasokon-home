# 新ツール「年齢計算・西暦和暦変換」（恒常需要の非YMYL定番ツール）

**状態**：提案（2026-08-14起票、未実装）
**対象**：`tools/`（`hasokon.com/tools/nenrei-keisan/`）
**起票**：2026-08-14

## 背景と根拠

### 競合ツールサイトとの比較で最も目立つ「不足コンテンツ」

「年齢計算」「満年齢」「和暦 西暦 変換」「昭和◯年生まれ 何歳」は
季節変動のない恒常的な大需要キーワードで、主要な計算ツールサイト
（keisan.casio.jp 等）は必ず備えている定番。当サイトには無い。

- 履歴書・行政手続き・保険申込みなど「今すぐ知りたい」場面が多く、
  ツール型ページと検索意図が完全に一致する
- 非YMYLで、立ち上げ期のドメインでも比較的上がりやすい
  （睡眠サイクル計算機が現在サイト内で最も検索表示されている
  ＝生活系・非YMYLが先に伸びるという実測とも整合）
- 既存の制度系ツール（年収の壁・在職老齢年金・iDeCo・高校無償化）は
  すべて年齢が関わる。内部リンクのハブとしても機能する

## 提案する仕様

### 構成（1ページ = 1ツールの原則どおり）

1. **年齢計算**
   - 入力：生年月日（西暦⇔和暦の切替入力）、基準日（初期値=今日）
   - 出力：満年齢・誕生日までの日数・生まれた日の和暦表記・干支・
     卒業/入学年の目安（早生まれ＝1/1〜4/1生まれの学年繰り上がりを考慮）
2. **西暦⇔和暦 早見表**：明治〜令和の静的テーブル（改元年の重複を明示。
   例：1989年は1/7まで昭和64年・1/8から平成元年）
3. **FAQ**：「満年齢と数え年の違いは？」「法律上はいつ歳をとる？
   （年齢計算ニ関スル法律により誕生日前日の満了時＝4/1生まれが早生まれになる理由）」
   「令和8年は西暦何年？」など。学年・4/1生まれの扱いはFAQで丁寧に扱う
4. jsonLd（WebApplication + FAQPage + BreadcrumbList）は既存ツールの型を踏襲

### データの持ち方

`lib/nenrei.ts` に元号データ（開始日・終了日）・干支を
**【データ更新箇所】**コメント付きで集約。
テストは境界ケースを厚くする：誕生日当日／前日、2/29生まれ（平年の扱い）、
改元日（1989-01-07/08、2019-04-30/05-01）、4/1生まれの学年、基準日が過去の場合。

### やらないこと

- 数え年の本格対応（FAQでの説明にとどめる。地域差・用途差が大きい）
- 生年月日からの占い・性格診断の類い（サイトの信頼性を毀損する）
- 六曜・旧暦変換（別ツールの領域。まず年齢・和暦で確立する）

## 期待される効果

- 恒常的なビッグキーワード群への露出。単発の法改正ものと違い
  賞味期限がなく、サイトの検索面のベースラインを底上げする
- 年齢入力を持つ既存ツール群との相互内部リンクでクラスタが強くなる
- 実装が軽く（外部データ不要・純粋な日付計算）、テストで正しさを
  保証しやすい
