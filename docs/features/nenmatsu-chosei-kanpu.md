## 背景と根拠

### なぜ今か

令和8年分（2026年1月〜12月の給与）の所得税は、**基礎控除が最大104万円
（本則62万円 + 特例加算42万円）、給与所得控除の最低保障額が74万円**に引き上げられている。
給与収入178万円までは所得税がかからない（[令和8年度税制改正](https://www.tohoren.or.jp/taxinfo/2026011322991.html)）。
この数字は `tools/lib/furusato-nozei.ts` と `tools/lib/nenshu-kabe.ts` に既に反映済みで、
本提案でも同じ定数を使う。

特例加算42万円は**令和8年・9年の2年間だけの時限措置**である。
つまり「令和8年分の年末調整」は、**この規模の減税が初めて年税額に効く年末調整**にあたる。

ここから、12月の年末調整で**例年より大きな還付が出る人が広く発生する**と見込まれる。
検索需要は例年10月（扶養控除等申告書の配布）から立ち上がり、
11〜12月（還付の着金）にピークを迎える。
**8月に着手すれば、需要のピークまでにインデックスされる時間がある。**
現在サイトには年末調整に関するツールが1本も無い（`tools/lib/registry.ts` の15本を確認）。

### 要確認事項（実装前に一次情報で裏を取ること）

**月次の源泉徴収税額表に、改正がどこまで反映されているか。**
令和8年1月から源泉徴収税額表は改定されており、源泉徴収が不要となる下限は
月額88,000円から105,000円に引き上げられている
（[いしい税理士事務所](https://ishihide-tax.com/tax/withholding-tax-table/)）。
一方で、基礎控除の特例加算42万円が月次表にどこまで織り込まれているかは、
上記の二次情報からは確定できなかった。

**この不確実性は、後述の入力設計（実額入力を主にする）で回避する。**
ただし推計モードの精度に直結するため、実装時に
国税庁「令和8年分 源泉徴収税額表」および「年末調整のしかた」で必ず確認すること。

## 何を作るか

### ツールが答える問い

> **「今年の年末調整で、いくら還付されるのか」**

年末調整の還付額は

```
還付額 ＝ 1〜12月に源泉徴収された所得税の累計 − 正しい年税額
```

で決まる。利用者は前者を給与明細で持っているが、後者を自力では出せない。
**このツールは後者（正しい年税額）を計算し、差額を還付額として提示する。**

### 入力

| 項目 | 必須 | 既定値 | 備考 |
|---|---|---|---|
| 年収（額面・賞与込み） | ○ | － | |
| 源泉徴収税額の累計 | △ | 推計 | **主たる入力。**給与明細の「所得税」の合計。未入力なら年収から推計する |
| 社会保険料の年間合計 | △ | 推計 | 未入力なら `estimateSocialInsurance()` で推計 |
| 配偶者の有無・配偶者の年収 | | なし | 配偶者控除／配偶者特別控除 |
| 扶養親族（一般・特定・老人の人数） | | 0 | 所得要件は58万円以下 |
| 19〜22歳の親族の年収 | | － | 特定親族特別控除（最大63万円）。`nenshu-kabe.ts` に判定ロジックあり |
| 生命保険料控除・地震保険料控除 | | 0 | 申告額をそのまま受け取る |
| iDeCo・小規模企業共済等掛金 | | 0 | |
| 住宅ローン控除 | | 0 | **税額控除**。`furusato-nozei.ts` の `applyHousingLoan()` と扱いを揃える |

**「源泉徴収税額の累計」を主たる入力にするのが本ツールの肝である。**
実額を受け取れば、月次表の織り込み具合に関する上記の不確実性から独立して、
還付額を正しく出せる。推計モードはあくまで明細が手元に無い人向けの補助とする。
推計値を使ったときは、結果に「概算です」と明示すること。

### 出力

1. **還付額（または追徴額）** — 最も大きく出す。マイナスなら「不足額を徴収」と表現する
2. **内訳** — 給与所得控除 / 各種所得控除 / 課税所得 / 年税額 / 源泉徴収累計 / 差額
3. **改正の効果** — 「令和7年分の控除額で計算した場合」との差額を併記し、
   今年の還付が大きい理由を金額で見せる。**これが本ツールの独自価値になる**
4. 住民税は年末調整の対象外である旨の注記（翌年6月から給与天引き）

### 再利用できる既存実装

`tools/lib/furusato-nozei.ts` に必要な部品がほぼ揃っている。**新規に書く税額計算はほぼ無い。**

| 関数 | 用途 |
|---|---|
| `salaryDeduction()` / `salaryIncome()` | 給与所得控除（令和8年分・最低保障74万円） |
| `basicDeductionIncomeTax()` | 基礎控除（本則62万 + 特例加算42万） |
| `incomeTaxRate()` / `incomeTaxAmount()` | 超過累進税率 |
| `RECONSTRUCTION_RATE` | 復興特別所得税 2.1% |
| `estimateSocialInsurance()` | 社会保険料の推計 |
| `applyHousingLoan()` | 住宅ローン控除 |

新規に必要なのは、配偶者控除・扶養控除・保険料控除の積み上げと、
源泉徴収累計との差額を取る部分だけである。

## 受け入れ条件

- [ ] 年収・源泉徴収累計を入れると還付額が出る
- [ ] 源泉徴収累計が未入力でも推計で動き、結果に「概算」と明示される
- [ ] 令和7年分の控除額との比較が出る
- [ ] 追徴（マイナス）になるケースが正しく「不足額」と表示される
- [ ] `ToolMeta` を `ymyl` で入れ、出典に国税庁「年末調整のしかた」を置く
- [ ] `registry.ts` に追加し、トップ一覧と sitemap に載る
- [ ] `home/index.html` と `home/404.html` のサイト一覧にも追加する（`CLAUDE.md` の約束）
- [ ] 単体テストを置く。少なくとも次の観点：
  - 年収178万円ちょうどで年税額0になる
  - 給与収入500万円・独身・社保推計での還付額が手計算と一致
  - 住宅ローン控除で年税額が0を下回らない（マイナス還付にならない）
  - 源泉徴収累計 < 年税額 のとき追徴になる

## 期待される効果と工数

**効果**：10〜12月に需要が立ち上がる、明確な季節性のあるキーワード群
（「年末調整 還付金 いくら」「年末調整 計算」「令和8年 年末調整 変更点」など）を取りに行ける。
特例加算42万円は令和8・9年限定なので、**この2年は「改正で還付が増える」という
競合の少ない切り口が使える**。既存の「お金・社会保険」カテゴリとの内部リンクも自然に張れる。

**工数**：**中規模。20万〜30万トークン程度**を見込む。
税額計算の中核が `furusato-nozei.ts` に既にあるため、
同種のツールを新規に起こす場合よりかなり軽い。内訳は
仕様の詰めと一次情報の確認に3割、実装（`lib` + `Calculator.tsx` + `page.tsx`）に5割、
テストと文言に2割。

**リスク**：月次源泉徴収表の織り込み具合が未確定である点（上記「要確認事項」）。
実額入力を主にする設計でリスクは限定されるが、
「改正の効果」の説明文を書く前には必ず一次情報にあたること。
