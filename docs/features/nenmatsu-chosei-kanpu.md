### なぜ今か

令和8年分（2026年1月〜12月の給与）の所得税は、**基礎控除が最大104万円
（本則62万円 + 特例加算42万円）、給与所得控除の最低保障額が74万円**に引き上げられている。
給与収入178万円までは所得税がかからない（[令和8年度税制改正](https://www.tohoren.or.jp/taxinfo/2026011322991.html)）。
この数字は `tools/lib/furusato-nozei.ts` と `tools/lib/nenshu-kabe.ts` に既に反映済みで、
本提案でも同じ定数を使う。

特例加算42万円は**令和8年・9年の2年間だけの時限措置**である。
つまり「令和8年分の年末調整」は、**この規模の減税が初めて年税額に効く年末調整**にあたる。

ここから、12月の年末調整で**例年より大きな還付が出る人が広く発生する**と見込まれる。
検索需要は例年10月（扶養控除等申告書の配布）から立ち上がり、
11〜12月（還付の着金）にピークを迎える。
**8月に着手すれば、需要のピークまでにインデックスされる時間がある。**
現在サイトには年末調整に関するツールが1本も無い（`tools/lib/registry.ts` の15本を確認）。

## 何を作るか

### ツールが答える問い

> **「今年の年末調整で、いくら還付されるのか」**

年末調整の還付額は

```
還付額 ＝ 1〜12月に源泉徴収された所得税の累計 − 正しい年税額
```

で決まる。利用者は前者を給与明細で持っているが、後者を自力では出せない。
**このツールは後者（正しい年税額）を計算し、差額を還付額として提示する。**

### 入力

| 項目 | 必須 | 既定値 | 備考 |
|---|---|---|---|
| 年収（額面・賞与込み） | ○ | － | |
| 源泉徴収税額の累計 | △ | 推計 | **主たる入力。**給与明細の「所得税」の合計。未入力なら年収から推計する |
| 社会保険料の年間合計 | △ | 推計 | 未入力なら `estimateSocialInsurance()` で推計 |
| 配偶者の有無・配偶者の年収 | | なし | 配偶者控除／配偶者特別控除 |
| 扶養親族（一般・特定・老人の人数） | | 0 | 所得要件は58万円以下 |
| 19〜22歳の親族の年収 | | － | 特定親族特別控除（最大63万円）。`nenshu-kabe.ts` に判定ロジックあり |
| 生命保険料控除・地震保険料控除 | | 0 | 申告額をそのまま受け取る |
| iDeCo・小規模企業共済等掛金 | | 0 | |
| 住宅ローン控除 | | 0 | **税額控除**。`furusato-nozei.ts` の `applyHousingLoan()` と扱いを揃える |

**「源泉徴収税額の累計」を主たる入力にするのが本ツールの肝である。**
実額を受け取れば、月次表の織り込み具合に関する上記の不確実性から独立して、
還付額を正しく出せる。推計モードはあくまで明細が手元に無い人向けの補助とする。
推計値を使ったときは、結果に「概算です」と明示すること。

### 出力

1. **還付額（または追徴額）** — 最も大きく出す。マイナスなら「不足額を徴収」と表現する
2. **内訳** — 給与所得控除 / 各種所得控除 / 課税所得 / 年税額 / 源泉徴収累計 / 差額
3. **改正の効果** — 「令和7年分の控除額で計算した場合」との差額を併記し、
   今年の還付が大きい理由を金額で見せる。**これが本ツールの独自価値になる**
4. 住民税は年末調整の対象外である旨の注記（翌年6月から給与天引き）

### 再利用できる既存実装

`tools/lib/furusato-nozei.ts` に必要な部品がほぼ揃っている。**新規に書く税額計算はほぼ無い。**

| 関数 | 用途 |
|---|---|
| `salaryDeduction()` / `salaryIncome()` | 給与所得控除（令和8年分・最低保障74万円） |
| `basicDeductionIncomeTax()` | 基礎控除（本則62万 + 特例加算42万） |
| `incomeTaxRate()` / `incomeTaxAmount()` | 超過累進税率 |
| `RECONSTRUCTION_RATE` | 復興特別所得税 2.1% |
| `estimateSocialInsurance()` | 社会保険料の推計 |
| `applyHousingLoan()` | 住宅ローン控除 |

新規に必要なのは、配偶者控除・扶養控除・保険料控除の積み上げと、
源泉徴収累計との差額を取る部分だけである。

## 実装の追記（2026-08-12）

### 「要確認事項」を一次情報で確認した — 結論が変わった

国税庁の原文に当たった結果、**この仕様書の想定より話がずっと単純で、かつ
このツールにとって有利な事実**が分かった。確認した資料は次の3つ。

- [令和8年度税制改正による所得税の基礎控除の引上げ等について](https://www.nta.go.jp/users/gensen/2026kiso/index.htm)
- [令和8年4月 源泉所得税の改正のあらまし（PDF）](https://www.nta.go.jp/publication/pamph/gensen/2026kaisei.pdf) 1〜2ページ
- [令和8年度税制改正（基礎控除の引上げ等関係）Ｑ＆Ａ（PDF）](https://www.nta.go.jp/users/gensen/2026kiso/pdf/0026005-024.pdf) Ｑ１－１・Ｑ３－１

**基礎控除の引上げ・給与所得控除の最低保障額の引上げ・扶養親族等の所得要件の改正は、
令和8年12月1日施行**である。国税庁は次のように明記している。

> 令和8年11月までの給与等の源泉徴収事務に変更は生じません。
> 令和8年分の給与等の源泉徴収事務においては、令和8年12月に行う年末調整の際に、
> 引上げ後の基礎控除額及び改正後の「年末調整等のための給与所得控除後の給与等の金額の表」に
> 基づいて1年間の税額を計算し、**改正前の「源泉徴収税額表」によって計算した
> 源泉徴収税額との精算**を行います。

「源泉徴収税額表」そのものの改正は**令和9年1月1日施行**で、令和8年中は使われない。

つまり**「月次表に42万円の特例加算がどこまで織り込まれているか」という問い自体が消える**。
答えは「1円も織り込まれていない」。1〜11月は改正前の控除額で源泉徴収され、
令和8年度改正による減税は**まるごと12月の年末調整で精算される**。

仕様書が仮定した「月次表の織り込み具合が不確実」という前提で書かれた
`docs` の記述（要確認事項・リスク）は、この確認をもって解消とする。

### 推計モードを修正した（RULES_R8 → RULES_R7）

上を受けて `estimateWithheld()` を**改正前（令和7年分）の控除額**で計算するよう直した。
当初は令和8年分の控除額で源泉徴収されている前提で書いていたが、これは誤りだった。

副作用として、**年末調整でしか効かない控除が1つも無い人でも還付が出る**ようになった
（給与収入500万円・独身で28,300円）。修正前は0円と表示していたので、
このツールの答えとしては正反対だった。`RULES_R7` は「比較用の令和7年分」と
「令和8年11月までの源泉徴収の基礎」の2役を兼ねる。

### 扶養親族の所得要件 —— 62万円で正しかった

あらまし2ページの表で確認した。仕様書の「58万円以下」は**改正前の値**である。

| 区分 | 改正後（令和8年分〜） | 改正前 |
|---|---|---|
| 扶養親族・同一生計配偶者 | 62万円以下（給与136万円以下） | 58万円以下（給与123万円以下） |
| 特定親族 | 62万円超123万円以下（給与136万円超197万円以下） | 58万円超123万円以下 |
| 配偶者特別控除の対象 | 62万円超133万円以下（給与136万円超207万円以下） | 58万円超133万円以下 |
| 勤労学生 | 89万円以下（給与163万円以下） | 85万円以下（給与150万円以下） |

`lib/nenshu-kabe.ts` の壁（136万・159万・163万・197万・207万）とすべて一致する。

### 既存の定数も突き合わせた（差分なし）

ついでに `lib/furusato-nozei.ts` の定数をあらまし1ページの表と照合した。**誤りは無かった。**

- 給与所得控除の最低保障額 74万円 ✓
- 基礎控除（令和8・9年分）: 合計所得489万円以下 104万円 / 489万円超655万円以下 67万円 /
  655万円超2,350万円以下 62万円 ✓（本則62万円 + 加算42万円・5万円）
- 配偶者特別控除額・特定親族特別控除額の表もあらまし2ページと完全一致 ✓

なお令和10年分以後は合計所得132万円以下の99万円（本則62万円 + 加算37万円）だけが残る。
時限措置が切れるときは `basicDeductionIncomeTax()` をこの形に更新する。

### 令和7年分の控除額（比較用）を新たに置いた

リポジトリに令和7年分の定数が無かったため、`lib/nenmatsu-chosei.ts` に
`salaryDeductionR7()`（最低保障65万円・境目190万円）と
`basicDeductionIncomeTaxR7()`（95万/88万/68万/63万/58万…）を足した。
比較は**給与所得控除と基礎控除だけを令和7年分に差し替え**、社会保険料や
保険料控除は同じ値で計算している（改正の効果だけを取り出すため）。

### 残った既知の誤差

あらまし1ページのハによると、令和8・9年分は給与収入219万1,000円〜220万円未満の帯で
給与所得が階段（145万1,000円／145万3,000円／145万6,000円）になる。
`salaryDeduction()` は連続式（収入−74万円）なので、この9,000円幅の帯だけ
所得が最大4,000円ずれる。税額にすると数百円で、ツール全体の概算の精度に対して
無視できるため直していない。

## 期待される効果と工数

**効果**：10〜12月に需要が立ち上がる、明確な季節性のあるキーワード群
（「年末調整 還付金 いくら」「年末調整 計算」「令和8年 年末調整 変更点」など）を取りに行ける。
特例加算42万円は令和8・9年限定なので、**この2年は「改正で還付が増える」という
競合の少ない切り口が使える**。既存の「お金・社会保険」カテゴリとの内部リンクも自然に張れる。

**工数**：**中規模。20万〜30万トークン程度**を見込む。
税額計算の中核が `furusato-nozei.ts` に既にあるため、
同種のツールを新規に起こす場合よりかなり軽い。内訳は
仕様の詰めと一次情報の確認に3割、実装（`lib` + `Calculator.tsx` + `page.tsx`）に5割、
テストと文言に2割。

**リスク**：月次源泉徴収表の織り込み具合が未確定である点（上記「要確認事項」）。
実額入力を主にする設計でリスクは限定されるが、
「改正の効果」の説明文を書く前には必ず一次情報にあたること。
