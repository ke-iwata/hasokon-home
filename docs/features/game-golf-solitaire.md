### ゴルフを選ぶ理由（次の1本としての優先度）

1. **クラスタの完成度**: クロンダイク・スパイダー・フリーセル・ピラミッド・
   トライピークスに次ぐ6本目。主要ポータル（Yahoo!ゲーム系・海外の
   Solitaire 専業サイト）が揃って置いている定番の中で、残っている大物がゴルフ。
   「ゴルフ ソリティア」は指名検索が細く長く続き、日本語の専用ページは手薄
2. **実装が既存資産の組み合わせで最小**: 「場札を1枚ずつ、捨て札の±1の数字で
   取っていく」というルールの芯は**トライピークスと同一**。カードの描画・
   タップ操作・アニメーション・`game-records`（ベストスコア）の機構をそのまま流用でき、
   新規はレイアウト（7列×5枚）と手詰まり判定くらい
3. **1プレイ2〜3分**: 短時間で区切りが付くタイプで、スキマ時間の再訪問に向く

## 提案する仕様

### ルール（最も広く遊ばれている形を採用）

1. 場札は**7列×5枚、全部表向き**。各列のいちばん手前の1枚だけ取れる
2. 捨て札の数字の**±1**の札を場から取れる（スートは問わない）。連続で取ると得点が伸びる
3. 取れる札がなければ山札（17枚）から1枚めくって捨て札にする
4. **場札を全部取り切ればクリア**。山札が尽きて手が無くなったら終了
5. A と K は既定では**つながらない**（Kで連鎖が止まる、最も一般的なルール）。
   「A↔K をつなげる」をオプションで用意する（ピラミッドの設定UIの作法に合わせる）

> **流用元との差分（実装時に必ず読む）**：下敷きにする `games/lib/tripeaks.ts` の
> ±1判定は**ラップあり**（AとKがつながる。同ファイル冒頭コメント参照）で、
> **このゴルフの既定ルールとは逆**。そのまま流用すると既定が「ラップあり」になってしまう。
> 判定には `wrap` フラグを持たせて**既定 off**とし、A↔K オプションが on のときだけ
> トライピークスと同じ判定になる、という向きで実装すること。

### スコアと成功の見せ方（クリアは珍しい前提で設計する）

ラップなしのゴルフは**クリア率が数%台**のゲームで、成功条件を「取り切ればクリア」
だけにすると、ほとんどのプレイが「負け」で終わってしまう。ゴルフという名前の由来
（打数＝残り札の少なさ）どおり、**残り枚数をスコアの主指標に据える**。

- 終了時は「残り◯枚」を結果として大きく出す（クリアは残り0枚の特別表示）。
  悪い配りでも「今回は残り12枚」という結果として成立させる
- `game-records` に残すのは**プレイ数・クリア数・最少残り枚数・最長連鎖**。
  トライピークスの「クリアの有無と最長連鎖」の作法を踏襲しつつ、
  ゴルフの主記録として**最少残り枚数（ベスト）**を足す

### 実装の要点

- ルールエンジンは `games/lib/golf-solitaire.ts` に新規（`deal()` / `canPick()` /
  `pick()` / `draw()` / `isCleared()` / `hasAnyMove()`）。**トライピークスの
  実装を下敷きにする**（±1判定・連鎖カウントは同じ）
- 盤面が完全公開情報なので、**配りは「クリア可能性」を保証しない**のが一般的。
  **配り直しのガードは入れない。** 完全公開情報のゲームで配りを検閲すると、
  「引きが弱かった」のか「手順が悪かった」のかの手応えが濁る。理不尽な配りは
  上の「残り枚数がスコア」の設計で吸収する（悪い配りも「今回は残り12枚」という
  結果として成立する）。判定条件と再配り上限を決める複雑さも丸ごと不要になる
- カード描画・タップ操作・もどす（アンドゥ）・記録は既存ソリティア群の共通機構を流用
- [mobile-one-screen.md](./mobile-one-screen.md) の作法どおり 320×568 で
  7列×5枚＋山札・捨て札が収まること。盤の大きさは作法どおり
  **`--chrome`（そのゲームで盤以外が使う高さの実測値）と `--board-max`** で決め、
  `maxWidth` を直に書かない。320px幅では1列45px弱と**既存のどのゲームより横に細く**、
  取れるのは各列の先頭1枚だけなので、**札の重なりの露出高さが実質のタップ領域**になる。
  横幅基準の自動縮小だけで済ませず、**先頭札のタップ領域を縦44px以上確保**すること
  （縦の重なりが詰まると隣の札の誤タップになる）
- ページ構成は他ゲームと同じ: ルール・コツ・由来・FAQ（＋JSON-LD の
  VideoGame / FAQPage）、`robots: robotsFor('golf-solitaire')`
- 由来セクションには「ゴルフの打数のように少ない残り札を目指すことが名前の由来」
  という一般的な説明を入れ、`ソリティア 種類` 系クエリへの内部リンク
  （他5本のソリティア）を張る
- 公開時に `home/index.html` のカード（ソリティア群の並びの最後）と
  `home/llms.txt` の行を同じPRで足す（公開の約束どおり）

## 期待される効果と工数

- **効果**: 自然検索で唯一評価が付き始めているソリティア面の強化。
  「ゴルフ ソリティア」指名クエリの受け皿新設と、既存5本との相互リンクによる
  クラスタ評価の底上げ。1プレイが短く、ゲーム面の再訪問率にも効く
- **工数の目安**: **10〜15万トークン程度**（ソリティア6本の中で最小。
  トライピークスのロジック・UIの流用率が高いため。ページ・テスト込み）

## 採らなかった選択肢

- **バブルシューター**: 検索需要はゴルフより大きいが、六角格子・照準・浮き判定と
  新規実装が重く（中規模）、既存資産との共有もない。ソリティア面の完成を先に取る。
  次の「新ジャンル枠」の候補として残す
- **日本語版 Wordle 系デイリーパズル**: リピート訪問を生む魅力はあるが、
  ひらがな辞書の整備が本体で、毎日の答え運用という新しい持ち物が増える。
  デイリー系はサイトの再訪基盤（PWA・記録）が育ってからのほうが活きる
- **15パズル**: 工数は同等に小さいが、検索需要も小さく、ソリティアのような
  クラスタ効果がない
