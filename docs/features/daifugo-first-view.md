- 大富豪は **games でリバーシに次いで2番目に着地が多い**のに、エンゲージメント率がリバーシの約 1/3
- 参照元に分けると、**大富豪の着地 44 件はすべて `chatgpt.com`**（Bing からの着地は 0）。ChatGPT が「無料で遊べる大富豪」として
  このページを案内している。うち **19 件は平均 6 秒未満（ほとんどが 0 秒）**、残りは 87〜3,708 秒と長く遊んでいる
  （10-07 は 2 件で平均 2,162 秒、10-12 は 1 件で 3,708 秒）
- 0 秒の着地には、ChatGPT のリンクの先読みやエージェントの閲覧のような**人でないもの**が混ざっている可能性が高く、
  **34% のうちどれだけが「人が最初の画面で帰った」かは GA4 だけでは分けられない**。
  なので本書の根拠の中心は数字ではなく、下の「最初の画面で起きていること」（実物の不具合）に置く
- 参考：**Bing から 1〜5 秒で帰る着地はフリーセルのほう**（Bing 29 件のうち 20 件が 6 秒未満）。下の「フリーセルについて」

### 最初の画面で起きていること（2026-11-19、本番 `https://hasokon.com/games/daifugo/` を Playwright で確認）

| 幅 | 「スタート」ボタンの上端 | 自分の手札（1枚目）の上端 | 画面の高さ |
|---|---|---|---|
| パソコン 1366×768 | 625px | **781px（画面の外）** | 768px |
| iPhone 13（390×664） | **633px（下端ぎりぎり）** | **746px（画面の外）** | 664px |

1. **スタート前なのに CPU の席に「考え中…」が出ている。** 配った直後は `state.turn` が ♦3 を持つ席を指していて、
   `Game.tsx` の席の表示は `isTurn ? '考え中…'` で `begun` を見ていない。CPU は `!begun` のあいだ動かない
   （`Game.tsx` 202〜204 行）ので、**画面は「CPUが考えている」と言いながら何も起きない**。
   初めての人には「読み込み中で止まっている」に見える。ChatGPT に案内されて初めて来た人が、最初に見る画面でこれが出ている
2. **自分の手札が最初の画面に1枚も出ていない。** 上から 強さ・速さ／ローカルルール／第n回戦・通算点／
   戦績の帯／CPU 3 席／場（スタートの覆い）／案内の1行 と積まれ、手札はその下。
   **トランプのゲームで「自分の札が見えない」は、何のゲームかが一目で分からない**のと同じ。
   リバーシは盤が 490px から始まり、最初の画面に盤の上半分と「スタート」が入っている
3. **「スタート」が場の文言（「場は空です。好きな役を出せます」）の上に重なって、文の両端だけが見えている。**
   リバーシは盤の上に重ねているので絵として成り立つが、大富豪は文字の上なので読みかけの文に見える

### 測り方の穴（実装と一緒に確かめる）

- 大富豪のページの `user_engagement` は 56 日で **2 件**しかない（`page_view` 56・`session_start` 45）。
  同じ期間のフリーセルは 29 件、リバーシは 68 件。`user_engagement` はタブを隠す・閉じるときに gtag が送るもので、
  **大富豪だけ極端に少ないのはおかしい**。CPU の `setTimeout` 連鎖や `beforeunload` まわりで送れていない可能性があり、
  そうならエンゲージメント率 34% は**実際より低く出ている**。直す前後の比較が狂うので、先にここを確かめる

## 提案する仕様

### A. スタート前は「考え中…」を出さない（必須・数行）

- 席の状態の表示を `begun && isTurn ? '考え中…' : …` にする。スタート前は、♦3 を持つ **CPU の席だけ**に **「♦3を持っています（先に出します）」** と出す
  （`df-msg` の案内「♦3を持つ人から出します」と同じことを席の側でも言う）。
  **自分の席には出さない**（自分が ♦3 を持つときは、下の `df-msg` が「あなたが♦3を持っています。札を選んで『出す』と始まります」と既に言っている）
- この直しが効くのは**1回戦の開始前だけ**（2回戦以降は `begun` が true のまま残る）。範囲としてはそれで足りる
- 席の枠の強調（`df-seat active`）もスタート前は付けない

### B. 最初の画面に自分の手札を入れる（必須）

パソコン 1366×768・スマホ 390×664 のどちらでも、**スタートを押す前に手札の上半分が見える**ことを目標にする。

1. **戦績の帯（「ふつうとの対戦 0回 大富豪 / 0試合 最高通算点 0点」）を、1試合以上遊んだ人にだけ出す。**
   初めての人には全部 0 で情報がない（約 40px）
2. **「ローカルルール」の `<details>` を強さ・速さの行の右端に寄せる**（独立した1行をやめる。約 30px）
3. **CPU 3 席を薄くする。** 裏向きの札を並べる帯（`df-seat-cards`）はそのままに、席の高さを詰める
   （名前と枚数を1行に。約 50px）
4. **スマホでは手札を画面の下に貼り付ける**（`position: sticky; bottom: 0`。リバーシのような盤のゲームと違い、
   大富豪は「手札から選ぶ」がすべての操作なので、場を見ながら手札に指が届く形にする）。
   パソコンは貼り付けない（1〜3 で収まる）
   貼り付けるときの決めごと：
   - **手札（`df-hand`）と「出す／パス」のボタンの行（その直後の `btn-row`）をひとまとめの1つの箱にして貼り付ける**。
     ボタンだけがスクロールの先に取り残されないようにする
   - **高さの上限は画面の高さの 40% 程度**（`max-height: 40vh` を目安）。13 枚を持っても場と CPU の席が隠れきらないよう、
     収まらない札は帯の中で**横に送る**（`overflow-x: auto`。縦には伸ばさない）
   - `padding-bottom: env(safe-area-inset-bottom)` を入れて、iPhone のホームバーと重ならないようにする
   - **背景は透けさせない**。既存の sticky（`games/app/globals.css` 7482 行あたりの `.hb-log th`）と同じ `var(--surface-2)` を使い、UI を揃える
5. 1〜4 でも収まらない幅があれば、**ページ冒頭の説明文（h1 の下の2行）を1行に縮める**のは可。
   ただし説明文は検索の要約に使われるので、`metadata.description` 側は変えない

### C. 「スタート」の覆いの中身を整える（推奨）

- スタート前は場に「場は空です…」を出さず、覆いの中に**「あなたが大富豪を目指す5回戦。最初に ♦3 を持つ人が出します」**の1行と「スタート」だけを置く。
  文字の上にボタンを重ねない
- **自分が ♦3 を持っているときの分岐は消さない。** いまは `df-msg`（`Game.tsx` 432〜433 行）が「あなたが♦3を持っています。札を選んで『出す』と始まります」に
  切り替わり、札を出すこと自体がスタートの合図になっている（250 行）。C の1行案内を入れても、
  - この案内文の切り替えと「札を出せば始まる」動きはそのまま残す
  - 覆い（`StartGate`）は**場の上だけ**にかけ、手札と「出す」ボタンを覆わない・押す邪魔をしない（B-4 で手札を貼り付けたスマホでも同じ）

### D. `user_engagement` が送れているかを確かめる（A〜C を止めない）

- テスト環境で GA4 の DebugView を開き、大富豪のページでスタート前・対局中・試合後のそれぞれでタブを切り替え、
  `user_engagement` が届くかを見る。リバーシ（届いている）と比べる
- 届いていなければ原因を [tool-use-coverage.md](./tool-use-coverage.md) か本書に追記し、直してから B の効果を測る
- **順番：A〜C の実装は D の結果を待たない。** D は運営者の画面操作（DebugView）が要るので、A〜C の PR をテスト環境に出したあとで確かめ、
  **結果はその同じ PR の本文に書く**。届いていなかった場合の直しは**別に起票**する（A〜C の PR には混ぜない）

### フリーセルについて（今回は直さない・観察だけ）

- フリーセルも 29% と低い。こちらは**最初の画面に盤（札の列）が出ている**のに、**Bing からの着地 29 件のうち 20 件が 6 秒未満**
  （平均 87 秒は 166〜222 秒の数件が引き上げている）。2 秒で盤を見て帰るのは「Windows のフリーセル」を探して来た人か、
  Bing 側の先読みかのどちらかで、GA4 だけでは分けられない。Bing の検索語（Bing Webmaster Tools、`scripts/bing-search-stats.mjs`）が取れれば判断できる。
  ゲーム番号で配る（Windows と同じ番号の盤を出す）機能を足すかどうかは、[game-freecell.md](./game-freecell.md) の範囲で別に起票する。本書では大富豪の直したあとの数字と並べて見るだけにする

## 確かめること（テストとテスト環境）

1. `games/tests/` に、配った直後（`begun=false`）の描画で「考え中」が出ないテストを足す
2. 1366×768 と 390×664 で、スタート前に手札の札が少なくとも1枚、上端が画面内にあること（Playwright のスクリーンショットで目視）
3. 手札を貼り付けたスマホで、場の札・CPU の席が手札の下に隠れないこと（最後までスクロールできる）
4. 1試合以上遊んだあとは戦績の帯が出ること（`localStorage` の記録を読む部分は変えない）
5. 「ローカルルール」を開いたとき、切り替えの説明（「切り替えると試合を最初からやり直します」）が読めること
6. D の確認結果（`user_engagement` が届くか）を PR の本文に書く（結果待ちでマージを止めない）
7. 自分が ♦3 を持つ配りで、スタートを押さずに ♦3 を選んで「出す」と始まること（覆いが手札・ボタンを塞がない）。自分の席には「♦3を持っています」が出ないこと
8. スマホで手札が 13 枚のとき、貼り付けた箱が画面の 40% 程度で止まり、札は横に送れること。iPhone のホームバーと「出す」が重ならないこと

## 期待される効果

- ChatGPT に案内されて来た人が最初の画面で迷わなくなる。数字の目標は置きにくい（0 秒の着地に人でないものが混ざる）ので、
  **「10 秒以上いた着地のうち、スタートを押した割合」**（`tool_use` の `begin-*` ÷ 10 秒以上の着地）を直す前後で比べる
- 年末年始に「大富豪 無料」と ChatGPT に聞く人を取りこぼさない。games は Google のインデックスが戻っておらず
  （[google-index-recovery.md](./google-index-recovery.md)）、**AI アシスタントからの紹介が大富豪の唯一の入口**になっている
- 「スタート前に CPU が考え中」は見た目の不具合なので、直すだけで品質の印象が上がる

### 効果の測り方

- 本番反映から 28 日後に、本書の表と同じ切り方（`landingPage` × `sessionSource`、セッションの秒数）と、`begin-*` の数で取り直して追記する
