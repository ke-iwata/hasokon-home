## 提案する仕様

### ルール

- スタート（左上）からゴール（右下）まで、壁を通らずに道をなぞる
- 迷路は**完全迷路**（すべてのマスがつながり、どの2マスの間の道もちょうど1本）。**必ず解けて、答えは1本**

### 大きさ（5段階）

| 段階 | マス | 目安 |
|---|---|---|
| ようじ | 5×5 | 3〜5歳。道が太く、マスが大きい |
| かんたん | 8×8 | 小学校低学年 |
| ふつう | 12×12 | 小学校高学年 |
| むずかしい | 20×20 | 中学生〜おとな |
| おにむず | 30×30 | おとな。スマホでは拡大して遊ぶ（ピンチ） |

### 遊び方の種類

- **今日の1面**（段階ごとに1面。`games/lib/daily.ts` の `dailySeed` で日付から決める。全員が同じ迷路）
- **フリー**（「新しい迷路」で何度でも）
- 記録は `games/lib/records.ts` の形で、段階ごとの最短タイム・今日の1面の連続日数

### 操作

- **指・マウスでなぞる**：押したまま進むと線が伸び、来た道を戻ると線が消える。壁の向こうへは伸びない（ずるができない）
- **キーボード**：矢印キーで1マスずつ（分かれ道まで自動で進む「すいすいモード」はオプション）
- ゴールに着いたらタイムと「もう1面」「印刷する」
- 「こたえを見る」：ゴールまでの道を薄く表示（記録は付かない）

### 印刷（このゲームの売り）

- 「印刷する」で **A4 縦1枚に迷路1面**、2枚目に答え（`@media print` で操作部品と広告を消す）
- 印刷用の線は黒・太め、背景は白（インクを使わない）。名前と日付を書く欄
- **「4面まとめて印刷」**（A4 1枚に小さめの4面。ようじ・かんたん向け）。**2枚目に4面分の答えをまとめて付ける**（1枚に小さく4つ）
- 答えは `break-before: page` で必ず2枚目に回す（1面のときも4面のときも）
- 印刷物の下に小さく `hasokon.com/games/meiro/` を入れる（配られた紙から人が来る入口）。**広告は印刷しない**
- 計測は新しいイベント名を作らず、**既存の `trackToolUse`（`games/lib/analytics.ts`）に統一**：`trackToolUse('meiro', 'print')`・`trackToolUse('meiro', 'print-4up')`。
  **数えているのは「印刷ボタンを押した回数」で、実際に印刷された枚数ではない**（印刷ダイアログで取り消しても数える）。**印刷物そのものはどこにも送らない**
- 印刷の CSS は tools の `bosai-bichiku-keisan` の書き方（`tools/app/globals.css` の `@media print`）にそろえる。**games の `globals.css` にはまだ `@media print` が無い**ので、このゲームの分を足す形にする

### 印刷物の配布と規約（運営者の確認待ち）

いまの `home/privacy.html` の著作権の項は「無断で複製・転載・改変・再配布することを禁じます」で、このままだと FAQ で家庭・教室での配布を「可」と答えられない。
「配れる」のがこのゲームの売りなので、**規約に例外を足す（案 a）**で進める：

- 文言の案：「印刷機能で出力した迷路・問題は、家庭・教育・保育の場での**非営利の配布**に限り、自由に使ってかまいません（販売・ほかのサイトへの転載は不可）」
- 作業：`home/privacy.html` の著作権の項に上を足し、`home/sitemap-home.xml` の `privacy.html` の `lastmod` を変更日に上げる。**実装PR（または `public` にするPR）に入れる**
- **文言は運営者の確認待ち。** 確認が取れないまま `public` にする場合は、案 (b)（FAQ は「家庭内での利用」までにとどめ、配布には触れない）に落とす

### 子ども向けと広告（運営者の確認待ち）

- サイトは一般向け。このページは**保護者が子どもと遊ぶ・印刷して子どもに渡す**ためのもので、**子ども単独の利用を前提にしない**
- 広告の設定はほかのゲームと同じにする（子ども向けとして扱うタグは付けない）。本文も「お子さんと」「印刷して渡せる」と保護者に向けた書き方にする
- この方針でよいかを運営者に確かめる（状態行に記載）

### ロジック（`games/lib/meiro.ts`。純関数のみ）

- 生成：**乱数つき深さ優先（穴掘り法）**または**Wilson 法**。どちらも完全迷路になる。
  Wilson 法は偏りが少なく、深さ優先は長い1本道ができやすい（子ども向けは深さ優先、おとな向けは Wilson、を実装PRで遊んで決める）
- 乱数は `mulberry32`（`daily.ts`）で注入し、同じシードで同じ迷路になる
- `solve(maze)`：幅優先で答えの道を返す
- `canMove(maze, from, to)`：壁の判定（なぞりの受け付けに使う）
- 迷路は「壁の有無」のビット列で持ち、描画は SVG 1枚（30×30 でも要素数を抑える。壁を横線・縦線の `path` にまとめる）

### テスト（`games/tests/meiro.test.ts`）

- 各段階で乱数シード 100 個ずつ生成し、**全マスがスタートから到達できる**・**辺の数 = マス数 − 1**（完全迷路＝木になっている）
- 同じシードで同じ迷路、違う日付で違う今日の1面
- `solve` の道が隣り合うマスだけでできていて、壁を通らない
- `canMove` が壁の向こうを拒む
- ページの `metadata` に `robots: robotsFor('meiro')`（既存の `stage.test.ts` が見る）

### 画面（[mobile-one-screen.md](./mobile-one-screen.md)）

- 幅 360px で 12×12 までは1画面に収まる（1マス 26px 前後）。20×20・30×30 はゲーム側で拡大する（下の「実装時の注意」）
- 色だけに頼らない（スタート・ゴールは「S」「G」の文字も出す）。なぞった線は太さでも区別する

### 本文

- 遊び方・段階の目安・印刷のしかた・「迷路の作り方（完全迷路とは）」の短い読み物
- FAQ 4問：印刷して配ってよいか（上の「印刷物の配布と規約」の案 a が通れば「家庭・教育・保育での非営利の配布は可」、通らなければ案 b で「家庭内での利用」まで）／答えが1本なのはなぜか／スマホで大きい迷路を遊ぶには／広告は印刷されるか

### 実装時の注意

- **今日の1面の固定**：`dailySeed(key, version)` の `version` は定数で固定する。生成方式（深さ優先／Wilson 法）や大きさを公開後に変えたら、**同じPRで `version` を上げる**（変えた日に端末で違う迷路が出るのを防ぐ）
- **30×30 をスマホで**：360px 幅だと1マス約 11px で指ではなぞれない。ブラウザのピンチ任せは、なぞり中のスクロール止め（`touch-action: none`）と両立しない。
  そこで**ゲーム側の拡大（＋／−ボタン。ピンチを自前で受けるのは任意）**を作り、拡大中は「なぞっていない指1本のドラッグ」ではなく**盤の外の移動ボタン、または2本指のドラッグ**で表示位置を動かす（どちらにするかは実装PRで実機で決める）。
  `touch-action: none` は**盤面の要素だけ**に付け、ページ全体には付けない
- **ようじ向けの画面**：タイムは小さめに出して急かさない。ゴールの表示は大きく、文字はひらがな（「ゴール！ よくできました」）
- **印刷**：上の「印刷」の節のとおり（答えは2枚目・4面まとめは答えも4面分・`hasokon.com/games/meiro/` の印・広告なし・CSS は `bosai-bichiku-keisan` にそろえる）

### やらないこと

- キャラクターや既存作品の迷路の模写、立体迷路・3D
- 画像からの迷路づくり、オンライン対戦・ランキング
- 入力・記録の送信（ブラウザ内で完結）
