## 提案する仕様

### ルール

- スタート（左上）からゴール（右下）まで、壁を通らずに道をなぞる
- 迷路は**完全迷路**（すべてのマスがつながり、どの2マスの間の道もちょうど1本）。**必ず解けて、答えは1本**

### 大きさ（5段階）

| 段階 | マス | 目安 |
|---|---|---|
| ようじ | 5×5 | 3〜5歳。道が太く、マスが大きい |
| かんたん | 8×8 | 小学校低学年 |
| ふつう | 12×12 | 小学校高学年 |
| むずかしい | 20×20 | 中学生〜おとな |
| おにむず | 30×30 | おとな。スマホでは拡大して遊ぶ（ピンチ） |

### 遊び方の種類

- **今日の1面**（段階ごとに1面。`games/lib/daily.ts` の `dailySeed` で日付から決める。全員が同じ迷路）
- **フリー**（「新しい迷路」で何度でも）
- 記録は `games/lib/records.ts` の形で、段階ごとの最短タイム・今日の1面の連続日数

### 操作

- **指・マウスでなぞる**：押したまま進むと線が伸び、来た道を戻ると線が消える。壁の向こうへは伸びない（ずるができない）
- **キーボード**：矢印キーで1マスずつ（分かれ道まで自動で進む「すいすいモード」はオプション）
- ゴールに着いたらタイムと「もう1面」「印刷する」
- 「こたえを見る」：ゴールまでの道を薄く表示（記録は付かない）

### 印刷（このゲームの売り）

- 「印刷する」で **A4 縦1枚に迷路1面**、2枚目に答え（`@media print` で操作部品と広告を消す）
- 印刷用の線は黒・太め、背景は白（インクを使わない）。名前と日付を書く欄
- **「4面まとめて印刷」**（A4 1枚に小さめの4面。ようじ・かんたん向け）
- 印刷の回数を GA4 に送る（`print_click`。既存の `tool_use` と同じ送り方）。**印刷物そのものはどこにも送らない**

### ロジック（`games/lib/meiro.ts`。純関数のみ）

- 生成：**乱数つき深さ優先（穴掘り法）**または**Wilson 法**。どちらも完全迷路になる。
  Wilson 法は偏りが少なく、深さ優先は長い1本道ができやすい（子ども向けは深さ優先、おとな向けは Wilson、を実装PRで遊んで決める）
- 乱数は `mulberry32`（`daily.ts`）で注入し、同じシードで同じ迷路になる
- `solve(maze)`：幅優先で答えの道を返す
- `canMove(maze, from, to)`：壁の判定（なぞりの受け付けに使う）
- 迷路は「壁の有無」のビット列で持ち、描画は SVG 1枚（30×30 でも要素数を抑える。壁を横線・縦線の `path` にまとめる）

### テスト（`games/tests/meiro.test.ts`）

- 各段階で乱数シード 100 個ずつ生成し、**全マスがスタートから到達できる**・**辺の数 = マス数 − 1**（完全迷路＝木になっている）
- 同じシードで同じ迷路、違う日付で違う今日の1面
- `solve` の道が隣り合うマスだけでできていて、壁を通らない
- `canMove` が壁の向こうを拒む
- ページの `metadata` に `robots: robotsFor('meiro')`（既存の `stage.test.ts` が見る）

### 画面（[mobile-one-screen.md](./mobile-one-screen.md)）

- 幅 360px で 12×12 までは1画面に収まる（1マス 26px 前後）。20×20・30×30 はピンチで拡大、なぞり中はスクロールを止める
- 色だけに頼らない（スタート・ゴールは「S」「G」の文字も出す）。なぞった線は太さでも区別する

### 本文

- 遊び方・段階の目安・印刷のしかた・「迷路の作り方（完全迷路とは）」の短い読み物
- FAQ 4問：印刷して配ってよいか（家庭・教室・保育での配布は可。販売・再配布サイトへの転載は不可、と既存の利用規約の書き方に合わせる）／答えが1本なのはなぜか／スマホで大きい迷路を遊ぶには／広告は印刷されるか

### やらないこと

- キャラクターや既存作品の迷路の模写、立体迷路・3D
- 画像からの迷路づくり、オンライン対戦・ランキング
- 入力・記録の送信（ブラウザ内で完結）
