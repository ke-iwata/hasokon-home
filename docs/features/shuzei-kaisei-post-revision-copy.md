## 背景と根拠

### 計算機は施行後に切り替わるが、静的な文面は切り替わらない

`tools/lib/shuzei-kaisei.ts` は `REVISION_DATE = '2026-10-01'` と `isRevised(asOf)` を持ち、`Calculator.tsx` は開いた日で
「あと N 日」→「改正は施行済みです。改正前と比べて〜」に切り替わる（マウント後に `new Date()` を入れる作法）。
**ここは正しく動く。**

一方で、静的 HTML に焼き込まれる文面は `formatDate(REVISION_DATE)` を差し込むだけで、**語尾と助言が「これから」のまま**：

| 場所 | いまの文面（2026-09-30 の main） | 10-01 以降の読まれ方 |
|---|---|---|
| `page.tsx` の `description`（meta・OGP・検索結果の説明文） | 「2026年10月1日にビール系飲料の酒税が…一本化**されます**。…**9月中に買うと得なもの**・待つと得なものも仕分けます」 | 検索結果に「9月中に買うと得」が出続ける。Bing はスニペットに description を使うことが多い |
| `registry.ts` の `description`（一覧カード・`/tools/llms.txt`・JSON-LD） | 「…一本化**されます**。…年間の負担がいくら増える（減る）かと、**9月中に買うと得なものが分かります**」 | AI アシスタントがこの行を読んで「9 月中に買うと得」と案内する |
| `page.tsx` のリード（`<p className="lead">`） | 「…一本化**されます**。…の増税**です**」 | ページを開いた瞬間に「まだ変わっていない」と読める |
| `<h2>買いだめの判断は種類で逆になる</h2>` と本文 | 「**施行前に買うほうが**酒税のぶんだけ得」 | 施行後は成り立たない助言が見出しごと残る |
| FAQ「9月のうちに買いだめしたほうが得ですか？」 | 「施行前に買っておくほうが…得です」 | FAQPage の JSON-LD にもそのまま載る |
| `<h2>2026年10月に変わるものを、まとめて確認する</h2>` | 「同じ 2026年10月1日には…もあります」 | 「変わったもの」に直せば残せる |
| `Calculator.tsx` の助言ラベル | `revised ? '値上がりした（増税）' : '9月中に買うと得'` | **こちらは切り替わる**（対応済み） |

`updatedAt: '2026-08-19'` も据え置きで、文面を直しても `updatedAt` を上げなければ sitemap の `lastmod` が動かず、
IndexNow の差分送信に乗らない（[sitemap-lastmod-guardrail.md](./sitemap-lastmod-guardrail.md) の指摘の tools 版）。

### 検索の意図が「いつから・買いだめ」から「いくらになった・新税率」に変わる

施行前の検索は「酒税 改正 いつから」「ビール 10月 値下げ」「発泡酒 買いだめ」。施行後は
「酒税 2026年10月 新税率」「ビール 酒税 いくら」「発泡酒 値上げ いくら」「第三のビール 税率 いくらになった」に寄る。
ページの中身（税率の早見表・負担額計算）はどちらにも答えられるので、**文面の語尾と見出しを「変わった」に直すだけで受け皿になる**。
逆に直さないと、施行後の検索者には「古い記事」に見える（description に「9月中」があるのは最悪の例）。

## 提案する仕様

### A. 文面を「施行後」に書き換える（10-01 直後のリリースに乗せる）

書き換え方針：**「何がいくら変わったか」を主語にし、日付は残し、買いだめの助言は「施行前はこうだった」の 1 段落に畳む**。
税率・計算・早見表の数値は触らない。

1. `page.tsx` の `title`：「酒税改正 早見表・負担額計算｜2026年10月からビール減税・第三のビール／チューハイ増税」→
   **「酒税改正 早見表・負担額計算｜2026年10月1日からの新税率。ビール減税・発泡酒／チューハイ増税で1本いくら変わった？」**
   （「2026年10月」「ビール減税」「チューハイ増税」の語は残す。施行後の検索語「いくら変わった」「新税率」を足す）
2. `page.tsx` の `description`：「一本化されます」→「一本化されました」、「9月中に買うと得なもの・待つと得なものも仕分けます」→
   「種類ごとに 1 本あたり・年間でいくら変わったかが分かります」
3. リード：「一本化されます」→「一本化されました」、「の増税です」はそのまま（現在の事実）
4. `<h2>買いだめの判断は種類で逆になる</h2>` → **`<h2>施行前の買いだめは、種類で判断が逆だった</h2>`** に変え、本文を過去形の 1 段落に縮める。
   FAQ「9月のうちに買いだめしたほうが得ですか？」→ **「施行前に買いだめしておく意味はありましたか？」** に変え、答えを過去形に
   （FAQ を消すと FAQPage の JSON-LD の項目が減る。残して過去形にするほうが「施行前の判断」の検索にも答えられる）
5. `<h2>2026年10月に変わるものを、まとめて確認する</h2>` → 「2026年10月に変わったものを、まとめて確認する」、
   本文「もあります」→「も同じ日に始まっています」（たばこ・最低賃金・106 万円の壁へのリンクは残す）
6. FAQ「酒税はいつ、どのように変わりますか？」→「酒税は 2026 年 10 月 1 日にどう変わりましたか？」。答えの語尾を過去形に
7. `registry.ts` の `description`：「一本化されます」→「一本化されました」、「9月中に買うと得なものが分かります」→
   「種類ごとに 1 本あたり・年間でいくら変わったかが分かります」。**`updatedAt` を書き換えた日に上げる**（sitemap の `lastmod` → IndexNow）
8. `Calculator.tsx` は触らない（施行後の表示は対応済み。施行前の分岐も、`asOf` を過去に固定するテストが残るので消さない）

### B. 「期日を持つツールの文面が期日を過ぎたら落ちる」テストを足す

同じ罠は次の期日でも踏む（2027-01-01 の生前贈与加算、2027-03-31 の相続登記、2027-04-01 の食料品 1%・たばこ 3 段階目、
2027-09 の厚生年金上限）。**「フラグは腐る」（CLAUDE.md）と同じで、文面も腐る**。

- `tools/tests/shuzei-kaisei.test.ts` に 1 件足す：`Date.now()` が `REVISION_DATE` 以降なら、`page.tsx` と `registry.ts` の
  `shuzei-kaisei` の `description` に **「されます」「9月中」「施行前に買う」** が含まれないこと
  （施行前の CI では自動的にスキップされ、**10-01 の最初の CI で赤くなる**。今回は A と同じ PR で入れれば最初から緑）
- 一般化は今回はしない（下記「やらないこと」）。ただし**同じ形のテストを、期日を持つツールの仕様書の「公開条件」に 1 行書く運用**を
  docs/features/README.md に足すかは、運営者の判断に委ねる（本提案の範囲外）

## 期待される効果

- **10-01 以降の検索者に「古い記事」と読まれない。** 効果は Bing の有機着地（`/tools/shuzei-kaisei/`、直近 28 日 60）が
  施行後 4 週で**減らない**こと（施行後は検索が減るのが自然なので、維持できれば成功）。Bing Webmaster Tools の API が入れば
  （[bing-search-performance-audit.md](./bing-search-performance-audit.md) の D）「酒税 新税率」「ビール 酒税 いくら」の表示回数で見る
- `updatedAt` を上げることで IndexNow に乗り、Bing が施行後の文面を取り直す（据え置くと 8 月の HTML を出し続ける可能性がある）
- B により、次の期日（2027-01-01・03-31・04-01）で同じ見落としが CI で止まる

## やらないこと

- **税率・計算ロジック・早見表の数値の変更**：施行後も改正前後の比較は価値が残る（「いくら変わったか」がこのページの主題）
- **施行前の文面を丸ごと消すこと**：「施行前はこうだった」の 1 段落と FAQ 1 問は残す。過去の判断を調べる検索も来る
- **開いた日で静的文面を切り替える仕組み**（`isRevised` を `page.tsx` に持ち込む）：静的書き出しなのでビルド時刻で固定され、
  「サーバ描画とハイドレーションの食い違い」を避けるために Calculator でだけやっている作法を崩す。文面は書き換えで済ませる
- **期日テストの一般化（全ツール共通の `revisionDates` レジストリ）**：期日の持ち方がツールごとに違い（`REVISION_DATE`・
  `LAW_EFFECTIVE_DATE`・`effectiveFrom`）、今そろえると実装 PR になる。まず酒税で 1 件、次の期日のツールで同じ形を 1 件ずつ足す
- **たばこ・年収の壁・最低賃金の文面変更**：確認したうえで直す箇所が無い（上記「現状」）
