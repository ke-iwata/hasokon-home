## 背景と根拠

### 「出産でもらえるお金」の3本が、入口の1本を欠いている

当サイトは妊娠〜育休の給付を **出産手当金・出産育児一時金**（[shussan-teate-keisan.md](./shussan-teate-keisan.md)、#225 実装済み・wip）→
**育児休業給付金**（[ikuji-kyugyo-kyufu.md](./ikuji-kyugyo-kyufu.md)、#202 実装済み・preview）→
**子ども・子育て支援金**（public）の順に持っている。**3本とも入力の起点は「出産予定日」**なのに、
予定日そのものを出すページが無い。

妊娠が分かった人が最初に検索するのは給付ではなく「出産予定日 計算」「妊娠週数 計算」で、
そこから「産休はいつから」「出産手当金はいくら」へ進む。**入口が無いと、給付の 3本には
検索で予定日を知った後の人しか来ない。** 予定日を出した画面から「産前休業の開始日」と
「出産手当金の計算へ（予定日を引き継ぐ）」の導線を置くのがこの提案の狙い。

### 需要（2026-09-18 Web 調査。月間推定検索数は aramakijake.jp、桁の参考値）

| 検索語 | 月間推定 |
|---|---|
| 出産予定日 計算 | 約 48,400 |
| 妊娠週数 計算 | 約 11,840 |
| 出産予定日 | 数十万規模（情報収集の意図が混ざる） |

上位は医師監修のメディア（トモニテ・ムーニー等）と産婦人科クリニックの計算ページ。
**計算そのものは公知の定義**（下記）で差が付かないが、
競合は「予定日を出して終わり」で、**産休の開始日・出産手当金・育休給付までつないでいるものが無い**。
給付を 3本持つ当サイトだけができる深さで、tools/docs/CONCEPT.md の「他がやらない深さ」に沿う。

GA4（プロパティ 548154955、2026-09-04〜09-17、2026-09-18 取得）では
`/tools/kosodate-shienkin/` は着地 0（8月の山が去った）。出産手当金・育休給付は `wip` / `preview` で
検索には出ていない。**このクラスタは入口ができて初めて動く**。

### 計算の定義（公知。日本産科婦人科学会の数え方）

- **最終月経開始日を妊娠 0週 0日**とし、**280日目（40週 0日）が分娩予定日**（ネーゲレ概算法と同じ）
- 排卵日（受精日）が分かる場合は **排卵日 = 2週 0日**、そこから 266日
- 超音波で医師が予定日を修正した場合は、その予定日を優先する（入力に「医師に言われた予定日」を持つ）
- 妊娠期間の区分：初期 〜13週6日／中期 14週0日〜27週6日／後期 28週0日〜。37週0日〜41週6日が正期産

### 産休の根拠（実装済みの `shussan-teate.ts` と同じ定数を使う）

- 産前休業：出産予定日の **6週間前**（多胎は **14週間前**）から請求できる（労働基準法 65条1項）
- 産後休業：出産日の翌日から **8週間**（65条2項。6週間経過後は本人の請求と医師の許可で就業可）
- 出産手当金の支給期間：出産の日以前 42日（多胎 98日）＋出産の日後 56日（健康保険法 102条）。
  `BEFORE_DAYS_SINGLE` / `BEFORE_DAYS_MULTIPLE` / `AFTER_DAYS` が既にある

## 提案する仕様

### 入力

1. 基準にするもの（セレクト）：**最終月経の開始日**（既定）／**排卵日・受精日**／**医師に言われた出産予定日**
2. その日付（`type="date"`。既定は空。最終月経は「今日から 300日前まで」の範囲）
3. 胎児数（1 / 2以上）— 産休の開始日にだけ効く
4. 「今日」（既定は端末の日付。`asOf` の仕組みは `nenshu-kabe` と同じで、SSR とのズレは `useEffect` で吸収）

### 計算（`tools/lib/shussan-yoteibi.ts`。純関数・日付は `lib/date-parts.ts` の暦日計算を使い、UTC のズレを作らない）

- `dueDate`：最終月経 + 280日／排卵日 + 266日／医師の予定日そのまま
- `gestationalAge(asOf)`：最終月経相当日（= 予定日 − 280日）からの経過日数を 週・日 に分解。負なら「まだ妊娠前の週数（計算できない）」、294日（42週）超なら「予定日を過ぎています」
- `trimester`：初期／中期／後期
- `maternityLeave`：**`shussan-teate.ts` の計算をそのまま呼ぶ**（新しく計算しない）。
  産前休業の開始日は「**予定日を含めて** 42日（多胎 98日）」なので `addDays(dueDate, -(baseBeforeDays - 1))`
  ＝ **予定日 − 41日**（多胎は **− 97日**）。`shussan-teate.ts` は `leaveFromDue` でこれを返しているので、
  **同じ関数を export して共有する**（日数の定数も計算も 1か所に保つ。法改正時に 2か所直す状態を作らない）。
  産後休業の終了日は予定日 + 56日、6週後の就業可能日は予定日 + 42日
- `milestones`：**根拠が法令か用語の定義にあるものだけ**を置く — 産前休業の開始日（労基法 65条1項）・
  正期産の開始（37週0日）・予定日（40週0日）・初期／中期／後期の区分。
  **「安定期」「妊婦健診の間隔」は入れない**（「安定期」は医学用語ではない俗称で、健診の間隔も
  医学的な指導にあたる。この仕様書自身の「医師監修が無い状態で医療情報を書かない」に反する）
- **すべて「予定日どおりに生まれた場合」**。実際の出産日が前後すると産後の日付が動くことを画面で明記する

### 表示

- 上部に大きく **出産予定日（西暦・和暦・曜日）** と **今日は妊娠 ◯週 ◯日（◯か月）**
- 週数の帯（0〜42週）に今日の位置・初期／中期／後期・産前休業開始・予定日を置く
- 「産休・給付」のカード：産前休業の開始日／産後休業の終了日／
  **「出産手当金を計算する」ボタン（予定日と胎児数をクエリで `/tools/shussan-teate/?due=YYYY-MM-DD&babies=1` に渡す。
  受け側は既存の入力に初期値として読む。無ければ既定どおり）**。
  **受け側で `useSearchParams` は使わない**（静的エクスポートでは Suspense 境界とページの CSR 化を招く。
  `tools/` にクエリを読むページはまだ無いので、ここで方式を決めておく）。
  `Calculator.tsx` の `useEffect` で `window.location.search` を読み、`date-parts.ts` の `parseDate()` で
  検証して、不正なら既定値のままにする／育児休業給付・子ども・子育て支援金へのリンク
- 解説：数え方（0週0日の起点・満と数えの違い）・「妊娠◯か月」の数え方（4週＝1か月）・予定日は目安（予定日当日に生まれるのは数%）・FAQ
- **医療上の判断はしない旨を冒頭に置く**（予定日は医師の診断が優先。体調の相談は産婦人科へ）

## やらないこと

- **胎児の大きさ・体重・症状の目安。** 医療情報で、当サイトの守備範囲（お金・日付）を外れる。医師監修が無い状態で書かない
- **基礎体温・月経周期からの排卵日推定。** 周期のばらつきが大きく「予定日」として出すと誤解を生む。
  排卵日は「分かっている場合」の入力にとどめる
- **妊婦健診の費用・出産費用の計算。** 自治体の助成券と病院で違い、データとして持てない。
  出産育児一時金（50万円）は出産手当金ツール側にある
- **出産費用の無償化（分娩費の現物給付）の先取り。** 方向は決まったが施行日は未定。FAQ の1行にとどめる。
  **法律番号は一次資料（e-Gov）で確認できたときだけ書く**（確認できなければ番号を書かない）
- **title・description に医療的な表現を入れない。** 「計算機」に留める（YMYL の医療側に寄せない）
