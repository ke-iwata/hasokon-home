# アスペクト比計算機のSEO強化（逆引き早見表・「変換」クエリ対応）

**状態**：実装済み（2026-08-17。本番反映はタグリリース待ち）
**対象**：`tools/`（`hasokon.com/tools/aspect-ratio/`）
**起票**：2026-08-17

---

## 背景と根拠

### サイト全ツールで最多の表示を集めているのに、クエリと中身が半歩ずれている

GSC（Search Analytics API・直近28日・2026-08-17取得）で、
`tools/aspect-ratio/` は**30表示（掲載順位 48.5）と、ツール系ページで
最多の表示**を集めている。表示が付いているクエリは：

- 「16 9 px」2表示（順位 93）／「16 9 aspect ratio」「16 9 アスペクト比」
  「16 9 比率」「16 9 計算」各1表示
- 「9 16 比率」3表示（順位 89.7）／「9 16 アスペクト比」2表示
- 「1920 かける 1080 比率」1表示（順位 65）
- 「アスペクト比 変換」1表示（順位 79）

共通するのは、**「16:9（9:16）の具体的なピクセル寸法を知りたい」**
**「比率を変換したい」**という意図。現状ページは「幅と高さから比率を
計算する」方向が主で、逆方向（比率からpxの一覧を引く）の受け皿が
用途別早見表（8行）しかない。「変換」という語もタイトル・見出しに
入っていない。検索意図に合わせてこの半歩を埋めれば、既に表示が
出ているぶん、新規ページを作るより早く順位に反映されやすい。

## 提案する仕様（既存ページの拡張のみ。新ページは作らない）

1. **16:9 / 9:16 の逆引き早見表を追加**
   - 幅 → 高さの一覧：640・854・960・1280・1366・1600・1920・2560・3840
     （16:9でよく使う幅を網羅。9:16は同じ表の縦横読み替えを併記）
   - 「16 9 px」「1920 かける 1080」系のクエリの直接の受け皿。
     表はビルド時に静的生成（値のハードコードでよい。比率は不変）
   - 4:3・3:2・21:9 は行数を絞った簡易版を続けて置く
2. **「アスペクト比の変換のやり方」の見出しを追加**
   - 「4:3の画像を16:9にするには（トリミング／余白／引き伸ばしの
     3通りと使い分け）」を短い解説として追加し、
     既存の計算機（比率を保ったサイズ変換）へ誘導する
   - 「アスペクト比 変換」クエリの意図（比率間の変換）に対して、
     現状は「同一比率内のサイズ変換」しか説明していないギャップを埋める
3. **title / description の調整**
   - title：`アスペクト比 計算機・早見表｜16:9のサイズ変換と一覧` の方向で、
     「早見表」「変換」「一覧」を含める（現：`アスペクト比 計算機｜16:9などの
     比率とリサイズ後のサイズ`）
   - description にも「幅から高さの逆引き」「16:9のサイズ一覧」を反映
4. **FAQ追加（2問）**
   - 「16:9で幅1280pxのとき高さは？」（計算式 幅×9÷16 を明示。
     逆引き表への内部アンカー）
   - 「1920x1080はなぜ16:9？」（120で約分する過程を明示。
     「1920 かける 1080 比率」系の受け皿）
5. **registry の `updatedAt` を更新日に変更**（sitemap の lastmod に反映）

### 変更しないこと

- Calculator（計算ロジック）は触らない。`lib/aspect-ratio` のテストも
  そのまま。純粋にページコンテンツとメタデータの強化のみ
- FAQPage / WebApplication / パンくずのJSON-LD構造は既存のまま
  （FAQの項目追加のみ）

## 期待される効果

- 既に表示が出ているクエリ群（合計10表示超/28日）で順位 48〜93 →
  30位台以内を狙う。「早見表・一覧」系は情報ページが上位のため、
  計算機＋一覧の複合ページは差別化しやすい
- ツール系で最多表示のページを伸ばすことは、サイト全体のクリック実績
  （現状28日で5クリック）の底上げに最短距離で効く
- 低リスク：既存機能・計算に手を入れないため、退行の可能性が最小
