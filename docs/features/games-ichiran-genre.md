## 提案する仕様

### A. registry に `genre` を持たせる

`GameDef` に必須の `genre: GameGenre` を足す。値は4つに絞る（多いと見出しだけが並ぶ）。
**ジャンルの定義（見出し・ページ内リンクの `id`・並び順）は registry に1か所で持つ**（例：`GENRES = [{ key: 'trump', label: 'トランプ・花札' }, …] as const`、`GameGenre` はその `key` の型）。
`id` は日本語の見出しから作らず、下の **ASCII の固定値**を使う（実装者ごとに変わらないように）。

| key（`id`） | 見出し | 入るもの（公開中 28 本。**この割り当てで確定**） |
|---|---|---|
| `trump` | トランプ・花札 | ソリティア・スパイダー・フリーセル・ピラミッド・トライピークス・ゴルフ・大富豪・七並べ・神経衰弱・スピード・ダウト・花札こいこい（12） |
| `board` | ボード・テーブル | リバーシ・五目並べ・ヨット（3） |
| `puzzle` | パズル・脳トレ | ナンプレ・ノノグラム・数字つなぎ一筆書き・四角わけパズル・橋かけパズル・マインスイーパー・2048・ヒット＆ブロー・色水ソート・ブロックパズル・麻雀ソリティア（11） |
| `action` | アクション・腕だめし | ブロック崩し・スネーク（2） |

- **麻雀ソリティアは `puzzle`**（2026-11-24 レビュー指摘）。一人で牌を取っていく絵合わせなので、利用者は「パズル」で探す。
  これに合わせて2つ目の見出しは対戦に限らない「ボード・テーブル」にした（ヨットは CPU と遊べるがダイスの卓上ゲーム）
- 4つ目を「アクション」だけにすると、タイピング・福笑いの置き場が無いので「アクション・腕だめし」とした

#### 付録：wip / preview のゲームも4つで足りるか（2026-11-24 の registry で確認）

wip / preview にも `genre` は必須（公開する PR で考え直さないで済むように）。いまの registry では**4つで足りる**。

| key | wip / preview |
|---|---|
| `trump` | ブラックジャック・ハーツ |
| `board` | 詰将棋・はさみ将棋・囲碁・チェス・バックギャモン・マンカラ・四目並べ |
| `puzzle` | 星置きパズル・ターゲット計算パズル・ペグ・ソリティア・ハノイの塔・二角取り・マッチ3パズル・間違い探し・矢印ぬき・数字けし・箱入り娘・ボルダリング合体パズル・熟語パズル（・提案中の15パズル） |
| `action` | ピンボール・タイピング練習・福笑い（目かくしで置く腕だめし） |

5つ目が要るのは「ことば・クイズ」系が3本を超えたとき（熟語パズル・提案中のことばさがし・百人一首かるた）。そのときはジャンルを足す PR を別に出す（ここに書いておく）。

### B. 一覧ページ（`games/app/page.tsx`）

1. リード文の下に**ジャンル目次**を置く：`<nav aria-label="ジャンル">` に `<a href="#trump">トランプ・花札 12</a>`・`#board`・`#puzzle`・`#action` のページ内リンクを4つ（`href` は A の key から作る）。
   横に並ぶチップ（スマホでは折り返し）。**`.quicknav` は使わない**（home の約束とは別物だが、名前の衝突を避ける）
2. ジャンルごとに `<section id="{key}">`（`trump` / `board` / `puzzle` / `action`）と `<h2>`・件数（tools の `.section-title` と同じ組み方）
3. ジャンル内の並びは registry の並び順のまま（「人気順」は計測が薄いので入れない）
4. **スマホ（幅 480px 未満）だけ、カードを2列の小さい形にする**：説明文は出さず名前だけ。デスクトップは今の大きいカードのまま（絵がこのページの売り）
   - **絵の大きさ**：390px 幅で1枚あたり幅 約170px・高さ 約75px（340×150 の比をそのまま縮める。トリミングしない）
   - **潰れないことの確かめ方**：実装 PR で 390×664 のスクリーンショットを全28本ぶん撮り、PR に貼る。ナンプレ・ノノグラム・数字つなぎ・札の数字が
     読めない絵があれば、その絵だけ文字を大きくするか、**その PR ではスマホ2列をやめて1列のまま**にする（見出しと目次だけでも効果はある）
   - **列の指定はインライン `style` から外す。** いまの `gridTemplateColumns` は `page.tsx` のインライン style なので、`@media` で上書きできない（`!important` は使わない）。
     一覧ページのセクションに付けたクラス（例：`.genre-section .game-grid`）で、デスクトップの列指定とスマホの2列を `globals.css` の1ブロックに書く。
     **`.tp-guide` などほかのページの `.game-grid` / `.game-card` には効かせない**（セレクタを一覧ページの section 配下に限る）
   - **card-illustrations.md の決定を games の一覧に限って変える。** [card-illustrations.md](./card-illustrations.md) は「トップは2列（スマホは1列）、絵は幅いっぱい」と決めている。
     games の一覧は28本で、スマホ1列だと約28画面になるため、**games の一覧だけ**スマホ2列にする。実装 PR で card-illustrations.md の該当行に
     「games の一覧（`/games/`）はスマホ2列（games-ichiran-genre.md）」と書き足す。
     tools の一覧はカテゴリが7つあって1つの節が短く、絵が「答えの形」（数字・文字が主役）で縮めると読めないので、スマホ1列のまま揃えない。ホーム（`home/index.html`）も変えない
   - **カードのマークアップ（`a.game-card > div.icon > svg`）は変えない。** `scripts/sync-home-card-art.mjs` が `games/out/index.html` からこの並びを正規表現で拾って
     ホームのカードの絵に写しているので、クラス名・`.icon` の div・SVG の並びを変えると**ホームの絵の同期が黙って欠ける**。
     スマホ2列は CSS だけで行い、マークアップを変えるなら sync スクリプトも同じ PR で直す
5. `publicGames` を通す約束は変えない。**`games` を直に `filter` しない**（ジャンル分けは `publicGames.filter((g) => g.genre === genre)`）

### C. 構造化データ

`@graph` に、ジャンルごとの `ItemList`（`itemListElement` に各ゲームの URL と名前）を足す。
リッチリザルトの対象ではないが、**AI クローラーと Bing が一覧の構造を読み取れる**ようにするのが目的。
JSON-LD のゲーム名・URL は registry から作る（手で書かない）。

### D. テスト（`games/tests/genre.test.ts`）

- registry の全ゲームが4つの `genre` のどれかを持つ
- 一覧に出るゲームの数＝`publicGames.length`（ジャンル分けで落ちたものが無い）。wip / preview が出ない
- 各ジャンルの `id` がページ内リンクの `href` と一致する
- JSON-LD の `ItemList` の URL 数＝`publicGames.length`
- **ホームの絵の同期が壊れていない**：tools・games をビルドしてから `node scripts/sync-home-card-art.mjs` を回して `home/index.html` に差分が出ない。
  `scripts/test/home-card-art.test.mjs` が通る

### やらないこと

- **絞り込み・検索ボックス・並べ替え UI。** 28本なら見出しと目次で足りる。60本を超えたら考える（ここに書いておく）
- **「人気」セクション。** PV の差が小さく、毎回入れ替えると一覧の `lastmod` が動いて IndexNow が騒ぐ
- **ジャンル別の一覧ページ（`/games/trump/` など）を新しく建てる。** 薄いページが増えるだけ。見出しで足りる
- ゲームページ下部の「他のゲーム」を同じジャンルで出す — 効きそうだが**別提案**（tools の [related-tools-topical.md](./related-tools-topical.md) の結果を見てから）
- home（`home/index.html`）のゲームの節の並べ替え。home にはビルド工程が無いので、別に考える
