## 背景と根拠

### スライド系パズルの需要が伸びていて、客層がこのサイトの強い型と合う

- Sensor Tower の集計（4Gamer 2026-06-23 https://www.4gamer.net/games/999/G999904/20260623012/ ）で、
  **日本のソート系・スライド系パズルの DL は 1年で 1.5倍**（2025年1〜4月 1,000万未満 → 2026年同期 1,500万超）、
  利用者の **40〜50% が 45歳以上**。マイベストのパズルアプリ上位（2026-09）にもブロックスライド型が複数入る
- GA4（プロパティ 548154955、2026-09-04〜09-17、2026-09-18 取得）で、games の滞在が長いのは
  **マインスイーパー 4,713秒・大富豪 6,196秒・ブロックパズル 3,193秒・花札 2,708秒**。
  「手を動かして整える」型（色水ソート 222秒）より **「盤面を見て考える」型**のほうがこのサイトでは長く遊ばれている。
  箱入り娘は「見て考える」と「指で動かす」の両方を持つ
- games 26本（main の registry。2026-09-18）のうち、**スライドして動かすパズルは無い**（ブロックパズルは「置く」、2048 は「盤全体を寄せる」、
  15パズルも無い）。ジャンルの空白を 1本で埋める

### 権利関係は無害（ルールは 100年以上前の古典）

- 英語圏で **Klotski**、中国で **華容道**、日本で **箱入り娘**と呼ばれるスライドブロックパズル。
  L. W. Hardy の「Pennant Puzzle」の米国特許は 1907年出願（1909年）で、**特許・意匠はとうに切れている**。
  日本で広まったのは 1935年ごろ（Wikipedia「箱入り娘 (パズル)」 https://ja.wikipedia.org/wiki/箱入り娘_(パズル) ）。
  木製の市販品・アプリ・ブラウザ版が多数共存するジェネリックなルールで、**ルール自体は著作権で保護されない**
  （ブロックパズル・2048・色水ソートと同じ整理）
- **駒の名前（娘・父・母・番頭・丁稚 など）と 4×5 の標準配置は伝統的なもの**で、特定社のものではない。
  ただし市販品のパッケージ絵・木目・書体・特定アプリの画面はなぞらない。駒は当サイトのトーンで
  色と文字だけの平面にする
- **「箱入り娘」の名称**：パズルの一般名として辞書（Weblio）・Wikipedia に載っており記述的だが、
  玩具の区分で商標登録がある可能性は排除できない。**実装着手前に運営者が J-PlatPat で確認**し（状態行）、
  登録があれば名称「娘を外に出すスライドパズル」・slug `slide-out-puzzle` に**切り替えてから**着手する
  （`name`・slug・`home/`・ページ文言。二角取りで「slug を先に切って公開後に動かせなくなる」順序違いを
  経験しているので、ここは着手前に済ませる）。
  英語名「Klotski」も使わない（外国での登録状況を追えないため）

## 提案する仕様

### ルール（伝統的な標準形）

- 盤は **横4 × 縦5**。下辺の中央 2マスが出口
- 駒 10個：**娘（2×2）1個**・**縦長（1×2）4個**・**横長（2×1）1個**・**小（1×1）4個**。
  標準配置は「娘が上中央、縦長が両脇、横長がその下、小 4個が下」（Wikipedia の図と同じ）
- 駒は空いているマスへ**上下左右にスライド**（跳び越し・回転なし）。
  **娘を出口まで下ろしたらクリア**
- **手数の数え方：駒 1つを 1回動かす＝1手。** スワイプ（ドラッグ）1回＝1手で、空きが続く限り
  1回で複数マス動かしてもまとめて 1手。スワイプは一方向なので**角を曲がる移動は 1手にならない**
  （縦に動かしてから横に動かすのは 2手）。
- 標準配置の最短手数は**この定義で BFS ソルバーが出した値**を使い、盤面データに書き込む。
  **確定値（81 など）を仕様・テスト・ページ文言に先に書かない。** 文献の「81手」は
  「駒ごとに数え、角を曲がる移動も 1手」という別の定義の値（en.wikipedia「Klotski」・Martin Gardner 1964）で、
  当サイトの定義とは一致しないことがある。ページの解説には「文献では駒ごと（角を曲がるのも 1手）の
  数え方で 81手とされる。このゲームでは 1方向の移動を 1手と数えるので最短は◯手」と、**出典つきで両方の
  定義を併記**する（「箱入り娘 81手」の検索はこれで拾う）

### レベル

`lib/hakoiri-musume.ts` に **盤面データ**として持つ（章をデータで持つ learn と同じ考え方）：

| レベル | 内容 | 目安の最短手数 |
|---|---|---|
| はじめて | 娘が出口の近くにある簡単な配置 3面（20手以内） | 10〜20 |
| 標準 | 伝統的な標準配置 1面 | ソルバーの値（当サイトの数え方） |
| むずかしい | 駒の種類・数は同じで配置だけ変えた 6面 | 標準より多い（ソルバーで選ぶ） |

- **全レベルの最短手数は、実装時に `lib/` の BFS ソルバーで計算して盤面データに書き込み、
  テストで「ソルバーの結果とデータの値が一致する」を固定する**（手で数えた値を信じない）。
  BFS の状態遷移は**「駒ごとに、その駒が 1方向に到達できる各位置」を 1手**として列挙する
  （上の数え方と同じ。1マスずつの遷移で回すと別の最短値が出る）。
  同種の駒を区別しなければ標準配置から到達できる状態は数万程度で、BFS はテスト内で 1秒以内に終わる
- 「はじめて」「むずかしい」の配置は、実装時に**ソルバーで解けることを確認したものだけ**入れる。
  解けない・娘が既に出口にあるデータは `tests` が落とす
- **むずかしい 6面は、開発時に候補の配置を複数作ってソルバーで最短手数を測り、標準配置より多いものを
  選ぶ**（手探りで作らない。実行時の自動生成はしない）
- 配置は自前で作る（他サイト・書籍の問題集からの転記はしない。伝統的な標準配置 1面だけは公有）

### 操作（スマホ・PC の両方。games/CLAUDE.md の「画面の約束」どおり）

- **ドラッグ（PC）／スワイプ（スマホ）で駒を動かす。** 指を離した位置ではなく
  **動かした方向**で判定する（ずれに強い）。1回のスワイプで空きが続く限りその方向に動き、
  **何マス動いても 1手**（上の数え方と一致させる）
- タップで駒を選び、動かしたい方向の空きマスをタップして動かす、も併用（ドラッグが苦手な人向け。こちらも 1回＝1手）
- **「1手もどす」**（履歴はゲーム内で保持。無限）と**「最初から」**
- 手数と最短手数を常に表示（「23手 ／ 最短 ◯手」。最短は盤面データの値）。**ヒントは出さない**（最短の 1手を光らせると
  解く楽しさが消える。要望があれば次版で「次の 1手」を有料級の機能として検討）
- 駒の移動はアニメーション（100〜150ms）。**演出は `Game.tsx` の ref に置き、`lib/` の状態に入れない**
  （画面の約束 9）

### 画面

- 盤は縦長（4:5）なので、画面の約束 2 の式（正方形前提）を縦長に合わせる：盤に `aspect-ratio: 4 / 5` を付け、
  **幅の上限を高さから逆算する** —
  `max-width: min(var(--board-max), calc((100dvh - var(--chrome)) * 4 / 5))`（`globals.css` に書く。
  `Game.tsx` からインラインで渡さない）。標準の 390×844 でレベル選択・手数・盤・ボタン 2つが 1画面に収まること
- **駒の表示は「娘だけ『娘』の 1文字、他の駒は色と形（縦長・横長・小）だけ」に決める。**
  同じ形の駒は遊ぶうえで区別する必要がなく、44px の小駒に文字を載せなくてよい。
  伝統的な呼び名（父・母・番頭・丁稚など）は盤上に出さず、解説の「箱入り娘とは」に歴史として書く
  （検索語はそこで拾う）。押す先は 44px を割らない（1マスが 44px 以上になるよう盤の下限を決める）
- クリア画面：手数・最短との差・記録（`games/lib/records.ts`：`plays` / `wins` / `bestMoves`・`bestTimeMs`。
  レベルごとの区分は `variant`）。`Improved.moves` で「ベスト更新！」
- 設定（レベル）は畳まない（画面の約束 5）

### ページ構成

- `app/hakoiri-musume/page.tsx`：`metadata` に `robots: robotsFor('hakoiri-musume')`。JSON-LD は
  `VideoGame` + `BreadcrumbList`（既存ゲームと同じ）
- 解説（h2）：「箱入り娘とは（1900年代からの古典。中国では華容道と呼ばれる同じルール）」
  ※**英語名は併記しない**（下の「やらないこと」が優先。2026-09-18 のレビューで確定）「遊びかた」
  「標準配置の最短手数（当サイトの数え方の値と、文献の 81手の定義を出典つきで併記）」「コツ（娘の下に横長を通す・小駒を角に集める）」
- `lib/registry.ts`：`icon` は `GameIcon.tsx` に新しく足す（例：`SlidingBlocks`。4×5 の枡に 2×2 の駒を描く）、
  `stage: 'wip'`。ブロックパズル・色水ソート・2048 と相互リンク

### テスト（`games/tests/hakoiri-musume.test.ts`）

- 駒は空きマスへしか動かない・盤外に出ない・重ならない
- 娘が出口に着いたときだけクリア
- BFS ソルバー：遷移が「駒 1つを 1方向に到達できる位置まで＝1手」になっている（1マス移動と複数マス移動が同じ 1手）。
  全レベルの `minMoves` がソルバーと一致し、全レベルが解ける（**81 のような確定値は書かない**）
- もどす：直前の状態に戻る。最初からで初期配置に戻る
- 記録：クリア時に `moves` を渡し、`bestMoves` が小さいほうで更新される（`games/lib/records.ts` の既存テストの型で）

## やらないこと

- **ヒント（次の 1手）。** 解く楽しさが消える。手数と最短の差だけ出す
- **盤面の自動生成。** ランダム配置は解けない・つまらないものが多く、面白い配置は人が作る。
  10面をデータで持つ。要望があれば面を足す
- **15パズル（数字のスライド）を同居させる。** 別のゲーム。要望があれば別ページ
- **他サイト・書籍の問題集からの配置の転記。** 標準配置以外は自前で作る
- **英語名「Klotski」の併記。** 外国での商標を追えない
- **タイムアタック。** 手数の少なさが本質。時間は記録に残すだけで競わせない
