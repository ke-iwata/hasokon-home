# 全ゲームに記録（ベスト・勝敗・クリアタイム）を揃える

**状態**：提案（2026-08-13）
**対象**：`games/`（全10ゲーム）
**起票**：2026-08-13

---

## 背景と根拠

### 記録が残るゲームと残らないゲームが混在している

`grep -rln "localStorage" games/app games/lib`（2026-08-13 実施）の結果、
プレイ記録を保存しているのは **10本中4本だけ**。

| 記録あり | 記録なし |
|---|---|
| 2048（ベストスコア）・リバーシ・ノノグラム・フリーセル | **ソリティア・スパイダー・マインスイーパー**・ナンプレ・麻雀ソリティア・ブロック崩し |

問題は、**「記録なし」側にアクセス上位のゲームが集中している**こと。
GA4（2026-08-13 取得 / GA4 Data API `runReport`、`properties/548154955`）の
直近28日のページビューは、ソリティア系35・マインスイーパー39・スパイダー35で、
ゲーム中トップ3がすべて記録なし側にある（新旧パス合算。
[ga4-page-path.md](./ga4-page-path.md) の重複期間のため合算で数えた）。

### なぜ記録が滞在時間・再訪に効くか

games/docs/DECISIONS.md は「ゲームは滞在時間がそのまま価値になる」と定義している。
ソリティア・マインスイーパーのような定番ゲームは他サイトでいくらでも遊べるので、
**「自分の記録がここにある」ことが、このサイトで遊び続ける数少ない理由になる**。
勝率・ベストタイムは「もう1回」の動機そのもので、
定番ゲームサイト（Solitr・Minesweeper Online 等）はほぼ例外なく統計を持っている。

## 現状

- ソリティア・スパイダー・マインスイーパー・ナンプレ・麻雀ソリティア・ブロック崩しは、
  クリアしても何も残らない。リロードすると痕跡が消える
- 記録を持つ4本も実装がバラバラ（キー名・保存形式が各ゲームの `Game.tsx` 内に直書き）

## 提案する仕様

### 共通モジュール

`games/lib/records.ts` を新設する（純関数＋薄いストレージ層）。

- キーは `hasokon-games:records:<gameId>:v1` に統一。値はJSON
  （`plays`・`wins`・`bestTimeMs`・`bestScore`・`bestMoves` のうちゲームが使うものだけ）
- SSR・`localStorage` 不可（プライベートモード等）でも落ちないよう
  try/catch で包み、読めなければ「記録なし」として動く
- 既存4本の旧キーは初回読み込み時に新形式へ移行する（読めたら移して旧キーを消す）

### 各ゲームへの組み込み

| ゲーム | 残す記録 |
|---|---|
| ソリティア・スパイダー・フリーセル・麻雀ソリティア | 勝利数／プレイ数・ベストタイム・（あれば）最少手数 |
| マインスイーパー | 難易度別ベストタイム・勝率 |
| ナンプレ・ノノグラム | 難易度別ベストタイム・クリア数 |
| 2048・ブロック崩し | ベストスコア（現状の2048の記録は移行） |
| リバーシ | 対CPU戦績（現状の記録は移行） |

表示は2箇所：盤面上部の小さな帯（例「ベスト 2:41」）と、
クリア／ゲームオーバー画面（今回の結果とベストの比較。ベスト更新時は明示）。

### テスト

`games/tests/records.test.ts` — 保存・読み出し・旧キー移行・壊れたJSONの無視・
ストレージ不可時のフォールバックを網羅する。

## 期待される効果

- 再訪の動機づけ。GA4の**リピーター率**と**平均エンゲージメント時間**
  （とくに `/games/solitaire/`・`/games/minesweeper/`・`/games/spider/`）を
  導入前後4週間で比較する
- 実装の統一により、今後の新ゲーム（例：[game-block-puzzle.md](./game-block-puzzle.md)）は
  `records.ts` を呼ぶだけで記録がつく

## 工数の見積り

- 実装1セッション。消費トークンの目安：**6万〜10万**
  （共通モジュール＋テストで2〜3万、6ゲームへの組み込みで3〜5万、
  既存4ゲームの移行で1〜2万）
- ゲームロジックには触らない（クリア判定のコールバックに1行足すのが基本形）

## やらないこと

- **サーバー側への記録・ランキング** — アカウントも API も持たない方針
  （静的配信のみ）のため。端末内で完結させる
- **プレイ履歴の時系列グラフ** — まず集計値だけ。需要が見えたら検討
- **ブロック崩しへのタイム記録** — スコア型のゲームにタイムは馴染まない。
  ベストスコアのみ
