## 背景と根拠

### 「かわいい皮をかぶせた純ロジックパズル」が 2026年の当たりの型

- App Store 日本・無料パズル（2026-09-19、m-s-y.com 集計）：**1位 Meowdoku!**（星置き＝Queens 型）、
  4位 ブロックブラスト、7位 漢字分解パズル。Google Play 日本・無料ゲーム（Similarweb 09-16）：
  **10位 NYT Games（Wordle・Crossword）**、18位 Meowdoku、30位 Color Logic
- LinkedIn の日替わりパズル群では、**Queens（星置き）に次いで遊ばれているのが Tango**
  （○と×を並べる 6×6 のバイナリーパズル）。攻略サイトが毎日答えを載せるほどの定着
  （pinpointdaily.org ほか）。**同ルールの古典が「バイナリーパズル（Binairo / Takuzu）」で、
  2009年から新聞のパズル欄にある**
- 当サイトの Bing 流入が付いている論理パズル：ナンプレ・ノノグラム・マインスイーパー
  （下記「計測値」）。**同じ客層の 3本目**を、既存の盤 UI（`mobile-one-screen.md` の
  高さ規則・タップ操作）で出せる

### ルール（一般に流通している形。出典：puzzle-binairo.com・LinkedIn Tango のヘルプ）

1. 各マスに ○ か × を置く（偶数辺の正方形。6×6・8×8・10×10）
2. **各行・各列で ○ と × の数が同じ**
3. **同じ記号を縦横に 3 つ以上並べない**
4. （古典の追加則）同じ並びの行・列を作らない
5. （Tango 型の追加則）マスとマスの間に **＝**（同じ記号）・**×**（違う記号）の印がある場合はそれに従う

当サイトは **2・3・5 を採用し、4 は採らない**（4 は解く手がかりとして弱く、初心者が気づけない。
Tango も 4 を持たない）。印（5）は 8×8 以上の「むずかしい」で使う。

### 名称と権利（2026-09-19 企画レビューで決定）

- **主名称は「バイナリーパズル」、○× は説明に回す**（ページ名「バイナリーパズル（○×で埋めるロジックパズル）」）。
  初版の「○×パズル」は、日本語で「○×ゲーム」が三目並べ、「○×」が正誤クイズを指すのが普通で、
  検索意図（「バイナリーパズル 無料」）に 1 文字も当たらず、既存の五目並べとも紛れるため取り下げた
- **権利の整理**：**ゲームのルール・遊び方それ自体に著作権は及ばない**（印つきの規則 5 は古典には無く
  Tango の特徴だが、採用してよい理由はこれ。「古典だから」ではない）。名称と盤面データを自前にすれば
  権利面はこれで足りる。「Binairo」（ベルギーの作者の名称）「Takuzu」（フランスの出版名）
  「Tango」（LinkedIn の名称）は **使わない**。説明文で「Binairo・Takuzu とも呼ばれる」と触れるのは可
- **調べた範囲（2026-09-19）**：ニコリの[パズル一覧](https://www.nikoli.co.jp/ja/business/puzzle_list/)・
  [著作権・登録商標](https://www.nikoli.co.jp/ja/copyright/)にこのパズルは無い。Android アプリ
  「バイナリパズル - 0と1だけのナンプレ」（applion.jp）がこの名前で流通しており、記述的な一般名として
  使われている。**J-PlatPat の商標検索は未実施**（上記のとおり運営者作業。結果をこの節に 1 行残す）

## 提案する仕様

### 日替わり・共有・連続日数の基盤は #232 が持ち主（本提案は使う側）

[game-hoshioki-puzzle.md](./game-hoshioki-puzzle.md)（#232）が **日替わり基盤の持ち主**と決めた：
`records.ts` の `RecordEntry` に `lastClearedOn` / `streak` を足し、`games/lib/daily.ts` に
日付シードの PRNG（`mulberry32`）と連続日数の計算を切り出し、`game-records.md` を改訂する。
本提案は **その基盤が main に入ってから着手**し、`daily.ts` と `variant: 'daily'` をそのまま使う。
基盤の仕様（「今日」は端末のローカル日付、結果コピーに答えを入れない、`DAILY_GENERATOR_VERSION`）は
#232 側に書いてあり、ここでは繰り返さない。**共有文の形式も #232 の基盤 PR で決める**
（初版の「`game-records.md` に共有文の形式を 1 節足す（別 PR）」はそちらに合流）。

### 盤面と操作

- サイズ：**6×6（かんたん）・8×8（ふつう）・10×10（むずかしい・印つき）**。既定は 6×6
- タップで **空 → ○ → × → 空** を巡回。長押し（PC は右クリック）で逆順。
  ドラッグで同じ記号を連続配置（ノノグラムと同じ）
- **違反の即時表示**：3 連続・数の超過・印の不一致を、該当する行・列・マスを赤で示す。
  ペナルティは無し（トレンド作の「間違えても減らない」に合わせる）
- **ヒント**：「次に確定できるマス」を 1 つ光らせ、**理由を 1 行で出す**
  （例：「この行は ○ があと 1 つ。ここに置くと 3 連続になるので ×」）。Meowdoku がいちばん褒められている点
- 元に戻す／やり直す／盤面リセット。タイマー表示（消せる）

### 生成器（`games/lib/binary-puzzle/`）

1. バックトラックで制約を満たす完成盤を作る
2. マスをランダムに空けていき、**一意解ソルバ**（伝播：3 連続禁止・数の上限・印 ＋ 詰まったら二分探索）が
   一意でなくなる直前で止める（ナンプレの `generatePuzzle()` と同じ骨格）
3. 難易度は「解くのに二分探索が要るか」と空きマス数で分ける。**むずかしいは伝播だけで解けない盤**
4. **一意解であることをテストで保証**（生成 200 盤×3 サイズ、CI で 10 秒以内。ヨットの
   #160 の教訓で、テスト時間の上限を先に決める）
5. 日替わり 1 問：`daily.ts` の日付シードで 1〜4 を決定論的に回す（基盤は #232）

### 共有・記録

- クリア時に「バイナリーパズル 6×6 2:31 🔥3日目」のような**ネタバレにならない結果テキスト**をコピー
  （盤面の絵は入れない。#232 と同じ理由）。X・LINE の intent リンク
- 連続日数は `records.ts` の `streak`（#232 の拡張）。`variant` は `easy` / `normal` / `hard` / `daily`

## やらないこと

- **日替わり・連続日数・共有文の基盤をこの提案で作る**：#232 の担当（上記）
- **#232 と並行して着手する**：`wip` の在庫が増えると、公開時のホームのカード・`llms.txt`・`404.html` の
  運用作業もまとめて増える。パズルは時期の価値が無いので、基盤 → #232 → 本提案の順で 1 本ずつ
- **漢字分解パズル**（App Store 7 位）：機構は自由だが、**良い問題を人手で選ぶコストが本体**
  （漢字の部品分解データ CHISE/KanjiVG から自動生成すると、正解が文字として不自然なものが混ざる）。
  データ整備に 100k 超が要り、ゲームというより出題集の編集になる。次回以降の候補
- **ひらがなの単語当て（Wordle 型）**：単語リストの編集と濁点・小書きの扱いが設計の本体で、
  既存の「ことのはたんご」が定着している
- **矢印ぬきパズル・砂ブロック**：どちらも流行中だが、前者は 3D 表現、後者は砂シミュレーションが
  スマホで重い
- **同じ並びの行・列を禁じる古典則（4）**：上記のとおり
- **対人・対 CPU**：一人で解くパズルなので無し
