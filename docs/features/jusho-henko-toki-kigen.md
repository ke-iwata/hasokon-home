## 背景と根拠

### 2026-04-01 から、住所・氏名が変わったら 2 年以内の変更登記が義務になった

法務省「住所等変更登記の義務化について」（https://www.moj.go.jp/MINJI/minji05_00693.html、2026-10-02 確認）：

| 項目 | 内容 | 根拠 |
|---|---|---|
| 義務の内容 | 不動産の所有者（所有権の登記名義人）は、**氏名若しくは名称又は住所に変更があったときは、変更日から 2 年以内**に変更の登記を申請する | 不動産登記法 76 条の 5 |
| 施行日 | **令和 8 年（2026 年）4 月 1 日** | 令和 3 年法律第 24 号 |
| 施行前の変更 | 施行日より前に変更していて未登記のものも対象。**令和 10 年（2028 年）3 月 31 日まで**に登記する | 同法附則 |
| 過料 | 正当な理由なく怠ると **5 万円以下の過料** | 不動産登記法 164 条 2 項 |
| 正当な理由の例 | 行政区画の変更、重病、DV 等で避難中、経済的困窮 など（法務省の案内に列挙） | 同ページ |
| 職権による登記 | 自然人は**検索用情報の申出**（いわゆるスマート変更登記。2025-04-21 以降の所有権の登記で申出）、法人は会社法人等番号の登記があれば、法務局が住基ネット等で変更を確認し、**本人への確認を経て職権で**変更登記をする。法務省の案内は、申出がされている場合を「正当な理由」の例に挙げている。**この効果の言い回し（職権登記で義務を果たしたことになるのか、義務違反にならないのか）は、実装時に法務省の案内の該当箇所を引用し、確認日を本仕様書に書いてから本文に載せる**（#316 レビュー必須 1。2026-10-02 時点では案内の要約で、原文の引用は未取得） | 不動産登記法 76 条の 6 |
| 対象の不動産 | 持っている**すべての不動産**（土地・建物・マンションの敷地権付き区分建物）。管轄の法務局が複数なら複数に申請 | — |
| 登録免許税 | 不動産 1 個につき 1,000 円（**実装時に e-Gov で登録免許税法 別表第一を確認する**） | 登録免許税法 |

### 検索は「2 年以内」より「自分はいつまで」で、記事は期限を数えてくれない

- 施行の 2026-04 に士業・不動産メディアの解説記事が一斉に出た（2026-10-02 の Web 調査で上位は法務省・司法書士事務所・住宅メディア）。
  内容は「変更日から 2 年」「施行前は 2028-03-31 まで」「過料 5 万円」の 3 点で揃っていて、**自分の引っ越し日を入れて期限を出す
  ツールは見当たらなかった**。相続登記（[sozoku-toki-kigen.md](./sozoku-toki-kigen.md) の「競合」）と同じ構図
- 実際に迷うのは「引っ越しが 2 回」「結婚で姓が変わり、同じ年に引っ越した」「施行前の引っ越しをまだ登記していない」の組み合わせで、
  **期限が複数立つ**。記事は 1 本の期限しか書かない
- 「スマート変更登記（検索用情報の申出）をすれば自分で申請しなくていい」という理解が広まりつつあるが、申出ができるのは
  **2025-04-21 以降に所有権の登記（購入・相続）をしたときに同時に**で、それ以前から持っている不動産は**別途の申出が要る**
  （法務省の案内）。ここを間違えると「申出済みのつもり」で期限を過ぎる

- 相続登記（`preview`）・贈与税（`preview`）・住宅取得等資金（提案）・住宅ローン控除（`wip`）と、**「不動産を持つ・もらう」の

- 2027-01〜03 の相続登記の検索期に、「相続で登記したあと、引っ越しの住所も直す」導線で受けられる
- 計測値（2026-10-02 取得、GA4 28 日）：期日型の既存ツールは 最低賃金 102・酒税 115・たばこ 269 の着地。
  同じ「期日のある改正」の型で、相続登記の提案が目標にした **公開 8 週で 50 セッション / 28 日** を本ツールの目標にも置く

### 法的リスク（司法書士法）

- 期限と要件の**一般的な説明と日付の計算**にとどめる。**個別の登記申請書類の作成・代理は司法書士の独占業務**（司法書士法 3 条・73 条）
  なので、「あなたの申請書はこう書く」は出さない。相続登記の仕様書の「法的リスク」と同じ線
- 「過料になる／ならない」は書かない。法務省の説明どおり「登記官の催告 → 裁判所が判断」の順で書く（相続登記の文面を流用）

## 提案する仕様

### 画面（1 画面 2 段）

**上段：期限の計算**

入力（既定値で埋めて「入れたら変わる」型）：

1. **変わったのは**：住所（引っ越し）／氏名（結婚・離婚など）／両方（ラジオ。既定「住所」）
2. **変わった日**：日付。既定は空（入れないと結果を出さない）。転入届の日ではなく**実際に住所が変わった日**（住民票の「住所を定めた日」）と注記
3. **その前にも、登記していない変更がありますか**：いいえ／はい（はいなら**いちばん古い未登記の変更日**を追加で入れる。既定「いいえ」）
4. **検索用情報の申出（スマート変更登記）または会社法人等番号の登記は済んでいますか**：いいえ／はい／分からない（既定「分からない」）

出力：

- **期限日と残り日数**（「2028 年 3 月 31 日まで、あと 546 日」）。根拠を 1 行：「2026 年 4 月 1 日より前の変更なので、経過措置の期限です（附則）」
  または「変更日から 2 年の応当日です（76 条の 5）」
- 入力 3 が「はい」のときは**期限を 2 行出し、早いほうを太字**にする。注記：「**最新の住所で 1 回登記すれば、途中の住所の登記は要りません**
  （中間の変更を省略して現在の住所へ直接変更できる扱い。**実装時に法務局の案内で確認し、確認日を仕様書に書く**）。
  ただし期限は**いちばん早いもの**が先に来ます」
- 入力 4 が「はい」：**期限日と残り日数は消さずにそのまま出し**、その下に「法務局が職権で変更登記をする対象です。職権登記は法務局から
  本人への確認を経て行われ、**応答が無ければ登記されません**。法務局からの通知に応答してください。期限までに職権登記がされない場合に備えて、
  期限は上のとおり把握しておいてください」。**「申出をしていれば何もしなくていい」「正当な理由として扱われる」とは書かない**
  （#316 レビュー必須 1。効果の言い回しは法務省の案内の原文を実装時に引用・確認してから確定する。上記「法的根拠」の表）。
  「分からない」：「2025 年 4 月 21 日より前に取得した不動産は、申出をしていない可能性が高いです。登記識別情報通知や法務局の案内で確認してください」
- 入力の検証（相続登記の `validateInput()` / `INPUT_ERROR_MESSAGES` と同じ作法）：変わった日が**未来の日付**なら
  「変わった日は今日以前の日付を入れてください」、「前の未登記の変更日」が**今回の変更日より後**なら「前の変更日は今回より前の日付を入れてください」。
  エラー中は結果を出さない
- 期限を過ぎている場合（そのまま画面に出す）：「**期限を過ぎています。法務省の説明では、登記官から催告書が届き、その期限内に申請がないと
  裁判所へ通知されます。過料になるかどうかは裁判所が決めます。**」（相続登記と同じ文面。「過料になる／ならない」は書かない）

### 計算ロジック（`tools/lib/jusho-henko-toki.ts`。純関数のみ）

```ts
import { addMonthsSameDay, daysLeft } from './sozoku-toki-kigen';

/** 【データ更新箇所】相続登記の同名定数（GIMUKA_START など）と同じファイルで import しても紛れないよう JUSHO_ を前置する */
export const JUSHO_GIMUKA_START = '2026-04-01';          // 不動産登記法 76 条の 5 施行
export const JUSHO_KEIKA_SOCHI_DEADLINE = '2028-03-31';  // 施行前の変更の経過措置
export const JUSHO_TOKI_MONTHS = 24;                     // 変更日から 2 年
export const JUSHO_KARYO_MAX_YEN = 50_000;               // 164 条 2 項
export const TOROKU_MENKYO_PER_PROPERTY = 1_000;         // 登録免許税（実装時に確認）
export const SEARCH_INFO_FROM = '2025-04-21';            // 検索用情報の申出の開始日
export const JUSHO_DATA_CHECKED_AT = '2026-10-02';

export function tokiDeadline(changedOn: string): { deadline: string; basis: 'principle' | 'transitional' };
export function earliestDeadline(changes: string[]): { deadline: string; basis: ...; of: string };
export function torokuMenkyo(count: number): number;
```

- `changedOn < JUSHO_GIMUKA_START` なら `transitional`（2028-03-31）、それ以外は `addMonthsSameDay(changedOn, 24)`
- `validateInput(changedOn, earlierChangedOn?, today)` → `'future' | 'order' | null` と `INPUT_ERROR_MESSAGES`（上記「画面」の 2 文）
- **祝日データ `HOLIDAYS` は 2027 年まで**で、本ツールの期限は 2028〜2030 年に落ちる。登記の期限は相続登記と同じく額面の日付を出し
  「末日が土日祝のときの扱いは法務局に確認」と**常に**注記する設計なので、2028 年以降の祝日が無くても困らない（繰り下げ計算をしない）。
  実装で `HOLIDAYS` を参照しないこと（参照すると 2028 年以降で黙って平日扱いになる）
- **施行日より前の変更日 ＋ 2 年が 2028-03-31 より後になることは無い**（2026-03-31 ＋ 2 年 ＝ 2028-03-31）ので、
  経過措置は「遅いほう」ではなく「施行前なら一律」でよい。テストで境界（2026-03-31 → 経過措置、2026-04-01 → 2028-04-01）を押さえる
- 応当日が無い日（2 月 29 日）は月末。**2028-02-29 に変わった → 2030-02-28** をテストに入れる

## やらないこと

- **登記申請書の作成支援・書式の出力。** 司法書士の独占業務に触れる。「必要な書類」の表までにとどめる
- **司法書士報酬の相場。** 費用の比較サイトが厚く、本ツールの主題（期限）から外れる
- **法人の名称・本店変更。** 義務の対象ではあるが、法人は会社法人等番号の登記で職権登記に乗るのが通常で、個人向けの検索意図と違う。
  FAQ で 1 問だけ触れる
- **職権登記の進捗の確認。** 法務局の通知の有無は当サイトから分からない。「通知に応答してください」までにする
- **「過料になる／ならない」の判定。** 相続登記と同じ線
- **DV 等の正当な理由の個別判定。** 法務省の例を列挙するだけにとどめ、避難中の方の住所を入力させる導線は作らない（入力は日付だけで住所は要らない）
