# 傷病手当金 計算機に「通算1年6ヶ月」の支給期間上限を入れる

**状態**：提案（未実装）
**対象**：`tools/lib/shobyo-teate.ts`・`tools/app/shobyo-teate/Calculator.tsx`・`tools/tests/shobyo-teate.test.ts`
**起票**：2026-08-13

---

## 背景と根拠

### 症状：ページの本文が書いている上限を、計算だけが守っていない

`/tools/shobyo-teate/` は**支給期間の上限が通算1年6ヶ月であることを本文で2箇所説明している**。

`tools/app/shobyo-teate/page.tsx` の見出し（111行目）と本文（113行目）:

> ## 支給期間は「通算」1年6ヶ月
>
> 支給期間は支給開始日から**通算1年6ヶ月**です。2022年1月の制度改正で、
> それまでの「支給開始から暦の上で1年6ヶ月」から
> 「支給された期間を通算して1年6ヶ月」に変わりました。

同ページのFAQ（32行目）にも同じ説明がある。
`tools/lib/shobyo-teate.ts` の冒頭コメント（10行目）にも一次情報として書いてある。

> \* - 支給期間は支給開始日から通算1年6ヶ月（2022年1月改正で「通算」に変更）

**にもかかわらず、計算にこの上限が一切入っていない。**
`calcShobyoTeate()` の支給対象日数はこうなっている（`tools/lib/shobyo-teate.ts`）。

```ts
// 待期3日間（最初の連続3日）は支給されない
const payableDays = Math.max(0, restDays - TAIKI_DAYS);
```

上限で頭打ちにする処理が無い。`Calculator.tsx` の入力欄にも `max` が無く、
`min={0} step={1}` だけである（33〜43行目）。
リポジトリ全体を `1年6|546|18ヶ月|通算` で検索しても、
ヒットするのは page.tsx の本文2箇所と lib の**コメント1箇所だけ**で、
計算コードにもテストにも1件も無い。

### 計測値：どれだけずれるか（2026-08-13、コードを追って算出）

平均月収30万円のとき、`GRADES`（`tools/lib/shaho-grades.ts` 46行目、22等級）から
標準報酬月額は 300,000円。ここから

- 標準報酬日額 = `Math.round(300000 / 30 / 10) * 10` = **10,000円**
- 日額 = `Math.round(10000 * 2 / 3)` = **6,667円**

| 入力した休業日数 | 支給対象日数 | 表示される支給総額 | 制度上の上限 | 差 |
|---|---|---|---|---|
| 30日 | 27日 | 180,009円 | （上限内） | 0円 |
| 730日（2年） | **727日** | **4,846,909円** | 546日 = 3,640,182円 | **+1,206,727円**（約33%過大） |

**2年休んだと入力すると、制度上ありえない2年分の金額をそのまま表示する。**
同じページが「上限は1年6ヶ月です」と説明している真下で、である。

### なぜこれが実害になるか

傷病手当金を調べる人は「**いつまで・いくらもらえるか**」で生活設計をする。
長期療養（がん治療・メンタル不調・難病）が想定される人ほど長い日数を入れるので、
**過大表示を踏むのは、いちばん切実に金額を知りたい層**である。

- 1年6ヶ月を超える見込みの人にとって重要なのは「いつ支給が終わるか」であり、
  そこが**このツールでは絶対に分からない**（むしろ終わらないかのように出る）
- 120万円の過大は、傷病手当金が切れた後の障害年金・退職の判断を誤らせる
- YMYL領域なので、金額を間違えるページは検索評価の面でも不利になる

`docs/features/zaishoku-rorei-nenkin.md` が指摘した「62万円と65万円で結論が逆になる」問題と
同じ構造だが、**あちらは他所の記事の誤り、こちらは自サイトの誤り**という違いがある。
外の間違いを正す前に、自分のページの本文と計算の食い違いを直すほうが先である。

## 何を作るか

### 1. `lib/shobyo-teate.ts` に上限日数を持たせ、支給対象日数を頭打ちにする

```ts
/**
 * 支給期間の上限日数（通算1年6ヶ月）。
 *
 * 令和4年（2022年）1月1日から「支給開始日から通算して1年6ヶ月」になった。
 * それ以前は「支給開始日から暦の上で1年6ヶ月」で、途中で復職しても
 * その期間が上限を食っていた。改正後は、支給されなかった期間は数えない。
 *
 * 「1年6ヶ月」は暦で数えるため、支給開始日によって実日数は 546〜548日で揺れる
 * （うるう年・月の大小）。ここでは短いほうの 546日 を採る。
 * 上限を過小に見積もる側に倒すのは、このツールが「いくらもらえるか」を
 * 調べる道具であり、多く出しすぎるほうが害が大きいため。
 */
export const MAX_PAYABLE_DAYS = 546;
```

`calcShobyoTeate()` を次のようにする。

```ts
const requestedDays = Math.max(0, restDays - TAIKI_DAYS);
const payableDays = Math.min(requestedDays, MAX_PAYABLE_DAYS);
const cappedByLimit = requestedDays > MAX_PAYABLE_DAYS;
```

`ShobyoTeateResult` に次の2つを足す。

| フィールド | 意味 |
|---|---|
| `requestedDays` | 上限を当てる前の支給対象日数（入力どおりの日数 − 待期3日） |
| `cappedByLimit` | 通算1年6ヶ月の上限に達したか |

**`total` は上限後の `payableDays` から計算する。** ここが本丸である。

### 2. 上限に達したときに、画面で理由を言う

黙って数字を丸めるのがいちばん悪い。利用者は「なぜこの額なのか」が分からなくなる。
`Calculator.tsx` の結果パネルに、`cappedByLimit` のときだけ注記を出す。

> 支給期間の上限（通算1年6ヶ月＝546日）に達しています。
> 入力の724日ぶんではなく、**546日ぶん**で計算しました。

`payableDays === 0` のときに待期期間の注記を出している既存の作りと同じ形にする
（`Calculator.tsx` 71〜75行目）。文言はページ本文の「通算1年6ヶ月」と同じ言葉を使い、
本文とパネルで用語がずれないようにする。

### 3. 入力欄には `max` を付けない

`restDays` に `max={549}` を付けて入力できなくする案は採らない。

- 実際に2年休んでいる人は「730」と入れるのが自然で、それを弾くのは体験として悪い
- 弾くと「1年6ヶ月で切れる」という**制度の説明の機会そのものを失う**
- 入れさせたうえで「546日ぶんで計算しました」と言うほうが、このツールの価値が高い

### 4. テストで固定する

`tools/tests/shobyo-teate.test.ts` に足す。

| ケース | 期待 |
|---|---|
| `restDays = 30` | `payableDays = 27`、`cappedByLimit = false`（既存の挙動を壊さない） |
| `restDays = 549`（546 + 待期3） | `payableDays = 546`、`cappedByLimit = false`（境界のちょうど上限） |
| `restDays = 550` | `payableDays = 546`、`cappedByLimit = true` |
| `restDays = 730` | `payableDays = 546`、`total = 3_640_182`（月収30万円） |
| `restDays = 100000` | `total` が上限額と一致する（青天井にならない） |

**上限額そのものを数値で書いたテストを1本入れる。** 日額の丸めと上限日数の両方を
同時に見張れるので、どちらかが壊れたときに気づける。

## 一次情報

いずれも 2026-08-13 に確認。

- 全国健康保険協会「病気やケガで会社を休んだとき（傷病手当金）」
  https://www.kyoukaikenpo.or.jp/g6/cat620/r306/
- 厚生労働省「傷病手当金の支給期間の通算化について」（令和4年1月1日施行）
  https://www.mhlw.go.jp/stf/newpage_22308.html

改正の要点は「**支給開始日から通算して1年6ヶ月**」であり、
途中で就労するなど支給されない期間があれば、支給開始日から起算して1年6ヶ月を
超えても繰り越して支給される。**通算した支給日数の上限が1年6ヶ月ぶん**という意味なので、
このツールのように「休業日数」から計算する形であれば、
支給対象日数を546日で頭打ちにするのが正しい実装になる。

## 想定する効果

- **本文と計算の矛盾が消える。** いま同じページの中で説明と数字が食い違っており、
  気づいた利用者はページ全体を信用しなくなる。金額を扱うページで最も避けたい状態である
- **長期療養の人に、いちばん知りたい情報が届く。** 「1年6ヶ月で切れる」を
  金額の形で見せられるのは計算機だけができることで、解説記事との差別化になる
- **検索面**：`傷病手当金 いつまで` `傷病手当金 1年6ヶ月 過ぎたら` のような
  期間側のクエリに、根拠のある本文で応えられるようになる。
  現状 `/shobyo-teate/` は88日間で表示11回・掲載順位57.4（Search Analytics API、
  2026-05-15〜2026-08-11 取得）で、ほぼ何も取れていない

## やらないこと

- **「通算」の厳密なシミュレーション**（復職期間を差し引いた通算日数の管理）は入れない。
  「いつからいつまで休んで、いつ復職して」を入力させる作りになり、
  1画面で完結する今のツールの性格から外れる。本文で通算の考え方を説明し、
  計算は「休んだ日数の合計」を入れてもらう前提を維持する
- **支給開始日から実日数（546〜548日）を厳密に求める**のもやらない。
  支給開始日の入力欄が必要になるうえ、差は最大2日（月収30万円で約1.3万円）で、
  上限を無視している現状（120万円ずれ）に比べれば無視できる
