# iDeCo 拠出限度額・節税額 計算機（2026年12月改正対応）

**状態**：実装済み（2026-08-13）
**対象**：`tools/`（新規ツール `ideco`）
**起票**：2026-08-13

---

## 背景と根拠

### なぜ今か：2026年12月1日にiDeCoの拠出限度額が大幅に変わる

確定拠出年金法等の改正により、**2026年12月1日**から iDeCo（個人型確定拠出年金）の
拠出限度額と加入可能年齢が変わる。新しい限度額は**2027年1月引落分**
（2026年12月拠出分）から適用される。

| 区分 | 現行（月額） | 改正後（月額） | 倍率 |
|---|---|---|---|
| 第1号被保険者（自営業など） | 6.8万円 | **7.5万円** | 1.10倍 |
| 第2号・企業年金なし（会社員） | 2.3万円 | **6.2万円** | **2.70倍** |
| 第2号・企業年金あり（企業型DC / DB） | 2.0万円 | **6.2万円**（他制度と合算） | **3.10倍** |
| 第3号被保険者（専業主婦・主夫） | 2.3万円 | 2.3万円 | 変更なし |

加入可能年齢も **65歳未満 → 70歳未満** に上がる
（老齢基礎年金・iDeCoの老齢給付金を受給していないことが条件）。

一次情報・確認先（いずれも 2026-08-13 に取得）:

- 厚生労働省 社会保障審議会 企業年金・個人年金部会 資料
  https://www.mhlw.go.jp/content/10600000/001365075.pdf
- 楽天証券「【2026年12月制度改正】iDeCoの加入可能年齢・拠出限度額が引き上げ」
  https://dc.rakuten-sec.co.jp/about/revised/202505/
- マネックス証券「iDeCo拠出限度額および加入可能年齢の引き上げ（2026年12月制度改正）」
  https://info.monex.co.jp/news/2026/20260514_01.html

### この改正の本質は「単純な引き上げ」ではなく「合算ルールへの切り替え」

**ここが計算機の存在理由になる。**

改正前は「iDeCo単体の上限」が区分ごとに決まっていた。改正後は
**iDeCo単体の上限が撤廃され、企業年金と合算した枠の残りがiDeCoの上限になる。**

```
iDeCoの拠出限度額 = 6.2万円 −（企業型DCの事業主掛金 ＋ DB等の他制度掛金相当額）
```

つまり **会社員のiDeCo上限は、勤め先の制度と事業主掛金の額で一人ひとり違う額になる。**

| 勤め先の状況 | iDeCoに出せる額（月） |
|---|---|
| 企業年金なし | 6.2万円 |
| 企業型DCの事業主掛金 1.0万円 | 5.2万円 |
| 企業型DCの事業主掛金 4.0万円 | 2.2万円 |
| 企業型DCの事業主掛金 6.2万円以上 | 0円（拠出できない） |

**「自分はいくらまで出せるのか」が引き算をしないと分からない。**
これは表を見て終わる話ではなく、まさに計算機の仕事である。
改正前は「会社員は2.3万円」と暗記で済んでいたものが、
改正後は個別計算になる——**需要の質そのものが変わる。**

### 検索需要のタイミングが、このサイトのリードタイムと噛み合っている

起票時点（2026-08-13）で施行まで**約3.5ヶ月**。
`docs/features/search-index-consolidation.md` が記録しているとおり、
`hasokon.com` は2026-08-08にドメイン統合したばかりで、
新URLの多くがまだインデックス未登録である。
**新規ページが検索に乗るまでの時間を考えると、いま作って12月に間に合う位置にある。**

需要が立つ山は2つある。

1. **2026年10〜12月**：改正の周知期。「iDeCo 改正 いくらまで」「iDeCo 上限 会社員」
2. **2026年12月〜2027年1月**：実際に掛金変更の手続きをする期。
   加入者は掛金額の変更届を出すので、**額を決めるために計算する動機が最も強い**

さらに年末調整・確定申告（小規模企業共済等掛金控除）と重なる時期なので、
既存の `nenmatsu-chosei`（年末調整 還付金 計算機）と相互リンクが自然に効く。

### 計測値：このサイトの「お金・社会保険」に、資産形成・節税の枠が無い

`tools/lib/registry.ts` の16本のうち「お金・社会保険」は6本
（`docs/features/zaishoku-rorei-nenkin.md` の分類に、その後追加された2本を足すと8本）。

| slug | 扱う制度 | 性格 |
|---|---|---|
| `kosodate-shienkin` | 子ども・子育て支援金 | 強制的に取られる額 |
| `furusato-nozei` | ふるさと納税 | **自分で選んで節税する額** |
| `nenshu-kabe` | 年収の壁 | 働き方の判断 |
| `hatarakizon` | 社会保険の加入と手取り | 働き方の判断 |
| `shobyo-teate` | 傷病手当金 | もらう額 |
| `nenmatsu-chosei` | 年末調整（所得税） | 戻る額 |

**「自分で選んで節税する」タイプは `furusato-nozei` の1本しかない。**
iDeCoはふるさと納税と並ぶ二大「自分で選ぶ節税」であり、
利用者層もほぼ重なる（給与所得者で、税金を意識している層）。
`furusato-nozei` は Search Analytics API（2026-05-15〜2026-08-11）で
表示16回・掲載順位82.2 と苦戦しているが、**それは競合の厚さの問題**であって、
需要がある証拠でもある。iDeCoは**改正直後という参入しやすい窓**がある点が違う。

## 何を作るか

`/tools/ideco/` に「iDeCo 拠出限度額・節税額 計算機」を1本。

### 入力

| 項目 | 形式 | 既定値 |
|---|---|---|
| 被保険者区分 | 選択（第1号 / 第2号 / 第3号） | 第2号 |
| 勤め先の企業年金（第2号のみ） | 選択（なし / 企業型DC / DB等 / 両方） | なし |
| 事業主掛金の月額（企業年金ありのみ） | 数値 | 0 |
| 年齢 | 数値 | 40 |
| 課税所得または年収 | 数値 | 年収500万円 |
| 実際に拠出する月額 | スライダー（上限まで） | 上限額 |

### 出力

1. **拠出限度額**（月額・年額）。改正前後を並べて「いくら増えたか」を出す
2. **限度額の内訳**。`6.2万円 − 事業主掛金 4.0万円 = 2.2万円` のように**引き算を見せる**
3. **年間の節税額**。所得税＋住民税。小規模企業共済等掛金控除は
   **全額が所得控除**なので `拠出額 × (所得税率 + 住民税率10%)`
4. **加入可能年齢までの累計**。70歳未満に延びたぶん、
   「65歳までなら○年 → 70歳までなら○年で、累計節税額は○円」

### 実装で流用できるもの

- **所得税の税率表**：`tools/lib/nenmatsu-chosei.ts` に累進税率の実装がある。
  制度データを二重に持たないよう、共通化するか import する
- **標準報酬月額**は不要（iDeCoは社会保険の等級と無関係）
- 計算ロジックは `tools/lib/ideco.ts`、テストは `tools/tests/ideco.test.ts`。
  既存16本と同じ構成に揃える
- `registry.ts` にカテゴリ `お金・社会保険`、アイコンは Phosphor の `PiggyBank` あたり

### 見せ方で1点だけ譲らないこと

**「2026年12月から」と「いまは」を必ず並べて出す。**

起票時点（2026-08-13）は改正前で、いま掛金変更の手続きをしても
適用されるのは2027年1月引落分からである。
新しい額だけを出すと、**いますぐ6.2万円出せると誤解される。**
`zaishoku-rorei-nenkin.md` が「62万円か65万円か」で問題にしたのと同じ、
**どの時点の数字なのかを取り違えさせない**という論点である。

## 想定する効果

- **改正で「暗記できる額」から「個別計算」に変わる。**
  解説記事は表を貼って終わるしかないが、事業主掛金を入れて引き算を見せられるのは
  計算機だけである。この差が最もはっきり出る題材
- **リードタイムが合っている。** 施行まで3.5ヶ月あり、
  新規ドメインのインデックス事情（`search-index-consolidation.md`）を踏まえても、
  12月の需要の山に間に合う位置で作れる
- **既存ツールとの回遊。** 年末調整（`nenmatsu-chosei`）・ふるさと納税
  （`furusato-nozei`）と控除の話で地続きなので、`RelatedTools` が実際に機能する
  数少ない組み合わせになる。ふるさと納税の上限はiDeCoの掛金で下がるという
  相互作用があり、**相互リンクに実質的な理由がある**

## やらないこと

- **運用商品の選択・利回りシミュレーション**はやらない。
  投資助言に踏み込む領域で、このサイトの他のツールと性格が違いすぎる。
  出すのは「掛金の上限」と「所得控除による節税額」という、**制度から一意に決まる額だけ**
- **受取時の税金（退職所得控除・公的年金等控除）**は初版では扱わない。
  勤続年数・受取方法・他の退職金との通算が絡み、それだけで1ツールになる。
  本文で「受取時にも課税がある」ことに触れるにとどめ、必要なら別仕様書に切る
- **マッチング拠出との選択**も初版では扱わない。改正で
  「マッチング拠出かiDeCoか」の選択制が撤廃される論点があるが、
  対象者が限られるため、まず限度額の本体を出す
