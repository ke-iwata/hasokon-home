# 新ツール「手取り計算機」（年収→手取り・令和8年の基礎控除引上げ対応）

**状態**：実装済み・`stage: 'preview'`（2026-09-01 起票／同日実装）。
テスト環境で年収300万・500万・800万の3点を国税庁の源泉徴収税額表・協会けんぽの
料額表と突合したら `public` に上げる（本文「検証」参照）。
**2026年10月までに公開するのが理想**
（年末調整・「来年の手取り」検索が立ち上がる10〜12月に間に合わせる。
遅くとも11月中に上げないと今季の特需を逃す）。
`public` にするPRで `home/index.html` のカードと `home/llms.txt` の行を同時に足すこと。
**対象**：`tools/`（`hasokon.com/tools/tedori-keisan/` を想定）
**起票**：2026-09-01

## 背景と根拠

### 「手取り 計算」は生活系で最大級の恒常クエリなのに、このサイトは入口を持っていない

カシオの keisan の人気ランキングでも給与・手取り系は常に上位に入る定番で、
「手取り 計算」「年収 手取り」「額面 手取り」は季節を問わず検索され続ける。
このサイトは年収の壁・社会保険損得・年末調整還付金・失業保険と
**「手取りの周辺」ばかり揃えて、本丸の手取り計算だけが無い**。

既存ツールの GSC 実測（2026-09-01 取得、直近28日）でも、税・社保系は
`nenshu-kabe` などに表示が付き始めており、クラスタとしての評価は育ち始めている。
手取り計算機はこのクラスタの**ハブ**になり、各ツールへの内部回遊の起点になる。

### 2026年は「手取りが変わる年」で、比較コンテンツの特需がある

令和8年分から基礎控除が最大104万円（本則62万円＋令和8・9年分だけの特例加算42万円）、
給与所得控除の最低保障額が74万円に上がる（いわゆる「178万円の壁」対応。
根拠と一次情報は実装済みの `tools/lib/nenmatsu-chosei.ts` 冒頭コメントに整理済み）。
この改正は**令和8年12月の年末調整で初めて給与明細に現れる**ため、
2026年10〜12月に「2026年 手取り いくら変わる」「基礎控除 引き上げ 手取り」の
検索が立ち上がることがほぼ確実。**改正前後の手取り比較を最初から組み込む**ことで、
汎用の手取り計算機との差別化と特需の両方を取る。

### 手取り計算のエンジンそのものが、すでに `hatarakizon.ts` にある

| 使い回すもの | ある場所 |
|---|---|
| **年間の手取りと内訳を返す `calcTakeHome(gross, enrolled, kaigo)`** | `tools/lib/hatarakizon.ts` |
| 社保（標準報酬月額・健保＋支援金＋介護・厚年・雇用保険）`calcPremiums()` | 同上 |
| 所得税（復興特別所得税込み）`calcIncomeTax()` | 同上 |
| **住民税（所得割10%＋均等割＋非課税限度額＋調整控除）`calcResidentTax()`** | 同上 |
| 令和7年・令和8年の給与所得控除・基礎控除・所得税速算表 | `tools/lib/nenmatsu-chosei.ts` |
| 標準報酬月額の等級表（健保50等級・厚年32等級の頭打ち込み） | `tools/lib/shaho-grades.ts` |
| 壁ページ群との相互リンク先 | `nenshu-kabe`・`hatarakizon`・`nenmatsu-chosei` |

つまりこのツールの本体は**新規実装ではなく、`hatarakizon.ts` の既存関数の共有**
（必要なら共通 lib への切り出し）で作る。`tools/CLAUDE.md` の
「制度データは1箇所に集約する」のとおり、**同じ計算の2実装を並べない**。
2実装が並ぶと料率改定のたびに片方だけが更新されて静かに腐り、
同じ年収に対してサイト内で違う数字が2つ出る（目安ツールとして一番効く信頼を落とす）。
新規に書くのは、令和8年分の控除（`nenmatsu-chosei.ts` の表）への差し替え部分と
月額換算・早見表のUIくらい。

## 提案する仕様

### 入力（最小構成・2つだけ）

1. 年収（額面。賞与込みの年間総額）
2. 年齢区分（40歳未満／40〜64歳）… 介護保険料の有無

**都道府県の入力は入れない。** 既存ツールは協会けんぽの全国平均1本
（`hatarakizon.ts` の `HEALTH_RATE`）で、47都道府県の健保料率表を持つツールは
このサイトに無い。入れると毎年3月に更新する持ち物が1つ増えるうえ、
このツール自身の「入力が増えるほど離脱する」という方針にも反する。
初期版は全国平均で計算し、**「健康保険料は都道府県で少し変わる（協会けんぽの
全国平均で計算）」の注記**を結果に出すことで代える。

扶養・各種控除も初期版では入れない（「独身・扶養なしの目安」と明記し、
細かい人は年末調整還付金計算機へ誘導する）。

### 出力

- **年間の手取り額**と**月あたりの手取り額**（賞与なし12分割の目安と明記）
- 内訳の表: 健康保険（＋介護保険）・厚生年金・雇用保険・所得税（復興特別所得税込み）・
  住民税（概算）
- **令和7年基準との比較**: 「2026年の改正で手取りが年 +◯円」を常に併記（特需の芯）
- 年収100万〜1,000万円の**手取り早見表**（「手取り 早見表」クエリの受け皿。
  最低賃金チェッカー・ふるさと納税早見表と同じ構え）

### 計算の約束（正確さより「目安として誠実」を優先）

- 社保は協会けんぽの標準報酬月額（年収÷12を等級に当てる）で計算し、
  「組合健保・公務員共済は料率が異なる」と明記
- **住民税は新規に書かず、`hatarakizon.ts` の `calcResidentTax()` を流用する。**
  基礎控除43万円・均等割・非課税限度額・調整控除の扱いを既存ツールと完全に揃える
  （素の「所得割10%」で別に書くと、働き損ゾーン計算機と違う住民税額がサイト内に並ぶ）。
  そのうえで**「同じ年収が続いた場合の目安」**であること、住民税は前年所得に
  課税される仕組みであることを結果の但し書きに必ず書く
  （ここを曖昧にすると「新社会人の1年目と合わない」というズレが必ず起きる）
- **「月々の手取りに改正が効くのは2027年1月から」を結果に必ず出す。**
  令和8年度改正は令和8年12月1日施行で、国税庁は「令和8年11月までの給与等の
  源泉徴収事務に変更は生じない」と明記している（源泉徴収税額表の改正は
  令和9年1月1日施行。`nenmatsu-chosei.ts` 冒頭の整理を参照）。つまりこのツールが
  狙う2026年10〜12月に見た人の給与明細は**まだ改正前の源泉徴収のまま**で、
  令和8年分の控除で出した月あたりの手取りとは必ずズレる。住民税の但し書きと同じ格で
  「2026年分の減税は12月の年末調整でまとめて戻る」と出し、
  **年末調整還付金計算機への導線をここに置く**（「手取りが増えるはずなのに
  明細が変わらない」という、この時期いちばん多い疑問への答えになる）
- 令和8年分の基礎控除は**合計所得に応じた段階**（`nenmatsu-chosei.ts` 実装済みの表）を使う。
  特例加算が令和8・9年分だけの時限措置である旨も注記する
- **高年収の頭打ちと賞与のズレを注記で言う。** 厚生年金は32等級・標準報酬月額65万円で
  頭打ち（`shaho-grades.ts` の `PENSION_STANDARD_MAX`。年収780万円あたりから増分に
  厚年保険料はかからない）、健康保険は50等級・139万円で頭打ち。賞与の社保は
  標準賞与額の別計算なので、**賞与がある人ほど社保を過大に見積もる向き**にずれる。
  結果に「賞与の有無でずれる（ずれる向きは社保の取りすぎ側）」の注記を出す

  JSON-LD（WebApplication＋FAQPage）、`publicTools` 経由の一覧掲載
- title 案: 「手取り計算機｜年収から手取りを自動計算（2026年の減税に対応）」
- FAQ: 「手取りは額面の何割？」「2026年からいくら増える？」「住民税はなぜ目安？」
  「賞与がある場合は？」
- 公開時に `home/index.html` のカードと `home/llms.txt` の行を同じPRで足す（公開の約束どおり）

### 検証

- 国税庁の源泉徴収税額表・協会けんぽの料額表と、年収300万／500万／800万の3点で突合
- `nenmatsu-chosei` と同一入力での所得税額一致をテストに入れる（ロジック共有の検証）
- `hatarakizon` と同一入力での住民税額・社保額の一致をテストに入れる（関数共有の検証）
- **厚生年金の上限張り付きを期待値として書く**（年収780万円と1,000万円で
  厚年保険料が同額になること。健保50等級の頭打ちも同様）
- 手取り早見表のスナップショットテスト（料率改定時に差分で気づけるように）。
  刻みには**給与所得控除の上限と基礎控除の逓減の境目の前後**を含め、
  改定時に境目のずれへ差分で気づけるようにする。
  **注意：逓減の境目「489万円超で104万→67万→62万」は合計所得（給与所得控除後）であって
  年収ではない。** 年収ベースの早見表では、境目は次の2つになる。
  - **1つ目（104万→67万）は年収665万円あたり**
    （年収666万 → 給与所得控除66.6万＋110万＝176.6万 → 合計所得489.4万）。
    刻みは **650万・700万** のあたりを跨がせること（489万前後に置いても境目は検出できない）
  - **2つ目（67万→62万）は年収850万ちょうど。** ここは**給与所得控除が上限195万円に
    達する点と重なる**（年収850万 → 給与所得控除195万 → 合計所得655万。
    ここまでが67万で、これを超えると62万）。刻みを **800万・900万** で跨がせれば、
    給与所得控除の上限と基礎控除の2段目の両方を1つのスナップショットで押さえられる

  つまり刻みが **650・700・800・900** を含めば、税側の2つの境目と
  給与所得控除の上限、そして社保側の厚生年金の頭打ち（年収780万あたり）が
  1本のスナップショットに揃う

### 保守の約束

- `tools/CLAUDE.md` の改定表に行を足す。`hatarakizon.ts` の関数を共有するので、
  毎年3月の協会けんぽ料率改定は**既存の `HEALTH_RATE` / `KAIGO_RATE` の行の
  1箇所更新が両ツールに効く**（これが2実装を並べない一番の利点）。
  新たに増える持ち物は、令和9年分以降の控除表の年度切り替えだけ

## 期待される効果と工数

- **効果**: 恒常需要の最大級クエリ群への入口＋2026年10〜12月の改正特需。
  既存の税・社保クラスタ（8ツール）の回遊ハブになり、サイト全体の
  滞在ページ数を押し上げる。YMYL領域なので上位表示には時間がかかる前提だが、
  「2026年改正でいくら変わる」の切り口は競合の更新が遅い領域で先行できる
- **工数の目安**: 実装＋テスト＋早見表で **15〜25万トークン程度**
  （手取り計算の本体が `hatarakizon.ts` の `calcTakeHome()` 一式の共有で済み、
  新規は令和8年分の控除への差し替えとUI・早見表だけのため。
  当初見積り25〜35万から、既存エンジン共有を前提に引き下げた）

## 採らなかった選択肢

- **扶養・生命保険料控除まで入れた詳細版**: 入力が8項目を超えると計算前の離脱が増える。
  詳細は年末調整還付金計算機が既に担っているので、住み分ける
- **賞与の別入力**: 社保の賞与分（標準賞与額）まで正確にやると入力も実装も倍になる。
  初期版は「年間総額を12分割した目安」と明記して単純化し、需要があれば次版で
- **住民税の自治体別対応**: 均等割の差は年数百円で、目安ツールの精度に見合わない
