### 需要と競合の状況（2026-11-07 の Web 調査）

「URL デコード」「URL エンコード」「URL 文字化け 戻す」「%E3 日本語 変換」は、どれも通年の定番クエリで、
上位は単機能のフォーム1つのツールが並ぶ。調べた範囲で足りていないのは次の5点で、ここを差別化にする：

1. **Shift_JIS・EUC-JP の自動判別が、ブラウザのツールにはほとんど無い。** 自動判別つきで紹介されているのは
   Windows 用のフリーソフト（2005〜2008 年の窓の杜の紹介記事）で、Web のツールは UTF-8 決め打ちか、文字コードを自分で選ばせる。
   ブラウザの `TextDecoder` は `shift_jis` / `euc-jp` / `iso-2022-jp` を標準で持つ（WHATWG Encoding Standard）ので、
   **辞書を持たずに**判別と変換ができる
2. **貼った URL をサーバーに送るものがある。** フォームを送信してサーバー側で変換する方式は、社内システム・会員ページの
   URL（セッション ID・メールアドレス・トークン入り）を貼るのにためらう。当サイトはブラウザの中だけで変換し、`fetch` を一切しない、
   **貼った URL を開かない（リンクにしない）**、を冒頭に書いて約束する
3. **クエリを表に分解しない。** `?q=…&page=2&utm_source=…` を1行の文字列で返すだけのものが多い。
   キーと値を表にして、値を1つずつデコードして見せる
4. **追跡用パラメータを外す機能が、デコードのツールと別になっている。** 「URL を短く」「utm 消す」で別のツールを探させている。
   デコードのついでに「共有用のきれいな URL」を出せば1回で済む
5. **日本語ドメインと、見た目の似た文字の注意が無い。** `xn--…` の Punycode を日本語に戻すツールは別に探す必要があり、
   キリル文字の `а`（U+0430）をラテン文字の `a` に混ぜた**見た目のそっくりなドメイン**（IDN ホモグラフ。フィッシングで使われる）を注意してくれるものは見当たらない

**本文には競合の名前を出さない**（JSON 整形の企画レビュー #444 の約束と同じ）。

## 提案する仕様

### 入力と出力

- **入力**：1つの欄。URL でも、URL の一部（`%E6%9D%B1%E4%BA%AC` だけ）でも、普通の文章でもよい。
  **1行に1つ**として複数行をまとめて変換できる（ログ・スプレッドシートの列を貼る場面）
- **向き**：`デコード（%XX → 文字）`／`エンコード（文字 → %XX）` の切り替え。既定は自動：
  `%[0-9A-Fa-f]{2}` か `xn--` を含めばデコード、含まず日本語を含めばエンコード。どちらに判定したかを結果の上に1行で示す。
  **どれも含まない入力**（`hello world` など）は、入力をそのまま出して「変換するもの（`%XX`・日本語・`xn--`）はありません」と1行出す（勝手にエンコードしない。向きを手で選べばその向きで変換する）
- **変換のタイミング**：入力が止まって 200ms 後に自動で変換（合わせて 10 万字・1,000 行まで。超えたら `変換する` ボタン）
- **出力**：
  - 変換後の文字列（行ごと）と `コピー`。複数行なら `まとめてコピー`
  - デコードしたときは**使った文字コード**を札で出す（`UTF-8`／`Shift_JIS`／`EUC-JP`／`ISO-2022-JP`）。判別がつかない・候補が2つ残るときは、**候補を並べて**選ばせる（下「文字コードの判別」）
  - 入力が URL として読めるとき（`new URL()` が通るとき）は、下に**分解の表**。
    **スキームの無い URL**（`www.example.com/検索?q=…`・`example.co.jp/…` のように、先頭がドメインらしい形＝ドットを含むラベルで始まり空白を含まないもの）は、**分解の表のためだけに** `https://` を仮に付けて読み、表の上に「`https://` を補って読みました」と1行出す。変換の結果・共有用 URL には `https://` を足さない（貼った形のまま返す）。ドメインらしくない入力（`/path?q=…` だけ・普通の文章）は表を出さない：
    スキーム・ホスト（日本語ドメインは日本語と `xn--` の両方）・パス（`/` ごとにデコード）・クエリ（キー／値の表）・フラグメント
  - 同じく URL のとき、**「共有用のきれいな URL」**（下「追跡用パラメータ」）と `コピー`・`このURLのQRコードを作る`（`/tools/qr-code/` へ。URL は渡さず、画面で貼り直してもらう。下「やらないこと」）

### 文字コードの判別（デコード）

1. `%XX` をバイト列に戻し、まず `new TextDecoder('utf-8', { fatal: true })` で読む。**通れば UTF-8 で確定**（UTF-8 は偶然通ることがほぼ無い）
2. 通らなければ `shift_jis` と `euc-jp` を `fatal: true` で読み、両方の結果を**日本語らしさ**で採点する：
   ひらがな・カタカナ・JIS 第1水準の漢字（`TextDecoder` で第1水準の範囲 0x889F〜0x9872 を一度読んで作る集合）・ASCII の割合が高いほど高い、
   半角カナ・私用領域・JIS 第2水準だけの漢字が続くほど低い。差が大きければ高いほうで確定、近ければ**両方を候補として並べる**
3. `%1B%24B`（ESC $ B）を含めば `iso-2022-jp` を先に試す
4. どれでも読めなければ「この文字コードでは読めません」として、読めなかったバイトの位置（何文字目の `%XX` か）を示し、そこまでは UTF-8 で読めた分を出す
5. ユーザーが札を押して文字コードを手で切り替えられる（自動判別の結果より優先）

### デコードの約束（テストで固定する）

1. `+` の扱いは切り替え：`+ を空白に戻す`（フォーム送信の `application/x-www-form-urlencoded`。クエリの部分の既定）／`+ のまま`（パスの部分の既定）。
   URL として分解したときは、**パスでは `+` を残し、クエリでは空白にする**（`URLSearchParams` と同じ）
2. 壊れた `%`（`%E3%81` で終わる・`%G1`・`%` だけ）は、例外で止めずに**その位置に印を付けて残し**、ほかは変換する。
   印の横に「何文字目に途中で切れた文字があります（コピーのときに末尾が欠けた可能性）」と原因の見当を日本語で示す
3. **二重エンコードの検出**：デコード結果がまた `%[0-9A-F]{2}` を含み、`%25` から始まっていたら「2回エンコードされています」と示し、
   `もう1回デコード` を出す（自動では繰り返さない。`%25` を本当に `%` として使う URL があるため）。最大5回まで
4. 文字は**書記素（`Intl.Segmenter`）単位**で数え、絵文字・結合文字を割らない（エラー位置の「何文字目」もこの単位）
5. 見えない文字（U+200B〜U+200D・U+FEFF・U+00A0・全角スペース・タブ・改行）がデコード結果に含まれたら印を付ける。
   呼び名は [テキスト比較](./text-hikaku.md) の実装（#469）が作る共通の一覧 `tools/lib/invisible-chars.ts` を使う。
   **この実装は #469 のマージ後に着手する**（上「着手条件」）。足りない文字があれば `invisible-chars.ts` に足す（`json-seikei.ts` の `ZENKAKU_NAMES` は `export` されておらず、U+200B〜U+200D・U+FEFF も入っていないので使わない）

### エンコードの約束（テストで固定する）

6. 範囲の切り替え：`URL の部品として`（既定。`encodeURIComponent` 相当。`/` `?` `&` `=` `#` も `%XX` にする）／
   `URL 全体として`（`encodeURI` 相当。`/` `?` `&` `=` `#` `:` を残す）。違いを切り替えの横に1行で示す（「検索語やファイル名を URL に入れるなら『部品』」）
7. 文字コードは UTF-8（既定）・Shift_JIS・EUC-JP。**ブラウザの `TextEncoder` は UTF-8 しか作れない**ので、
   Shift_JIS・EUC-JP は**初めて選んだときに `TextDecoder` で2バイトの全組み合わせを一度読んで逆引き表を作る**（データファイルを持たない。作る時間はテスト環境で 100ms 以内を確認の条件にする）。
   **結果は WHATWG Encoding Standard の encoder（＝ブラウザのフォーム送信）と同じにする**。逆引きでは同じ文字が2か所から読めるもの（`纊` は `0xED40` と `0xFA5C` の両方）があるので、重複は encoder の規則で選ぶ：
   - Shift_JIS は **pointer 8272〜8835（NEC 選定 IBM 拡張、`0xED40`〜`0xEEFC`）を候補から除き**、それ以外は最初の pointer を採る（`纊` → `%FA%5C`。`%ED%40` にしない）。EUC-JP は最初の pointer を採る
   - encoder の特別扱いも同じにする：U+00A5 `¥` → `0x5C`、U+203E `‾` → `0x7E`、U+2212 `−` は U+FF0D `－` と同じに扱う
   - その文字コードに無い文字（絵文字・`𠮷`（U+20BB7）など）は変換せずに印を付け、「Shift_JIS に無い文字です」と示す（`髙` は Windows-31J の `0xFBFC` で変換できるので、無い文字の例にしない）
8. 空白は `%20`（既定）／`+`（フォーム用）の切り替え。大文字の16進（`%E3`）で出す（RFC 3986 2.1 の推奨）

### 追跡用パラメータ（共有用のきれいな URL）

9. 次のキーを外した URL を「共有用」として出す。**元の URL は書き換えない**（下に並べて出す）。外したキーは表で取り消し線にして、
   チェックを外せば残せる：
   - `utm_` で始まるもの（`utm_source` `utm_medium` `utm_campaign` `utm_term` `utm_content` `utm_id` ほか）
   - 広告・SNS のクリック ID：`gclid` `gbraid` `wbraid` `dclid` `fbclid` `msclkid` `yclid` `twclid` `ttclid` `li_fat_id` `igshid` `mc_cid` `mc_eid` `_ga` `_gl`
   - 一覧は `tools/lib/url-decode.ts` に**理由（どこの何の ID か）つきの定数**で持つ。**ページを動かすのに要るパラメータ（`id` `q` `page` `v` など）は一覧に入れない**。
     迷うもの（`ref` `source` など、サイトによっては中身に効くもの）は入れない
   - フラグメントの `#:~:text=…`（検索結果やブラウザの「ハイライトへのリンク」）は外さず、**デコードして「ハイライトする文字：◯◯」と表で示す**

### 日本語ドメインと、見た目の似た文字の注意

- ホストに `xn--` のラベルがあれば Punycode を日本語に戻して並べる（RFC 3492 のデコードを自前で約 80 行。外部ライブラリは入れない）。
  逆に日本語のホストは `new URL()` の `hostname` で `xn--` に変換して並べる
- **1つのラベルに複数の文字体系が混ざっていたら注意を出す**（`Intl.Segmenter` で書記素に分け、**`\p{Script_Extensions=…}`**（`Latin` `Cyrillic` `Greek` `Han` `Hiragana` `Katakana` など）で判定する。`\p{Script=…}` は使わない。
  **Common・Inherited（数字・`-`・長音の `ー`・結合文字など）は混在の数に入れない**。`ー` は Script=Common なので、Script で判定すると「カタカナ＋Common」の扱いがぶれるため）。
  例：`аpple.com`（先頭がキリル文字）→「**このドメインには見た目の似た別の文字（キリル文字の а）が混ざっています。本物のサイトではない可能性があります**」。
  日本語（漢字・ひらがな・カタカナ）とラテン文字の混在（`日本-shop.jp`）は普通にあるので注意しない
- **注意が出ないことは安全の保証ではない**：この方式は、ラベル全体が別の文字体系で書かれたもの（全部キリル文字で `аррӏе` と書く、いわゆる whole-script confusable）を拾えない。
  そこで分解の表のホストの横（注意の有無にかかわらず）と本文に「**注意が出ないことは、本物のサイトである保証ではありません**」を1行出す（煽らず事実だけ）
- `javascript:` `data:` `vbscript:` のスキームは分解の表で赤い札にして「このURLは開くとプログラムが動きます」と示す（このツールは開かないが、貼る人に知らせる）

### 安全の約束

- 入力と結果は **React のテキストとして描くだけ**で、`dangerouslySetInnerHTML` を使わない。**結果を `<a href>` にしない**（`javascript:` を貼られても押せない）。
  テストで `<script>`・`javascript:alert(1)`・`%3Cimg%20onerror%3D…%3E` を貼っても文字として出ることを確かめる
- `fetch`・`navigator.sendBeacon` を一切使わない。`tool_use` には入力も結果も入れない（下「計測」）
- 入力は URL のハッシュ・`localStorage` に残さない（トークン入りの URL がブラウザの履歴・端末に残るため）

### 計測

- `trackToolUse('url-decode', …)` を、変換の向き（`decode`／`encode`）・判別した文字コード（`utf8`／`sjis`／`eucjp`／`jis`／`ambiguous`）・
  行数の区分（`single`／`multi`）で送る。`共有用URLをコピー`（`copy-clean`）・`もう1回デコード`（`decode-again`）・見た目の似た文字の注意を出した（`homograph-warn`）も送る
- **入力・結果・ホスト名・外したパラメータのキーは送らない**（[tool-use-coverage.md](./tool-use-coverage.md) の「入力値は送らない」）

## 期待される効果

- 「URL デコード」「URL エンコード」「URL 文字化け」「%E3 日本語」「パーセントエンコーディング 変換」「utm 消す」「Punycode 変換」の

## やらないこと

- 短縮 URL（`bit.ly` など）の展開・リンク先の安全確認（**URL を開かない**の約束を崩す。サーバーへの問い合わせが要る）
- 短縮 URL の発行（保存と転送のサーバーが要る）
- 結果を `/tools/qr-code/` へ URL のクエリで渡すこと（トークン入りの URL がアクセスログ・履歴・GA のページ URL に残るため。画面で貼り直してもらう）

- 追跡用パラメータの一覧をネットから取ってくる更新（一覧はコードに持ち、増やすときは PR で足す）
