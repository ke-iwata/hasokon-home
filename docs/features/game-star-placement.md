## 背景と根拠

- **いま日本の App Store で無料パズル 1位・全ゲーム 2位**（2026-09-17 取得。
  https://apps.apple.com/jp/iphone/charts/7012 、https://m-s-y.com/app/ranking/top-free-all-games/ ）
  のアプリの中身が、**「各行・各列・各領域に星（女王）を1つずつ置き、斜めを含めて隣接させない」**
  という 2003年の世界パズル選手権で発表された公知の形式（Star Battle の 1★版。
  https://www.gmpuzzles.com/blog/star-battle-rules-and-info/ ）。
  LinkedIn の日替わりパズル「Queens」（2024年〜）も同じルールで、**ブラウザで遊べる日本語の実装は少ない**
- 当サイトのパズル（ナンプレ・ノノグラム・色水ソート）は**「必ず解ける・答えは 1 通り」を生成器で保証する**
  型で作ってきた（`games/lib/nanpre.ts` の `countSolutions()`、`nonogram.ts` の唯一解チェック）。
  星配置パズルは同じ型で作れる（N-Queens の解を先に置き、領域を育て、唯一解を検証する）
- GA4 直近28日（2026-09-17 取得）：`/games/` はデスクトップが多数派だが、
  **ブロックパズル 平均 800秒・マインスイーパー 783秒・ノノグラム 363秒**と、
  盤面パズルは滞在が長い。星配置は 1問 1〜3分で「もう 1問」が効く**反復型**で、
  日替わり（日付シード）を置けば再訪の理由になる
- 権利関係：ルールは公知・著作権の対象外。盤面は自前生成、星の絵柄も自前 SVG（花札で確立した作法）。
  避けるのは**名称・キャラクター・配色の模倣**だけ

## 提案する仕様

### 遊び方

1. N×N の盤（5×5〜10×10）が N 個の領域に色分けされている
2. **各行・各列・各領域に星をちょうど 1 つ**置く。**星どうしは斜めを含めて隣接してはいけない**
3. タップで「空 → ×（星は置けない）→ ★ → 空」を循環。ドラッグで × をまとめて塗れる
4. 全部の星を正しく置くとクリア。**矛盾したマス（同じ行・列・領域に 2 つ、隣接）は赤く**出す

### サイズと難易度

| レベル | 盤 | 生成の狙い |
|---|---|---|
| かんたん | 5×5・6×6 | 領域が細長く、消去法で決まるマスが多い |
| ふつう | 7×7・8×8 | 「この領域は 2 行にまたがるので、この行の他のマスは ×」の推論が要る |
| むずかしい | 9×9・10×10 | 領域の形が入り組み、複数領域をまとめて見る推論が要る |

- **日替わり**（`games/lib/star-placement.ts` の `dailySeed(date)` で日付から乱数を作る。
  `bouldering-merge.ts` の `nextRandom(seed)` と同じ mulberry32 系）と**エンドレス**（乱数）の 2 モード
- 記録は `lib/records.ts`（[game-records.md](./game-records.md)）で **クリア数・最短タイム**（サイズ別）。
  ゲームごとの localStorage キーは作らない

### 生成器（`games/lib/star-placement.ts`。純関数・乱数注入）

1. **配置を先に決める**：N-Queens の「斜め隣接だけ禁止」版（通常の N-Queens より緩い。同じ対角線上でも
   隣接しなければ可）をバックトラックで 1 つ作る（乱数で列の順をシャッフル）
2. **領域を育てる**：N 個の星をそれぞれ種にして、隣接マスへランダムに広げる（BFS。領域の大きさに
   ばらつきを持たせる）。すべてのマスがどれかの領域に属するまで
3. **唯一解の検証**：行ごとに星の位置を選ぶバックトラック（`countSolutions(limit = 2)`）。
   2 つ以上解があれば **2 に戻って領域を作り直す**（最大 N 回。それでも駄目なら 1 から）
4. 難易度は「解くのに必要な推論の深さ」で測りたいが初版はサイズで代用し、
   **生成時間の上限（10×10 で 200ms 以内、テストで固定）**だけを守る

### 画面（games の「画面の約束」に従う）

- 盤は正方形。`max-width: min(var(--board-max), max(200px, calc(100dvh - var(--chrome))))` で
  高さからも決める。**10×10 でもマスは 44px を割らない**ように、`--board-max` を 480px にし、
  狭い画面では 10×10 のマスが 32px になるのを許容するか、むずかしいを 9×9 までにするかを実装時に
  Playwright の実測で決める（44px の下限を優先）
- ヒントボタン：**矛盾のあるマスを示す**だけ（答えを教えない）。`phase` で出し分け、
  クリア後は盤を固定して「次の問題」「日替わりに戻る」を出す
- 演出（クリア時の星の光り）は `Game.tsx` の ref に持つ（`lib/` の状態に入れない）
- アイコン：**`Star`**（Phosphor。games では未使用）。`games/app/GameIcon.tsx` の import と一覧に足す。
  実装時に存在を確認

### SEO

- 想定キーワード：「スターバトル パズル」「星 パズル 無料 ブラウザ」「クイーンズ パズル 日本語」
  「一列一つ パズル」。ビッグワードは無く、**アプリのランキング上位で「ブラウザで遊びたい」需要が
  検索に流れる**のを拾う
- 本文に「解き方のコツ」（1 領域が 1 行に収まるならその行の他マスは ×、2 領域が 2 行に収まるなら
  他の領域はその 2 行に星を置けない、など）を 3〜4 個。ナンプレ・ノノグラムへの内部リンク
- `metadata` に `robots: robotsFor('star-placement')`（feature-flags の約束）
- 先行アプリの名称を本文・`description`・FAQ に書かない（「〇〇風」と書かない）

## 公開の判定リスト（preview に上げる条件）

- [ ] 生成器の唯一解テスト（各サイズ 20 問を固定シードで生成し `countSolutions() === 1`）が通る
- [ ] 生成時間の上限テスト（10×10 で 200ms）が通る
- [ ] 隣接判定（斜め含む）・行/列/領域の重複判定のテストが通る
- [ ] 日替わりのシードが日本時間の日付で切り替わる（UTC で切り替わらない）
- [ ] 390px 幅で 8×8 までマスが 44px 以上、10×10 でも盤が 1 画面に収まる（Playwright 実測）
- [ ] 記録（クリア数・最短タイム）が `records` に保存され再訪時に出る

## やらないこと

- **2★版（各行・列・領域に星 2 つ）。** ルールの説明が倍になり、初版の対象（アプリで 1★に慣れた人）
  とずれる。次版候補
- **自動で「次に確定するマス」を教えるヒント。** 解答の一部を渡すことになる。矛盾の表示だけ
- **対戦・ランキング。** サーバーが要る。自己記録のみ
- **猫・女王などのテーマ付け。** 先行アプリの要素を避け、星と抽象的な色分けだけにする
