### 競合の状況（2026-11-18 の Web 調査）

「勤務時間 計算」「時間 足し算」で上に出るものは、出勤・退勤・休憩から実働を出す・日またぎ（夜勤）を翌日扱いにする・
小数時間（8:30 → 8.5）を出す、まではどれも揃っている（海外の勤怠 SaaS の日本語版、個人の計算サイト、有料の iPhone アプリなど）。
調べた範囲で足りていないのは次の 4 点で、ここを差別化にする：

1. **1日の計算と「月の合計」が別のページ・別のアプリに分かれている。** 1日ずつ出してから電卓で足すことになる。
   **1行＝1日で何行でも足せ、Excel・スプレッドシートの列（`9:00	18:00	1:00` のタブ区切り）を貼れば一括で月の合計**にする
2. **日本の労働法の目安（休憩・深夜・8時間）を出すものが少ない。** 海外製は深夜の 22〜5 時も、休憩の 45分／60分も知らない。
   **「6時間を超えるのに休憩 45分未満」「深夜 22〜5 時に ◯時間◯分」「8時間を超えた ◯時間◯分」を印で出す**（判定ではなく目安。下「やらないこと」）
3. **端数の丸めの扱いが書いていない／毎日 15分単位で切り捨てる設定を既定にしているものがある。**
   通達（昭和63年3月14日 基発第150号）は**1日ごとの切り捨てを認めていない**。認めるのは「**1か月の時間外労働・休日労働・深夜業それぞれの時間数の合計**の 30分未満切り捨て・以上切り上げ」だけで、
   **ふつうの労働時間（実働）の合計を丸めてよいという定めではない**（実働を丸めて払わないと全額払いの原則・労基法24条にぶつかる）。
   **既定は丸めなし**、丸めは「8時間を超えた時間の月の合計」と「深夜の月の合計」にだけ選べるようにし、**実働の合計と時給の額には丸めを置かない**。毎日の切り捨ての設定も置かない
4. **Excel で同じことをする式が無い。** 「24時間を超えると 0:30 に戻る」「8:30 を 8.5 にしたい」は Excel の検索で非常に多い。
   **結果の下に、同じ計算の Excel の式（`[h]:mm` の表示形式・`=(B2-A2-C2)*24`・日またぎの `MOD`）を1つずつ出し、コピーできる**

**本文には競合の名前を出さない**（JSON 整形の企画レビュー #444 の約束と同じ）。

## 提案する仕様

### 3つのタブ（同じページ・URL は変えない）

#### A. 勤務時間（既定のタブ）

- **入力**：1行＝1日。`出勤`・`退勤`・`休憩`（分か `h:mm`）。行の追加・削除、`Excel から貼り付け`（タブ・カンマ区切りの 2〜3 列）
- 時刻の入力は `9:00`・`900`・`9時`・`９：００`（全角）を受け付ける（`tools/lib/hankaku-zenkaku.ts` の `convertWidth` で半角にしてから読む）。
  `24:00`〜`29:59` の「25時表記」も受け付け、翌日の時刻として読む
- **退勤が出勤より前（または同じ）なら翌日の退勤**とみなし、行に「日またぎ」の印を出す
- **1行ごとの結果**：拘束時間・実働時間（`h:mm` と 10進数の両方）・深夜（22〜5 時）の実働・8時間を超えた実働・休憩の不足の印
  - 休憩を**いつ取ったか**は聞かない。そのため深夜帯の実働は**幅で出す**：「**最小（休憩を全部深夜帯に取った）〜 最大（休憩を全部深夜帯の外で取った）**」。
    最小 = `max(0, 深夜帯の拘束 − 休憩)`、最大 = `min(深夜帯の拘束, 実働)`。最小と最大が同じなら1つの値だけ出す。
    最大だけを出すと、深夜手当を請求する根拠として多めの数字が一人歩きしかねないため（決めること 1）
- **合計**：日数・実働の合計（`168:45` のように 24時間を超えて表示）・10進数（168.75 時間）・深夜の合計・8時間を超えた時間の合計
- **時給**（任意）を入れたら、`実働 × 時給` の額を出す。**割増は出さない**（残業代は `zangyodai-keisan` へのリンク。「時間外・深夜の割増は残業代の計算機で」）
  - 額は**円未満も小数第2位まで表示**し（例 `8,990.67円`）、その横に四捨五入した `8,991円` を「目安」として添える。**切り捨ての選択肢は置かない**（ツールが「切り捨てて払ってよい」と勧めているように見えるため）
  - 注記：「基発第150号の (2)(3) は1時間あたりの賃金額・割増賃金額と、1か月の割増賃金の総額の端数についての定めで、ふつうの賃金の円未満を切り捨てて払ってよいという定めではありません。実際の支払いは就業規則・賃金規程によります」

#### B. 時間の足し算・引き算

- `1:30 + 0:50 − 0:15` の形で何行でも。行頭の `+`／`−` で足すか引くかを切り替える
- 入力は `h:mm`・`h:mm:ss`・`90分`・`1.5時間`（10進数）を受け付け、混ぜてよい
- 結果は `h:mm(:ss)`・合計の分・10進数の時間・「◯日と◯時間◯分」の4つ。マイナスになったら `−0:25` と符号つきで出す

#### C. 10進数 ⇔ 時分の換算

- `7:45` → `7.75 時間`、`7.8 時間` → `7:48`、`465 分` → `7:45` の3方向。早見表（15分刻みの 0:15＝0.25 … 1:00＝1.00、と 5分刻み）を本文に置く
- **10進数への換算は分を整数で持ってから `÷ 60`** し、表示時だけ小数第2位で丸める（`7:20` は `7.33…`。途中で丸めた値をさらに掛けない）

### スマホ（幅 390px）の画面の形

- **横スクロールを出さない**（320px 幅でも）。勤務時間のタブは表ではなく**1日＝1枚の行**にする：
  - 1段目：`出勤`・`退勤`・`休憩` の3つの入力と、右端に**実働**（`8:00`）だけ
  - 2段目（小さい文字）：`深夜 0:00〜1:00`・`8h超 0:15`・休憩の不足の印・日またぎの印。値が 0 のものは出さない
  - 拘束時間・10進数は2段目にも出さず、**合計の欄**と、行を押して開く詳細にだけ出す
- パソコン（幅 900px 以上）は同じ部品を横に広げ、2段目を1段目の右に並べる（表の形にしてよい）
- **合計の欄は行の一覧の上**に置く（20行を貼ったあと、スクロールせずに合計が見える）
- 時刻の欄は `inputMode="numeric"`（`type="text"`）にし、`900` → `9:00`・`1730` → `17:30` をスマホのテンキーだけで打てるようにする（`:` を打たせない）。休憩の欄も同じ（`60` → 60分、`100` → `1:00`。3桁以上は `h:mm` と読む）
- 入力欄の文字は 16px（iOS Safari の拡大を防ぐ。`app/unix-jikan/Calculator.tsx` の `FONT_SIZE` と同じ）
- **タブ3つは新しい部品を作らず**、`app/unix-jikan/Calculator.tsx` と同じ `buttonStyle`（`minHeight: 44`、選ばれているものは `var(--accent)` の枠）と `aria-pressed` の切り替えボタンに揃える

### 計算の約束（`lib/jikan-keisan.ts`。純関数）

1. **時間はすべて整数の秒で持つ。** 小数の時間（`8.5`）は入力時に秒へ直し、表示のときだけ戻す（二進小数の誤差で `0.1 + 0.2` 型のずれを出さないため。`shohizei.ts` の教訓）
2. 深夜帯は**区間の重なり**で数える：勤務 `[出勤, 退勤)` と、前日・当日・翌日の `[22:00, 29:00)` の和集合の重なり。
   36時間を超える勤務は1行で受け付けない（入力の誤りとして止める）
3. 丸めは**「8時間を超えた時間の月の合計」と「深夜の月の合計」にだけ**、`zangyodai.ts` の `roundHoursSimplified` を import して使う。**実働の合計・時給の額・1日ごとの値には丸めを持たない**。
   `roundHoursSimplified` は時間（小数）を受け取るので、**秒の合計を分の整数に直して（秒は切り捨て）から ÷60 して渡す**（`20:29:30` のような秒の端数で切り上げ・切り捨てが入れ替わる事故を防ぐ）
4. 時給の額は `秒 × 時給` を整数で出し、`÷ 3600` は表示のときだけ（小数第2位まで表示・四捨五入の目安を併記。切り捨ては出さない）
5. Excel の式は**入力の並び（A列=出勤・B列=退勤・C列=休憩）を前提にした固定の文字列**で出す：
   実働 `=MOD(B2-A2,1)-C2`、10進数 `=(MOD(B2-A2,1)-C2)*24`、合計の表示形式 `[h]:mm`。
   **C列の休憩が時刻の形（`1:00`）のときだけ正しい**ので、式の横に「休憩を分（`60`）で入れているなら `C2` を `C2/1440` に」と但し書きを添え、その形の式も出す（`=MOD(B2-A2,1)-C2/1440`）。
   「60 を引いたらマイナスになった」は Excel の質問で多い

## 確かめること（テストとテスト環境）

`tests/jikan-keisan.test.ts` に次を入れる（一次資料の数字と境界値）：

1. `9:00〜18:00・休憩60分` → 実働 8:00・10進数 8.00・8時間超 0:00・休憩の不足なし
2. `9:00〜18:00・休憩45分` → 実働 8:15・**8時間を超えるので休憩不足の印**（34条：8時間超は60分）
3. `9:00〜15:00・休憩0分` → 実働 6:00・**ちょうど6時間は不足の印なし**／`9:00〜15:01・休憩0分` → 印あり
4. `22:00〜翌7:00・休憩60分` → 日またぎ・実働 8:00・深夜帯の拘束 7:00 → 深夜の実働は **6:00〜7:00**（最小＝休憩を深夜帯に取った・最大＝外で取った）
   ／`9:00〜18:00・休憩60分` → 深夜は 0:00 だけ（幅を出さない）
5. `17:00〜26:00`（25時表記）と `17:00〜2:00` が同じ結果になる
6. 足し算：`1:30 + 0:50 − 0:15` = `2:05`、`23:30 + 1:00` = `24:30`（0:30 に戻らない）
7. 換算：`7:45` ⇔ `7.75`、`7.8` → `7:48`、`7:20` → `7.33`（表示）だが内部は 26,400 秒のまま
8. 時給 1,226 円 × 7:20 = 8,990.666… → 表示 `8,990.67円`・目安（四捨五入）`8,991円`。**切り捨ての値を返す関数・表示が無い**ことも確かめる
9. 合計の丸め（丸めを選んだとき）：**8時間を超えた時間の月の合計** `20:29` → 20:00、`20:30` → 21:00、`20:29:59` → 20:00（分に切り捨ててから渡す）。深夜の合計も同じ。
   **実働の合計は 168:45 のまま変わらない**（丸めの選択に関係なく）。結果は `zangyodai.ts` の `roundHoursSimplified` と一致する

テスト環境では 1366×768（パソコン）と 390×844・320×568（スマホ）で、20行を貼り付けたときに**横スクロールが出ない**こと・合計が一覧の上に見えること・時刻の欄でテンキーが出ることを見る。

## 決めること（実装前に運営者と）

1. **深夜帯の実働の扱い**：休憩の時間帯を聞かない代わりに「最小〜最大」の幅で出す（既定。レビュー #520 の推奨）か、休憩の開始時刻の入力欄を任意で足して1つの値にするか
2. **休憩の不足の印**：34条の判定の基準（実働か拘束か）を一次資料で確かめられなかったときは、印を出さず注記だけにする（既定）
3. **入力を `localStorage` に残すか**：既定は残さない（共用 PC の配慮）。残すなら「この端末に保存」のスイッチを既定オフで
4. **slug**：`jikan-keisan`（既定）か `kinmu-jikan`。「時間計算」の語が最も広いので前者を推す

## やらないこと

- **違法かどうかの判定**：変形労働時間制・フレックス・管理監督者・36協定の上限は判断しない。「法定の目安」とだけ出す
- **割増賃金の計算**：`zangyodai-keisan` の仕事。ここでは時給 × 実働のみ
- **シフト表・勤怠の保存・共有・CSV の書き出し**：勤怠システムを作らない（コピーで足りる）
- **タイムゾーン・夏時間**：日本の勤務を前提に、壁時計の時刻だけで計算する
- **民間の勤怠ソフト・SaaS の名前を出すこと**
