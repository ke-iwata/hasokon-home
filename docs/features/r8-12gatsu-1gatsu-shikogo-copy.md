### iDeCo の「70 歳まで加入」の条件が、厚労省資料より狭く書かれている

本文と FAQ は「**老齢基礎年金・iDeCoの老齢給付金を受給していないことが条件です**」とだけ書いている。
厚生労働省「iDeCo 加入可能年齢の引上げについて」（https://www.mhlw.go.jp/content/12500000/001714615.pdf 、2026-10-07 取得）では、
国民年金被保険者**以外**の 60 歳以上 70 歳未満の人が加入できるのは次のいずれかで、**令和 8 年 12 月から**：

1. 申出の日の前日に **iDeCo の加入者**（掛金を拠出）だった人
2. 申出の日の前日に **iDeCo の運用指図者**（拠出せず運用のみ）だった人
3. **企業型 DC 等の年金資産を iDeCo に移換する**人

さらに【留意事項】として「**経過措置期間である令和 11 年 11 月末までは、対象者パターン１～３に該当しない 60 歳～70 歳未満の方であっても、新たに iDeCo に加入することができます**」。
加えて、各社の解説（楽天証券・りそな銀行・マネイロ ほか）は**企業型 DC でマッチング拠出をしている人は iDeCo に加入できない**点を条件に挙げている。
**ただし上の厚労省 PDF にはマッチング拠出の記載が無く、根拠は民間の解説だけ**（2026-10-07 時点）。扱いは下記 B の条件つき。

いまの書き方だと、

- 「60 代で iDeCo を初めて始められるのは 2029-11 末までの経過措置」であること（**2029-12 以降は加入歴が要る**）が分からない
- （一次情報で確認できれば）マッチング拠出中の会社員が「70 歳まで iDeCo で積める」と読める

**誤った金額は出していない**（累計は「加入し続けた場合」の計算で、条件 1 に当たる）が、**条件の説明が足りず、読み手が自分は対象だと誤解しうる**。

### B. iDeCo の 70 歳の条件（すぐ直してよい）

- 本文の h2「加入できる年齢も 70 歳未満まで…」の段落と FAQ を、上の厚労省資料の 3 パターンで書き直す：
  「**60〜64 歳で会社員・公務員（第 2 号）や国民年金の任意加入の方は、これまでどおり加入できます。**国民年金に加入していない 60〜69 歳の方は、①直前まで iDeCo に掛金を出していた ②直前まで運用指図者だった ③企業型 DC などの資産を iDeCo に移す、のいずれかなら 70 歳まで加入できます。
  **2029 年 11 月末までは経過措置で、これに当たらない方も新たに加入できます。**老齢基礎年金や iDeCo の老齢給付金を受け取り始めた方は加入できません。」
- **マッチング拠出の除外は、一次情報（厚労省の Q&A・国民年金基金連合会の iDeCo 公式・確定拠出年金法の法令解釈通知）で確認できた場合だけ**、出典つきで上の文に「企業型 DC でマッチング拠出をしている方も加入できません」を足す。**確認できなければ本文に書かない**（民間の解説だけを根拠にしない）。2025 年の年金制度改正法ではマッチング拠出まわりの見直しもあるので、**12-01 の施行日時点のルール**で書く
- 累計の表示（65 歳まで・70 歳まで）に注記を 1 行：「70 歳までの累計は、60 歳以降も加入を続けられる条件に当たる場合の計算です」
- 定数を足す：`lib/ideco.ts` に `KEIKA_SOCHI_UNTIL = '2029-11-30'`（経過措置の終わり）。本文の日付はこの定数から組み立てる
- 出典に厚労省 PDF（上記）を足す

### D. CI で止める（`post-effective-copy.test.ts` にエントリを足す）

```ts
{ slug: 'ideco', effectiveOn: REFORM_EFFECTIVE_FROM,
  patterns: [/6\.2万円に。/, /6\.2万円へ/, /6\.2万円になります/],
  // title は page.tsx の const title にあり description の検査では見えないので、本文側にも入れる
  sourcePatterns: [/6\.2万円へ/, /6\.2万円になります/, /いますぐ月6\.2万円/, /必ず並べて表示します/, /広がります/, /延びます/, /引き上げられます/, /7\.5万円になります/, /から出せる額は違います/],
  extraFiles: ['Calculator.tsx'], extraPatterns: [/延びます（老齢基礎年金/],   // Calculator は extraPatterns だけで見る（下記）
  description: String(idecoMeta.description) },
{ slug: 'tedori-keisan', effectiveOn: WITHHOLDING_TABLE_EFFECTIVE_ON,
  patterns: [], sourcePatterns: [/給与明細に現れるのは2027年1月から/, /天引きが変わるのは2027年1月から/], ... },
{ slug: 'iryohi-kojo', effectiveOn: SELF_MED_REFORM_EFFECTIVE_ON,
  patterns: [], sourcePatterns: [/見直されるので/], ... },
```

- **`Calculator.tsx` も検査する**：いまの `Entry` は `../app/${slug}/page.tsx` しか読まない。`extraFiles?: string[]` を足し、同じディレクトリのファイルを `extraPatterns` で検査する（`sourcePatterns` は page.tsx 用のまま）。
  ただし Calculator の「延びます」「倍になります」は `reformApplied` の分岐で**施行前の枝に残るのが正しい**ので、Calculator には別の `extraPatterns` を持たせ、
  **分岐の外に置いてはいけない文面**（`/延びます（老齢基礎年金/`＝条件つきの旧い注記）だけを見る。分岐が正しく効くかは `ideco.test.ts` に
  「asOf 2026-12-01 で `reformApplied` が true」の既存ケースがあり、表示の文面は Calculator のレンダリングテストを 1 件足して見る（asOf 2026-12-01 で「延びました」「倍になりました」が出る）
- 手取り計算 FAQ の「月々の天引きが変わるのは2027年1月からです」は、施行後は「**2027年1月から月々の天引きが変わりました**」に決め打ちする（`sourcePatterns` の `/天引きが変わるのは2027年1月から/` と対応）
- テストは**実行した日**で判定するので、エントリを今入れても 12-01 までは緑のまま。**12-01 の朝から main の CI が落ちる**ことで、A の切り替え漏れが必ず目に入る
- 期日前に未来形が**ある**ことは検査しない（10-01 分と同じ）
