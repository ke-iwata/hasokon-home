# 新ツール「パスワード生成」（完全ローカル生成系の2本目）

**状態**：提案（2026-08-18 起票）。実装時は `wip` で入れ、ページ・テストが
揃ったPRで `public` に上げる（home のカード・llms.txt は公開PRで追加）
**対象**：`tools/`（`hasokon.com/tools/password/`）
**起票**：2026-08-18

---

## 背景と根拠

### 「ローカル生成×信頼」の路線を1本で終わらせない

QRコード作成（[qr-code-seisei.md](./qr-code-seisei.md)・preview 中）で
開拓した「**ブラウザ内で完結・データ送信なし**」の生成系ジャンルは、
パスワード生成と最も相性がよい。パスワードは**入力・生成した値を外部に
送ってはいけない**性質のデータそのもので、「パスワード 生成 安全」
「パスワード ジェネレーター 信頼できる」という不安クエリが恒常的にある。
サーバー生成のサービスに対して、静的サイト＋Web Crypto という構成は
「送信しようがない」ことをコードの構造で説明できる。

### 「パスワード生成」は年間を通じた大ボリューム定番

「パスワード 生成」「パスワード 作成 自動」「強力なパスワード」は
季節変動のない恒常クエリで、主要ツールサイト（LUFT・ラッコツールズ等）が
必ず備える定番。当サイトのツール群（計算系・テキスト系・生成系）に対し、
**セキュリティ系の入口が1本もない**のはジャンルの欠けとして大きい。
文字数カウント（[mojisu-count.md](./mojisu-count.md)）と同じく
「実装が軽く、恒常需要があり、面の幅を広げる」枠。

## 提案する仕様

1. **生成（すべてブラウザ内・Web Crypto）**
   - 乱数は **`crypto.getRandomValues()` のみ**を使う（`Math.random()` 禁止。
     剰余バイアスを避ける棄却サンプリングで文字を選ぶ。ここはテストで固定）
   - 長さ 8〜64（既定 16）。文字種は 英大文字／英小文字／数字／記号 の
     ON/OFF と「紛らわしい文字（l, 1, I, O, 0 等）を除く」オプション
   - ON にした文字種が**必ず1文字以上含まれる**ことを保証する
     （含まれるまで引き直すのではなく、各種1文字を先に確保してから
     シャッフルする決定的な方法。偏りが出ない設計であることをテストで固定）
   - 一度に10件まとめて生成し、1クリックコピー。**生成結果はどこにも
     保存しない**（localStorage にも残さない）ことを明記
2. **強度の目安表示**
   - 選んだ設定のエントロピー（bit）と「総当たりにかかる時間の目安」を表示
   - 根拠の計算式（log2(文字種数^長さ)）を本文で説明し、目安であることを断る
3. **パスフレーズモード（差別化の柱）**
   - 単語をつなぐ方式（例：4〜6語・区切り記号選択）。日本語ローマ字の
     単語リストを同梱し、これもローカル生成。「覚えやすく長い」の受け皿
4. **解説コンテンツ（このページの本体）**
   - 総務省・IPA の公表資料に沿った「安全なパスワードの条件」
     （長さ優先・使い回し禁止・定期変更の強制は不要になった経緯）を、
     一次情報へのリンクつきで解説
   - 「無料パスワード生成サイトは安全か」の判断基準（通信の有無・
     保存の有無）を、当サイト自身の構成を例に説明
   - FAQ（JSON-LD）：「生成したパスワードは送信される？」「何桁あれば安全？」
     「記号は入れるべき？」「パスフレーズとは？」
5. **テスト**
   - 棄却サンプリングの範囲・文字種保証・長さ・「紛らわしい文字除外」の
     文字集合・エントロピー計算を単体テストで固定
   - `stage.test.ts` の robots 検査に乗せる（`robots: robotsFor('password')`）
6. **registry**：`stage: 'wip'` で追加。カテゴリは QR コードと同じ生成系の並び

## やらないこと

- パスワードの強度判定機（既存パスワードを入力させる機能）。
  **入力させないこと自体が信頼の設計**なので、生成専用にする
- パスワード管理（保存・同期）機能
- 外部ライブラリの追加（既存の依存方針どおり自前実装）

## 期待される効果

- 大ボリューム恒常クエリ「パスワード 生成」群への受け皿。本体クエリでの
  急上位は狙わず、QR と同じく「パスワード 生成 安全」「パスワード 生成
  オフライン」等の**不安解消ロングテール**を解説の厚みで取る
- セキュリティ系ジャンルの1本目としてサイトの面を広げ、
  「登録不要・データ送信なし」というサイト共通の売りを強化する
- 効果は GSC の `/tools/password/` の表示・クリックで計測

## 工数（消費トークン目安）

約100k〜140k（生成ロジック＋テスト 40k、UI 30k、解説・FAQ 執筆 30k〜50k、
パスフレーズ用単語リスト 20k）。レビュー往復込みで180k以内。
QRコード（260k〜310k）より軽く、mojisu-count より一回り大きい規模。
