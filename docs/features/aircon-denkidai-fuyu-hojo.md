### 制度（一次情報で確認。2026-11-13）

経済産業省 資源エネルギー庁「電気・ガス料金支援」<https://denkigas-gekihenkanwa.go.jp/>：

|---|---|---|---|

## 作るもの

### A. 「冷房／暖房」の切り替え

- 計算機の先頭に `冷房｜暖房` のトグル。**既定は日付で決める**（11〜3月は暖房、それ以外は冷房）。式は同じ（W ÷ 1000 × h × 単価）
- 暖房のときはプリセットの消費電力を暖房の値に差し替える。**値は実装時に資源エネルギー庁「省エネ性能カタログ」または
  メーカーの公表値（定格消費電力・暖房）から畳数ごとに取り、出典を本文に書く**（この仕様書では数値を決めない。根拠のない数字を置かないため）
- 「暖房は外気温が低いほど消費電力が増える（定格より大きくなることがある）」を結果の下に1行
- 例・FAQ に暖房の例を1つずつ足す（「暖房 1時間 いくら」「つけっぱなしと こまめに消す」）

### B. 電気・ガス料金支援の値引きを、使用月で自動で引く

- `tools/lib/denki-gas-shien.ts`（新規）に表をデータで持つ：

  ```ts
  // 出典: 資源エネルギー庁「電気・ガス料金支援」https://denkigas-gekihenkanwa.go.jp/（2026-11-13 確認）
  export const SHIEN_PERIODS = [
    { usageMonth: '2026-12', lowVoltageYenPerKwh: 1.0, cityGasYenPerM3: 4.0 },
    { usageMonth: '2027-01', lowVoltageYenPerKwh: 4.5, cityGasYenPerM3: 18.0 },
    { usageMonth: '2027-02', lowVoltageYenPerKwh: 4.5, cityGasYenPerM3: 18.0 },
  ] as const;
  export function discountFor(usageMonth: string): { lowVoltage: number; cityGas: number } | null;
  ```

- 計算機に「**使用月**」の選択（既定は今日の月）。支援の月なら、結果に
  「**補助の値引き後：○円／月（値引き −○円）**」の行を足し、単価は `入力単価 − 値引き` で計算する（入力単価は税込の目安のまま）
- 支援の月でなければ行を出さない（**期間が過ぎたら自動で消える**。手で消し忘れても嘘にならない）

### C. 「今月の請求でいくら引かれるか」の小さな計算（同じページの下の節）

- 入力：**検針票の使用量（kWh）**と**「使用月で見る／請求月で見る」の切り替え**（**電気だけ**。エアコン電気代のページの主題をぼかさないため、都市ガスは B の表に1行添えるだけにする）
- 出力：値引き額（例：260kWh × 4.5円 = **1,170円**）と、「この値引きが載る請求書は ○月分」
- 置き場所は計算機の下の節（スマホでは折りたたみ）。1画面目には入れない
- 請求月で見るときは「検針日によって1か月ずれることがある」を必ず添える（使用月の定義は上の表のとおり）
- 「申請は不要。値引きを理由に個人情報や手数料を求める電話は詐欺の可能性」を1行（公式ページの注意喚起に沿う）

### D. 期日つきの文言の出し分け（本番で嘘にならないために）

**`tools/` は Next.js の静的エクスポートなので、`page.tsx` の本文・`metadata.description`・FAQ の JSON-LD はビルドした日の内容で固まる。**
日付で出し分けるものを、次の2つに分けて書く（[nenmatagi-2027-rollover.md](./nenmatagi-2027-rollover.md)「ページを開いた日で切り替える作りは、ビルドとずれる」と同じ問題）。

| 決まるとき | もの | 書き方 |
|---|---|---|
| **ビルドのとき** | `metadata`（title・description）、FAQ と JSON-LD、本文の支援の節の文 | **期間が過ぎても嘘にならない書き方にする**：「2026年12月〜2027年2月使用分の値引き（低圧 1.0円／4.5円/kWh）」のように期間を書き、「現在」「今月」「いま」と書かない |
| **開いたとき** | 冷房／暖房トグルの既定、使用月の既定、支援の行を出すか、下の表の言い回し | `otc-ruijiyaku/Calculator.tsx` と同じく **`useEffect` で後から入れる**（初期描画は日付に依らない既定）。`useState(() => new Date())` は使わない（ハイドレーションの食い違いを避ける） |

- そのうえで、ビルドで固まる文の切り替えのために **2027-03-01 と 2027-05-01 の後に tools を再リリースする**（状態行と下の表に書く。リリースは運営者の承認が要るので、それぞれ前週にテスト環境の確認を依頼する）
- 説明文に入れる「電気代の補助」は、**2027-05-01 後の再リリースで外す**（暖房の語は残す）

開いたときに決まるものの出し分け：

| 日付 | 表示 |
|---|---|
| 〜2027-02-28 | 支援の節を本文の上の方に置き、FAQ「電気代の補助はいつから・いくら？」を出す |
| 2027-03-01〜2027-04-30 | 「2027年2月使用分で終了（3〜4月の請求書まで値引きが載ることがある）」に言い換える |
| 2027-05-01〜 | 節ごと畳む（`SHIEN_PERIODS` は残し、過去の制度として FAQ 1問だけ残す）。**ビルドで固まる FAQ・説明文は 05-01 後の再リリースで差し替える** |

- 境目の日付は `denki-gas-shien.ts` の定数にし、`tools/tests/denki-gas-shien.test.ts` で
  **「日付を差し込んで」**出し分けを確かめる（今日の日付で分岐するテストにしない。元日・3月に落ちる検査を増やさない＝[nenmatagi-2027-rollover.md](./nenmatagi-2027-rollover.md) の教訓）
- 支援が延長・3月分追加になったら `SHIEN_PERIODS` に1行足すだけで済む形にする

### E. ついでに直すもの（2026-11-04 の精査の残り）

- 「設定温度を1度変えると約10%の省エネ」に出典を付ける（資源エネルギー庁「省エネポータルサイト」の家庭向け省エネの目安。
  **冷房と暖房で目安が違うので、A のトグルに合わせて書き分ける**）。出典が取れなければ文を消す
- 説明文（`metadata.description`）と registry の説明に「暖房」「電気代の補助」を入れる。`updatedAt` を上げる（sitemap の `lastmod`→ IndexNow で Bing に通知される）

## やらないこと

- 電力会社・プランごとの単価のデータ化（入力で足りる。民間の料金表は更新を追えない）
- LP ガス・灯油の暖房費（制度の対象外で、別ツールの候補として残す）
- **都市ガスの値引き額の計算**（エアコンのページの主題から外れる。要るなら「ガス代の計算機」として別ツールの候補にする）
- 高圧（法人）向けの計算（家庭の需要に絞る。高圧の単価は表にだけ載せる）

## 期待される効果

- **夏以降 0 PV の公開ページを、12〜2月にもう一度使わせる。** 冬の検索語（暖房・補助金）と、記事しか無い「補助の値引き額の計算」を取りに行く
- 公的支援の値引きを**使用月と請求月の両方で**出すことで、検索で多い「いつの請求から安くなる？」に答える
- 制度の表を lib に持つので、次の支援（夏・冬の再開）は1行足すだけで反映できる
- 測り方：12-01〜02-28 の `/tools/aircon-denkidai/` の PV（**下限 30**）と `tool_use`、C の計算の実行回数
