## 1. 半角⇔全角：①・※・○・×・℃ などを「半角」に数える（計算の誤り）

### 現状

- `tools/lib/hankaku-zenkaku.ts` の `countChars`（全角の判定は U+1100〜・U+2E80〜A4CF・FFxx・絵文字・追加面の漢字だけ）
- そのため、日本語の文書で普通に使う**全角の記号**が半角 1 文字として数えられる。例（いずれも JIS X 0208 にある全角文字）：

| 文字 | コードポイント | いまの判定 | 正しい判定（「全角2・半角1」のフォーム） |
|---|---|---|---|
| ① ② | U+2460〜 | 半角 | 全角 |
| ※ | U+203B | 半角 | 全角 |
| → ← | U+2190〜 | 半角 | 全角 |
| ○ ● ■ □ ◆ | U+25A0〜 | 半角 | 全角 |
| ★ ☆ ♪ | U+2600〜 | 半角 | 全角 |
| ℃ | U+2103 | 半角 | 全角 |
| × ÷ ° § | U+00D7・00F7・00B0・00A7 | 半角 | 全角 |
| α β Ω | U+0391〜03C9 | 半角 | 全角 |
| ─ │（罫線） | U+2500〜 | 半角 | 全角 |
| “ ” ‘ ’ … ‥ | U+2018〜2026 | 半角 | 全角 |

- ページは「『全角2文字・半角1文字』で数えるフォーム向けに、変換前後の内訳を表示しています」とうたっている（`page.tsx` の「文字数制限を確認する」）。
  **内訳が少なく出ると、制限を超えた文章を「収まる」と思わせる**ので、文言ではなく計算の誤り

### 原因

Unicode の East Asian Width は、これらを **Ambiguous（A：文脈で幅が変わる）** に分類している。コードの判定は Wide（W）と Fullwidth（F）だけを全角にしていて、
A を半角側に倒している。**日本語の文脈（Shift_JIS・JIS X 0208 のフォーム）では A は全角**として扱うのが通例。

### 提案する仕様

**原則（2026-10-13 企画レビュー #382 で決定）：「ASCII と半角カナ類だけを半角、それ以外はすべて全角」に倒す。**
一覧に無い文字で迷ったら全角。このツールの用途は「文字数制限を超えていないか」の確認なので、外れるなら**多めに数える側（安全側）**に外す。
JIS X 0208 の表で 1 文字ずつ判定する方式（案 a）は採らない。範囲の取り違えで少なく数える側に外れる余地が残り、表の保守も要るため。

- `countChars` の判定を「全角の範囲を列挙する」から「**半角の範囲を列挙し、それ以外を全角**」に裏返す。半角は次の 3 つだけ：
  - U+0000〜007F（ASCII。改行・タブを含む。いまと同じ）
  - U+FF61〜FFDC（半角カナ・半角ハングル。いまと同じ）
  - U+FFE8〜FFEE（半角の記号。いまと同じ）
- その結果、①・※・○・×・℃・α・罫線・“” に加え、**é・ü・ñ などアクセント付きのラテン文字も全角**（2）として数える。
  いまは半角（1）なので**数えが 1 増える方向の変更**。制限を超えた文章を「収まる」と見せる誤りは起きない
- 判定の範囲は `tools/lib/hankaku-zenkaku.ts` に名前つきの定数（`HALF_WIDTH_RANGES`）で持ち、コメントに「列挙した範囲以外は全角。迷う文字は多めに数える側に倒す（#382）」と書く
- `tools/lib/mojisu-count.ts`（文字数カウント）は全角/半角の内訳を出していない（UTF-8 のバイト数だけ）ので**対象外**
- ページの解説に 1 行：「①・※・℃ などの記号や é などのアクセント付き文字も全角（2）として数えます。半角（1）は英数字・半角記号・半角カナだけです」

### テスト（`tools/tests/hankaku-zenkaku.test.ts` の `countChars` に追加）

| 入力 | 期待 |
|---|---|
| `'①※→○★℃×'` | `{ total: 7, full: 7, half: 0 }` |
| `'αΩ─“”…'` | `full: 6` |
| `'café'` | `{ total: 4, full: 1, half: 3 }`（é は全角に倒す） |

| `'a\nb'` | `{ total: 3, full: 0, half: 3 }`（改行は半角。変わらない） |
| 既存の `'あいうAB'` | `{ total: 5, full: 3, half: 2 }`（変わらない） |

## 2. ふるさと納税：例の「課税所得 約224万円」が令和7年分の基礎控除と合わない（文言）

- `tools/app/furusato-nozei/page.tsx` の「2026年（令和8年）の改正で上限額が下がる人がいます」の `.note`
- 「給与収入500万円・独身の場合、課税所得が約224万円から約179万円に下がり」の **224 万円**は、基礎控除 58 万円で計算した値
- 令和 7 年分の基礎控除は、合計所得 336 万円超 489 万円以下で **68 万円**（令和 7 年度改正の特例加算。このサイト自身の `basicDeductionIncomeTaxR7` も 68 万円）。
  給与所得 356 万円（給与所得控除 144 万円）− 社会保険料 約 73.6 万円 − 68 万円 ＝ **約 214 万円**
- **`tools/lib` の関数で計算し直した結果**（2026-10-13、#382 の企画レビューを受けて。社会保険料は `estimateSocialInsurance` の概算 735,750 円）：

| | 令和 7 年分（2025 年の寄附） | 令和 8 年分（2026 年の寄附） |
|---|---|---|
| 所得税の基礎控除 | 680,000 円（`basicDeductionIncomeTaxR7`） | 1,040,000 円（`calcFurusato` の `incomeTax.basicDeduction`） |
| 課税所得 | **2,144,000 円（約214万円）** | **1,784,000 円（約178万円）** |
| 所得税率 | 10% | 5% |
| 住民税所得割 | 236,900 円 | 236,900 円（住民税の基礎控除 43 万円は同じ） |
| 上限額 | 約 61,381 円（236,900 × 20% ÷（90% − 10% × 1.021）＋ 2,000） | **57,810 円**（`calcFurusato` の `limit`） |

- **直すのは 2 か所**：「約224万円」→「**約214万円**」、「約179万円」→「**約178万円**」（1,784,000 円。いまの「約179万円」も lib の値と合わない）。
  上限額「約61,000円→約58,000円」・税率 10%→5% はそのままでよい
- **実装時も、ページに書く数字は `calcFurusato`（令和 8 年分）と `basicDeductionIncomeTaxR7`（令和 7 年分）で出し直して確かめる。手計算の値を書かない**
  （`calcFurusato` の年分は 2026・2027 だけなので、令和 7 年分は上の表の式で lib の部品から組み立てる）
- 出典：国税庁 No.1199「基礎控除」https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1199.htm

## 3. 年齢計算：FAQ「満18歳になるのは何年生まれ？」の生まれ年の言い方が論理的に誤り（文言）

- `tools/app/nenrei-keisan/page.tsx` の FAQ 1 問目（JSON-LD の `FAQPage` にも出る）：
  「2026年に満18歳になるのは、誕生日を迎えたあとの人が2008年…生まれ、**誕生日がまだの人が2007年**…生まれです」
- 2007 年生まれは **2025 年に 18 歳になっている**。2026 年に「なる」のは 19 歳。「なる」と「である」が混ざっている
  （学年の部分は 10-05 の監査で直し済み。今回は生まれ年の文だけ）
- 直し方：「**いま**満18歳**である**のは、今年の誕生日を迎えた人が`${baseYear - 18}`年生まれ、まだの人が`${baseYear - 19}`年生まれです。
  `${baseYear}`年中に満18歳に**なる**のは`${baseYear - 18}`年生まれです」と 2 文に分ける。数字は `baseYear` から出す（いまと同じ）
- 早見表（「年齢の逆引き早見表」）の見出しも同じ言い方をしていないか、実装時に確認する

## 4. 最低賃金：FAQ「2026年10月から最低賃金はいくら上がりますか？」が目安の段階のまま（文言）

- `tools/app/saitei-chingin/page.tsx` の FAQ 1 問目（JSON-LD にも出る）
- 答えが「目安どおりに改定されれば…になります」「実際の金額は都道府県ごとの地方最低賃金審議会が決めます」と**決定前の書き方**。
  47 都道府県で決定・公示が済み、10-01 以降に順次発効している（厚労省「令和8年度 地域別最低賃金 全国一覧」https://www.mhlw.go.jp/content/11200000/001753404.pdf ）
- **FAQ で使う数字は「答申額」の全国加重平均 `NATIONAL_AVERAGE.answered`（1,177 円）のまま**（#382 の企画レビューを受けて明記）。
  厚労省の全国一覧（上の PDF）は**「答申された改定額」の一覧**で、全国加重平均は 1,177 円（改定前 1,121 円、+56 円）。
  この一覧と `tools/lib/saitei-chingin.ts` の 47 都道府県の額・発効日が一致することは 2026-10-13 の監査で確認済み。
  発効日（`effectiveOn`）は各労働局の決定・公示から入れてあり 47 県とも埋まっているが、**決定額が答申額と同じかは全県では照合していない**ので、FAQ では「決定額」と書かない
- 直し方：問いを「2026年（令和8年度）の最低賃金はいくら上がりましたか？」に、答えの 1 文目を
  「47都道府県の改定額（答申額）が出そろい、全国加重平均は`${current}`円から`${answered}`円（+`${answered - current}`円）です。発効日は10月1日から12月2日まで都道府県ごとに異なります」に。
  目安（A 54 円・B/C 56 円）は経緯として 2 文目に残し、「実際の金額は審議会が決めます」（決定前の書き方）は消す
- 実装時に厚労省の全国一覧を再取得し、全国加重平均が 1,177 円のままか確かめる（変わっていたら `NATIONAL_AVERAGE` の更新は別 PR）
- **#378（リードと FAQ「発効日」）と同じファイル**なので、#378 のマージ後に着手する（コンフリクトを避ける）

## やらないこと

- **JIS X 0208 の表で 1 文字ずつ全角・半角を判定すること**：範囲の取り違えで少なく数える側に外れる余地が残る。é・ñ などは全角（2）に倒し、欧文中心の文章では多めに出ることを解説の 1 行で示す（制限を超えた文章を「収まる」と見せる誤りより害が小さい）
- **バイト数（Shift_JIS）を出すこと**：需要はあるが別機能。文字数カウント（`mojisu-count`）の側で別に提案する
- **最低賃金の「答申額ベース」の表記を「決定額」に全部書き換えること**：決定額と答申額が一致しているかを全県の決定公示で確かめてからにする。上の 4 の FAQ も答申額として書く（今回の監査では一致を確認したが、表記の変更は #378 のマージ後にまとめて）
