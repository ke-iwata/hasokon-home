# スマホで1画面に収める（ゲームの縦の詰め方）

**状態**：実装済み（2026-08-16。本番反映はタグリリース待ち）
**対象**：`games/`（全ゲーム。とくにCPU対戦とカードゲーム）
**起票**：2026-08-16（運営者のフィードバック「スマホで見るとひと画面に収まってない。
表示されてる端末に最適化してひとつの画面に収まるように全部のゲームを調整して欲しい」）

## 解いている問題

スマホでゲームを開くと、盤より上（設定・状態・記録）と下（実況・ボタン・補足）で
画面を使い切ってしまい、**盤が画面の外に出ていた**。実測（幅390px・表示高さ720px）で
リバーシ912px・大富豪1002px・花札1550px。遊ぶたびに上下にスクロールが要る状態だった。

原因は2つ:

1. **盤の大きさを幅からしか決めていなかった。** 盤は正方形なので、幅いっぱいに
   広げると高さもそのぶん伸びる。画面の高さは見ていなかった
2. **盤以外が積み上がっていた。** 設定の切り替えが2〜3段に折り返し、記録の帯の
   注記が1段増え、末尾の説明文が段になり……と、1つずつは小さいものの合計で
   400〜600px使っていた

## 1. 盤の大きさを画面の高さからも決める

`app/globals.css`:

```css
.rv-board, .gm-board, .ms-board {
  max-width: min(var(--board-max, 100%), max(200px, calc(100dvh - var(--chrome, 400px))));
  margin-inline: auto;
}
```

- `--chrome` は**そのゲームで盤以外が使う高さ**（実測値。リバーシ・五目並べ410px、
  マインスイーパー250px）。盤の側の規則で宣言する
- `--board-max` は広い画面で肥大させないための上限。**各盤で `max-width` を
  書き直さないこと**。書くとこの指定を上書きして高さの制限が効かなくなる
  （メディアクエリと違い、ここは同じ詳細度の後勝ちになる）
- `100dvh` はブラウザのバーを除いた実際の表示高さなので、端末ごとに効く。
  低い画面では盤が縮み、高い画面では広がる（実測：表示高さ620pxでリバーシ565px、
  850pxで691px）
- マインスイーパーは列数で上限が変わるので、`Game.tsx` から
  `--board-max`（`'380px'` / `'560px'`）を渡す。**`maxWidth` を直に書かない**

## 2. 狭い画面（600px以下）で盤以外を詰める

`app/globals.css` の**末尾**にある `@media (max-width: 600px)` にまとめてある。

> **この規則はスタイルシートの末尾に置くこと。** メディアクエリは詳細度を上げない。
> 上のほうに置くと、後ろで宣言している `.df-msg` などの通常の規則に負けて
> 黙って効かなくなる（一度これで踏んだ）。

主なもの:

| 対象 | 前 | 後 | 効き |
|---|---|---|---|
| `.card` の内側の余白 | 18px | 10px | 全ゲーム −16px |
| `.seg button` / `.btn` | 既定 | 小さめ | 設定が3段→2段 |
| `.rec-note summary` | 「記録の保存について」 | `ⓘ`（`::after`） | 記録の帯が2段→1段（−33px） |
| `.rec-items` の行間 | `gap: 14px` | `gap: 2px 10px` | 折り返したときの1段ぶん |
| `.df-msg` / `.sn-msg` | `height: 4.5em` | `3em` | −22px |
| `.df-slot` / `.sn-slot` | `clamp(38px, 9.5vw, 54px)` | `34px` | 手札2段ぶんが縮む |
| `.hf-hand` | 2段ぶん確保 | **1段**（`clamp(24px, calc(10.2vw - 2px), 44px)`） | −100px |
| `.hf-taken` | 2段ぶん確保 | **1段**（あふれは中で横に流す） | −80px×2 |

> 花札の手札の `10.2vw` は当て推量ではない。手札の幅は画面幅のおよそ86%なので、
> 8枚＋隙間2px×7が収まる上限は `10.7vw − 1.8px`。**ここを緩めると8枚目が2段目に
> 折り返し、高さは1段ぶんで固定してあるので実況に重なる**（一度これで踏んだ）。
> 同じ理由で山札（`.hf-deck`）も広げない。裏の束とめくった札の2枚を縦に積む列なので、
> 幅を10px広げると列の高さが35px伸びて、場より背が高くなり台ごと伸びる。

**「高さは固定」の約束は崩していない。** 盤面が動かないよう `height` で確保する
方針（[cpu-speed.md](./cpu-speed.md) の「大きさを変えない」）はそのままで、
確保する行数・札の大きさだけを狭い画面向けに小さくしている。

## 3. 末尾の説明文を畳む

各ゲームの末尾にあった説明の段落を `<details class="game-tips">`（「この画面の見かた」）
に入れた。開いたままだと1ゲームあたり70〜92px使っていて、しかも**初回に一度読めば
足りる**内容だった。

同じ理由で、記録の帯の注記は**初回に自動で開かない**ようにした
（`app/_records/Records.tsx`）。開くと139px押し下げて盤が画面の外に出ていた。
これに伴い `lib/records.ts` の `noteSeen` / `markNoteSeen` は使う人がいなくなったので消した。

## 4. 花札だけの構造変更

花札は設定が4つ（強さ・月数・速さ・最初の親）＋チェック2つあり、切り替えだけで
狭い画面では3段120pxを使っていた。**強さ・速さ・「配り直す」だけを段に残し、
月数・最初の親・ローカルルールは `<details class="hf-rules">` に畳んだ**
（大富豪の `.df-rules` と同じ扱い）。毎局変えるものではない。

## 結果（幅390px・表示高さ720pxで実測）

| ゲーム | 前 | 後 | 遊ぶ範囲※ |
|---|---|---|---|
| リバーシ | 912 | 665 | 623 |
| 五目並べ | 912 | 665 | 623 |
| 大富豪 | 1002 | 690 | 648 |
| 七並べ | 947 | 671 | 629 |
| 神経衰弱 | 887 | 644 | 602 |
| スピード | 765 | 652 | 610 |
| マインスイーパー | 565 | 489 | 447 |
| 花札こいこい | 1550 | **752** | 682 |

※「遊ぶ範囲」＝カードの上端から、最後の操作ボタンの下端まで（末尾の畳んである
補足を除く）。**全8ゲームで遊ぶ範囲が720pxに収まっている。**

花札だけは末尾の補足2つ（「あと何枚で役になるか」「この画面の見かた」）を足すと
752pxになり、表示高さ720pxの端末では最後の32pxがわずかに画面の下に出る。
どちらも畳んである補足なので、遊ぶのに支障はない。

## 2026-08-22：ヨットを詰めた

ヨットは後から足したゲームで、上の表に入っていなかった。測ったところ
**遊ぶ範囲700px**——基準の720pxには収まっているが、**全ゲーム中いちばん重い**
（次点の花札682pxを超える）。実機で多い**幅375px・表示高さ667px**（iPhone SE 2/3世代）
では画面に入らないので詰めた。**651px**（card全体は742→693px）。

| | 前 | 後 |
|---|---|---|
| 遊ぶ範囲（390×720・375×667・414×896とも） | 700 | **651** |
| `main .card` 全体 | 742 | 693 |

効いたのは2つ:

- **`.seg button` の横の余白を 10px → 8px。** ヨットは設定が2組（強さ・速さ）あり、
  10pxのままだと2組で331px要って、**幅375pxでは2段に折り返していた**（実測）。
  横を2px詰めると5個ぶんで20px浮いて1段に収まる。
  **縦は触っていない**（押す先の高さが変わるため）。−36px
- **終局の知らせを、手番の案内と同じ行に出すようにした。** 別に1行（`.result-row`）
  取っていたが、**遊んでいるあいだずっと空のまま43px＋余白12pxを使う**。
  手番の案内は終局後には用が無いので、同じ場所で足りる。−55px
  （起こりうるいちばん長い文言「🎉 あなたの勝ち 375対298」を入れても
  行の高さは26pxのまま・文字のはみ出し無しを実測で確認。**盤は動かない**）

### 測る物差しを間違えないこと

この作業で一度、**320×568 の `main .card`** で測って「238pxはみ出している」と
報告してしまった。**基準は幅390px・表示高さ720pxの「遊ぶ範囲」**（カード上端から
最後の操作ボタンの下端まで。末尾の畳んである補足は含めない）で、
**iPhone SE級（600px前後）に全部収めることは、この仕様書が「やらないこと」に
挙げている**。物差しを間違えると、仕様どおりのものを不合格と読んでしまう。

## やらないこと

- **カードゲームの札や席を、表示高さ（`dvh`）から動的に縮めること。**
  盤と違って中身が正方形ではなく、高さを詰めると押す先（札）が44pxを割る。
  幅からの `clamp()` で止めている
- **iPhone SE 級（表示高さ600px前後）で全部を収めること。** カードゲーム
  （大富豪・七並べ・花札）はそこまで詰めると札が押せなくなる。盤ゲーム
  （リバーシ・五目並べ・マインスイーパー）は `100dvh` の指定で自動的に収まる
- **設定を隠すこと**（花札を除く）。まず小さくして段を減らす方を採る。
  スタートと先手・後手の選択は [cpu-speed.md](./cpu-speed.md) で足したばかりの導線なので、
  畳んで1タップ奥にしない

## 測り方

`games/` で `npm run dev` して、Playwright で幅390pxの端末を作り
`main .card` の高さを測る。目で見て「収まっていそう」は当てにならない
（この作業でも、実測ではじめて記録の帯の注記や行間 `gap` が効いていると分かった）。
