## 背景と根拠

### 「ローカル完結×信頼」路線のいちばん太い需要が画像

QRコード作成（[qr-code-seisei.md](./qr-code-seisei.md)）→ パスワード生成
（[password-seisei.md](./password-seisei.md)）で確立した
「**ブラウザ内で完結・どこにも送信しない**」路線の3本目。
「画像 リサイズ」「画像 圧縮」「写真 サイズ 小さく」「jpg 軽くする」は
ツール系サイトの中でも最大級の恒常クエリ群で、当サイトには**画像系が1本もない**
（2026-08-19、`tools/lib/registry.ts` 確認。テキスト系3本・生成系2本・計算系多数に
対しジャンルの空白）。

主要競合（iLoveIMG・Bulk Resize 等）は**サーバーにアップロードする**か、
広告過多で「この写真、送って大丈夫？」という不安が残る。履歴書・証明写真・
子どもの写真・免許証の写しなど、**送りたくない画像ほどリサイズが必要**になる
場面が多く、静的サイト＋Canvas API の「送信しようがない」構成は
パスワード生成と同じ説明がそのまま効く。

### 既存ツールとの相乗効果

アスペクト比計算（[aspect-ratio-gyakubiki-seo.md](./aspect-ratio-gyakubiki-seo.md)）は
Search Console 上で当サイト最多の表示があるページ（2026-08-12〜18、表示33回・
掲載順位44.9位。https://hasokon.com/ プロパティ）。「比率を計算した次は
実際にリサイズしたい」という導線がつながるので、相互に「関連ツール」で結ぶ。

## 現状

- 画像を扱うツールがゼロ。GA4（property 548154955、2026-08-12〜18）でも
  流入の柱は games で、tools は制度系・変換系に着地が散在する段階
- 検索面では「〜 変換」「〜 計算」クエリでの表示が増え始めており
  （aspect-ratio・nenrei 等）、変換系の面を太らせる時期

## 提案する仕様

1. **入力**：ファイル選択またはドラッグ&ドロップ（複数可・上限20枚程度）。
   **アップロードは発生しない**（`<input type="file">` → `createImageBitmap` で
   ブラウザ内処理）ことをファーストビューで明記
2. **リサイズ**：幅・高さ指定（比率固定が既定）／パーセント指定／
   長辺指定の3モード。縮小は段階的に行い、ぼやけ・モアレを抑える
   （`createImageBitmap` の `resizeQuality: 'high'` を基本に、非対応環境は
   多段Canvas縮小にフォールバック）
3. **圧縮**：JPEG/WebP の品質スライダー＋**「目標ファイルサイズ（KB）以下」**
   指定（品質を二分探索して到達）。処理前後のサイズを並べて表示
4. **形式変換**：JPEG ⇔ PNG ⇔ WebP（`canvas.toBlob` の対応形式のみ。
   HEIC 入力はブラウザ対応が割れるため初版では非対応と明記）
5. **メタデータの扱い（差別化の柱）**：Canvas 経由の再エンコードで
   EXIF（位置情報・撮影日時）が**結果として除去される**ことを説明し、
   「SNSに上げる前の位置情報消し」の用途を明示。EXIF の回転向き
   （orientation）だけは読み取って正しい向きで出力する
6. **出力**：1枚ならそのままダウンロード、複数枚は連続ダウンロード。
   処理結果は保存しない（localStorage にも残さない）
7. **ページ構成**：既存ツールと同じ（metadata / robotsFor / JSON-LD / FAQPage /
   パンくず / AdUnit / 関連ツール）。関連はアスペクト比計算・QRコード作成。
   registry へは `stage: 'preview'` で追加
8. **テスト**：リサイズ後の寸法計算（比率固定・長辺指定の丸め）と
   目標サイズ二分探索の収束条件を純関数に切り出して単体テストで固定
   （Canvas 描画そのものはブラウザ依存なのでテスト対象にしない）

## 期待される効果

- 最大級の恒常クエリ群「画像 リサイズ／圧縮」の受け皿＋画像系ジャンルの開拓。
  「ローカル完結」路線のページが3本になり、サイトとしての信頼の説明が
  面で効くようになる
- 計測：Search Console のクエリ「画像 リサイズ」「画像 圧縮」「exif 削除」の
  表示・順位、GA4 の `/tools/gazo-resize/` 着地数と処理実行イベント

## 工数（消費トークン目安）

- 実装 約120k〜160k（UI＋純関数テスト。Canvas 部分は既存ライブラリを使わず
  素の API で書ける規模）。レビュー往復込みで 200k 以内

## やらないこと

- **サーバーサイド処理・外部ライブラリでの HEIC 対応**（wasm デコーダは
  バンドルが MB 級になり静的サイトの軽さを損なう。需要が見えたら別途検討）
- **トリミング・回転・文字入れなどの編集機能**（リサイズ・圧縮に絞る。
  編集は別ツールとして切る方が検索の受け皿としても強い）
- **PNG の減色圧縮（pngquant 相当）**（wasm 依存。初版は toBlob の
  ロスレス出力のみで、JPEG/WebP への変換で「軽くする」需要を受ける）
