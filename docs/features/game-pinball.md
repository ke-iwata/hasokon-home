## 何を作るか

プランジャーで球を打ち出し、左右のフリッパーで打ち返してバンパーと的で点を稼ぐ、
1人用のアクション。ブロック崩し（`lib/breakout.ts`）と同じく、**物理を純関数の
ステート機械にして描画から切り離す**（`lib/pinball.ts`）。

## 名称と意匠（商標）

運営者の言う「昔のWindowsに入っていたピンボール」は特定の製品名を持つ作品。
ページ名は一般名詞の「ピンボール」とし、解説文でも製品名は出さず、
「パソコンに標準で付属するようになり」という事実の記述にとどめる
（games/CLAUDE.md「名称の商標に注意する」）。

**2026-08-19、運営者の指示で「元の盤面配置をなぞる」方向に寄せた。**
そのときに引いた線は次のとおりで、以後もここを守る:

| | 扱い |
|---|---|
| 名称・ロゴ・ミッション名・階級名 | **使わない**（保護される表現） |
| 盤面の絵柄・配色・キャラクター・意匠 | **なぞらない**（同上） |
| 骨格（周回レーン・戻りレーン・的やバンパーの位置関係） | 寄せてよい。仕掛けの配置そのものは機能で、寸法は自前で決めている |

つまり**「あの台を思い出せる骨格」までで、絵と名前は自前**。
題材（宇宙もの）や仕掛け（周回・ランプ・ミッション進行）自体は、
どのメーカーの台にもある一般的なもの。

## 座標系

**幅1 × 高さ1.5** の正規化空間。原点は左上、yは下向きに正。

ブロック崩しは幅1×高さ1だったが、ピンボールは重力が効くので、**縦横比を座標に
持たせないと重力が縦横で違う強さになる**。描画側（`.pb-stage`）は
`aspect-ratio: 1 / 1.5` で canvas を置き、拡大率は幅だけから出す。

## 台の作り

**周回レーン（オービット）と戻りレーンを持つ骨格**にしてある。

| もの | 位置 | ふるまい |
|---|---|---|
| 打ち出しレーン | 右端 x=0.87〜0.97 | 押している長さで打ち出しの強さが決まる |
| 一方通行の門 | レーンの口 y=0.30 | **上る球は通し、降りる球は跳ね返す** |
| スピナー | レーンの中 y=0.72 | 通り抜けると回る。半回転ごとに60点 |
| 周回レーン | 左〜天井（ガイド x=0.15 と外周のあいだ） | 左へ打ち上げると台を1周する |
| 天井のレーン（3つ） | 周回レーンの中 y=0.10 | 50点。3つ通すとボーナス1000点＋倍率+1 |
| バンパー（大3つ） | 三角 (0.52,0.29) (0.41,0.44) (0.63,0.44) | 100点。強く蹴り返す |
| 吸い込みホール | (0.60, 0.62) | 500点。0.7秒抱えてから上へ撃ち出す |
| 的（3つ・階段状） | 左 y=0.64〜0.81 | 250点。3つ倒すとボーナス1000点＋倍率+1 |
| 戻りレーン | 右 x=0.75〜0.87 | 上から降りた球を斜面まで導く |
| バンパー（小2つ） | y=0.92 | 的とフリッパーのあいだの返し |
| 斜面（スリングショット） | y=1.02〜1.31 | 勢いよく当たると10点。跳ね返す |
| フリッパー | 支点 (0.21, 1.31) / (0.69, 1.31) | 振り上げる勢いが球に乗る |

**通り道の幅は球3つぶんを下回らせない。** 球の直径は 0.044、壁の太さが片側 0.012
あるので、見た目の幅から 0.024 引いた値が実際に通れる幅になる。

## 決めたこと

- **打ち出しには下限を置いた**（`LAUNCH_MIN`）。弱く打っても台の上まで届く。
  届かないと球がレーンに落ちて戻るだけで遊びが止まる。強さで変わるのは
  「盤面のどこへ入るか」
- **フリッパーの先端の隙間は球3つぶん空ける。** ここが球1〜2つぶんだと、
  **両方を連打しているだけで球が落ちなくなる**（実測で90秒たっても落ちなかった）。
  遊びとして成立しないので、支点を外へ出して隙間を 0.156 にした。
  結果は「無操作6.1秒 / 連打5.5秒 / 狙って振ると50.7秒」で、
  連打では助からず狙えば続く。`tests/pinball.test.ts` が比で見張っている
- **1フレームを6回に割って進める**（`SUBSTEPS`）。球が速いので1回で進めると
  薄い壁を抜ける。速さの上限（`MAX_SPEED`）も置いてある
- **止まったら自動で突く**（`restSec`）。壁や的の上で球が止まると先へ進めなくなる。
  ほとんど動かない状態が1.5秒続いたら横に小さく突く
- **記録の帯は1回も遊んでいなくても出す。** 記録ができた瞬間に現れると台が
  34px押し下げられる（games/CLAUDE.md「画面の約束」の1）

## 2026-08-19：見た目の作り直しとギミック3つ

運営者から「見た目が残念すぎる。バンパーみたいなのもギミックが少ない」。
**物理には手を入れず、描画とギミックだけを足した。**

### ギミック（`lib/pinball.ts`）

- **スピナー**（レーンの回転板）。**当たり判定を持たせず「線をまたいだか」だけを見る。**
  当たり判定を置くと打ち出した球がレーンで減速して台の上まで届かない。
  勢いは指数で減り、回っているあいだ半回転ごとに点が入る。
  これで「強く打ち出すほど得」という手応えが打ち出しに生まれた
- **吸い込みホール**（サドン）。0.7秒抱えてから上のバンパー地帯へ撃ち出す。
  **撃ち出したあとの無効時間（`cool`）が要る。** 無いと出口で即再捕獲されて
  出入りを繰り返し、抜け出せなくなる。
  抱えているあいだは物理を止める（重力で抜けていくと待つ意味が無い）
- **天井のレーン3つ**。的4つと並ぶ「倍率を上げるもう1本の道」。
  **点灯の判定は重なりではなく「線をまたいだか」。** 重なりで見ると、3つそろえて
  消灯した直後にまだ帯の中にいる球が同じレーンを点け直してしまう（実際に落ちた）

いずれも `tests/pinball.test.ts` で見張っている（36件）。
**球の保ち方（無操作 / 連打 / 狙う）の比のテストはそのまま通る。**
吸い込みが抱えるぶん狙ったときの寿命は伸びた（実測 50.7秒 → 72.2秒）が、
無操作6.0秒・連打5.6秒は変わっていないので、遊びの成立は崩れていない。

### 見た目（`app/pinball/Game.tsx`）

一色塗りをやめ、**当たりの余韻・残像・得点の表示**を足した。

- **演出の値は `PinballState` に持たせない**（`Fx` として Game.tsx の ref に置く）。
  物理の状態に演出を混ぜると、テストがUIの都合で壊れるようになる。
  どのバンパーが光るかは「球にいちばん近いもの」で当てている
  （`hits` は種類しか持っていないが、演出にはこれで十分）
- 地はグラデーション＋バンパー地帯の淡い明かり＋同心の弧、
  バンパーは球形の陰影＋当たると白く光って輪が広がる、
  球は金属の陰影・接地の影・残像、フリッパーは根元が太く先が細い板、
  プランジャーはばね、当たった場所に得点が浮かぶ
- **四角く塗った影は台の上の箱に見える。** 排水口は線形グラデの矩形をやめ、
  口を中心にした放射に直した。レーンの地も上端をぼかしている
- 打ち出し前の案内（`.pb-hint`）は32%だと**吸い込みホールを覆う**ので47%へ下げた
  （的と下のバンパーのあいだの空き）

`main .card` の高さは 320×568=536 / 375×667=635 / 390×720=687 / 414×896=693 で、
どの端末でも1画面に収まる（実測）。**遊んでいるあいだ高さは変わらない。**

## 2026-08-19（2回目）：周回レーンを持つ骨格に組み替えた

運営者の「Windowsの3Dピンボールリスペクトのマップにしてほしい」から。
**寄せたのは骨格まで**（上の「名称と意匠」の表）。

### 一方通行の門が要る

組み替えて最初に測ったとき、**どの強さで打っても4秒でレーンに戻っていた**。
周回した球が打ち出しレーンの口へそのまま落ちて「打ち直し」になり、
遊びが始まらないまま台を1周して終わっていた。
本物の台と同じく**逆流防止の門**を口に置いて解決した
（`kind: 'gate'`。`ball.vy < 0` のときだけ当たり判定を飛ばす）。

### 折れた通路は球を挟む

戻りレーンを途中で内側へ折ったら、**無操作で55秒動かない**個体が出た。
折れ目が球1つぶんの楔になり、しかも詰まり対策の突きが壁側へ押すので
自力で出られない。**通路は折らずに1本の直線**にして直した。
突きの上向きの成分も 0.2 → 0.45 に上げてある（横だけだと壁へ押しつけて終わる）。

### 遊びの成立の見張り方を変えた

**1回だけ測るのをやめ、打ち出しの強さ9通りの平均で見るようにした。**
物理は初期値のわずかな違いで結果が大きく振れる。同じ台で、1回測りだと
連打5.1秒・9回平均だと15.0秒という差が出た。**1回測りの数字で係数を
決めていたら、意味のない値に合わせて台を歪めていた**。

見張る中身も、元の「連打 < 無操作×2」から次の3つに変えた。
組み替えで台の性格が変わり（周回が球を上に戻すので、触れば延びる）、
元の閾値は**意図ではなく当時の台の数字**に合っていただけだったため。

| 見張ること | 意図 | 実測 |
|---|---|---|
| 無操作の平均 < 8秒・最長 < 15秒 | 放っておけば必ず落ちる＝どこにも挟まらない | 平均4.6秒・最長5.1秒 |
| 連打の最長 < 60秒 | 連打で永久に落ちることが無い、は起きない | 最長29.7秒 |
| 狙う平均 > 連打平均×2 | 腕前が連打よりはっきり効く | 105.1秒 対 15.0秒（7倍） |

**閾値をゆるめたのではなく、測り方を直して意図を書き直した。**
元の規則が捕まえたかった事故（連打で90秒落ちない）は、いまも最長29.7秒で捕まる。

## 操作

| | フリッパー左 | フリッパー右 | 打ち出し |
|---|---|---|---|
| タッチ | 台の左半分 | 台の右半分 | 打ち出し前はどこでも（押している長さ） |
| キーボード | ← / Z | → / X | スペース |
| ボタン | 「◀ 左」 | 「右 ▶」 | — |

タッチは**指を置いた位置**で左右を決める。両手の親指をそのまま置いて遊べる。

## 大きさ

`.pb-stage` は `max-width: min(var(--board-max), max(150px, calc((100dvh - var(--chrome)) / 1.5)))`。
**共通の盤の指定（mobile-one-screen.md）は正方形の盤が前提なので、ここは自分で
1.5 で割る**。実測（幅390px）で、表示高さ620pxならカード588px、720pxなら687px。

## やらないこと

- **傾き（ナッジ）・ティルト。** 台を揺らす操作はスマホでの表現が難しく、
  ティルトで球を失う体験は初めての人には理不尽に映る
- **複数球（マルチボール）。** 1球で成立させる方針は変えない
- **ランプ（立体的な通路）。** 上下の重なりを持たない2Dの当たり判定で作ると、
  「どちらの高さにいるか」を状態で持つことになり、物理が一気に複雑になる
- ~~スピナー~~ は 2026-08-19 に足した（運営者の「ギミックが少ない」から）。
  **やらないことに書いたものを足すときは、ここを消さずに理由ごと書き換える**
- **音。** 他のゲームにも入れていない（`docs/features/` に音の仕様が無い）
