## 解いている問題

### 計測値：ソリティア3本だけ、パソコンの客が数秒で帰っている

GA4（プロパティ 548154955、2026-10-17 取得、直近 90 日、`pagePath` × `deviceCategory`）。
「1PVあたりの滞在」は `userEngagementDuration ÷ screenPageViews`。

| ページ | 端末 | PV | 滞在の合計 | 1PVあたり | エンゲージ率 |
|---|---|---:|---:|---:|---:|
| `/games/freecell/` | desktop | 27 | 239 秒 | **約 9 秒** | 40% |
| `/games/solitaire/` | desktop | 10 | 16 秒 | **約 2 秒** | 88% |
| `/games/solitaire/` | mobile | 19 | 38 秒 | 約 2 秒 | 91% |
| `/games/spider/` | mobile | 14 | 67 秒 | 約 5 秒 | 90% |
| `/games/spider/` | desktop | 2 | 47 秒 | 約 24 秒 | 60% |
| 比較：`/games/daifugo/` | desktop | 63 | 23,224 秒 | 約 369 秒 | 61% |
| 比較：`/games/mahjong-solitaire/` | desktop | 13 | 546 秒 | 約 42 秒 | 67% |

直近 28 日に絞っても `/games/freecell/` desktop は 24 PV・合計 61 秒（1PVあたり約 2.5 秒）・エンゲージ率 36%。
**ゲームの着地ページで、フリーセルは大富豪（13）に次ぐ 2 番目に多い入口（直近 14 日 8 セッション）なのに、エンゲージ率は 12.5%（8 中 1）**。

サイト全体の入口は Bing が 410／564 セッション（直近 14 日）で、**端末は desktop 469・mobile 88・tablet 7**。
ゲームに来る Bing の客の大半はパソコンで、「フリーセル」「ソリティア」で検索する層は
**Windows の Microsoft Solitaire Collection に慣れていて、カードはマウスでつかんで運ぶもの**と思って来る。

### 原因：ドラッグがまったく効かない（押した札と離した場所が違うと、何も起きない）

3本ともカードは `<button onClick>`（`app/_cards/CardView.tsx`）で、操作は「タップで選ぶ → 行き先をタップ」だけ。
ブラウザの `click` は**押したのと同じ要素の上で離したときにしか発火しない**ので、
パソコンの客がいつもの癖で札をつかんで別の列へ運ぶと、

1. 押した札でも離した列でも `click` が出ず、**何も起きない**（札は動かず、選択もされない）
2. 画面には「つかめる」手がかり（`cursor: grab`・持ち上がる影）も無い
3. 2〜3回試して「壊れている」と判断して帰る — 1PVあたり 2〜9 秒という数字と合う

**ただし、ドラッグだけでは説明しきれない数字もある**（#404 企画レビューの指摘 3）。タップで遊べているはずのスマホでも
`/games/solitaire/` mobile は 1PVあたり約 2 秒・`/games/spider/` mobile は約 5 秒で、パソコンと同じくらい短い。
しかもエンゲージ率は 88〜91% と高く、PV も 10〜27 件と少ない。**GA4 のエンゲージ時間が取り切れていない**
（短い滞在が `user_engagement` に乗る前に離脱している等）可能性があり、1PVあたり滞在は当てにしきれない。
そこで本提案は、(1) 主指標を新設する「最初の 1 手まで進んだ割合」にし、(2) スマホ（ドラッグの変更が効かない側）を対照群にして
「パソコンの伸び − スマホの伸び」で効果を見る（下の「期待される効果と測り方」）。

リードには「タップで選んでタップで置くだけ」と書いてあるが、**読む前に手が動く**。
`game-freecell.md` の「ドラッグ＆ドロップは入れない（既存2本がタップ主体なので操作体系を揃える）」は、
当時は計測値が無いなかでの判断で、**揃えた結果 3 本とも同じ形で客を落としている**。

### 競合と比べて足りないもの（2026-10-17 確認）

客が比べる相手（Windows の Microsoft Solitaire Collection・Google 検索の「ソリティア」で出るゲーム）は、
**ドラッグとクリックの両方**で動かせる（Windows 版はダブルクリックで自動移動）。
「ドラッグでは動かない」こと自体が、パソコンの客には想定外になる。

## やること

### 1. ドラッグで動かす（タップはそのまま残す）

`app/_cards/` に**ソリティア3本で共有するドラッグの部品**を足す（名前の案：`useCardDrag.ts`）。

| 項目 | 仕様 |
|---|---|
| イベント | Pointer Events（`pointerdown` / `pointermove` / `pointerup` / `pointercancel`）。マウス・タッチ・ペンを1本で扱う。`setPointerCapture` で指が盤の外に出ても追う |
| ドラッグの開始 | 押してから **6px 以上**動いたらドラッグ。6px 未満で離したら**今までどおりのタップ**として扱う（タップの客を壊さない） |
| ドラッグのあとの `click` | **ドラッグとして扱った操作のあとに来る `click` は捨てる**（6px 以上動かして同じ札の上で離すと、ブラウザは `pointerup` のあとに `click` も出し、タップの経路で選択や自動移動が走ってしまうため）。`pointerup` でドラッグだったら「次の `click` を 1 回捨てる」印を立て、`click` の捕捉段階（capture）で `preventDefault`／`stopPropagation` して印を下ろす。印は次のフレームで必ず下ろす（`click` が来なかった場合に、次の本物のタップを捨てないため） |
| つかむ範囲 | 押した札から下の並び（動かせる並びのときだけ）。動かせない並びはつかめない（札が少し揺れて戻る） |
| 運んでいる間 | つかんだ並びを指・カーソルに追従させる（`transform: translate` のみ。レイアウトを動かさない）。元の位置は半透明で残す |
| 落とす場所の判定 | 離した点の `document.elementFromPoint` から、列・フリーセル・ホームセルの要素（`data-drop="tableau:3"` など）を探す。**つかんだ札の中心が重なっている先**も候補に入れ、近いほうを採る |
| 置けたとき | 既存の `move()` をそのまま呼ぶ（ルールの判定はいまの `lib/*.ts` が持つ。ドラッグ用に別の判定を書かない） |
| 置けなかったとき | 元の位置へ 150ms で戻す。`prefers-reduced-motion` のときは即座に戻す |
| 落とし先の強調 | 運んでいる間、**置ける列だけ**枠を緑にする（`move()` を試算して判定） |
| `cursor` | 動かせる札に `grab`、運んでいる間は `grabbing` |
| スクロールとの両立 | 札の上だけ `touch-action: none`。盤の余白と札の無い所ではスクロールできる（スマホで「盤の上で縦にスクロールできない」を起こさない）。**前提：盤が 1 画面に収まっている**（[mobile-one-screen.md](./mobile-one-screen.md)）。クロンダイクの長い列などで盤の大半が札で埋まっても、盤の外（見出し・ボタン・記録の帯）でスクロールできれば足りる。1 画面に収まらない画面幅が見つかったら、その幅だけ `touch-action: pan-y` に戻してドラッグを諦める |
| `undo` | ドラッグの 1 回 = 1 手。いまの `history` にそのまま積む |

**タップの操作は 1 つも変えない。** 「タップで選んでタップで置く」「同じ札をもう一度タップで自動移動」は残す
（スマホ・iPad の客は今の操作で遊べている。タップの経路はドラッグの判定の手前で分ける）。

### 2. ダブルクリックで自動移動（パソコン）— **`dblclick` には処理を足さない**

いまの「同じ札をもう一度タップ」は、2 回目の `click` ですでに `autoMove()` が走る（`games/app/freecell/Game.tsx` 122〜125行・140〜143行。
ソリティア・スパイダーも同じ形）。ブラウザのダブルクリックは `click` → `click` → `dblclick` の順に出るので、
**`dblclick` にも `autoMove()` を付けると、2 回目の `click` で札が動いたあと、その位置に新しく来た別の札に対して `autoMove()` がもう一度走り、
意図しない 2 手目が出る**（`undo` の履歴も 2 つ積まれる）。#404 企画レビューの指摘 1。

決めること：

- **`dblclick` のハンドラは付けない。** ダブルクリックでの自動移動は、既存の「同じ札を 2 回 `click`」の経路だけで出す
- そのうえで、リード・FAQ ではこの操作を「**ダブルクリック（2 回タップ）で自動移動**」と呼ぶ（Windows のソリティアの操作名で探す客に伝わるように）
- 2 回の `click` の間に札が動かないこと（1 回目は選択だけ・2 回目で自動移動）は、いまの実装のまま保つ。ドラッグを足すときにこの流れを変えない

### 3. 最初の 1 手を計測する

いまの計測は `win` と `new` / `replay` だけで、**「来た客が 1 手でも動かせたか」が分からない**。
直したかどうかを確かめるために、1 ゲームにつき 1 回だけ次のイベントを送る。

```ts
trackToolUse('freecell', 'first-move-drag');   // 最初の1手をドラッグで
trackToolUse('freecell', 'first-move-tap');    // 最初の1手をタップ・クリックで（キーボードの Enter/Space による1手目もこちらに数える）
trackToolUse('freecell', 'drag-miss');         // 置けない所へ落とした（1ゲーム最大1回）
```

キーボード（Enter/Space）は `button` の `click` として届くので、タップと区別せず `first-move-tap` に入れる（区別するほど件数が無い）。

`solitaire` / `spider` も同じ名前で送る。既存の `tool_use` イベントに `action` を足すだけで、GA4 側の設定は増えない。

### 4. リード・FAQ を直す

| ページ | いま | 直したあと |
|---|---|---|
| フリーセルのリード | 「タップで選んでタップで置くだけの簡単操作」 | 「**ドラッグでもタップでも**動かせます。ダブルクリック（2回タップ）で自動移動」 |
| フリーセル FAQ「スマホで遊べますか？」 | 「ドラッグは不要で〜」 | 「ドラッグでも、タップで選んでタップで置く2回の操作でも動かせます」 |
| ソリティア・スパイダーのリード | 同上 | 同上 |
| `description`（meta） | 「タップするだけの簡単操作」 | 「ドラッグでもタップでも」を入れる（検索結果の文面で Windows の客に伝わるように） |

**ページの文言（リード・FAQ・`description`・title）には他社の製品名を入れない**（「Microsoft Solitaire Collection」「Windows のソリティア」などは
この仕様書の中で比較に使うだけ）。操作名の「ドラッグ」「ダブルクリック」は一般名詞なので使ってよい。

## やらないこと

- **他のカードゲーム（ピラミッド・トライピークス・ゴルフ・七並べ・スピード・大富豪など）には入れない。**
  1 枚ずつ取るゲームで、タップ 1 回で済むので運ぶ必要が無い。計測値でも同じ落ち方はしていない（大富豪は 1PVあたり 369 秒）
- **ルール（`lib/klondike.ts` などの `move()`）は触らない。** ドラッグは入力の経路を 1 本足すだけ
- **ドラッグ中のアニメーションに凝らない**（影 1 段と 150ms の戻りだけ）。カード 52 枚 × 毎フレームの再描画を避けるため、
  追従はつかんだ並びの外側の要素 1 つに `transform` をかける
- **右クリック・キーボードの新しい操作は入れない**（今ある `button` のフォーカスと Enter/Space で選べる操作はそのまま残る）

## 受け入れ条件（テスト）

- `games/tests/card-drag.test.ts`（新規。jsdom で `PointerEvent` を合成）
  - 6px 未満の移動で離すと `onClick` と同じ結果（タップ扱い）になる
  - 列 A の札を列 B へドラッグ → `move()` と同じ盤になる／置けない列へ落とすと盤が変わらない
  - 動かせない並び（フリーセルで `maxMovable()` を超える枚数）はつかめない

  - **ダブルクリック 1 回（`click` → `click` → `dblclick` を合成）で手が 1 つだけ進み、`history` も 1 つだけ増える**
- 既存の `solitaire` / `spider` / `freecell` のテストが通る（タップの経路を壊していない）
- 実機の確認（テスト環境）：
  - **1366×768 のパソコン（マウス）**で、3 本ともドラッグで 1 手目が動く・ダブルクリックで自動移動する

## 期待される効果と測り方

- **主指標**：`tool_use` の `first-move-*` の件数 ÷ PV（**最初の 1 手まで進んだ割合**）。3 本の合計で、desktop と mobile を分けて出す。
  GA4 のエンゲージ時間に頼らず、「動かせたか」を直接数えられるため
- **副指標**：desktop の 1PVあたり滞在（`userEngagementDuration ÷ screenPageViews`）。上の「解いている問題」のとおり取り切れていない疑いがあるので、
  主指標と向きが揃っているかの確認にだけ使う
- **対照群**：mobile（ドラッグの変更が効かず、タップの経路は変えない側）。**効果は「desktop の伸び − mobile の伸び」で見る**。
  季節やBingの流入の増減は両方に同じように効くので、差を取れば打ち消せる
- **目標**：desktop の最初の 1 手まで進んだ割合 **50% 以上**、かつ mobile との差が公開前の水準より縮む（公開前は `first-move-*` が無いので、
  公開直後の 1 週間の mobile の割合を基準にする）。副指標は desktop の 1PVあたり滞在 9 秒（フリーセル）→ 60 秒以上
- **判定の下限**：3 本合計の desktop の PV が **100 PV に達するまで判定しない**（直近 90 日で 3 本の desktop は 39 PV しかない。
  4 週間で 100 PV に届かなければ、届くまで判定を延ばす。最長 12 週間で、それでも届かなければ「件数不足で判定できず」と記録する）
- 1PVあたりの滞在が伸びれば、ゲームの 2 番目の入口が「来て帰るページ」から「遊ばれるページ」になり、
  ゲーム一覧（`/games/`）への回遊と広告の表示機会も増える
- 判定の下限（100 PV）に達した時点で、desktop の最初の 1 手まで進んだ割合が 50% に届かず、mobile との差も縮んでいなければ、
  原因は操作ではない（盤の大きさ・読み込み・期待した遊びと違う）と判断し、1366×768 で盤の下が画面の外に出ている件（下記「気づいたこと」）を次に見る
