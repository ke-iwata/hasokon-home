# 「106万円の壁」撤廃（2026年10月1日施行）に年収の壁 計算機を追随させる

**状態**：実装済み（2026-08-11。本番反映はタグリリース待ち）
**対象**：`tools/lib/nenshu-kabe.ts`・`tools/app/nenshu-kabe/`（`hasokon.com/tools/nenshu-kabe/`）
**起票**：2026-08-11
**期限**：2026-10-01（施行日）。**この日を過ぎると計算結果が誤りになる**

## 背景と根拠

### 施行が7週間後に迫っている法改正

2025年6月成立の**年金制度改正法**により、短時間労働者が厚生年金・健康保険に加入する
要件のうち **賃金要件（月額8.8万円以上＝年収106万円相当）が2026年10月1日に撤廃**される。

| 時期 | 加入の判定条件 |
|---|---|
| 〜2026年9月 | 週20時間以上 **かつ** 月額賃金8.8万円以上 **かつ** 従業員51人以上 |
| 2026年10月〜 | 週20時間以上（学生を除く） **かつ** 従業員51人以上。**金額の条件は無くなる** |

企業規模要件も2027年10月から段階的に縮小され、2035年10月に撤廃される。

| 時期 | 対象になる企業規模 |
|---|---|
| 2027年10月 | 従業員36〜50人 |
| 2029年10月 | 従業員21〜35人 |
| 2032年10月 | 従業員11〜20人 |
| 2035年10月 | 従業員10人未満 |

出典：[厚生労働省 年金制度改正法（2025年6月成立）](https://www.mhlw.go.jp/)、
[企業法務弁護士ナビ「【2026年10月】106万円の壁撤廃」](https://houmu-pro.com/legalrevision/384/)、
[グロースリンク社会保険労務士法人「【2027年度改正】社会保険適用拡大」](https://growthlink-sr.com/news/900040/)

## 現状

`tools/lib/nenshu-kabe.ts` の判定は**日付の概念を持たない静的なテーブル**で、
106万円の壁は常に「壁」として存在する。

```ts
// tools/lib/nenshu-kabe.ts:82
{
  amount: 106 * M,
  label: '106万円の壁',
  category: '社会保険',
  impact: 'high',
  inclusive: true,
  applies: (i) => i.position !== 'none' && i.size51 && i.hours20,
},
```

撤廃の予定は `note` の文章と、`app/nenshu-kabe/page.tsx` のFAQ・早見表に
**文字として**書いてあるだけで、判定ロジックには反映されていない。

### 10月1日以降に起きる誤り（再現手順）

1. `hasokon.com/tools/nenshu-kabe/` を開く
2. 年収 **100**（万円）、立場「配偶者の扶養内で働いている（パート等）」
3. 「勤務先の従業員が51人以上」と「週20時間以上働いている」の両方にチェック

**期待**（2026年10月以降の事実）：この人は年収に関係なく勤務先の社会保険に加入する。
「あと6万円まで大丈夫」ではない。

**実際**：`evaluateKabe()` が `over: false, diff: 60000` を返し、`nextWall()` は
106万円の壁を「次に到達する壁」として選ぶ。画面上部の目立つ位置に
**「次の壁は106万円の壁。あと6万円」**と出る。

利用者は「106万円を超えないよう働く時間を抑えよう」と読む。
**制度上まったく逆の行動**（週20時間未満に抑えるのが正解）に誘導してしまう。

### 130万円の壁との重複も残る

上と同じ条件（51人以上・週20時間以上）の人は、10月以降は勤務先の社保に入るため
**扶養から外れる130万円の壁はそもそも到達しない**。にもかかわらず、
`applies: (i) => i.position === 'spouse' || i.position === 'dependent'` は
勤務条件を見ないので、130万円の壁も併記され続ける。

## 提案する仕様

### 1. 判定の基準日を入力にする

`KabeInput` に基準日を足し、`WALL_DEFS` に有効期間を持たせる。
基準日はビルド時刻ではなく**画面を開いた日**（`new Date()`）を既定にする。
静的書き出しなのでビルド時に固定してしまうと、10月をまたいでも古い判定のままになる。

```ts
export interface KabeInput {
  income: number;
  position: Position;
  size51: boolean;
  hours20: boolean;
  /** 判定の基準日。省略時は実行時の現在日（クライアントで評価される） */
  asOf?: Date;
}

interface WallDef {
  // …既存のフィールド…
  /** この壁が存在する期間。省略は「ずっと」 */
  effectiveUntil?: string; // 'YYYY-MM-DD'（この日を含まない）
  effectiveFrom?: string;
}
```

106万円の壁に `effectiveUntil: '2026-10-01'` を付ける。
`evaluateKabe()` は `asOf` が期間外の壁を落とす。

### 2. 壁の代わりに「加入判定」を返す

金額の壁が消えても、**加入するかどうかの判定自体は残る**（むしろそちらが本題になる）。
壁の一覧とは別に、社会保険の加入見込みを1つ返す。

```ts
export type ShahoStatus =
  | { kind: 'enrolled'; reason: '週20時間以上・従業員51人以上のため、年収に関係なく加入' }
  | { kind: 'wage-gate'; threshold: number }   // 2026年9月まで
  | { kind: 'not-applicable'; reason: string };

export function evaluateShaho(input: KabeInput): ShahoStatus;
```

`kind: 'enrolled'` のとき、画面の最上部は
**「勤務先の社会保険に加入します（年収の多少にかかわらず）。手取りを気にするなら、
調整すべきは年収ではなく週の所定労働時間です」**という主旨の文言にする。

### 3. 130万円の壁を条件付きにする

`applies` に「まだ勤務先の社保に入っていないこと」を足す。

```ts
applies: (i) =>
  (i.position === 'spouse' || i.position === 'dependent') &&
  evaluateShaho(i).kind !== 'enrolled',
```

| ファイル | 変更 |

サイト内でこの語を持つページが現在ゼロ（`grep -r "週20時間の壁" tools/` → 0件、2026-08-11）。

### 5. テスト

`tools/` に既存のテストがあれば同じ形で、`asOf` を 2026-09-30 と 2026-10-01 に
固定した2ケースを足す。**施行日をまたぐ境界が壊れていないこと**が唯一の検証点なので、
現在時刻に依存させない。

## やらないこと

- **企業規模要件（2027年10月以降）の段階的縮小まで作り込む。**
  いま入れても3年以上先まで画面に出ない。`WALL_DEFS` に期間の仕組みさえ入れておけば、
  2027年に定義を1行足すだけで済む。仕組みだけ用意して定義は入れない
- **加入したときの保険料額の試算。**
  標準報酬月額の等級表・都道府県別の健保料率・介護保険該当の有無まで要り、
  ツール1本ぶんの規模になる。別ツールとして切り出すべきで、この改修に混ぜない
- **施行日を運営者が手で切り替える運用。**
  切り替え忘れが起きる。日付で自動的に切り替わる実装にする
