## 2026-08-14：年齢計算・西暦和暦変換を追加した（23本目のツール）

恒常需要の非YMYLツールとして `tools/nenrei-keisan/` を追加した。生年月日から満年齢・
和暦表記・干支・誕生日までの日数・入学卒業年の目安を出し、明治〜令和の西暦⇔和暦
早見表も同じページに載せている。仕様は
[features/nenrei-keisan.md](../../docs/features/nenrei-keisan.md)。

**元号は「開始日・終了日」の組で持った。** 年だけで持つと改元年（1989年＝昭和64年と
平成元年、2019年＝平成31年と令和元年）を1つに丸めてしまう。`ERAS` に暦日の範囲を
持たせ、`toWareki()` は日付で元号を引く。早見表でも改元年は両方の元号に行が出て、
備考に「1月7日まで」「1月8日から」と入る。書類の記入で迷うのがまさにここなので、
重複を隠さないほうを選んだ。

**存在しない和暦は弾くだけにせず、理由を返した。** 「昭和64年1月8日」のような入力に対して
`fromWareki()` は `{ error }` を返し、「1989年1月8日から平成」と示す。単に無効と出すより、
正しい表記に辿り着ける。

**明治より前には対応しない。** グレゴリオ暦の採用は明治6年1月1日（1873-01-01）で、
それ以前の和暦の月日は旧暦なので西暦と機械的に対応しない。明治元年〜5年は年の対応だけを
示し、`WarekiDate.lunisolar` を立てて注記を出す。

**満年齢は誕生日の当日から新しい年齢にした。** 年齢計算ニ関スル法律＋民法143条では
誕生日の前日の終了時（24時）に増えるので、日付の比較としては当日で増えるのと一致する。
2月29日生まれは平年に応当日が無く、民法143条2項ただし書きで2月28日の終了時に満了するため、
**平年は3月1日に増える**（2月28日はまだ増えない）。`nextBirthday()` も同じ日へ寄せる。

**学年は「4月2日〜翌年4月1日生まれ」で1つのまとまりにした。** 学校教育法17条の
「満6歳に達した日の翌日以後における最初の学年の初め」と、前日満了の年齢の増え方を
合わせると、4月1日生まれは3月31日に6歳になってその年の4月に入学する。早生まれが
1月1日〜4月1日になる理由がここにあるので、FAQでも導出を書いた。

**早見表の現行元号は固定の上限年（`TABLE_END_YEAR`）まで出す。** ビルド時刻から作ると
ビルドのたびに行数が変わり、テストが不安定になる。表の末尾に近づいたら定数を伸ばす。

## 2026-08-14：最低賃金 早見表・チェッカーを追加した（22本目のツール）

令和8年度の地域別最低賃金の改定（2026年10月前後に発効）に合わせて
`tools/saitei-chingin/` を追加した。都道府県を選ぶと現行額・改定後の額・引上げ幅・
発効日が出て、自分の時給が下回っていないかの判定と、時給×週労働時間からの
月収・年収換算、年収の壁までの余裕まで1ページで引ける。仕様は
[features/saitei-chingin-checker.md](../../docs/features/saitei-chingin-checker.md)。

**目安と答申を型で分けた。** 7月末に国が示すのはランク別の「目安」で、
金額を決めるのは8〜9月の各都道府県の審議会（「答申」）である。目安を上回る答申を出す県が
実際にあるため、目安から機械的に足した額を確定額として見せると誤情報になる。
`Prefecture.answered` を任意フィールドにして、労働局の発表で確認できた県だけが持つ形にし、
持たない県は `revisionOf()` が status: '目安' の**見込み**として返す。UIは状態を必ず添える。
2026-08-14 時点で答申を確認できたのは8県（北海道・千葉・東京・神奈川・愛知・三重・大阪・兵庫）。

**出典を各エントリの必須フィールドにした。** 現行額は厚労省の全国一覧PDF、答申額は
各都道府県労働局の報道発表を `source` / `answered.source` に持たせ、UIに根拠リンクとして出す。
`tests/saitei-chingin.test.ts` が出典URLの欠落と、答申の出典が mhlw.go.jp 以外のドメインに
なっていないかを落とす。**答申額を二次情報（まとめサイト）から写さないための仕掛け。**

**発効日を推測で埋めなかった。** 答申の発表時点で効力発生日を示さない労働局がある
（東京・大阪・千葉）。10月1日と決め打ちすると県によって外れるので `effectiveOn` は任意にし、
未公表は「未公表（10月ごろの見込み）」と出す。日付を持つ県は基準日を過ぎると
status が自動で '発効済み' に変わるので、運営者の切り替え作業は要らない。

**年収の壁の定義は持たなかった。** 壁の金額・施行日・適用条件は `lib/nenshu-kabe.ts` が
単一の情報源なので、`wallsFor()` は `evaluateKabe()` を呼ぶだけにしてある。
2026年10月1日の賃金要件撤廃で106万円の壁が消えるのも、そのまま引き継がれる。

## 2026-08-14：自転車の反則金（青切符）早見表・チェッカーを追加した（21本目のツール）

2026年4月1日施行の改正道交法（令和6年法律第34号）で自転車にも青切符
（交通反則通告制度）が適用されたことを受け、`tools/jitensha-hansokukin/` を追加した。
「イヤホンをして乗る」「傘をさして乗る」といった日常の行為を選ぶと、該当し得る
違反名・反則金・青切符か赤切符かが出る。仕様は
[features/jitensha-hansokukin.md](../../docs/features/jitensha-hansokukin.md)。

**行為から引く形にしたのは、利用者が条文の言葉で検索しないため。** 実際の検索は
「自転車 イヤホン 違反」「自転車 歩道 罰金」であって「公安委員会遵守事項違反」ではない。
競合は保険会社・銀行のコラムと自動車学校のブログが中心で、違反名から引く記事はあっても
行為から引けるものが無かった。`BEHAVIORS` が日常の言い方から違反名へ橋渡しする層で、
1つの行為が複数の違反に当たり得る（傘さし＝公安委員会遵守事項違反5,000円だが、
運転操作が不確実なら安全運転義務違反6,000円）ので `violationIds` は配列にしてある。

**警察庁の一覧PDFを全65項目そのまま収録した。** 主要項目だけの抜粋にすると
競合のコラムと変わらなくなるうえ、「載っていない違反」を調べに来た人を取りこぼす。
金額・根拠条文はPDFから読み取り、愛媛県警の早見表PDFとも突合している。
`tests/jitensha-hansokukin.test.ts` が主要17項目の金額と条文を直接固定しているので、
二次情報を見て書き換えるとテストが落ちる。**自治体サイトにも金額の誤りの実例があるため、
金額は警察庁PDFを正とする。**

**「113種類」という数字は使わない。** 銀行系コラム等が使っている二次的な数え方で、
警察庁一覧の行数（65）と一致しない。`VIOLATION_COUNT` を単一の情報源にして、
ページ本文・FAQ・meta descriptionのすべてがそこを参照している。

**「2026年4月に罰則ができた」と書かないよう歯止めを入れた。** 酒気帯び運転と
ながらスマホの罰則強化自体は2024年11月1日に先行施行されており、2026年4月に
変わったのは青切符の対象になったこと。`SYSTEM.penaltyStrengthenedFrom` として
別に持ち、テストが施行日との取り違えを検知する。

**赤切符側には罰則の額を持たせていない。** 一次情報で額まで確認できたものだけを書く方針で、
警察庁「取締りについて」は該当する違反の種類しか示していないため、
ページでも「刑事手続に進む」までにとどめた。テストが `RED_TICKET_VIOLATIONS` に
懲役・罰金の額が書き足されるのを止める。

**都道府県ごとの遵守事項は網羅しない。** イヤホン・傘の細則は47都道府県の規則にあり、
持つと更新が破綻する。「都道府県により異なる」と明示して各県警の規則へ案内する。

このサイトで初めての**非YMYL系の制度ツール**でもある（`ToolMeta` に `ymyl` を付けていない）。
税・社会保険ではなく交通ルールの一次情報の整理なので、若いドメインでも順位が付きやすい
睡眠サイクル・ヘボン式と同じ枠に入る。

## 2026-08-14：ヘボン式ローマ字ページに五十音の一覧表と戸籍フリガナの節を足した

`lib/hebon-romaji.ts` に表示用の `SEION_TABLE` / `DAKUON_TABLE` / `YOON_TABLE` と
`hebonOf()` を足し、ページに「ヘボン式ローマ字 一覧表（五十音）」（清音・濁音/半濁音・
拗音の3表）を出した。表のかなの並びだけをデータに持ち、綴りは既存の
`BASE_MAP` / `DIGRAPH_MAP` から引いているので、変換結果と一覧表がずれることはない
（`tests/hebon-romaji.test.ts` が全マスについて `toHebonRomaji()` の結果と突き合わせる）。
あわせて「戸籍のフリガナとパスポート（2025年5月26日施行の改正戸籍法）」の節と、
戸籍フリガナ・自署（サイン）のFAQを2問足し、description に「五十音の一覧表つき」を
1文だけ含めた。仕様は
[docs/features/hebon-romaji-seo-kyoka.md](../../docs/features/hebon-romaji-seo-kyoka.md)。

**理由**：Search Console（2026-08-14 取得・直近28日）で `/tools/hebon-romaji/` は
ツール中2番目の表示回数（50回）がありながら掲載順位49位で止まっていた。
上位の都道府県パスポート案内には必ずある五十音の対応表が自ページに無く、
「ヘボン式 一覧」系のボリュームの大きいクエリの受け皿が無かった。
変換ロジックには完全なテーブルが既にあるので、表示するだけで埋められる欠落だった。

**title は変えていない。** 主軸クエリ（ヘボン式ローマ字変換・パスポート）で
既に表示が出ているため、検索面はコンテンツで広げ、title は動かさない方が安全と判断した。

**自署（サイン）はヘボン式である必要がない**ことをFAQで明記した。
表示実績のあるクエリ「パスポート 自署 ローマ字」に対する答えがページに無く、
かつ「ローマ字ページ＝すべてヘボン式で書く」と誤解されやすいところなので、
1問で否定形の答えを置いている。非ヘボン式表記（外国式の綴り）の変換対応は、
窓口ごとに判断が違いツールで断定すると危険なため、今回も入れていない。

## 2026-08-14：高校授業料 実質負担 計算機を追加した（20本目のツール）

`lib/koko-jugyoryo.ts` / `app/koko-jugyoryo/` を追加し、2026年4月の
高等学校等就学支援金の改正（所得制限の撤廃・私立全日制45万7,200円への引き上げ）に
対応した計算機を作った。進学先（公立全日制／私立全日制／私立通信制の単位制）を選び、
授業料と「授業料以外の年間費用」を入れると、就学支援金・授業料の自己負担・
3年間の総額・公立との差額が出る。仕様は
[docs/features/koko-jugyoryo-mushoka.md](../../docs/features/koko-jugyoryo-mushoka.md)。

**理由**：所得制限が撤廃されて「もらえるか」の判定が不要になった一方、論点が
「実際の自己負担がいくら残るか」に移った。私立の授業料が45万7,200円を超える分と、
支援の対象外である入学金・施設費・制服・教材が残るため、「無償化と聞いていたのに
思ったより払う」というギャップが検索需要の中心にある。進路決定・出願は9月〜1月に
集中するので、いま出せば季節需要の立ち上がりに間に合う。

**世帯年収を入力させない。** 2026年度から国の就学支援金の額は年収で変わらないため、
入力項目を増やしても結果が動かない。都道府県の上乗せ助成には所得要件が残る場合が
あるが、47都道府県のデータ化は更新負荷が高いので v1 では注記と外部リンクに留めた。

**仕様書の記述を一次情報で補正した点が2つある。**
仕様書は通信制を「1単位13,668円・年30単位・通算74単位」とだけ書いていたが、
文科省の令和8年度説明会資料（p.4 / p.24）で確かめたところ、
私立通信制には**定額授業料の場合の年33万7,200円**という別の限度額があり、
13,668円/単位は**単位制授業料を設定している学校**の額だった。ツールは単位制だけを
扱うことにし（通信制は単位制が主流のため）、定額制の33万7,200円は解説の表に載せた。
もう1つは**支給が授業料を超えない**こと。就学支援金は授業料債権への充当なので、
限度額より安い学校では授業料の額で止まり、差額が現金でもらえるわけではない。
`Math.min(限度額, 実際の授業料)` を必ず取っている。

通算74単位の上限は**在学年数をまたいで効く**ので、学年ごとに残り単位数を減らしながら
積んでいる。年30単位を3年続けると90単位になり、超過した16単位分は丸ごと自己負担になる。
黙って丸めず、頭打ちに当たったときは学年ごとの支給対象単位数を画面に出す
（`lib/shobyo-teate.ts` の通算1年6ヶ月と同じ考え方）。

「授業料以外の年間費用」の目安ボタン（公立15万円／私立30万円）は
**公式の統計値そのものではない**。子供の学習費調査の学習費総額から授業料と
学校外活動費を除いてならした概算なので、初期値には使わず（0を初期値にした）、
ボタンとしてだけ提示し、学校案内の「初年度納付金」で入れ替えてもらう建て付けにした。

## 2026-08-13：睡眠サイクル計算機に仮眠モードを足し、検索面を広げた

`lib/sleep-cycle.ts` に `NAP_PLANS`（15〜20分 / 30分 / 90分）と `napPlans()` を足し、
計算機に3つ目のモード「仮眠・昼寝の時間」を追加した。開始時刻から3案の起床時刻を
同時に出す。15〜20分の案だけ幅を持たせて「13:30〜13:35」と両端を出し、
90分は `CYCLE_MINUTES` を参照して定義の二重持ちを避けている。
ページには「仮眠（昼寝）は90分ではなく15〜20分」「年齢・生活リズムと睡眠時間の目安」の
2見出しとFAQ3問を足し、title / description に仮眠を1文だけ含めた。

**理由**：Search Console（2026-08-13 取得・2026-07-15〜08-11）で、指名検索を除いて
表示が出ているページは `/tools/sleep-cycle/` だけだった（表示10回・掲載順位16.8位）。
税・社会保険系はYMYLで立ち上げ期は時間がかかる一方、生活系のこのページが先に動いており、
伸びている芽に足すのがいちばん近い勝ち筋だと判断した。しかもページのFAQには
「昼寝は15〜20分」と既に書いてあるのに計算機能が無く、仮眠の検索意図を受ける器が
無い状態だった。仕様は
[docs/features/sleep-cycle-nap-and-seo.md](../../docs/features/sleep-cycle-nap-and-seo.md)。

仮眠を `/nap/` などの別ページに切らず既存URLに積んだのは、評価され始めているURLを
割ると内部競合と評価の分散を招くため。診断・アドバイス機能やアラームは入れない
（前者は医療領域、後者は静的サイトの範囲外）。モード切替では `trackToolUse` を呼ぶ
ようにしたので、仮眠モードが昼休みのリピート利用を生むかをGA4で確かめられる。

`formatDuration()` は1時間未満を「0時間15分」と出していたので「15分」に直した。
既存の呼び出しは睡眠時間（270分以上）だけなので表示の変化はない。

## 2026-08-13：傷病手当金の支給対象日数に「通算1年6ヶ月」の上限を入れた

`lib/shobyo-teate.ts` に `MAX_PAYABLE_DAYS = 546` を置き、支給対象日数を
`min(休業日数 − 待期3日, 546)` で頭打ちにした。上限に達したときは結果パネルに
「入力の◯日分ではなく546日分で計算しました」と理由を出す（黙って丸めない）。
入力欄に `max` は付けない。2年休んだ人が「730」と入れるのは自然で、弾くと
「1年6ヶ月で切れる」という制度説明の機会そのものを失うため。

**理由**：ページ本文とFAQが「支給期間は通算1年6ヶ月」と2箇所で説明しているのに、
計算だけが上限を持たず青天井だった。月収30万円で730日と入れると4,846,909円と出るが、
制度上の上限は546日分の3,640,182円で、約120万円・33%の過大表示になっていた。
長期療養を想定して長い日数を入れる人ほど踏むので、いちばん切実に金額を知りたい層が
誤った額を見ることになる。仕様は
[docs/features/shobyo-teate-shikyu-kikan-cap.md](../../docs/features/shobyo-teate-shikyu-kikan-cap.md)。

546日は「1年6ヶ月」を暦で数えたときの実日数（546〜548日）のうち短いほうを採ったもの。
金額を調べる道具なので、多く出しすぎる側より過小に倒すほうが害が小さい。

## 2026-08-11：ルーレットの「配色」テーマ選択を廃止した

4種類（ポップ／パステル／ビビッド／あたたか）から選べたテーマを廃止し、
`lib/roulette/colors.ts` の固定セット（旧ポップの札10色 + 共有画像の代表色）に一本化した。
localStorage の `roulette:theme` は読まなくなっただけで、残っていても害はない。

**理由**：デザイントークン統一の際、テーマがページ全体の配色（--bg / --text 等）を
上書きしてライト/ダーク対応を壊していたため、まず効き先を「札の色」だけに縮めた。
その時点でテーマの差は札の色だけになり、選択UIを残す価値が薄くなったので
運営者の判断で機能ごと外した。選択肢が減るぶん初見の画面も簡素になる。

## 2026-08-08：hasokon.com/tools/ へドメイン統合した

`tool.hasokon.com` から `hasokon.com/tools/`（basePath: /tools）へ移し、旧ドメインは301。

**理由**：サブドメインを分けていると、ドメインの評価が tools / games / home の3つに分散する。
1ドメインに集約したほうが、どのページの成果もサイト全体の評価に積み上がる。
