## 2. 内部リンクとパンくずを足す（tools 側の主な作業）

### 根拠

URL検査の「参照元」を見ると、発見経路が偏っています。

| ページ | 発見された参照元 |
|---|---|
| `/tools/group/`、`/tools/dice/` | `/tools/nenshu-kabe/`（旧ドメインが正規と判定されている弱いページ） |
| `/tools/hebon-romaji/`、`/tools/hankaku-zenkaku/`、`/tools/aspect-ratio/` | 旧サイトマップのみ |
| `/tools/warikan/` | `/tools/sleep-cycle/` |

新規サイトでは、サイトマップだけでクロールを引き出すのは難しいのが実情です。

### 提案する対応

1. **`/tools/` から `/games/` への導線を張る**
   現在フッターは `hasokon.com` トップにしか繋がっておらず、姉妹サイトへは2ホップかかります。
   games 側は9ページ全部が未インデックスなので、tools からリンクを送る意味があります
2. **BreadcrumbList の構造化データを入れる**
   `hasokon.com > 無料計算ツール集 > 年収の壁 計算機`。
   各ページの `page.tsx` は既に `WebApplication` + `FAQPage` の JSON-LD を出しているので、
   同じ場所に足すだけで済みます。共通化するなら `app/ToolMeta.tsx` あたり
3. **`app/RelatedTools.tsx` の露出を確認する**
   関連ツールの一覧は既にありますが、全ページに入っているか、
   リンク先が偏っていないか（同じ数本ばかり指していないか）を点検する

### 期待できる効果

未クロールの6ページがクロール対象に入ります。
順位を上げる施策ではなく「土俵に乗せる」施策なので、効果の出方は分かりやすいです。

### 工数

- 1：半日
- 2：半日（既存のJSON-LDに追記する形）
- 3：2〜3時間（点検のみで済む可能性が高い）

## 3. OGP画像がない（UI/UX・CTR）

`app/layout.tsx` の `openGraph` は `type` / `siteName` / `locale` のみで、
**`og:image` が設定されていません。** home / games も同様です。

計算ツールは「これ便利」と共有されて広がる余地があるので、
LINE・X・Slack に貼られたときのカードが無地なのはもったいない状態です。

**対応**：3サイト共通のOG画像を1枚作り、`layout.tsx` の `openGraph.images` に設定する。
ツールごとに変える必要はありません。

**工数**：半日〜1日（画像デザイン込み。既存のロゴを流用するなら半日）

## 4. プライバシーポリシー・お問い合わせの重複（統合の後始末）

ドメイン統合の副作用で、同一ドメイン内に同じ役割のページが並んでいます。

| 役割 | URL |
|---|---|
| プライバシーポリシー | `/privacy.html`（home）、`/tools/privacy/`、`/games/privacy/` |
| お問い合わせ | `/tools/contact/`、`/games/contact/` |

サブドメインで別サイトだった頃は必要でしたが、いまは1ドメインです。
実際、home の `/privacy.html` が掲載順位16位で表示されており、
少ない表示回数がポリシーページに使われています。

**対応**：ルートの `/privacy.html` に一本化し、`/tools/privacy/` は canonical をルートに向けるか、
フッターのリンク先をルートに変える。
**AdSense の審査要件としてポリシーページ自体は必要なので、削除ではなく集約にする**こと。

**工数**：半日
